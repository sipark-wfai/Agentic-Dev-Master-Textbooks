# 08. 모델 선택 전략 & 비용 관리

> **학습 목표**
> - Cursor 요금제 구조와 Fast Request 개념을 정확히 이해한다
> - 2026년 기준 사용 가능한 모델의 특성과 적합한 용도를 파악한다
> - BYO(Bring Your Own) API Key를 설정하고 비용을 모니터링한다
> - Fast Request를 아끼면서도 생산성을 유지하는 전략을 익힌다

## 1. Cursor 요금제 구조

### 1.1 요금제별 비교

| 요금제 | 월 비용 | Fast Request | Slow Request | 팀 기능 | Privacy Mode |
|--------|---------|-------------|-------------|---------|--------------|
| Free | $0 | 50회/월 | 무제한 | ✗ | ✗ |
| Pro | $20 | 500회/월 | 무제한 | ✗ (개인) | ✗ |
| Business | $40/인/월 | 500회/인/월 | 무제한 | ✓ | ✓ (팀 강제) |

### 1.2 Fast Request vs Slow Request

Fast Request와 Slow Request의 차이는 **모델 품질과 응답 속도**다.

```
Fast Request 사용 모델 (품질 높음, 응답 빠름):
- claude-sonnet-4-5
- claude-opus-4-5
- gpt-4o
- gemini-2.5-pro

Slow Request 사용 모델 (추론 중심):
- o3 (OpenAI)
- 위 모델들의 "느린 요청" 대기열 (Fast 소진 시)

무제한 (Fast Request 소비 안 함):
- Tab (예측 편집) ← 핵심!
- cursor-fast 모델
```

### 1.3 Fast Request 소진 시 동작

```
Fast Request 500회를 모두 사용하면:
→ Slow Request 대기열로 자동 전환
→ 응답 시간 증가 (몇 초~수십 초)
→ 품질은 거의 동일

대안:
1. 다음 달 초기화 대기
2. BYO API Key로 전환
3. 요금제 업그레이드 (Business)
```

## 3. 모델 선택 전략

### 3.1 상황별 모델 선택표

```
[일반 기능 구현]
사용 모델: claude-sonnet-4-5
이유: 코딩 능력 최상위, 속도 빠름, Fast Request 효율적
예시: CRUD API 구현, 컴포넌트 생성, 리팩터링

[복잡한 아키텍처 설계]
사용 모델: claude-opus-4-5
이유: 복잡한 요구사항 분석과 다층적 설계에 강함
예시: 마이크로서비스 분리, 캐싱 전략 설계, 보안 아키텍처

[빠른 질문/답변]
사용 모델: gpt-4o 또는 cursor-fast
이유: 응답 빠름, 단순 질문에 충분한 품질
예시: 문법 확인, 짧은 함수 설명, 오타 찾기

[알고리즘·복잡한 논리]
사용 모델: o3
이유: 단계별 추론 능력 최강
예시: 복잡한 정렬 알고리즘, 최적화 문제, 수학 계산

[대용량 파일 분석]
사용 모델: gemini-2.5-pro
이유: 1M 토큰 컨텍스트로 수십만 줄 코드 한번에 분석
예시: 레거시 코드베이스 전체 분석, 긴 로그 파일 파싱
```

### 3.2 멀티 게시판 프로젝트에서의 모델 전략

```
마일스톤 1 (DB 스키마):
→ claude-sonnet-4-5 (Prisma 스키마 생성)

마일스톤 2 (인증 모듈):
→ claude-sonnet-4-5 (JWT 구현)
→ claude-opus-4-5 (보안 검토 시)

마일스톤 3 (게시판 CRUD):
→ claude-sonnet-4-5 (반복적인 CRUD)
→ Tab (보일러플레이트 생성)

마일스톤 4 (프론트엔드):
→ claude-sonnet-4-5 (SvelteKit 컴포넌트)
→ gpt-4o (디자인 관련 빠른 질문)

버그 수정:
→ claude-sonnet-4-5 (일반 버그)
→ claude-opus-4-5 (원인 불명 복잡한 버그)
```

### 3.3 모델 전환 방법


## 4. BYO (Bring Your Own) API Key 설정

### 4.1 BYO Key의 장점

```
장점:
✓ Cursor Fast Request 한도와 별개로 사용
✓ 최신 모델 즉시 사용 가능
✓ 비용을 직접 통제
✓ 회사 계약 요금 적용 가능 (엔터프라이즈)

단점:
✗ API 호출 비용 직접 부담
✗ 설정 복잡성
✗ 카드 등록 필요
```

### 4.2 Anthropic API Key 설정

```
1. https://console.anthropic.com 접속
2. [API Keys] → [Create Key]
3. 키 이름 입력 (예: cursor-dev)
4. 생성된 키 복사 (sk-ant-으로 시작)

Cursor에서:
Cursor Settings → Models → API Keys → Anthropic
[Add API Key] → 키 붙여넣기 → [Save]
```

### 4.3 OpenAI API Key 설정

```
1. https://platform.openai.com/api-keys 접속
2. [Create new secret key]
3. 키 이름 입력 (예: cursor-production)
4. 생성된 키 복사 (sk-으로 시작)

Cursor에서:
Cursor Settings → Models → API Keys → OpenAI
[Add API Key] → 키 붙여넣기 → [Save]
```

### 4.4 비용 모니터링

```bash
# Anthropic 비용 모니터링
# https://console.anthropic.com/usage

# 주요 확인 항목:
- 모델별 사용량 (claude-sonnet-4-5 vs claude-opus-4-5)
- 일별 토큰 사용량
- 예상 월 비용

# OpenAI 비용 모니터링
# https://platform.openai.com/usage
```

### 4.5 API 비용 예상표 (2026년 기준)

```
claude-sonnet-4-5:
- 입력: $3 / 1M 토큰
- 출력: $15 / 1M 토큰

claude-opus-4-5:
- 입력: $15 / 1M 토큰
- 출력: $75 / 1M 토큰

gpt-4o:
- 입력: $2.50 / 1M 토큰
- 출력: $10 / 1M 토큰

일반적인 Chat 요청: 2,000~5,000 토큰

하루 50번 Chat 사용 시 (sonnet-4-5 기준):
50 × 5,000 토큰 = 250,000 토큰 ≈ $1.5~2/일 ≈ $45~60/월
```

*(가격은 변동될 수 있으므로 [Anthropic 공식 페이지](https://www.anthropic.com/pricing)에서 확인하세요)*

## 5. Fast Request 아끼는 전략

### 5.1 Tab 최대 활용 (Fast Request 0 소비)

```
전략: Tab이 할 수 있는 것은 모두 Tab으로

Tab으로 가능한 것:
✓ 함수 구현체 생성
✓ DTO 필드 연속 생성
✓ 테스트 케이스 연속 생성
✓ Import 구문 추가
✓ CRUD 엔드포인트 연속 생성
✓ 반복 패턴 코드

Tab으로 불가능한 것:
✗ 복잡한 비즈니스 로직 설계
✗ 버그 원인 분석
✗ 멀티파일 변경
```

### 5.2 Cmd+K 활용 (Fast Request 소량 소비)

```
Cmd+K는 Chat보다 Fast Request를 적게 소비한다.
단일 파일의 특정 코드 수정은 Chat보다 Cmd+K 사용 권장.

Cmd+K 적합:
✓ 선택 영역 수정 (단일 파일)
✓ 유효성 검사 추가
✓ 에러 처리 추가
✓ 주석 작성
✓ 코드 리팩터링 (단일 함수)
```

### 5.3 Agent 사용 최적화

```
나쁜 Agent 사용 (Fast Request 낭비):
- 작은 변경을 Agent로 처리
  예: "변수명 하나 바꿔줘" → Chat으로 충분

좋은 Agent 사용 (Fast Request 가치 있게 사용):
- 전체 기능 모듈 구현
  예: "인증 모듈 전체 구현"
- 테스트 코드 일괄 생성
  예: "모든 서비스의 테스트 작성"
```

### 5.4 컨텍스트 최소화

```
불필요한 @멘션 제거:
나쁜 예: @Codebase @Files apps/ @Docs NestJS
→ 거대한 컨텍스트 = Fast Request 많이 소비

좋은 예: @Files apps/backend/src/post/post.service.ts
→ 필요한 파일만 = Fast Request 적게 소비
```

### 5.5 cursor-fast 모델 활용

```
간단한 작업에는 cursor-fast 사용:
- 문법 오류 확인
- 짧은 코드 설명
- 변수명 제안
- 주석 번역

claude-sonnet-4-5는 실제 구현 작업에만 사용
```

## 6. 월별 비용 예측 및 관리

### 6.1 사용 패턴별 비용 예측

```
[가벼운 사용자] - 하루 1~2시간 코딩
- Tab: 무제한 (비용 없음)
- Chat: 하루 20회
- Agent: 주 5회
→ Fast Request: 월 ~200회
→ Pro 요금제($20)로 충분

[일반 개발자] - 하루 4~6시간 코딩
- Tab: 무제한
- Chat: 하루 50회
- Agent: 하루 2~3회
→ Fast Request: 월 ~400회
→ Pro 요금제 + BYO Key 일부 사용 권장

[헤비 유저] - 하루 8시간+ 코딩
- Tab: 무제한
- Chat: 하루 100회+
- Agent: 하루 5회+
→ Fast Request: 월 500회+ 초과
→ Business 요금제 + BYO Key 필수
```

### 6.2 비용 모니터링 대시보드

```
Cursor 사용량 확인:
Cursor Settings → Account → Usage

확인 항목:
- Fast Request 사용량 / 한도
- 모델별 사용 빈도
- 일별 사용 추이

BYO Key 사용량:
- Anthropic: console.anthropic.com/usage
- OpenAI: platform.openai.com/usage
```

### 6.3 월별 예산 설정

```typescript
// .env 파일에 예산 알림 설정 (OpenAI)
// platform.openai.com/account/billing → Usage limits
// Soft limit: $30 (알림만)
// Hard limit: $50 (차단)

// Anthropic
// console.anthropic.com → Settings → Billing → Spending limits
```

## 7. 팀에서의 비용 관리 전략

### 7.1 Business 요금제 팀 관리

```
팀장이 할 일:
1. Business 계정 생성 (팀원 수 × $40/월)
2. 팀원 초대 (이메일 또는 도메인 기반)
3. Privacy Mode 팀 전체 활성화
4. 사용량 대시보드 모니터링

팀원이 할 일:
1. 초대 이메일로 계정 연결
2. Cursor에서 팀 계정으로 로그인
3. Privacy Mode 활성화 확인
```

### 7.2 팀 BYO Key 전략

```
방식 1: 개인 BYO Key (각자 부담)
- 팀원 각자가 API Key 등록
- 개인 사용량 개인 부담
- 관리 분산

방식 2: 팀 BYO Key (회사 부담)
- 회사 Anthropic/OpenAI 계정에서 팀 API Key 생성
- 팀 공유 Key를 각자 등록
- 중앙 모니터링 가능
- 주의: Key 유출 시 전체 팀 영향

방식 3: Cursor Business (권장)
- $40/인/월로 Fast Request 500회 포함
- 사용량 관리 Cursor가 담당
- Privacy Mode, 팀 Rules 공유 등 부가 기능
```

## 8. 실습: 비용 최적화 워크플로우

### 8.1 하루 작업 시작 루틴

```
오전 작업 시작:
1. Fast Request 잔여량 확인
   (Cursor Settings → Account → Usage)
2. 오늘 주요 작업 파악
3. 큰 Agent 작업은 오전에 집중
   (Fast Request가 충분한 시간)
```

### 8.2 Fast Request 절약 패턴

```
오전 (Fast Request 풍부):
→ Agent로 새 기능 구현
→ claude-sonnet-4-5로 복잡한 작업

오후 (Fast Request 절반 이상 사용):
→ Tab 위주로 작업
→ cursor-fast 모델로 간단한 질문
→ Cmd+K로 단일 파일 수정

저녁 (Fast Request 소진 임박):
→ Tab만 사용
→ 내일을 위해 남기기 또는 BYO Key 전환
```

### 8.3 Agent 일괄 처리

```
Fast Request 효율 극대화:
→ 관련 작업을 묶어서 한번의 Agent 실행

나쁜 방법:
Agent 1: "UserController 만들어줘"
Agent 2: "UserService 만들어줘"
Agent 3: "UserModule 만들어줘"
(3번의 Agent = 3배 Fast Request 소비)

좋은 방법:
Agent 1: "User 모듈 전체 만들어줘. 
          UserController, UserService, UserModule, 
          CreateUserDto, UpdateUserDto 모두 포함."
(1번의 Agent = 1배 Fast Request 소비)
```

## 9. 고급 비용 시나리오별 권장 설정

### 9.1 스타트업 초기 (예산 제한)

```
상황: 1~2인 개발, 예산 최소화
권장:
- 요금제: Pro ($20/월)
- BYO Key: 없음 (월 500회 Fast Request 내에서 관리)
- 기본 모델: claude-sonnet-4-5
- Tab 의존도: 80% 이상
- Agent: 주요 기능 1개당 1회

절약 팁:
- 오전에 Agent 몰아서 실행 (하루 2~3회로 제한)
- 반복 작업은 무조건 Tab
- 간단한 질문은 cursor-fast 모델
```

### 9.2 개인 개발자 (일반 사용)

```
상황: 일 4~6시간 코딩, 생산성 중시
권장:
```
