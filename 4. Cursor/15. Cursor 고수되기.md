## 2. Fast Request 절약 고급 전략

### 2.1 Tab을 최대한 활용하는 5가지 기법

**기법 1: 함수 시그니처 먼저, 구현은 Tab으로**
```typescript
// 함수 이름과 파라미터만 작성
async findBoardsByUser(userId: string, options: PaginationDto): Promise<PaginatedResult<Board>> {
  // [Tab] → 구현 전체 생성
}
```

**기법 2: 주석으로 의도 선언 후 Tab**
```typescript
// 투표 마감 여부 확인 (expiresAt이 null이거나 미래이면 활성)
// 이미 투표한 사용자는 다시 투표 불가
// allowMultiple이 false이면 optionIds는 1개여야 함
async validateVote(postId: string, userId: string, optionIds: string[]) {
  // [Tab] → 주석을 이해하고 구현
}
```

**기법 3: 반복 패턴은 첫 번째만 직접 작성, 나머지는 Tab**
```typescript
// 첫 번째 DTO 직접 작성
export class CreateNoticeDto {
  @IsString() @MinLength(2) @MaxLength(100) title: string;
  @IsString() @MinLength(10) content: string;
  @IsBoolean() @IsOptional() isPinned?: boolean;
}

// 두 번째부터는 "export class CreateFree" 까지만 쓰고 Tab
export class CreateFreeDto {
  // [Tab] → 비슷한 패턴으로 자동 생성
}
```

**기법 4: 테스트 첫 케이스만 작성, 나머지는 Tab**
```typescript
it('정상적으로 게시글 목록을 반환한다', async () => {
  // 첫 번째 테스트 직접 작성
});
// [Tab] → 두 번째 테스트 케이스 자동 제안
```

**기법 5: import 구문 자동 완성**
```typescript
// 코드에서 JwtService를 사용하면
// 파일 상단에서 Tab → import 자동 추가
import { JwtService } from '@nestjs/jwt';  // ← Tab으로 생성
```

### 2.2 Chat을 최소화하는 전략

```
Chat 대신 Cmd+K 사용:
- 단일 파일의 특정 코드 수정: Cmd+K (Fast Request 적게 소비)
- 여러 번 수정 필요한 경우: Chat (맥락 유지)

Claude-fast 모델 적극 활용:
- 문법 설명, 짧은 함수 질문: cursor-fast
- 실제 코드 생성: claude-sonnet-4-5

Notepads로 반복 컨텍스트 절약:
- 자주 참조하는 패턴 → Notepad 저장
- Chat에서 @Notepads로 참조 (파일 전체 포함보다 가볍게)
```

### 2.3 Agent 효율 극대화

```
1회 Agent로 최대 작업량 처리:
나쁜 방법 (3회 Fast Request 소비):
  Agent 1: Controller 만들어줘
  Agent 2: Service 만들어줘
  Agent 3: DTO 만들어줘

좋은 방법 (1회 Fast Request 소비):
  Agent: Controller, Service, DTO 전체 모듈을 한 번에 만들어줘

Agent 전 준비로 재실행 방지:
  - Git 커밋 상태 확인
  - 지시문 3번 검토
  - 범위와 완료 기준 명시
```

## 3. 팀 협업에서 Cursor 활용

### 3.1 팀 공유 .cursor/rules 관리

`.cursor/rules`를 Git으로 관리하면 팀 전체가 동일한 AI 동작을 경험한다.

```bash
# .cursor/rules는 .gitignore에 포함하지 않음
# (기본적으로 .gitignore에 없음)

# 팀 Rules 업데이트 절차
git checkout -b chore/update-cursor-rules
# rules 파일 수정
git add .cursor/rules
git commit -m "chore(rules): 소프트 삭제 패턴 명시 추가"
git push
# PR 통해 리뷰 후 병합
```

```markdown
# .cursor/rules에 추가 (팀 설정)

## 팀 컨벤션
- 브랜치 전략: feature/[기능명], fix/[버그명], chore/[작업명]
- 커밋 메시지: conventional commits 형식
  feat, fix, docs, style, refactor, test, chore
- PR: 기능 단위로 작성, 리뷰어 1명 이상 필수
- 코드 리뷰: Cursor Chat으로 리뷰 후 PR 등록 권장

## 팀원별 역할
- 백엔드: apps/backend/ 담당
- 프론트엔드: apps/frontend/ 담당
- 공용: docs/, .cursor/, docker-compose.yml
```

### 3.2 팀원별 BYO Key 설정

```
방식 1: 개인 Key (권장)
- 각 팀원이 자신의 Anthropic/OpenAI Key 등록
- 개인 사용량 개인 부담
- Key 유출 시 영향 범위 최소화

방식 2: 팀 Key
- 팀장이 하나의 Key 생성

### 3.3 PR 리뷰에 Chat 활용

```
PR 리뷰 프로세스:
1. 변경된 파일을 @Files로 Chat에 포함
2. Chat에서 리뷰 요청:
   "@Files [변경된 파일들]
   이 PR을 리뷰해줘:
   - .cursor/rules에 위배되는 패턴 있는지
   - 보안 취약점 있는지
   - 성능 문제 있는지
   - 테스트 누락된 케이스 있는지"
3. AI 리뷰 결과를 참고하여 실제 PR 코멘트 작성

주의: AI 리뷰는 보조 수단이며, 팀원 간 직접 리뷰 대체 불가
```

## 4. Privacy Mode 완전 가이드

### 4.1 Cursor의 데이터 처리 방식

```
기본 모드:
코드 → Cursor 서버 → AI 모델 처리 → 결과 반환
- 코드가 Cursor 서버를 통과
- 처리 후 즉시 삭제 (학습에 사용 안 함)
- SOC 2 Type II 인증 준수

Privacy Mode:
코드 → 직접 AI 모델 처리 → 결과 반환
- 코드가 Cursor 서버에 저장되지 않음
- AI 처리 완료 즉시 삭제
- 로그, 캐시 없음
```

### 4.2 어떤 데이터가 전송되는가

```
전송되는 것:
✓ 코드 내용 (컨텍스트로 포함된 것)
✓ Chat 메시지
✓ 사용 통계 (익명화)

전송되지 않는 것:
✗ 로컬 환경변수 (.env 파일 - .gitignore에 있으면)
✗ 시스템 파일
✗ .cursorignore에 포함된 파일
```

### 4.3 Privacy Mode 활성화

```
개인 계정:
Cursor Settings → General → Privacy Mode → Enable

Business 계정 (팀 전체 적용):
Cursor Admin → Organization Settings → Privacy Mode → Force Enable

확인 방법:
Settings 우측 상단에 "Privacy Mode: ON" 배지
```

### 4.4 SOC 2 인증의 의미

```
SOC 2 Type II 인증:
- 독립 감사 기관이 보안 통제 검증
- 데이터 보안, 가용성, 처리 무결성 평가
- 6개월+ 기간 동안 실제 운영 검증

의미:
- 코드가 무단으로 사용·저장되지 않음을 제3자가 검증
- 엔터프라이즈 보안 요구사항 충족
- 금융·의료·공공 분야 사용 가능 기반
```

## 5. Cursor와 Claude Code 함께 사용하기

### 5.1 각 도구의 강점 비교

| 작업 유형 | Cursor | Claude Code |
|-----------|--------|-------------|
| 코드 작성/편집 | 최강 | 가능 |
| 멀티파일 시각화 | 최강 | 불편 |
| CI/CD 자동화 | 불편 | 최강 |
| 스크립트 자동화 | 가능 | 최강 |
| 배포 작업 | 불편 | 최강 |
| 터미널 자동화 | 제한적 | 네이티브 |
| 대화형 코드 탐색 | 최강 | 가능 |

### 5.2 통합 워크플로우

```
[개발 단계] → Cursor
- PRD 작성, 설계서 작성 (Chat)
- 코드 구현 (Tab + Agent)
- 코드 리뷰 (Chat)
- 버그 수정 (Chat + Cmd+K)

[자동화 단계] → Claude Code
- 테스트 자동화 실행
- 빌드 파이프라인
- 배포 스크립트

[전환 기준]
Cursor → Claude Code: "이 작업이 터미널 자동화가 필요한가?"
Claude Code → Cursor: "이 작업이 파일 편집이 필요한가?"
```

## 6. 유용한 VS Code 확장 + Cursor 조합

- GitHub Pull Requests: PR 에디터에서 리뷰

언어 지원:
- Svelte for VS Code: SvelteKit 개발 필수
- Prisma: Prisma 스키마 자동완성, 포맷

```
Error Lens + Cursor Tab:
- Error Lens가 인라인으로 에러 표시
- Cursor Tab이 에러를 보고 수정 제안
- 에러를 보면서 Tab으로 즉시 수정

GitLens + @Git:
- GitLens로 누가 언제 작성했는지 시각화
- @Git으로 AI가 커밋 이력 분석
- "이 코드가 왜 이렇게 됐는지" 파악 빠름

Prisma + Tab:
- Prisma 확장: 스키마 구문 하이라이팅
- Tab: 스키마 모델 연속 생성
- 두 가지 조합으로 DB 스키마 작업 극히 빠름

## 이 시리즈의 마지막 말

이 15편 시리즈를 완주했다면, 이제 Cursor를 단순한 에디터가 아닌 **AI와 함께 개발하는 환경**으로 완전히 이해한 것이다.

핵심을 기억하자.

1. **Rules가 모든 것을 결정한다**: Rules 없는 Cursor는 일반 에디터다
2. **Tab은 항상 켜져 있어야 한다**: 무료이고, 빠르고, 프로젝트 패턴을 학습한다
3. **Agent 전에 반드시 Git 커밋**: 잘못되면 언제든 돌아올 수 있어야 한다
4. **문서가 코드의 품질을 결정한다**: PRD와 설계서가 정밀할수록 Agent의 코드도 정밀하다
5. **비용을 의식하는 것이 고수의 습관**: Fast Request는 생각보다 빠르게 소진된다

이제 직접 프로젝트에 적용하고, 경험을 쌓아가는 일만 남았다.
