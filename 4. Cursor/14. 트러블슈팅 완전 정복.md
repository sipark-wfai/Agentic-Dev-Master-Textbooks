# 14. 트러블슈팅 완전 정복

> **학습 목표**
> - 트러블슈팅 진단 프레임워크(A~F 유형)를 이해한다
> - 20가지 오류 시나리오의 원인·증상·해결·예방을 숙지한다
> - Git을 활용한 비상 복구 절차를 익힌다

---

## 1. 트러블슈팅 진단 프레임워크

### 1.1 오류 유형 분류

| 유형 | 이름 | 대표 증상 |
|------|------|-----------|
| A | 환경/인증 오류 | 로그인 실패, API Key 오류 |
| B | 인덱싱/컨텍스트 오류 | Tab 미작동, @Codebase 결과 부정확 |
| C | Agent 실행 오류 | 무한루프, 잘못된 파일 수정 |
| D | 코드 품질 오류 | 빌드 실패, TypeScript 에러 |
| E | 런타임 오류 | DB 연결 실패, CORS 오류 |
| F | 컨텍스트 오염 | AI 응답 일관성 저하 |

### 1.2 1차 진단 절차

```
문제 발생 →
1. 에러 메시지 전문 복사
2. 유형(A~F) 분류
3. 해당 유형의 해결법 적용
4. 해결 안 될 시: Cursor 재시작 + Git 복구 고려
```

## 2. 오류 시나리오 20가지

### 오류 1: Cursor 로그인 실패 / 계정 인증 오류 [유형 A]

**증상**
```
"Failed to sign in"
"Authentication error"
Cursor 실행 시 로그인 화면이 계속 뜸
```

**원인**
- 인터넷 연결 불안정
- 방화벽/VPN 차단
- 브라우저 쿠키 문제 (소셜 로그인 시)
- Cursor 서버 장애

**해결**
```
1. 인터넷 연결 확인
2. VPN 비활성화 후 재시도
3. Cursor 캐시 삭제:
   macOS: rm -rf ~/Library/Caches/Cursor/
   (주의: ~/Library/Application Support/Cursor/ 전체 삭제 시 설정까지 초기화됩니다. 캐시만 삭제하려면 ~/Library/Caches/Cursor/ 를 사용하세요)
   Windows: %LOCALAPPDATA%\Cursor\Cache 삭제
4. 브라우저에서 cursor.com 직접 접속하여 로그인 <!-- R3 수정: cursor.com → cursor.com 도메인 이전 -->
5. GitHub 소셜 로그인 → 이메일/비밀번호 로그인으로 전환
```

**예방**
```
- 안정적인 네트워크 환경에서 사용
- 회사 방화벽 환경: cursor.com, cursor.com, anthropic.com 화이트리스트 등록 <!-- R3 수정: cursor.com 추가 -->
```

### 오류 2: 코드베이스 인덱싱 실패 [유형 B]

**증상**
```
상태 바에 "Indexing failed" 또는 인덱싱 진행이 멈춤
@Codebase 검색 시 "No results found"
```

**원인**
- node_modules/ 등 대용량 폴더 포함
- 파일 수 너무 많음 (10만 파일 이상)
- 심볼릭 링크 문제
- 디스크 용량 부족

**해결**
```bash
# 1. .cursorignore 파일 생성/수정
cat > .cursorignore << 'EOF'
node_modules/
dist/
build/
coverage/
.git/
*.log
*.lock
EOF

# 2. 인덱싱 재실행
Cmd+Shift+P → "Cursor: Reindex Codebase"

# 3. Cursor 재시작
```

**예방**
```
프로젝트 생성 시 즉시 .cursorignore 생성
```

### 오류 3: Tab 제안이 뜨지 않는 경우 [유형 B]

**증상**
```
코드 입력 중 회색 제안 텍스트가 나타나지 않음
```

**원인**
- Tab 기능 비활성화
- 인덱싱 미완료
- 모델 로딩 실패
- 파일이 .cursorignore에 포함됨

**해결**
```
1. Cursor Settings → Features → Tab → Enable Cursor Tab: ON 확인
2. 상태 바 하단 Tab 아이콘 → Enabled 확인
3. 인덱싱 완료 대기 (상태 바에서 확인)
4. Cursor 재시작
5. 다른 파일에서 Tab 테스트 → 특정 파일 문제인지 확인
```

### 오류 4: Agent가 잘못된 파일을 수정하는 경우 [유형 C]

**증상**
```
Agent가 명시하지 않은 파일을 수정함
다른 모듈의 파일에 영향을 줌
```

**원인**
- 지시문에 범위 제한 없음
- @Files로 참조 파일을 지정하지 않음
- Agent가 의존성을 따라 너무 많은 파일 수정

**해결**
```
1. Esc로 Agent 즉시 중단
2. 잘못 수정된 파일 Git으로 복구:
   git checkout -- apps/backend/src/wrong-file.ts

3. 지시문 수정 (범위 제한 추가):
   나쁜: "인증 기능을 개선해줘"
   좋은: "@Files apps/backend/src/auth/ 이 폴더 안에서만 작업해줘"
```

**예방**
```
Agent 지시문에 항상 범위 제한 포함:
"@Files [작업할 폴더] 이 폴더 안에서만 작업해줘"
```

### 오류 5: Agent 무한 루프 / 멈춤 [유형 C]

**증상**
```
같은 파일을 계속 수정하고 완료하지 못함
10분 이상 진행이 없음
"Thinking..." 상태가 지속됨
```

**원인**
- 목표가 모호하여 Agent가 판단 불가
- 컴파일 에러를 수정하다가 새 에러 발생 반복
- 컨텍스트 창 오버플로우

**해결**
```
1. Esc로 Agent 중단
2. Git으로 변경 취소:
   git checkout -- .
3. 지시문을 더 작은 단위로 분리
4. 완료 기준 명시 ("빌드 성공 후 종료")
```

### 오류 14: Prisma 마이그레이션 충돌 [유형 E]

**증상**
```
Error: P3006 - Migration failed
Error: There is 1 migration that could not be applied
Drift detected between your database and your migration history
```

**해결**
```bash
# 1. 마이그레이션 상태 확인
pnpm prisma migrate status

# 2. 개발 환경: DB 리셋 후 재마이그레이션
pnpm prisma migrate reset  # 경고: 모든 데이터 삭제!
pnpm prisma migrate dev

# 3. 마이그레이션 기록 수동 수정
pnpm prisma migrate resolve --applied [migration-name]

# 4. 충돌하는 마이그레이션 파일 삭제 후 재생성
rm prisma/migrations/[충돌_마이그레이션]/
pnpm prisma migrate dev --name [새_이름]
```

**예방**
```
- 마이그레이션 전 git commit
- schema.prisma 수정 후 즉시 migrate dev 실행
- 팀 작업 시 마이그레이션 파일 충돌 방지 (브랜치 전략)
```

### 오류 16: NestJS 의존성 주입 오류 [유형 D]

**증상**
```
Error: Nest can't resolve dependencies of the PostService (?).
Please make sure that the argument PrismaService is available
```

**원인**
- 필요한 모듈이 imports에 없음
- Provider가 등록되지 않음
- Circular Dependency

**해결**
```typescript
// 1. PostModule에 필요한 모듈 추가 확인
@Module({
  imports: [PrismaModule],  // ← 누락된 경우
  providers: [PostService],
  controllers: [PostController],
})
export class PostModule {}

// 2. PrismaModule이 Global인지 확인
@Global()  // ← 이 데코레이터가 있으면 imports 불필요
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}

// 3. Circular Dependency: forwardRef 사용
@Inject(forwardRef(() => UserService))
private readonly userService: UserService
```

```
AI 응답이 이전과 다르게 모순됨

응답 품질이 갈수록 저하됨
긴 대화 후 AI가 혼란스러운 답변을 함
```

**원인**
- 대화 이력이 너무 많아 컨텍스트 창이 과부하
- 잘못된 가정이 대화에 쌓임
- 여러 다른 주제가 혼재

**해결**
```
New Chat이 필요한 신호:
- 같은 질문에 대화마다 다른 답변
- AI가 "이전에 구현한 것"이라고 잘못 말함
- 응답 속도가 갑자기 느려짐
- 대화가 30~50 턴 이상 지속됨

해결:
1. Cmd+N → New Chat 시작
2. 새 Chat에서 현재 상태 재설명
3. 필요한 @Files, @Docs 참조 다시 지정
```

**예방**
```
- 작업 단위를 마칠 때마다 New Chat
- 완전히 다른 기능 시작 시 New Chat
- 긴 대화는 Notepad에 중요 내용 저장 후 New Chat
```

## 3. Git 비상 복구 절차

### 3.1 Agent가 잘못 수정한 경우

```bash
# 현재 변경 내용 확인
git diff

# 특정 파일만 복구
git checkout -- apps/backend/src/post/post.service.ts

# 여러 파일 복구
git checkout -- apps/backend/src/post/

# 모든 변경 취소
git checkout -- .

# 커밋 이전 상태로 완전 복구
git reset --hard HEAD
```

### 3.2 최근 커밋으로 롤백

```bash
# 최근 커밋 내역 확인
git log --oneline -10

# 특정 커밋으로 롤백 (작업 내역 보존)
git revert HEAD
git revert [커밋 해시]

# 특정 커밋으로 완전 롤백 (위험! 이후 커밋 삭제)
git reset --hard [커밋 해시]
```

### 3.3 Agent 작업 전 안전망 만들기

```bash
# Agent 실행 전 항상 커밋
git add -A
git commit -m "chore: Agent 작업 전 스냅샷"

# 또는 임시 브랜치 생성
git checkout -b temp/agent-work
# Agent 작업...
# 결과가 좋으면: main으로 merge
# 결과가 나쁘면: 브랜치 삭제, main으로 복귀
git checkout main
git branch -D temp/agent-work
```

## 4. 자주 나오는 에러 메시지 해석표

| 에러 메시지 | 유형 | 빠른 해결 |
|------------|------|-----------|
| `Cannot find module` | D | import 경로 확인, pnpm install |
| `Type 'X' is not assignable to type 'Y'` | D | 타입 불일치, 타입 가드 추가 |
| `Property 'X' does not exist on type 'Y'` | D | 인터페이스 정의 확인 |
| `P2002 Unique constraint failed` | E | 중복 데이터, 409 처리 추가 |
| `P2025 Record not found` | E | 소프트 삭제 필터 확인 |
| `401 Unauthorized` | A | JWT 토큰 확인, 만료 여부 |
| `403 Forbidden` | A | 사용자 역할 확인 |
| `ECONNREFUSED` | E | Docker 컨테이너 실행 확인 |
| `Cannot read properties of undefined` | D | null 체크 추가 |
| `window is not defined` | D | SSR 환경, browser 가드 추가 |
