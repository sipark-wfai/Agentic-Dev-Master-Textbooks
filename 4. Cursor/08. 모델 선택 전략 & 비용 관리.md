### 1.1 요금제별 비교

### 1.2 과금 방식: 토큰 기반 (2025년 6월부터)

2025년 6월부터 Cursor는 **요청(Request) 수 기반**에서 **토큰(Token) 사용량 기반** 과금으로 전환했다.

```
새 방식 (2025년 6월부터):
- 입력 토큰 + 출력 토큰 합산 과금
- 플랜에 따라 월 토큰 쿼터 제공
- 초과 시 BYO Key 사용 또는 상위 플랜 업그레이드

영향:
- 짧은 질문은 토큰 소비 적음 → 유리
- 대규모 컨텍스트(@Codebase 등)는 토큰 소비 많음 → 주의
- Tab 자동완성은 별도 쿼터 (토큰 기반 과금 제외)
```

## 4. BYO (Bring Your Own) API Key 설정

### 4.1 BYO Key의 장점

```
장점:
✓ Cursor 플랜 크레딧 한도와 별개로 사용
✓ 최신 모델 즉시 사용 가능
✓ 비용을 직접 통제
✓ 회사 계약 요금 적용 가능 (엔터프라이즈)

단점:
✗ API 호출 비용 직접 부담
✗ 카드 등록 필요
```

### 4.2 API Key 설정

```
Anthropic:
Cursor Settings → Models → API Keys → Anthropic
→ sk-ant-으로 시작하는 키 입력

OpenAI:
Cursor Settings → Models → API Keys → OpenAI
→ sk-으로 시작하는 키 입력
```

### 4.3 API 비용 예상표 (2026년 기준 참고)

```
claude-sonnet-4-6:
- 입력: $3 / 1M 토큰
- 출력: $15 / 1M 토큰

claude-opus-4-6:
- 입력: $15 / 1M 토큰
- 출력: $75 / 1M 토큰
```

*(가격은 변동될 수 있으므로 [Anthropic 공식 페이지](https://www.anthropic.com/pricing)에서 확인)*

## 5. 크레딧 아끼는 전략

### 5.1 Tab 최대 활용 (크레딧 0 소비)

```
Tab으로 가능한 것:
✓ 함수 구현체 생성
✓ DTO 필드 연속 생성
✓ 테스트 케이스 연속 생성
✓ CRUD 엔드포인트 연속 생성
✓ 반복 패턴 코드
```

### 5.2 Auto 모드 활용

```
Auto 모드: Cursor가 작업에 맞는 최적 모델 자동 선택
→ 비용-품질 자동 균형
→ Teams 플랜에서 비-Auto 추가 과금 방지
```

### 5.3 컨텍스트 최소화

```
나쁜 예: @Codebase @Files apps/ @Docs NestJS
→ 거대한 컨텍스트 = 크레딧 많이 소비

좋은 예: @Files apps/backend/src/post/post.service.ts
→ 필요한 파일만 = 크레딧 적게 소비
```
