# 11. PRD를 코드로

> **학습 목표**
> - PRD의 기능 요구사항을 Agent 지시문으로 변환하는 방법을 익힌다
> - Plan Mode로 구현 계획을 검토하고 단계별로 실행한다
> - 마일스톤 단위로 Agent를 실행하여 전체 기능을 구현한다
> - 구현 완료 기준을 검증하는 방법을 익힌다

---

## 1. PRD → Agent 지시문 변환 원칙

### 1.1 변환 공식

```
PRD 요구사항:
[AUTH-001] 회원가입
- 입력: email, password, name
- 출력: 201, User 객체
- 에러: 400, 409

↓ 변환 ↓

Agent 지시문:
"@Docs docs/prd.md @Docs docs/erd.md
[AUTH-001] 회원가입 API를 구현해줘.

요구사항:
- 이메일, 비밀번호, 이름을 받아서 User를 생성
- 비밀번호: bcrypt(cost 12) 해시
- 기본 role: USER
- 이미 존재하는 이메일이면 409 Conflict

파일 위치:
- apps/backend/src/auth/auth.service.ts
- apps/backend/src/auth/dto/register.dto.ts

완료 기준:
- pnpm build 에러 없음
- 유효성 검사 (class-validator)
- TypeScript 타입 에러 없음"
```

---

## 2. Plan Mode로 사전 계획 수립

### 2.1 Plan Mode 활용 흐름

```
1단계: Plan 모드로 계획 수립
Composer → [Plan] 버튼

"@Docs docs/prd.md M2 인증 시스템 전체를 구현하기 위한
단계별 계획을 수립해줘.
코드는 아직 작성하지 마."

2단계: 계획 검토
AI가 제시한 계획:
- 1. 데이터베이스 스키마 (RefreshToken 모델)
- 2. AuthModule, AuthController, AuthService 생성
- 3. JWT 전략 구현 (jwt.strategy.ts)
- 4. Guards 구현 (jwt-auth.guard.ts)
- 5. DTO 유효성 검사 설정
- 6. app.module.ts에 AuthModule 등록

3단계: 계획 승인 후 실행
"이 계획대로 구현해줘"
```

## 3. 마일스톤별 Agent 실행 전략

### 3.1 M1: DB 스키마 구현

```
지시문:
"@Docs docs/erd.md ERD를 참조해서
apps/backend/prisma/schema.prisma를 작성해줘.

요구사항:
- ERD의 모든 모델과 관계 반영
- 모든 모델에 softDelete (deletedAt: DateTime?)
- 모든 모델에 createdAt, updatedAt 자동 관리
- User, Post, Board, Comment에 적절한 인덱스 추가

완료 기준:
- pnpm prisma validate 통과
- 모든 ERD 엔티티가 스키마에 포함됨"
```

### 3.2 M2: 인증 시스템

```
지시문:
"@Docs docs/prd.md M2 인증 시스템을 구현해줘.
@Files apps/backend/src/ 기존 구조를 파악하고
AUTH-001~AUTH-004 모두 구현해줘.

완료 기준:
- pnpm build 에러 없음
- JwtAuthGuard가 정상 작동
- AuthModule이 AppModule에 등록됨
- class-validator 유효성 검사 포함"
```

### 3.3 M3: 게시글 CRUD

```
지시문:
"@Docs docs/prd.md M3 게시글 CRUD API를 구현해줘.
@Files apps/backend/src/auth/ 인증 가드를 그대로 활용해줘.

특히 중요한 요구사항:
- 게시판 타입별 유효성 검사 (GALLERY: 이미지 필수 등)
- 소프트 삭제 (deletedAt)
- 페이지네이션
- 권한 검사 (작성자 또는 BOARD_ADMIN만 수정/삭제)

완료 기준:
- pnpm build 에러 없음
- GET /api/v1/posts?boardId=... 페이지네이션 동작"
```

## 4. 구현 완료 기준 검증

### 4.1 빌드 검증

```bash
# 터미널에서 (Ctrl+` 로 Cursor 내장 터미널)
cd apps/backend
pnpm build

# 에러 없이 빌드 성공해야 함
# dist/ 폴더가 생성되어야 함
```

### 4.2 TypeScript 타입 검증

```bash
pnpm tsc --noEmit
# 타입 에러 없어야 함
```

### 4.3 API 동작 검증

```bash
# Swagger UI로 확인
pnpm dev
# http://localhost:3000/api 접속

# 또는 curl로 직접 테스트
curl -X POST http://localhost:3000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"Pass1234!","name":"테스트"}'
```
