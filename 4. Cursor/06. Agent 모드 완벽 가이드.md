## 1. Agent(Composer)란

### 1.1 Chat과 Agent의 근본적 차이

Chat(Cmd+L)은 AI와 대화하며 개발자가 Apply를 클릭해야 코드가 적용된다. 반면 Agent(Composer)는 **스스로 파일을 읽고, 계획을 세우고, 코드를 작성하고, 수정하는 자율 에이전트**다.

```
Chat 흐름:
개발자 → 지시 → AI 응답 → 개발자 Apply 클릭 → 코드 적용
(매 단계 개발자 개입 필요)

Agent 흐름:
개발자 → 목표 지정 → Agent 자율 실행 → 완료 후 검토 요청
(Agent가 여러 파일을 알아서 작업)
```

### 1.2 Agent가 할 수 있는 것

```
✓ 여러 파일을 동시에 읽고 이해
✓ 새 파일 생성
✓ 기존 파일 수정
✓ 파일 삭제 (승인 후)
✓ 터미널 명령어 실행 (설정 시)
✓ 에러 발생 시 자체 수정 시도
✓ 변경 파일 목록 제공
✓ 각 변경 사항에 대한 설명 제공
```

### 1.3 언제 Agent를 사용하는가

```
Agent 적합:
✓ 새로운 기능 전체 구현 (모듈 단위)
✓ 전체 리팩터링
✓ 여러 파일에 걸친 버그 수정
✓ 새 프로젝트 기본 구조 생성
✓ 테스트 코드 일괄 생성

Chat/Cmd+K 적합:
✓ 단일 파일 수정
✓ 짧은 코드 조각 생성
✓ 코드 설명 요청
✓ 빠른 질문/답변
```

## 2. Agent 실행 방법

### 2.1 Composer 탭 열기

```
방법 1: Cmd+I
방법 2: 에디터 우측 상단 [Composer] 아이콘 클릭
방법 3: View 메뉴 → Composer
방법 4: Cmd+L로 Chat 열기 → 상단 [Composer] 탭 선택
```

### 2.2 Agent 모드 vs Normal 모드

```
Normal 모드: Chat과 유사, 파일 수정 제안만 함
Agent 모드: 자율적으로 파일을 읽고 수정

Agent 모드 활성화:
Composer 하단 → [Agent] 토글 클릭 (또는 기본값으로 설정)
```

## 3. Agent 작동 원리

### 3.1 4단계 실행 흐름

```
1단계: 파일 읽기
Agent가 @멘션된 파일, 관련 파일, .cursor/rules를 읽음

2단계: 계획 수립
변경할 파일 목록과 각 파일에서 할 작업을 계획

3단계: 코드 작성
파일을 하나씩 수정하며 진행 상황을 실시간 표시

4단계: 검토 요청
"모든 변경을 완료했습니다. 검토해주세요."
```

### 3.2 개별 수락/거절

```
[Accept All]: 모든 파일 변경 수락
[Reject All]: 모든 변경 취소
개별 파일 클릭 → diff 상세 보기 → 줄 단위 수락/거절
```

## 4. Background Agent

### 4.1 Background Agent란

일반 Agent는 Composer 패널이 열려 있는 동안 실행된다. Background Agent는 **백그라운드에서 독립적으로 실행**되어, 개발자가 다른 작업을 하는 동안 Agent가 큰 태스크를 처리한다.

```
Background Agent 활성화:
Cursor Settings → Features → Background Agent → Enable

실행 방법:
Composer에서 지시문 작성 후 [Run in Background] 버튼 클릭
```

### 4.2 최대 8개 동시 실행 (2026년 2월)

<!-- R6 수정: 최대 8개 동시 실행(git worktree 기반) 추가 -->

2026년 2월 업데이트로 **최대 8개의 Background Agent를 동시에 실행**할 수 있게 되었다. 각 Agent는 **git worktree** 기반으로 독립된 작업 공간을 사용한다.

```
Background Agent 동시 실행 구조:
Agent 1: feature/auth-module    (git worktree 1)
Agent 2: feature/post-api       (git worktree 2)
Agent 3: feature/frontend-board (git worktree 3)
...최대 8개 동시 실행...

활용 시나리오:
- 서로 의존성이 없는 여러 기능을 병렬로 구현
- 8개의 마이크로서비스를 동시에 리팩터링
- 여러 버그 픽스를 동시에 진행
```

### 4.3 독립 VM 환경 (Computer Use 통합)

<!-- R6 수정: 독립 VM 풀 데스크톱 환경 설명 강화 (R5 검증보고서 🟡 반영) -->

2026년 2월 업데이트로 Background Agent에 **Computer Use**가 통합되었다. 각 Background Agent는 **독립된 VM 환경**에서 실행되며, 브라우저를 포함한 **풀 데스크톱 환경**을 가진다.

```
Cloud Agent (Background Agent) VM 환경:
✓ 독립 VM (다른 Agent와 완전히 격리)
✓ 풀 데스크톱 환경 (GUI 포함)
✓ 브라우저 내장 (웹 앱 자동 조작 가능)
✓ 터미널 명령 실행
✓ 파일 시스템 직접 접근

활용 예:
"로그인 페이지를 열고 회원가입 E2E 테스트를 실행한 뒤 스크린샷을 첨부해줘"
→ Background Agent가 VM 내 브라우저를 열고 직접 테스트 수행
→ 결과 스크린샷 + 로그 자동 첨부
```

### 4.4 BugBot Autofix

Agent 모드와 연동되는 **BugBot Autofix**는 GitHub PR에서 발견된 이슈를 자동으로 수정하는 기능이다. 2026년 2월 fixer 모드로 업그레이드되어 PR에 직접 수정안을 제안한다.

```
BugBot Autofix 동작 방식:
1. GitHub PR 생성 시 BugBot이 자동으로 코드 리뷰
2. 버그·보안 취약점·성능 이슈 감지
3. Autofix 버튼 클릭 → Agent가 자동으로 수정 커밋 생성

성능 수치 (공식 확인):
- PR merge rate: 약 35% (Autofix가 직접 PR로 이어지는 비율)
- 사용자 해결률(resolution rate): 약 76%

설정: Cursor Settings → Features → BugBot → Enable GitHub Integration
```

> **주의**: 2026년 6월 이후 BugBot 갱신 시 usage-based billing으로 전환됩니다.

## 6. Agent Skills (오픈 표준)

Cursor의 **Agent Skills**는 에이전트 기능을 확장하는 오픈 표준(open standard)으로 설계되어 있다. `SKILL.md` 파일과 `scripts/`, `references/`, `assets/` 디렉토리로 구성된 스킬 패키지를 `.cursor/skills/`에 배치하면 Agent가 자동으로 발견하여 활용한다.

```
.cursor/skills/
└── my-skill/
    ├── SKILL.md       ← 스킬 설명 (Agent가 읽는 파일)
    ├── scripts/       ← 실행 스크립트
    ├── references/    ← 참조 문서
    └── assets/        ← 이미지·설정 파일
```

## 7. Agent 툴콜 제한 이해

```
표준 Agent 모드: 최대 25회 툴콜
Max 모드:        최대 200회 툴콜 (Ultra 플랜 이상 또는 추가 비용)

툴콜 소진 시:
→ Agent가 작업을 완료하지 못하고 멈춤
→ "계속해줘" 또는 새 세션으로 나머지 작업 진행
→ 큰 작업은 여러 마일스톤으로 분할하여 각각 Agent 실행 권장
```
