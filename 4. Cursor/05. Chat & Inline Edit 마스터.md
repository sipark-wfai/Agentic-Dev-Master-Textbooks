# 05. Chat & Inline Edit 마스터

> **학습 목표**
> - Chat(Cmd+L)으로 코드를 질문하고, Apply로 직접 적용하는 방법을 익힌다
> - Inline Edit(Cmd+K)으로 빠르게 특정 코드를 수정하는 방법을 익힌다
> - Chat vs Inline Edit 선택 기준을 명확히 이해한다
> - 멀티 게시판 프로젝트에 적용하는 실전 시나리오 10가지를 습득한다

---

## 1. Chat (Cmd+L) 완전 가이드

### 1.1 Chat 패널 구조

`Cmd+L`을 누르면 에디터 우측에 Chat 패널이 열린다.

```
┌─────────────────────────────────┐
│ Cursor Chat                  ✕  │
├─────────────────────────────────┤
│ [모델 선택: claude-sonnet-4-6 ▼]│
├─────────────────────────────────┤
│                                 │
│ [대화 내용]                     │
│                                 │
│ AI: 여기에 코드가 표시됩니다.    │
│ ┌─────────────────────────┐    │
│ │ 코드 블록               │    │
│ └─────────────────────────┘    │
│              [Apply] [Copy]     │
│                                 │
├─────────────────────────────────┤
│ @ # 메시지 입력...         [↑]  │
└─────────────────────────────────┘
```

### 1.2 코드 수정 없이 질문하기

```
질문 유형별 예시:

[이해] "이 컴포넌트에서 JWT 토큰은 어디서 관리되나?"
[분석] "@Files src/auth/auth.service.ts 이 파일에서 보안 취약점이 있으면 알려줘"
[비교] "findOne과 findUnique의 차이가 뭐야?"
[설명] "이 에러가 왜 발생하는지 설명해줘"
[리뷰] "@Files src/post/ 이 폴더의 코드를 리뷰해줘"
```

### 1.3 Apply 버튼으로 코드 적용

```
1. 질문: "findAll에 검색 기능을 추가해줘"
2. AI: 변경된 코드를 코드 블록으로 표시
3. [Apply] 클릭 → 에디터에서 해당 파일이 열리며 diff 표시
4. 변경 내용 확인
5. [Accept All] 또는 [Reject All] 선택
```

### 1.4 대화 맥락 이어가기

```
[대화 1] "PostService에 findAll 메서드를 추가해줘"
         → AI가 기본 findAll 생성, Apply

[대화 2] "방금 만든 findAll에 키워드 검색 기능을 추가해줘"
         → AI가 이전 코드를 기억하고 검색 기능 추가

[대화 3] "검색 결과를 관련도 순으로 정렬해줘"
         → AI가 누적된 변경사항을 이해하고 정렬 추가
```

## 2. Inline Edit (Cmd+K) 완전 가이드

### 2.1 Inline Edit의 3가지 모드

**모드 1: 커서 위치에 코드 추가 (선택 없이)**
```typescript
function createPost(dto: CreatePostDto) {
  // [커서 위치에서 Cmd+K → "에러 처리와 트랜잭션을 추가해줘"]
}
```

**모드 2: 선택 영역 수정**
```typescript
// 이 코드를 드래그 선택 후 Cmd+K
const posts = await prisma.post.findMany({
  where: { boardId },
});
// → "페이지네이션을 추가하고 소프트 삭제 필터를 적용해줘"
```

**모드 3: 터미널에서 명령어 생성**
```bash
# 터미널에서 Cmd+K → "PostgreSQL 데이터베이스를 생성하는 Docker 명령어를 알려줘"
```

### 2.2 Accept/Reject 처리

```
Cmd+K 실행 후 변경 사항이 표시됨:
- 초록색: 추가된 코드
- 빨간색: 삭제된 코드

수락: Cmd+Enter
거절: Cmd+Backspace
```

## 3. Chat vs Inline Edit 선택 기준표

| 상황 | 권장 도구 | 이유 |
|------|-----------|------|
| 코드에 대해 질문만 할 때 | Chat | 에디터 변경 없이 설명 |
| 한 파일의 특정 코드 수정 | Inline Edit (Cmd+K) | 빠르고 컨텍스트 명확 |
| 여러 번 대화하며 점진적 개선 | Chat | 대화 맥락 유지 |
| 새 파일 전체 생성 | Inline Edit (Cmd+K) | 파일 전체를 직접 생성 |
| 여러 파일에 걸친 변경 | Agent (Cmd+I) | 멀티파일 자율 편집 |
| 에러 메시지 분석 | Chat | 에러 컨텍스트 제공 가능 |
| 코드 리뷰 요청 | Chat | 설명+제안 형식 |
| 터미널 명령어 생성 | Inline Edit (터미널에서 Cmd+K) | 터미널 컨텍스트 |

## 4. @멘션으로 컨텍스트 추가

```
@Files src/auth/auth.service.ts    → 특정 파일 참조
@Files src/post/                   → 폴더 전체 참조
@Codebase                          → 전체 코드베이스 검색
@Docs https://nestjs.com           → 외부 문서 참조
@Web CORS NestJS 설정              → 실시간 웹 검색
@Git                               → 최근 커밋 참조
```

## 5. 실전 시나리오 10가지 (요약)

1. TypeScript 에러 수정 (Chat) — 에러 메시지 붙여넣기
2. DTO 유효성 검사 추가 (Cmd+K) — 선택 후 데코레이터 추가
3. 코드 설명 요청 (Chat) — 팀원 코드 이해
4. 단위 테스트 생성 (Chat) — 케이스 목록 제시
5. Prisma 쿼리 최적화 (Cmd+K) — N+1 제거
6. SvelteKit 로그인 폼 생성 (Cmd+K) — 빈 파일에서
7. 에러 로그 분석 (Chat) — 프로덕션 에러 진단
8. 리팩터링 (Cmd+K) — 메서드 분리
9. 타입 정의 생성 (Chat) — API 응답 타입
10. Docker 설정 (터미널 Cmd+K) — 명령어 생성
