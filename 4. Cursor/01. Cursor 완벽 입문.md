# 01. Cursor 완벽 입문

> **학습 목표**
> - AI 퍼스트 에디터 패러다임이 기존 에디터와 어떻게 다른지 이해한다
> - Cursor의 4대 핵심 기능(Tab·Chat·Inline Edit·Agent)의 개념을 파악한다
> - Claude Code·ChatGPT Codex·Antigravity와 Cursor의 차이를 명확히 구분한다
> - 이 시리즈 전체 학습 로드맵을 이해하고 자신에게 맞는 경로를 선택한다

## 1. AI 퍼스트 에디터란 무엇인가

### 1.1 기존 에디터의 한계

2020년대 초까지 개발자는 에디터와 AI를 별개로 사용했다. VS Code에서 코드를 작성하고, 별도 브라우저 탭에서 ChatGPT에게 질문하고, 답변을 복사해서 다시 에디터에 붙여넣는 방식이었다. 이 워크플로우는 다음과 같은 문제가 있었다.

- **컨텍스트 단절**: AI는 내 프로젝트 전체를 모른다. 파일 하나씩 복사해서 보여줘야 한다
- **수동 적용**: AI가 제안한 코드를 직접 찾아서 편집해야 한다
- **반복 마찰**: 질문 → 복사 → 붙여넣기 → 오류 → 다시 질문의 루프가 반복된다
- **컨텍스트 소실**: 새 대화를 열면 이전 맥락이 사라진다

### 1.2 AI 퍼스트 패러다임의 전환

Cursor는 이 문제를 근본적으로 해결한다. **AI가 에디터 안에 내장**되어 있고, AI는 처음부터 프로젝트 전체를 인덱싱하여 이해한다. 개발자는 코드 작성 중에 자연어로 AI에게 지시하면 AI가 직접 파일을 읽고, 수정하고, 새 파일을 만들고, 빌드 오류를 수정한다.

"AI가 코드를 이해한다"는 것은 구체적으로 다음을 의미한다.

```
전통적 AI 보조 개발:
개발자 → [코드 복사] → ChatGPT → [답변 복사] → 에디터
                ↑ 맥락 단절, 수동 작업, 반복 마찰

AI 퍼스트 개발 (Cursor):
개발자 ↔ Cursor AI (프로젝트 전체 인덱싱 상태)
              ↓ 직접 파일 읽기/쓰기/수정
         실시간 멀티파일 자율 편집
```

### 1.3 Cursor가 VS Code와 다른 점

Cursor는 VS Code를 포크(fork)하여 만들어졌다. 즉, VS Code의 모든 기능이 그대로 작동한다.

| 항목 | VS Code | Cursor |
|------|---------|--------|
| 기반 | Electron + Monaco Editor | VS Code 포크 |
| 확장 | VS Code Marketplace 전체 | 동일하게 사용 가능 |
| 단축키 | 표준 VS Code 단축키 | 동일 + Cursor 전용 단축키 추가 |
| AI 통합 | GitHub Copilot 확장 (별도 설치) | 핵심 기능으로 내장 |
| 코드 이해 | 파일 단위 | 프로젝트 전체 인덱싱 |
| 멀티파일 편집 | 수동 | Agent가 자율 실행 |
| 컨텍스트 | 열린 파일만 | @멘션으로 지정 + 전체 검색 |

핵심 차이는 AI가 **에디터의 일부**로 통합되어 있다는 점이다. Copilot은 확장이지만, Cursor의 AI는 에디터 자체다.

## 2. Cursor 4대 핵심 기능 개요

### 2.1 Tab — 예측 편집 (Predictive Editing)

Tab은 GitHub Copilot의 자동완성과 유사해 보이지만 근본적으로 다르다. 단순히 현재 줄을 완성하는 것이 아니라, **다음에 올 코드 블록 전체**를 예측하여 제안한다.

```typescript
// 개발자가 함수 시그니처만 작성하면
async function getUserById(id: string): Promise<User> {
  // Cursor Tab이 아래 전체를 회색으로 제안
  const user = await prisma.user.findUnique({
    where: { id },
    include: {
      profile: true,
      boards: true,
    },
  });
  if (!user) {
    throw new NotFoundException(`User with id ${id} not found`);
  }
  return user;
}
```

Tab 수락 방법:
- `Tab`: 전체 제안 수락
- `Ctrl+→` (macOS: `Opt+→`): 단어 단위 수락
- `Esc`: 제안 거절

### 2.2 Chat — AI와 대화하며 코드 수정 (Cmd+L)

`Cmd+L`을 누르면 우측 패널에 Chat 창이 열린다. 코드에 대해 질문하거나 수정을 요청할 수 있다. AI가 코드를 제안하면 Apply 버튼으로 에디터에 직접 적용한다.

```
# Chat 사용 예시
개발자: "@Files src/auth/auth.service.ts 파일에서 JWT 만료 시간을 
        7일에서 24시간으로 변경해줘"

AI: [변경된 코드 제안]
    [Apply 버튼]

개발자: [Apply 클릭] → 에디터에 즉시 적용
```

### 2.3 Inline Edit — 빠른 인라인 수정 (Cmd+K)

코드를 선택하거나 커서를 놓고 `Cmd+K`를 누르면 인라인 편집 창이 뜬다. 채팅 패널 없이 바로 수정 지시를 내릴 수 있다.

```
# Inline Edit 사용 예시
1. createBoard 함수 전체를 드래그 선택
2. Cmd+K
3. "에러 처리와 트랜잭션을 추가해줘"
4. AI가 변경 사항을 인라인으로 보여줌
5. Cmd+Enter로 수락, Cmd+Backspace로 거절
```

### 2.4 Agent — 자율 멀티파일 편집 (Cmd+Shift+I)

Agent(Composer)는 여러 파일을 동시에 읽고 수정하는 자율 에이전트다. 큰 기능 구현, 전체 리팩터링, 복잡한 버그 수정에 사용한다.

```
# Agent 사용 예시
"PRD의 [AUTH-001] JWT 로그인 기능을 구현해줘.
@Files docs/prd.md를 참조하고,
@Files src/auth/ 폴더 구조를 그대로 유지해줘.
완료 후 npm run build가 성공해야 해."

→ Agent가 자율적으로:
  - auth.module.ts 수정
  - auth.service.ts 생성/수정
  - auth.controller.ts 생성/수정
  - jwt.strategy.ts 생성
  - 관련 DTO 파일 생성
  - app.module.ts에 AuthModule 등록
```

## 3. Cursor vs 경쟁 도구 비교

### 3.1 4자 비교표

| 항목 | Cursor | Claude Code (CLI) | ChatGPT Codex | Antigravity |
|------|--------|-------------------|---------------|-------------|
| 형태 | 데스크톱 에디터 | CLI 도구 | 웹/API | 데스크톱 앱+IDE |
| 기반 | VS Code 포크 | 터미널 | 웹 브라우저 | 독자 에디터 |
| 작업 환경 | 에디터 내부 | 터미널/쉘 | 웹 인터페이스 | 앱 내부 |
| 기존 설정 마이그레이션 | VS Code 설정 그대로 | 불필요 | 불필요 | 부분적 |
| 파일 편집 | 직접 (에디터 내) | 직접 (파일 시스템) | 제한적 | 직접 |
| 코드 시각화 | 실시간 diff | CLI 출력 | 텍스트 | 실시간 diff |
| 멀티파일 | Agent로 자율 | 네이티브 지원 | 제한적 | 지원 |
| 학습 곡선 | VS Code 경험 있으면 낮음 | 낮음 (CLI) | 매우 낮음 | 중간 |
| 오프라인 | 불가 (AI 기능) | 불가 | 불가 | 불가 |
| 주요 사용 | 풀스택 개발 | 자동화·스크립트 | 빠른 질문 | AI 네이티브 개발 |

### 3.2 Cursor가 적합한 상황

Cursor는 다음 상황에 특히 강력하다.

1. **기존 VS Code 사용자**: 설정·확장·단축키 그대로 이전 가능
2. **장기 프로젝트**: 코드베이스 인덱싱으로 AI가 프로젝트 전체를 기억
3. **팀 개발**: .cursor/rules를 Git으로 공유하여 팀 전체 AI 동작 통일
4. **풀스택 개발**: 프론트엔드·백엔드·DB를 동시에 편집하는 작업
5. **시각적 코드 리뷰**: diff를 에디터에서 바로 확인하며 수락/거절

### 3.3 Claude Code(CLI)와 함께 사용하는 전략

Cursor와 Claude Code는 경쟁 관계가 아니라 **보완 관계**다.

```
Cursor → 에디터에서 코드 작성·리뷰·실시간 편집
Claude Code → CI/CD 파이프라인·자동화 스크립트·배포 작업

예시 워크플로우:
1. Cursor에서 기능 구현 (Agent + Chat)
2. Claude Code로 테스트 자동화 실행
3. Cursor에서 테스트 결과 확인 및 수정
4. Claude Code로 배포
```

## 4. 코드베이스 인덱싱 이해

### 4.1 인덱싱이란

Cursor가 프로젝트를 처음 열면 백그라운드에서 전체 코드베이스를 **벡터 임베딩**으로 변환하여 인덱싱한다. 이 작업이 완료되면 AI는 `@Codebase` 검색을 통해 프로젝트 전체에서 관련 코드를 의미론적으로 찾을 수 있다.

```
인덱싱 과정:
1. 프로젝트 파일 스캔 (node_modules 제외)
2. 각 파일을 청크(chunk)로 분할
3. 각 청크를 벡터 임베딩으로 변환
4. 로컬 벡터 DB에 저장 (Privacy Mode 시 서버 전송 안 함)

검색 시:
질문 → 벡터 변환 → 유사도 검색 → 관련 청크 반환 → AI 컨텍스트에 포함
```

### 4.2 인덱싱 상태 확인

에디터 하단 상태 바에서 인덱싱 진행 상황을 확인할 수 있다. 대규모 프로젝트(10만 줄 이상)는 5~10분 정도 소요될 수 있다.

### 4.3 .cursorignore 설정

`node_modules`, `dist`, `.git` 등 불필요한 폴더는 자동으로 제외되지만, 추가로 제외할 폴더가 있다면 `.cursorignore` 파일을 사용한다.

```bash
# .cursorignore
*.log
*.lock
coverage/
.env*
secrets/
dist/
build/
```

## 5. Privacy Mode 이해

### 5.1 기본 동작

기본 설정에서는 코드가 Cursor 서버를 통해 AI 모델로 전송된다. Cursor는 SOC 2 인증을 받았으며, 코드를 AI 학습에 사용하지 않는다고 명시하고 있다.

### 5.2 Privacy Mode

Privacy Mode를 활성화하면 **코드가 Cursor 서버에 저장되지 않는다**. AI 처리 후 즉시 삭제된다. Business 요금제에서는 팀 전체에 Privacy Mode를 강제 적용할 수 있다.

```
Privacy Mode 적용 범위:
✓ 코드 내용 서버 미저장
✓ 대화 내역 서버 미저장
✓ AI 학습에 사용 안 함
✗ 인터넷 연결 없이 사용 불가 (추론은 외부 서버 필요)
```

Privacy Mode 활성화 위치:
`Cursor Settings → General → Privacy Mode → Enable`

## 6. 역할별 가치

### 6.1 개발자

- 반복적인 보일러플레이트 코드 생성 시간 90% 단축
- 복잡한 리팩터링을 Agent에게 위임
- 생소한 라이브러리나 프레임워크를 빠르게 익히며 사용
- 코드 리뷰 전 AI로 먼저 품질 검토

### 6.2 기획자·PM

- Chat으로 기존 코드를 물어보며 기능 현황 파악
- PRD를 작성하고 AI가 이를 코드로 변환하는 과정 감독
- 기술 부채, 복잡도 설명을 비개발자 언어로 번역 요청

### 6.3 디자이너

- SvelteKit 컴포넌트 구조를 Chat으로 질문
- 디자인 토큰(CSS 변수)을 코드에 반영 요청
- Figma에서 복사한 CSS를 Tailwind 클래스로 변환 요청

## 7. 예제 프로젝트: 멀티 게시판 허브

이 교재 시리즈 전체에서 하나의 프로젝트를 완성해 나간다. **멀티 게시판 허브**는 8가지 유형의 게시판을 제공하는 풀스택 웹 애플리케이션이다.

### 7.1 기술 스택

```
프론트엔드:  SvelteKit 2.x + TypeScript + Tailwind CSS
백엔드:      NestJS 10.x + TypeScript
데이터베이스: PostgreSQL 16 + Prisma v5
인증:        JWT (Access Token + Refresh Token)
파일:        Multer + S3 호환 스토리지
컨테이너:    Docker + Docker Compose
패키지 관리: pnpm workspaces (모노레포)
```

### 7.2 8종 게시판 유형

| 코드 | 게시판명 | 특징 |
|------|----------|------|
| NOTICE | 공지사항 | 관리자만 작성, 상단 고정 |
| FREE | 자유게시판 | 일반 텍스트, 댓글 지원 |
| QNA | Q&A | 질문/답변 구조, 채택 기능 |
| GALLERY | 갤러리 | 이미지 필수, 썸네일 |
| FILE | 자료실 | 파일 첨부 필수 |
| NEWS | 뉴스 | 외부 링크, 원문 출처 |
| POLL | 투표 | 옵션 선택, 결과 집계 |
| SECRET | 비밀게시판 | 작성자·관리자만 열람 |

## 9. 실습: 첫 번째 Cursor 경험

### 9.1 사전 준비

이 실습은 02편에서 설치를 완료한 후 진행한다. 개념적으로 먼저 읽어두면 된다.

### 9.2 30초 실습 시나리오

```
1. Cursor에서 새 파일 hello.ts 생성
2. 다음을 타이핑: "// 사용자 이름을 받아서 인사말을 반환하는 함수"
3. Enter 후 "function greet" 타이핑
4. Tab 키를 눌러 AI 제안 수락
5. Cmd+L로 Chat 열기
6. "이 함수에 유효성 검사를 추가해줘" 입력
7. Apply 버튼 클릭
8. 결과 확인
```

### 9.3 기대 결과

```typescript
// Tab으로 생성된 코드 (예시)
function greet(name: string): string {
  return `안녕하세요, ${name}님!`;
}

// Chat Apply 후 추가된 유효성 검사 (예시)
function greet(name: string): string {
  if (!name || name.trim().length === 0) {
    throw new Error('이름을 입력해주세요');
  }
  return `안녕하세요, ${name.trim()}님!`;
}
```

## 11. Cursor의 생태계와 미래

### 11.1 Anysphere와 Cursor의 방향성

Cursor는 Anysphere가 개발한다. 2023년 출시 이후 빠르게 성장하여 2026년 기준 전 세계 수십만 명의 개발자가 일상적으로 사용한다. Anthropic, OpenAI, Google 등 주요 AI 기업들과 파트너십을 맺어 최신 모델을 빠르게 통합한다.

Cursor의 핵심 비전은 **"코드 작성의 마찰을 0에 가깝게"** 하는 것이다. 개발자가 무엇을 만들지 생각하는 것에 집중하고, 어떻게 코드로 표현할지는 AI가 처리하는 세계를 지향한다.

### 11.2 AI 에디터 생태계의 현재

2026년 기준 AI 에디터/코딩 도구 시장은 다음 플레이어들이 경쟁한다.

```
Cursor (Anysphere)
  강점: VS Code 호환, 가장 성숙한 Agent 기능
  
Windsurf (Codeium)
  강점: Flow 기능, 독자적인 AI 아키텍처
  
GitHub Copilot Workspace
  강점: GitHub 생태계 통합, PR 중심 워크플로우
  
Claude Code (Anthropic)
  강점: 터미널 네이티브, 자동화에 최적
  
JetBrains AI Assistant
  강점: Java/Kotlin 생태계, IDE 통합 깊이
```

### 11.3 Cursor를 선택하는 이유

이 많은 선택지 중에서 Cursor를 선택하는 개발자들은 다음 이유를 꼽는다.

1. **VS Code 호환성**: 기존 투자(확장, 단축키, 설정)를 버리지 않아도 됨
2. **성숙한 Agent**: 멀티파일 자율 편집이 가장 잘 완성되어 있음
3. **Rules 시스템**: 팀 컨벤션을 AI에게 강제 적용 가능
4. **모델 유연성**: Anthropic, OpenAI, Google 모델 선택 가능
5. **활발한 업데이트**: 매주 새 기능이 추가됨

## 12. 이 교재가 다루지 않는 것

이 시리즈는 다음 주제를 의도적으로 다루지 않는다.

- **MCP 서버 개발**: Cursor용 커스텀 도구를 만드는 방법 (별도 시리즈 필요)
- **Cursor API**: 프로그래매틱 접근 방법 (현재 제한적)
- **고급 SvelteKit**: SSR, SEO, 성능 최적화 (별도 SvelteKit 교재 필요)
- **NestJS 심화**: 마이크로서비스, GraphQL (별도 NestJS 교재 필요)
- **PostgreSQL 고급**: 파티셔닝, 복제, 성능 튜닝

이 시리즈는 **Cursor를 사용하여 AI와 협업하는 방법**에 집중한다. 개별 기술 심화는 각 기술의 공식 문서와 별도 교재를 참고하기를 권한다.
