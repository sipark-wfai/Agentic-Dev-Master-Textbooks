# 07. @멘션 컨텍스트 시스템

> **학습 목표**
> - @멘션 시스템의 각 유형(@Codebase·@Files·@Docs·@Web·@Git·@Notepads)의 역할을 이해한다
> - 임베딩 기반 @Codebase 검색 원리를 이해한다
> - @Docs에 커스텀 문서 URL을 등록하는 방법을 익힌다
> - @멘션 조합 전략으로 최소 컨텍스트에서 최대 정확도를 얻는다

---

## 1. @멘션 시스템 개요

### 1.1 왜 @멘션이 필요한가

AI의 컨텍스트 창(Context Window)은 유한하다. 모든 코드를 AI에게 주면 비효율적이고 비용도 많이 든다. @멘션은 AI에게 **"이 작업에 필요한 것만 알려주는"** 메커니즘이다.

```
나쁜 방법: "프로젝트 전체를 분석해서 인증 버그를 찾아줘"
→ 수만 줄의 코드를 컨텍스트에 포함 = 느리고 비쌈

좋은 방법: "@Files src/auth/ 이 폴더에서 JWT 처리 로직의 버그를 찾아줘"
→ 필요한 파일만 포함 = 빠르고 정확
```

### 1.2 @멘션 유형 요약

| 유형 | 역할 | 사용 시나리오 |
|------|------|--------------|
| `@Files` | 특정 파일/폴더 직접 포함 | 특정 서비스 수정 |
| `@Codebase` | 임베딩 기반 의미 검색 | 관련 코드 탐색 |
| `@Docs` | 커스텀 문서 URL 참조 | 설계서, API 문서 |
| `@Web` | 실시간 웹 검색 | 최신 라이브러리 정보 |
| `@Git` | Git 히스토리 참조 | 최근 변경 분석 |
| `@Notepads` | 사용자 작성 메모 참조 | 반복 컨텍스트 재사용 |

## 2. @Files — 직접 파일 포함

### 2.1 기본 사용법

```
# 단일 파일
@Files src/auth/auth.service.ts

# 폴더 전체
@Files src/post/

# 여러 파일
@Files src/auth/auth.service.ts @Files src/auth/jwt.strategy.ts
```

### 2.2 효과적인 @Files 활용

```
[단일 파일 수정]
"@Files apps/backend/src/post/post.service.ts
findAll 메서드에 title 키워드 검색을 추가해줘"

[관련 파일 묶음]
"@Files apps/backend/src/auth/auth.service.ts
@Files apps/backend/src/auth/dto/
JWT 토큰 만료 시간을 15분에서 30분으로 변경해줘"

[범위 제한]
"@Files apps/backend/src/board/ 이 폴더만 수정해줘.
다른 폴더는 건드리지 마."
```

## 3. @Codebase — 의미론적 전체 검색

### 3.1 동작 원리

`@Codebase`는 프로젝트 전체를 벡터 임베딩으로 변환하여 인덱싱한 결과를 검색한다.

```
검색 과정:
1. 질문을 벡터로 변환
2. 코드베이스 임베딩 DB에서 유사도 검색
3. 가장 관련성 높은 코드 청크 반환
4. AI 컨텍스트에 포함
```

### 3.2 @Files vs @Codebase

| 항목 | @Files | @Codebase |
|------|--------|-----------|
| 방식 | 지정한 파일 직접 포함 | 임베딩 기반 유사 검색 |
| 정확도 | 명시적 (내가 선택) | AI가 관련성 판단 |
| 컨텍스트 크기 | 지정한 파일 전체 | 관련 청크만 |
| 사용 시나리오 | 정확한 파일 알 때 | 모르지만 검색 필요 시 |

## 4. @Docs — 커스텀 문서 참조

### 4.1 기본 사용법

```
@Docs https://docs.nestjs.com/techniques/database
→ AI가 NestJS 데이터베이스 공식 문서를 읽고 코드 생성

@Docs https://www.prisma.io/docs/concepts/components/prisma-schema
→ Prisma 스키마 문서 참조
```

### 4.2 커스텀 문서 등록

프로젝트 내부 문서를 @Docs로 등록하면 AI가 항상 참조할 수 있다.

```
Cursor Settings → Features → Docs → Add Custom Doc

등록 예시:
- URL: http://localhost:3000/api-docs (개발 중인 Swagger)
- URL: https://notion.so/my-team/api-spec (팀 API 명세)
- URL: https://github.com/my-org/multi-board-hub/blob/main/docs/prd.md
```

## 7. @Notepads — 반복 컨텍스트 재사용

### 7.1 Notepads란

@Notepads는 자주 사용하는 컨텍스트를 저장하고 필요할 때만 불러오는 기능이다. Rules와 달리 선택적으로 포함한다.

### 7.2 Notepads 생성 예시

```markdown
# api-conventions Notepad

## API 응답 컨벤션
성공 응답: { "data": T, "meta"?: PaginationMeta }
에러 응답: { "statusCode": number, "error": string, "message": string }
```

### 7.3 사용 방법

```
"@Notepads api-conventions 를 따라서
PostController에 게시글 목록 조회 API를 추가해줘"
```

## 8. @멘션 조합 전략

### 8.1 최소 컨텍스트 원칙

```
나쁜 조합:
@Codebase @Files apps/ @Docs https://docs.nestjs.com
→ 거대한 컨텍스트 = 느린 응답 + 높은 비용

좋은 조합:
@Files apps/backend/src/post/post.service.ts
→ 필요한 파일만 = 빠른 응답 + 낮은 비용
```

### 8.2 작업 유형별 권장 조합

```
[기능 구현]
@Files [관련 서비스 파일]
@Files [관련 DTO]
@Notepads [프로젝트 컨벤션]

[버그 수정]
@Files [버그 발생 파일]
@Git [최근 변경사항]

[새 기능 설계]
@Docs [기술 문서]
@Files docs/prd.md

[레거시 코드 이해]
@Codebase [기능명]
@Git [변경 히스토리]
```
