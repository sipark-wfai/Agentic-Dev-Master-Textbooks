## 1. @멘션 시스템 개요

### 1.1 왜 @멘션이 필요한가

AI의 컨텍스트 창(Context Window)은 유한하다. 모든 코드를 AI에게 주면 비효율적이고 비용도 많이 든다. @멘션은 AI에게 **"이 작업에 필요한 것만 알려주는"** 메커니즘이다.

```
나쁜 방법: "프로젝트 전체를 분석해서 인증 버그를 찾아줘"
→ 수만 줄의 코드를 컨텍스트에 포함 = 느리고 비쌈

좋은 방법: "@Files src/auth/ 이 폴더에서 JWT 처리 로직의 버그를 찾아줘"
→ 필요한 파일만 포함 = 빠르고 정확
```

### 1.2 @멘션 유형 요약

```
@Codebase    → 전체 코드베이스에서 시맨틱 검색
@Files       → 특정 파일 또는 폴더 직접 참조
@Docs        → 외부 문서 URL 참조 (공식 문서, 커스텀)
@Web         → 실시간 웹 검색 (최신 정보)
@Git         → Git 커밋 이력 및 diff 참조
@Notepads    → 저장된 Notepad 문서 참조
#file        → 빠른 파일 참조 (단축 문법)
```

## 2. @Codebase — 전체 코드베이스 시맨틱 검색

### 2.1 작동 원리

@Codebase는 코드베이스 인덱싱 결과를 활용한다. 질문을 벡터로 변환하여 가장 유사한 코드 청크를 검색한다.

```
검색 과정:
1. 질문 "JWT 토큰 생성하는 곳이 어디야?"를 벡터로 변환
2. 인덱싱된 모든 코드 청크와 유사도 계산
3. 관련도 높은 청크 상위 5~10개 선택
4. AI 컨텍스트에 포함하여 답변 생성
```

### 2.2 @Codebase를 사용하는 상황

```
✓ 적합한 사용:
- 특정 패턴이 프로젝트 어디에 있는지 찾을 때
  "@Codebase 에서 RefreshToken을 처리하는 코드가 어디 있어?"
  
- 프로젝트 전체의 패턴을 이해할 때
  "@Codebase 이 프로젝트에서 에러 처리를 어떻게 하고 있어?"
  
- 파일 경로를 모를 때
  "@Codebase JWT 관련 모든 파일을 찾아줘"

✗ 부적합한 사용:
- 특정 파일 위치를 이미 알 때 → @Files 사용
- 외부 라이브러리 문서 질문 → @Docs 사용
- 최신 트렌드 질문 → @Web 사용
```

### 2.3 @Codebase 검색 품질 향상

인덱싱 품질이 검색 품질을 결정한다.

```bash
# 인덱싱 재실행
Cmd+Shift+P → "Cursor: Reindex Codebase"

# 인덱싱 제외 파일 설정 (.cursorignore)
node_modules/
dist/
build/
coverage/
*.log
*.lock
```

## 3. @Files — 파일·폴더 직접 참조

### 3.1 기본 사용법

```
# 단일 파일 참조
@Files apps/backend/src/auth/auth.service.ts

# 폴더 전체 참조
@Files apps/backend/src/post/

# 여러 파일 참조
@Files apps/backend/src/auth/auth.service.ts
@Files apps/backend/src/auth/auth.controller.ts

# 패턴으로 참조 (글로브)
@Files apps/backend/src/**/*.dto.ts
```

### 3.2 파일 경로 자동완성

Chat에서 @Files를 타이핑하면 파일 경로 자동완성이 활성화된다.

```
@Files [타이핑 시작]
→ 드롭다운에서 파일 선택
→ Enter로 확정
```

### 3.3 폴더 참조 시 주의사항

폴더 전체를 참조하면 모든 파일이 컨텍스트에 들어간다. 폴더가 클수록 컨텍스트가 커진다.

```
주의:
@Files apps/   ← 전체 apps 폴더 (너무 큼)
@Files apps/backend/src/   ← src 전체 (크기에 따라)
@Files apps/backend/src/auth/  ← auth 모듈만 (적절)
@Files apps/backend/src/auth/auth.service.ts  ← 파일 하나 (최소)
```

### 3.4 실전 활용 패턴

```
[특정 서비스 수정]
"@Files apps/backend/src/post/post.service.ts
findAll 메서드에 캐싱을 추가해줘"

[관련 파일 묶음 참조]
"@Files apps/backend/src/board/
이 모듈 전체 코드를 리뷰해줘"

[DTO 패턴 참조]
"@Files apps/backend/src/post/dto/create-post.dto.ts
이 패턴과 동일하게 UpdateBoardDto를 만들어줘"
```

## 4. @Docs — 외부 문서 참조

### 4.1 @Docs란

@Docs는 외부 문서(공식 문서, 개인 문서 등)를 AI 컨텍스트에 포함한다. Cursor가 문서를 인덱싱하여 관련 내용을 자동으로 검색한다.

### 4.2 사전 등록된 공식 문서 목록

Cursor는 주요 프레임워크 문서를 미리 인덱싱하고 있다.

```
사용 가능한 인덱싱된 문서 예시:
- NestJS: @Docs NestJS
- SvelteKit: @Docs SvelteKit
- Prisma: @Docs Prisma
- TypeScript: @Docs TypeScript
- TailwindCSS: @Docs Tailwind
- PostgreSQL: @Docs PostgreSQL
- Docker: @Docs Docker
- React: @Docs React
```

### 4.3 커스텀 문서 URL 추가

프로젝트 내부 문서나 사전 등록되지 않은 외부 문서를 추가할 수 있다.

```
Cursor Settings → Features → Docs → [+ Add]
URL 입력: https://example.com/docs
또는 로컬 파일 경로

또는 Chat에서 직접 URL 사용:
"@Docs https://docs.nestjs.com/techniques/caching
NestJS에서 Redis 캐싱을 설정하는 방법을 알려줘"
```

### 4.4 프로젝트 내부 문서 등록

멀티 게시판 프로젝트의 `docs/` 폴더를 @Docs로 등록한다.

```
Cursor Settings → Features → Docs → [+ Add]
Path: /Users/{사용자}/multi-board-hub/docs/

또는 .cursor/rules에서 참조 설정:
# docs/ 폴더는 항상 참조 가능
# 사용법: @Docs docs/prd.md, @Docs docs/erd.md, @Docs docs/api.md
```

### 4.5 실전 활용

```
[공식 문서 참조]
"@Docs Prisma
Prisma v5에서 cursor-based pagination 구현 방법을 보여줘"

"@Docs NestJS
NestJS에서 WebSocket 게이트웨이를 만드는 방법을 알려줘"

[프로젝트 문서 참조]
"@Docs docs/api.md
이 API 명세서를 참조해서 PostController의 엔드포인트를 구현해줘"

[여러 문서 조합]
"@Docs docs/erd.md
@Docs Prisma
ERD를 기반으로 Prisma 스키마를 작성해줘"
```

## 5. @Web — 실시간 웹 검색

### 5.1 @Web란

@Web은 Cursor가 웹을 검색하여 최신 정보를 AI 컨텍스트에 포함한다. 인덱싱된 문서에 없는 최신 정보나 트렌드를 찾을 때 유용하다.

### 5.2 사용 시나리오

```
✓ @Web이 적합한 경우:
- 최신 보안 취약점 정보
  "@Web NestJS 2024 security vulnerabilities"
  
- 최신 라이브러리 버전 확인
  "@Web Prisma v5 latest changes"
  
- 특정 에러의 알려진 해결책
  "@Web SvelteKit SSR authentication cookie issue solution"

- npm 패키지 최신 버전
  "@Web latest stable version of @nestjs/jwt"

✗ @Web이 불필요한 경우:
- 공식 문서에 있는 내용 → @Docs 사용
- 프로젝트 내부 코드 → @Files 또는 @Codebase
```

### 5.3 실전 활용

```
"@Web PostgreSQL 16 new features performance improvements
이 기능들 중 멀티 게시판 프로젝트에 활용할 수 있는 것이 있어?"

"@Web NestJS Guard vs Interceptor vs Middleware differences 2024
JWT 인증 구현에 어떤 것을 사용하는 게 좋을지 알려줘"
```

## 6. @Git — 커밋 이력 및 diff 참조

### 6.1 @Git란

@Git은 Git 커밋 이력, diff, 브랜치 정보를 AI 컨텍스트에 포함한다. 코드 리뷰, 변경 이력 분석, 버그 유입 시점 파악에 유용하다.

### 6.2 활용 패턴

```
[최근 변경 리뷰]
"@Git 최근 3개 커밋에서 변경된 내용을 리뷰해줘.
잠재적인 버그나 보안 문제가 있는지 확인해줘"

[특정 기능 변경 이력]
"@Git auth 관련 파일의 변경 이력을 보여줘.
언제 JWT 만료 시간이 변경됐는지 찾아줘"

[PR 리뷰 준비]
"@Git main 브랜치와 현재 브랜치의 diff를 분석해줘.
변경 사항 요약과 잠재적 문제를 알려줘"

[버그 유입 시점 파악]
"@Git @Files src/auth/auth.service.ts
이 파일에서 마지막으로 변경된 곳이 어디야?
최근 로그인 버그가 언제 유입됐는지 찾아줘"
```

## 7. @Notepads — 반복 컨텍스트 저장 및 참조

### 7.1 Notepads와 @멘션 통합

Notepads는 자주 사용하는 컨텍스트를 저장한다. @Notepads로 참조하면 원할 때만 컨텍스트에 포함된다.

### 7.2 Notepad 생성 방법

```
방법 1: Chat 패널 → 상단 [Notepads] 아이콘 → [+] 클릭
방법 2: Cmd+Shift+P → "Cursor: New Notepad"
방법 3: 파일 탐색기에서 .cursor/notepads/ 폴더에 .md 파일 생성
```

## 8. @멘션 조합 전략

### 8.1 최소 컨텍스트 원칙

```
원칙: 필요한 것만, 정확하게

나쁜 조합 (너무 많음):
@Codebase @Files apps/ @Docs NestJS @Web ...
→ 컨텍스트 과부하, 느린 응답, 높은 비용

좋은 조합 (최소 + 정확):
@Files apps/backend/src/post/post.service.ts
→ 딱 필요한 파일만
```

### 8.2 상황별 최적 @멘션 조합

```
[기능 구현]
@Files docs/api.md          ← API 명세
@Files apps/backend/src/board/board.service.ts  ← 참조 패턴
지시문: "이 패턴으로 PostService를 구현해줘"

[버그 수정]
@Files [오류 발생 파일]
@Git                         ← 최근 변경 이력
지시문: "이 에러를 수정해줘: [오류 메시지]"

[새 라이브러리 통합]
@Docs [라이브러리 공식 문서]
@Files apps/backend/src/app.module.ts  ← 기존 설정
지시문: "이 라이브러리를 프로젝트에 추가해줘"

[코드 리뷰]
@Files [검토할 파일 또는 폴더]
@Notepads error-messages     ← 에러 메시지 표준
지시문: "이 코드를 Rules에 따라 리뷰해줘"

[프로젝트 내 패턴 학습]
@Codebase                    ← 전체 검색
지시문: "이 프로젝트에서 페이지네이션을 어떻게 구현하고 있어?"
```

## 9. 실전 시나리오 10가지

### 시나리오 1: 인증 서비스 버그 분석

```
"@Files apps/backend/src/auth/auth.service.ts
@Files apps/backend/src/auth/jwt.strategy.ts
@Git
이 파일들에서 refresh token 갱신 시 간헐적으로 401 에러가 발생해.
원인을 찾아줘."
```

### 시나리오 2: 게시판 컴포넌트 생성

```
"@Notepads board-types
@Files apps/frontend/src/routes/board/
이 폴더의 기존 컴포넌트 패턴을 참조해서
GALLERY 게시판용 이미지 업로드 컴포넌트를 만들어줘"
```

### 시나리오 3: 공식 문서 기반 구현

```
"@Docs NestJS
@Files apps/backend/src/app.module.ts
NestJS 공식 문서를 참조해서 Redis 캐싱을 설정해줘.
Cache-Control 헤더도 함께 설정해줘."
```

### 시나리오 4: 최신 보안 이슈 확인

```
"@Web JWT security best practices 2024
@Files apps/backend/src/auth/
현재 JWT 구현에서 최신 보안 이슈가 있으면 알려줘"
```

### 시나리오 5: 코드베이스 패턴 분석


## 10. @멘션 고급 활용

### 10.1 #file 빠른 참조

```
# @Files와 동일하지만 더 짧은 문법
#auth.service.ts
#post.service.ts

# Chat에서:
"#post.service.ts 와 #board.service.ts를 비교해서 
findAll 메서드 패턴의 일관성을 확인해줘"
```

### 10.2 Cmd+K에서 @멘션

Inline Edit에서도 @멘션이 작동한다.

```
코드 선택 후 Cmd+K:
"@Files apps/backend/src/auth/auth.service.ts
에서 사용하는 JWT 생성 패턴과 동일하게 수정해줘"
```

### 10.3 컨텍스트 크기 모니터링

Chat 패널 하단에 현재 컨텍스트 토큰 수가 표시된다. 컨텍스트가 너무 크면 응답이 느려지거나 잘릴 수 있다.

```
적정 컨텍스트 크기:
- 간단한 질문: ~2K 토큰
- 일반 작업: ~10K 토큰
- 복잡한 구현: ~30K 토큰
- 전체 모듈 분석: ~50K 토큰

너무 크면: 가장 관련 있는 파일만 선택적으로 포함
```
