## 1. 에이전트 친화적 PRD란

### 1.1 일반 PRD와 에이전트 친화적 PRD의 차이

일반 PRD는 **사람이 읽기 위한 문서**다. 에이전트 친화적 PRD는 **AI가 코드로 변환하기 위한 문서**다.

```
일반 PRD:
"사용자가 쉽고 편하게 게시글을 작성할 수 있어야 한다"
→ AI가 이해 못함: "쉽고 편하다"는 게 뭔가?

에이전트 친화적 PRD:
"[POST-001] 게시글 작성
- 입력: title(2~100자), content(10자 이상), boardId(UUID)
- 출력: 201 Created, { data: Post }
- 에러: 400 (유효성 실패), 401 (미로그인), 404 (게시판 없음)"
→ AI가 즉시 코드로 변환 가능
```

### 1.2 에이전트 친화적 PRD의 5가지 원칙

```
원칙 1: 구체적 수치 (모호함 금지)
- 나쁜 예: "빠르게 로드해야 한다"
- 좋은 예: "페이지 로드 시간 2초 이내"

원칙 2: 측정 가능한 완료 기준
- 나쁜 예: "로그인 기능 구현"
- 좋은 예: "회원가입/로그인 API가 Jest 테스트 통과, E2E 테스트 통과"

원칙 3: HTTP 메서드·상태코드 명시
- GET/POST/PATCH/DELETE + 성공/실패 상태코드

원칙 4: 의존성 명시
- "[AUTH-002]는 [AUTH-001] 완료 후 구현"

원칙 5: 마일스톤 분할
- 전체를 구현 가능한 단위로 분할
```

## 2. Cursor Chat으로 PRD 작성하기

### 2.1 브레인스토밍 단계

```
1단계: 아이디어 확장
Cmd+L로 Chat 열기

"멀티 게시판 허브 서비스를 기획하려고 해.
핵심 기능 목록을 작성해줘.
게시판 유형: 공지, 자유, Q&A, 갤러리, 자료실, 뉴스, 투표, 비밀"

AI가 기능 목록 초안 제시 → Apply로 docs/brainstorm.md에 저장
```

### 2.2 구조화 단계

```
2단계: PRD 구조화
"이 기능 목록을 에이전트 친화적 PRD 형식으로 변환해줘.
각 기능은 다음 형식으로:
[기능ID] 기능명
- 입력: (파라미터, 타입, 유효성)
- 출력: (HTTP 상태코드, 응답 구조)
- 에러: (상태코드, 조건)
- 의존성: (선행 기능ID)"
```

### 2.3 검토 및 보완 단계

```
3단계: 누락 기능 확인
"이 PRD에서 누락된 기능이 있으면 알려줘.
특히 인증 흐름, 파일 업로드, 권한 관리를 중점으로 검토해줘"
```

## 3. 멀티 게시판 허브 PRD 예시

### 3.1 PRD 헤더

```markdown
# 멀티 게시판 허브 PRD (Product Requirements Document)
버전: 1.0.0
작성일: 2026-06-01
작성자: 개발팀
기술 스택: SvelteKit + NestJS + PostgreSQL + Prisma

## 구현 마일스톤
- M1: DB 스키마 + 기본 CRUD API
- M2: 인증 시스템 (회원가입/로그인/JWT)
- M3: 게시글 CRUD (8가지 게시판 타입)
- M4: 댓글·파일 업로드·투표 기능
- M5: 프론트엔드 (SvelteKit)
- M6: 테스트 + 배포 (Docker)
```

### 3.2 인증 기능 PRD 예시

```markdown
## M2: 인증 시스템

### [AUTH-001] 회원가입
- **입력**: email(이메일 형식), password(8자 이상, 영문+숫자+특수문자), name(2~20자)
- **출력**: 201 Created, { data: { id, email, name, role: 'USER' } }
- **에러**:
  - 400 Bad Request: 유효성 검사 실패
  - 409 Conflict: 이미 존재하는 이메일
- **비즈니스 로직**:
  - 비밀번호는 bcrypt(cost 12)로 해시
  - 기본 role은 USER

### [AUTH-002] 로그인
- **의존성**: [AUTH-001] 완료 후
- **입력**: email, password
- **출력**: 200 OK, { data: { accessToken, refreshToken, user: { id, email, name, role } } }
- **에러**:
  - 400 Bad Request: 필수 필드 누락
  - 401 Unauthorized: 이메일/비밀번호 불일치
- **비즈니스 로직**:
  - accessToken: JWT, 15분 만료
  - refreshToken: UUID, 7일 만료, DB 저장

### [AUTH-003] 토큰 재발급
- **의존성**: [AUTH-002] 완료 후
- **입력**: refreshToken (Body 또는 Cookie)
- **출력**: 200 OK, { data: { accessToken } }
- **에러**:
  - 401 Unauthorized: 유효하지 않거나 만료된 refreshToken
```

## 4. PRD를 .cursor/rules에 연동하기

```markdown
# .cursor/rules/project.mdc에 추가
---
alwaysApply: true
---
## PRD 참조
PRD 파일 위치: docs/prd.md
구현 시 PRD의 [기능ID]를 커밋 메시지에 포함:
feat(auth): [AUTH-001] 회원가입 API 구현
```
