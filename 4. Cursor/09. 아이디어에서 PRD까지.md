## 1. 에이전트 친화적 PRD란

### 1.1 일반 PRD와 에이전트 친화적 PRD의 차이

일반 PRD는 **사람이 읽기 위한 문서**다. 마케팅 언어, 비즈니스 목표, 사용자 스토리가 중심이다.

에이전트 친화적 PRD는 **AI가 코드로 변환하기 위한 문서**다. 구체적이고, 측정 가능하고, 모호함이 없어야 한다.

```
일반 PRD:
"사용자가 쉽고 편하게 게시글을 작성할 수 있어야 한다"
→ AI가 이해 못함: "쉽고 편하다"는 게 뭔가?

에이전트 친화적 PRD:
"[POST-001] 게시글 작성
- 입력: title(2~100자), content(10자 이상), boardId(UUID)
- 조건: 로그인한 USER 이상만 가능
- 결과: Post 객체 반환, HTTP 201 Created
- 예외: 게시판이 없으면 404, 권한 없으면 403"
→ AI가 즉시 코드로 변환 가능
```

### 1.2 에이전트 친화적 PRD의 특징

```
1. 기능 ID 부여 ([AUTH-001] <!-- R3 수정: 이 ID 체계는 이 교재에서 사용하는 컨벤션이며 업계 표준 아님 -->, [POST-001] 등)
2. 입력/출력 명시 (타입, 형식, 범위)
3. 성공 조건 명시 (HTTP 상태 코드, 반환 데이터)
4. 예외 처리 명시 (어떤 상황에서 어떤 에러)
5. 비기능 요구사항 수치화 (응답 시간 500ms 이하)
6. 사용자 역할별 권한 명시
7. 마크다운 형식 (AI가 구조 파악 쉬움)
```

## 2. Cursor Chat으로 브레인스토밍

### 2.1 아이디어 구조화 프로세스

```
단계 1: 아이디어 자유 표현
"커뮤니티 게시판 서비스를 만들고 싶어.
여러 종류의 게시판이 있고, 회원제로 운영하려고 해.
어떤 기능이 필요할지 생각해줘."

단계 2: 핵심 기능 도출
AI가 기능 목록을 제안하면 취사선택

단계 3: 사용자 역할 정의
"이 서비스에서 사용자 유형을 어떻게 나눠야 할까?"

단계 4: 기능 우선순위 정의
"이 기능들 중 MVP(최소 기능 제품)를 위한 
필수 기능과 나중에 추가할 기능을 나눠줘"

단계 5: PRD 구조 생성
"위 내용을 바탕으로 에이전트 친화적 PRD 구조를 만들어줘"
```

### 2.2 Chat 브레인스토밍 예시

```
개발자: "멀티 게시판 서비스의 핵심 기능을 도출해줘.
8가지 게시판 유형(공지·자유·Q&A·갤러리·자료실·뉴스·투표·비밀)을 
지원해야 해."

AI: "다음 기능 그룹을 제안합니다:
1. 인증 (회원가입, 로그인, 토큰 관리)
2. 게시판 관리 (생성, 수정, 활성화/비활성화)
3. 게시글 CRUD (타입별 다른 필드)
4. 댓글 (일반 댓글, 대댓글)
5. 파일 첨부 (이미지, 문서)
6. 검색 (제목, 내용, 작성자)
7. 권한 관리 (역할별 접근 제어)
8. 투표 (옵션 생성, 참여, 결과)

MVP에 포함할 기능: 1, 3, 4
나중에 추가할 기능: 6, 7(고급), 8"
```

## 3. PRD 필수 구성 요소

### 3.1 문서 헤더

```markdown
# PRD: 멀티 게시판 허브 (Multi Board Hub)

**버전**: 1.0.0
**작성일**: 2026-01-01
**작성자**: 홍길동
**상태**: 확정

## 문서 목적
이 PRD는 Cursor Agent가 멀티 게시판 허브를 구현하는 데 필요한
모든 요구사항을 명시한다.

## 변경 이력
| 버전 | 날짜 | 변경 내용 |
|------|------|-----------|
| 1.0.0 | 2026-01-01 | 최초 작성 |
```

### 3.2 프로젝트 개요

```markdown
## 프로젝트 개요

### 서비스 설명
멀티 게시판 허브는 8가지 유형의 게시판을 통합 관리하는 
커뮤니티 플랫폼이다.

### 기술 스택
- 프론트엔드: SvelteKit 2.x + TypeScript + Tailwind CSS v3
- 백엔드: NestJS 10.x + TypeScript
- DB: PostgreSQL 16 + Prisma v5
- 인증: JWT (Access 15분 + Refresh 7일)
- 파일: Multer + S3 호환 스토리지
- 배포: Docker Compose

### 접근 URL
- 프론트엔드: http://localhost:5173 (개발)
- 백엔드 API: http://localhost:3000/api/v1
- Swagger: http://localhost:3000/api/docs
```

## 4. 멀티 게시판 허브 전체 PRD

```markdown
# PRD: 멀티 게시판 허브

**버전**: 1.0.0  **날짜**: 2026-01-01  **상태**: 확정

---

## 1. 프로젝트 개요

멀티 게시판 허브는 8가지 게시판 유형(공지·자유·Q&A·갤러리·자료실·뉴스·투표·비밀)을
통합 제공하는 웹 커뮤니티 플랫폼이다.

**기술 스택**: SvelteKit 2.x + NestJS 10.x + PostgreSQL 16 + Prisma v5  
**인증**: JWT Access Token(15분) + Refresh Token(7일)

---

## 2. 사용자 역할

| 역할 | 코드 | 게시글 작성 | 댓글 | 파일 첨부 | 게시판 관리 |
|------|------|------------|------|---------|-----------|
| 최고 관리자 | SUPER_ADMIN | 모든 게시판 | ✓ | ✓ | ✓ |
| 게시판 관리자 | BOARD_ADMIN | 담당 게시판 | ✓ | ✓ | 담당만 |
| 일반 사용자 | USER | 허용 게시판 | ✓ | ✓ | ✗ |
| 비회원 | GUEST | ✗ | ✗ | ✗ | ✗ |

---

## 3. 게시판 유형

| 코드 | 이름 | 작성 권한 | 파일 | 특수 기능 |
|------|------|-----------|------|-----------|
| NOTICE | 공지사항 | BOARD_ADMIN+ | 선택 | 상단 고정, 읽음 표시 |
| FREE | 자유게시판 | USER+ | 선택 | 없음 |
| QNA | Q&A | USER+ | 선택 | 채택 기능, 해결/미해결 표시 |
| GALLERY | 갤러리 | USER+ | 이미지 필수(1~10개) | 썸네일, 슬라이드 |
| FILE | 자료실 | USER+ | 파일 필수(1~5개) | 다운로드 카운트 |
| NEWS | 뉴스 | BOARD_ADMIN+ | 선택 | 외부 링크 URL 필수 |
| POLL | 투표 | USER+ | 불가 | 옵션 2~10개, 중복투표 설정 |
| SECRET | 비밀게시판 | USER+ | 선택 | 작성자·관리자만 내용 열람 |

## 4. 기능 명세

### [AUTH] 인증

**[AUTH-001] 회원가입**
- 입력: email(RFC 5321 형식), password(8~20자, 영문+숫자+특수문자), name(2~20자)
- 처리: password는 bcrypt(saltRounds=12)로 해시 저장
- 결과: User 객체(비밀번호 제외), HTTP 201
- 예외: 이미 사용 중인 email → 409 Conflict

**[AUTH-002] 로그인**
- 입력: email, password
- 처리: email로 User 조회, password 검증
- 결과: { accessToken, refreshToken, user }, HTTP 200
- 예외: email 없음 → 401, password 불일치 → 401
- 토큰: accessToken(15분), refreshToken(7일, DB 저장)

**[AUTH-003] 토큰 재발급**
- 입력: refreshToken (쿠키 또는 헤더)
- 처리: DB에서 refreshToken 유효성 확인, 새 accessToken 발급
- 결과: { accessToken }, HTTP 200
- 예외: refreshToken 없음/만료/사용됨 → 401

**[AUTH-004] 로그아웃**
- 입력: refreshToken
- 처리: DB에서 해당 refreshToken 삭제
- 결과: HTTP 204 No Content
- 인증: accessToken 필요

**[AUTH-005] 내 정보 조회**
- 입력: 없음
- 결과: User 객체(비밀번호 제외), HTTP 200
- 인증: accessToken 필요

---

### [BOARD] 게시판 관리

**[BOARD-001] 게시판 목록 조회**
- 입력: 없음 (비회원도 접근 가능)
- 결과: Board[] (isActive=true인 것만), HTTP 200
- 포함: 각 게시판의 최근 게시글 수(_count)

**[BOARD-002] 게시판 상세 조회**
- 입력: boardId (URL 파라미터)
- 결과: Board 객체, HTTP 200
- 예외: 없는 boardId → 404

**[BOARD-003] 게시판 생성**
- 입력: name(2~50자), type(BoardType), description(최대 200자), isActive(기본 true)
- 결과: Board 객체, HTTP 201
- 인증: BOARD_ADMIN+ 필요
- 예외: 동일 name 존재 → 409

**[BOARD-004] 게시판 수정**
- 입력: name, description, isActive (모두 선택)
- 결과: 수정된 Board 객체, HTTP 200
- 인증: BOARD_ADMIN+ 필요
- 예외: boardId 없음 → 404

**[BOARD-005] 게시판 비활성화 (소프트 삭제)**
- 처리: isActive = false 또는 deletedAt 설정
- 결과: HTTP 204
- 인증: SUPER_ADMIN 필요

---

### [POST] 게시글

**[POST-001] 게시글 목록 조회**
- 입력: boardId (필수), page(기본 1), limit(기본 20, 최대 100), search(선택)
- 결과: { data: Post[], meta: PaginationMeta }, HTTP 200
- 포함: author(id, name), _count(comments)
- 정렬: createdAt 내림차순 (공지사항은 상단 고정)
- 필터: deletedAt = null

**[POST-002] 게시글 상세 조회**
- 입력: postId
- 처리: viewCount + 1 (같은 사용자 1시간 내 중복 카운트 제외)
- 결과: Post 객체 (전체 필드 + author + board + files), HTTP 200
- 예외: 없는 postId → 404, SECRET 게시판 비작성자 → 403(내용 마스킹)

**[POST-003] 게시글 작성**
- 공통 입력: title(2~100자), content(10자~), boardId
- GALLERY 추가: imageUrls(최소 1개, 최대 10개)
- FILE 추가: fileUrls(최소 1개, 최대 5개)
- POLL 추가: options[](2~10개), allowMultiple(boolean), expiresAt(선택)
- NEWS 추가: externalUrl(URL 형식 필수)
- 결과: Post 객체, HTTP 201
- 인증: USER+ (NOTICE·NEWS는 BOARD_ADMIN+)

**[POST-004] 게시글 수정**
- 입력: title, content, imageUrls, fileUrls (모두 선택)
- 인증: 작성자 본인 또는 BOARD_ADMIN+
- 결과: 수정된 Post, HTTP 200
- 예외: 권한 없음 → 403, 없는 postId → 404

**[POST-005] 게시글 삭제 (소프트 삭제)**
- 처리: deletedAt = 현재 시각
- 인증: 작성자 본인 또는 BOARD_ADMIN+
- 결과: HTTP 204
- 예외: 권한 없음 → 403

**[POST-006] QnA 채택**
- 입력: commentId (채택할 댓글 ID)
- 처리: post.acceptedCommentId = commentId
- 인증: 게시글 작성자 본인
- 예외: 이미 채택됨 → 400

**[POST-007] 투표 참여**
- 입력: optionIds[] (단일 또는 복수, allowMultiple에 따라)
- 처리: 기존 투표 있으면 수정, 없으면 신규
- 인증: USER+
- 예외: 투표 기간 종료 → 400

**[POST-008] 조회수 상위 게시글 (인기 게시글)**
- 입력: boardId(선택), limit(기본 10)
- 결과: 최근 7일 조회수 기준 상위 N개, HTTP 200

---

### [COMMENT] 댓글

**[COMMENT-001] 댓글 목록 조회**
- 입력: postId, page(기본 1), limit(기본 50)
- 결과: 댓글 + 대댓글 트리 구조, HTTP 200
- 포함: author(id, name), 대댓글 최대 depth 2

**[COMMENT-002] 댓글 작성**
- 입력: content(1~500자), postId, parentId(대댓글 시 필수)
- 결과: Comment 객체, HTTP 201
- 인증: USER+
- 예외: SECRET 게시판 댓글은 작성자·관리자만 열람 가능

**[COMMENT-003] 댓글 수정**
- 인증: 작성자 본인만
- 결과: 수정된 Comment, HTTP 200

**[COMMENT-004] 댓글 삭제 (소프트 삭제)**
- 처리: content = "삭제된 댓글입니다", deletedAt 설정
- 인증: 작성자 본인 또는 BOARD_ADMIN+
- 결과: HTTP 204

---

### [FILE] 파일 업로드

**[FILE-001] 파일 업로드**
- 입력: file (multipart/form-data), postId
- GALLERY: jpg, png, gif, webp만 허용, 최대 10MB/개
- FILE 게시판: 모든 형식, 최대 50MB/개
- 처리: S3 업로드 후 URL 반환
- 결과: { id, filename, url, mimeType, size }, HTTP 201
- 인증: USER+

**[FILE-002] 파일 다운로드**
- 처리: downloadCount + 1
- 결과: 파일 스트림

## 5. 비기능 요구사항

### 5.1 성능

| 항목 | 목표 |
|------|------|
| API 응답 시간 | 95% 이하 500ms 이내 |
| 목록 조회 | 20개 기준 100ms 이하 |
| 파일 업로드 | 10MB 파일 5초 이내 |
| 동시 접속 | 100명 동시 사용 지원 |
| DB 쿼리 | 모든 쿼리 N+1 없음 |

### 5.2 보안

| 항목 | 기준 |
|------|------|
| 인증 | JWT, HTTPS 필수 |
| 비밀번호 | bcrypt 해시 (saltRounds=12) |
| SQL 인젝션 | Prisma ORM으로 방지 |
| XSS | HTML 이스케이프 처리 |
| CORS | 허용 도메인 화이트리스트 |
| 파일 업로드 | MIME 타입 서버 측 검증 |
| Rate Limiting | API: 분당 60회, 인증: 분당 10회 |

### 5.3 접근성

| 항목 | 기준 |
|------|------|
| WCAG 준수 | Level AA |
| 키보드 탐색 | 모든 기능 키보드만으로 사용 가능 |
| 이미지 대체 텍스트 | 모든 이미지에 alt 속성 필수 |
| 색상 대비 | 4.5:1 이상 |

### 5.4 브라우저 지원

- Chrome 최신 3개 버전
- Firefox 최신 3개 버전
- Safari 최신 2개 버전
- Edge 최신 2개 버전
- 모바일: iOS 15+, Android 10+
```

## 6. PRD 품질 자가 검증 체크리스트

```
기능 명세 완전성:
[ ] 1. 모든 기능에 고유 ID가 있다 ([AUTH-001] 형식)
[ ] 2. 모든 기능에 입력 데이터가 명시되어 있다
[ ] 3. 모든 기능에 예상 출력이 명시되어 있다
[ ] 4. 모든 기능에 HTTP 상태 코드가 있다
[ ] 5. 모든 예외 케이스가 나열되어 있다
[ ] 6. 모든 기능에 인증 요구사항이 명시되어 있다

데이터 정의:
[ ] 7. 모든 입력 필드에 타입이 명시되어 있다
[ ] 8. 모든 문자열 필드에 길이 제한이 있다
[ ] 9. 숫자 필드에 범위가 명시되어 있다
[ ] 10. Enum 값이 모두 나열되어 있다

역할과 권한:
[ ] 11. 모든 역할(SUPER_ADMIN~GUEST)이 정의되어 있다
[ ] 12. 각 기능별 필요 역할이 명시되어 있다
[ ] 13. 권한 없는 경우의 에러 처리가 있다

비기능 요구사항:
[ ] 14. 응답 시간 목표가 수치로 있다
[ ] 15. 동시 접속 목표가 있다
[ ] 16. 보안 요구사항이 명시되어 있다
[ ] 17. 파일 크기/형식 제한이 있다

문서 구조:
[ ] 18. 버전과 날짜가 있다
[ ] 19. 마일스톤으로 분할되어 있다
[ ] 20. API 엔드포인트 요약이 있다
```
