## 1. Tab이란: 예측 편집 (Predictive Editing)

### 1.1 단순 자동완성과의 차이

기존 IDE의 자동완성(IntelliSense)은 현재 타이핑 중인 단어를 완성한다. `get`을 타이핑하면 `getUser`, `getPost` 같은 메서드명을 제안한다. 이것은 **단어 수준**의 완성이다.

Cursor Tab은 다르다. **다음에 올 코드 블록 전체**를 예측한다. 함수 시그니처를 작성하면 함수 구현체 전체를, 테스트 한 개를 작성하면 다음 테스트 케이스 전체를, DTO 필드 하나를 추가하면 연관된 모든 필드를 예측한다.

```typescript
// 개발자가 타이핑한 것 (2줄)
async function createPost(dto: CreatePostDto): Promise<Post> {
  // [여기서 Tab]

// Cursor Tab이 제안하는 것 (10줄+ 전체)
async function createPost(dto: CreatePostDto): Promise<Post> {
  const board = await this.prisma.board.findUnique({
    where: { id: dto.boardId },
  });
  if (!board) {
    throw new NotFoundException('게시판을 찾을 수 없습니다');
  }
  return this.prisma.post.create({
    data: {
      ...dto,
      authorId: dto.authorId,
    },
    include: { author: true, board: true },
  });
}
```

### 1.2 GitHub Copilot Tab과의 차이

| 항목 | GitHub Copilot Tab | Cursor Tab |
|------|-------------------|------------|
| 컨텍스트 | 열린 파일 위주 | 프로젝트 전체 인덱싱 |
| 제안 범위 | 현재 줄~몇 줄 | 멀티라인, 멀티블록 |
| Rules 반영 | 없음 | .cursor/rules 반영 |
| 최근 편집 반영 | 제한적 | 최근 편집 이력 학습 |
| 프로젝트 패턴 | 현재 파일 기반 | 프로젝트 전체 패턴 학습 |
| Fast Request 소비 | 별도 구독 | 소비 없음 (무제한) |

### 1.3 Tab Fusion 모델 (2026년)

Cursor Tab은 **Fusion 모델**로 업그레이드되었다.

- **25% 더 어려운 편집** 정확히 예측 (기존 대비)
- **10배 긴 변경사항** 제안 가능
- 서버 레이턴시 475ms → **260ms**로 단축
- 컨텍스트 윈도우 5,500 → **13,000 토큰**으로 확장
- 일일 **4억 건** 이상 요청 처리

### 1.4 Tab 동작 원리

Cursor Tab이 제안을 생성할 때 다음 신호를 종합적으로 분석한다.

```
1. 커서 위치와 주변 코드 (현재 파일)
2. 최근 편집 이력 (방금 뭘 만들었는가?)
3. .cursor/rules (프로젝트 규칙)
4. 코드베이스 인덱스 (프로젝트 전체 패턴)
5. 열려 있는 다른 탭 파일
6. 파일 임포트 구조
```

이 신호들을 조합하여 "개발자가 다음에 하려는 것"을 예측한다.

## 2. Tab 수락 방법

### 2.1 세 가지 수락 방식

```
Tab         → 회색 제안 전체를 한 번에 수락
Opt+→ (macOS) / Ctrl+→ (Windows/Linux)  → 단어 하나씩 수락
Esc         → 제안 거절 (현재 제안 무시)
```

### 2.2 실전 사용 패턴

```typescript
// 상황: prisma.post.findMany를 타이핑 중
// Cursor가 다음을 제안한다:
await prisma.post.findMany({
  where: {
    boardId: dto.boardId,
    deletedAt: null,
  },
  include: {
    author: { select: { id: true, name: true } },
    _count: { select: { comments: true } },
  },
  orderBy: { createdAt: 'desc' },
  skip: (page - 1) * limit,
  take: limit,
});

// 전체가 좋으면: Tab (한 번에 수락)
// "where"까지만 쓰고 싶으면: Ctrl+→로 단어씩 수락
// 제안이 마음에 안 들면: Esc
```

## 3. Tab이 잘 작동하는 10가지 패턴

### 패턴 1: 함수 시그니처 → 구현체

```typescript
// NestJS 서비스 예시
async findPostsByBoard(boardId: string, paginationDto: PaginationDto): Promise<PaginatedResult<Post>> {
  // [Tab] → 구현체 전체 제안
  const { page = 1, limit = 20 } = paginationDto;
  const where = { boardId, deletedAt: null };
  const [data, total] = await this.prisma.$transaction([
    this.prisma.post.findMany({ where, skip: (page-1)*limit, take: limit }),
    this.prisma.post.count({ where }),
  ]);
  return { data, meta: { page, limit, total, totalPages: Math.ceil(total/limit) } };
}
```

## 5. 비용: Tab은 플랜 크레딧을 소비하지 않는다

**Tab은 월 크레딧(Fast Request) 한도를 소비하지 않는다.** Tab을 하루에 수백 번 사용해도 플랜 크레딧과 전혀 관계없다.

```
크레딧 소비 여부:
- Tab: ✗ (소비 안 함, 무제한)
- Cmd+K (Inline Edit): 소량 소비
- Chat (Cmd+L): 크레딧 소비
- Agent (Composer): 크레딧 소비
```
