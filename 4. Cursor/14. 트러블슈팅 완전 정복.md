## 1. 트러블슈팅 진단 프레임워크

### 1.1 오류 유형 분류

| 유형 | 이름 | 대표 증상 |
|------|------|-----------|
| A | 환경/인증 오류 | 로그인 실패, API Key 오류 |
| B | 인덱싱/컨텍스트 오류 | Tab 미작동, @Codebase 결과 부정확 |
| C | Agent 실행 오류 | 무한루프, 잘못된 파일 수정 |
| D | 코드 품질 오류 | 빌드 실패, TypeScript 에러 |
| E | 런타임 오류 | DB 연결 실패, CORS 오류 |
| F | 컨텍스트 오염 | AI 응답 일관성 저하 |

### 1.2 1차 진단 절차

```
문제 발생 →
1. 에러 메시지 전문 복사
2. 유형(A~F) 분류
3. 해당 유형의 해결법 적용
4. 해결 안 될 시: Cursor 재시작 + Git 복구 고려
```

## 2. 오류 시나리오 20가지

### 오류 1: Cursor 로그인 실패 [유형 A]

```
해결:
1. 인터넷 연결 확인
2. VPN 비활성화 후 재시도
3. Cursor 캐시 삭제:
   macOS: rm -rf ~/Library/Caches/Cursor/
4. 브라우저에서 cursor.com 직접 접속하여 로그인
```

### 오류 2: 코드베이스 인덱싱 실패 [유형 B]

```bash
# .cursorignore 생성
cat > .cursorignore << 'EOF'
node_modules/
dist/
build/
coverage/
.git/
*.log
*.lock
EOF

# 인덱싱 재실행
# Cmd+Shift+P → "Cursor: Reindex Codebase"
```

### 오류 3: Tab 제안이 뜨지 않는 경우 [유형 B]

```
1. Cursor Settings → Features → Tab → Enable Cursor Tab: ON 확인
2. 상태 바 하단 Tab 아이콘 → Enabled 확인
3. 인덱싱 완료 대기
4. Cursor 재시작
```

### 오류 4: Agent가 잘못된 파일을 수정하는 경우 [유형 C]

```
1. Esc로 Agent 즉시 중단
2. 잘못 수정된 파일 Git으로 복구:
   git checkout -- apps/backend/src/wrong-file.ts
3. 지시문에 범위 제한 추가:
   "@Files apps/backend/src/auth/ 이 폴더 안에서만 작업해줘"
```

### 오류 5: Agent 무한 루프 / 멈춤 [유형 C]

```
1. Esc로 Agent 중단
2. git checkout -- . (변경 취소)
3. 지시문을 더 작은 단위로 분리
4. 완료 기준 명시 ("빌드 성공 후 종료")
```

### 오류 6: 플랜 크레딧 한도 초과 [유형 A]

```
단기 해결:
- BYO API Key로 전환 (Cursor Settings → Models → API Keys)

장기 해결:
- Tab 활용 극대화 (크레딧 소비 안 함)
- Pro+ 또는 Ultra 플랜 업그레이드 고려
```

### 오류 7: BYO API Key 인증 실패 [유형 A]

```
1. Key 앞뒤 공백 제거 후 재입력
2. Anthropic Key: "sk-ant-" 로 시작 확인
3. OpenAI Key: "sk-" 로 시작 확인
4. 각 콘솔에서 Key 활성 상태 확인
```

### 오류 8: @Docs 문서가 인덱싱되지 않는 경우 [유형 B]

```
1. URL 직접 브라우저에서 접근 가능한지 확인
2. Cursor Settings → Features → Docs → 해당 문서 삭제 후 재추가
3. Cmd+Shift+P → "Cursor: Reindex Docs"
```

### 오류 9: .cursor/rules 미적용 [유형 B]

```
1. 파일 위치 확인: ls -la .cursor/rules/
2. .mdc 파일 형식 확인 (.cursorrules는 Agent 모드에서 무시됨)
3. Chat에서 확인: "현재 적용된 Rules 내용을 보여줘"
4. Rules 파일 용량 확인 (500줄 이하 권장)
```

### 오류 10: @Codebase 검색 결과가 부정확한 경우 [유형 B]

```
1. Cmd+Shift+P → "Cursor: Reindex Codebase"
2. @Files로 직접 파일 지정 (더 정확)
3. 검색 쿼리 구체화: "JWT" 대신 "JWT accessToken 생성하는 함수"
```

### 오류 11: Cmd+K Apply 후 빌드 오류 [유형 D]

```
방법 1: Cmd+K로 즉시 수정 (에러 메시지 선택 후 Cmd+K)
방법 2: Chat으로 수정 요청
방법 3: git checkout -- [파일] (변경 취소)
```

### 오류 12: Agent가 PRD를 무시하고 임의 구현 [유형 C]

```
지시문에 PRD 참조 명시:
"@Docs docs/prd.md
PRD의 [POST-003] 요구사항을 그대로 구현해줘."
```

### 오류 13: TypeScript 타입 오류 누적 [유형 D]

### 오류 20: 컨텍스트 창 오염 (New Chat 필요 시점) [유형 F]

```
- 같은 질문에 대화마다 다른 답변
- AI가 "이전에 구현한 것"이라고 잘못 말함
- 응답 속도가 갑자기 느려짐
- 대화가 30~50 턴 이상 지속됨

해결: Cmd+N → New Chat → 현재 상태 재설명 + @Files/@Docs 다시 지정
```

## 3. Git 비상 복구 절차

### 3.1 Agent가 잘못 수정한 경우

```bash
git diff                                          # 변경 내용 확인
git checkout -- apps/backend/src/post/post.service.ts  # 특정 파일 복구
git checkout -- apps/backend/src/post/            # 폴더 전체 복구
git checkout -- .                                  # 모든 변경 취소
git reset --hard HEAD                              # 커밋 이전 상태로
```

### 3.2 Agent 작업 전 안전망 만들기

```bash
# Agent 실행 전 항상 커밋
git add -A
git commit -m "chore: Agent 작업 전 스냅샷"

# 또는 임시 브랜치
git checkout -b temp/agent-work
# 결과가 좋으면: git checkout main && git merge temp/agent-work
# 결과가 나쁘면: git checkout main && git branch -D temp/agent-work
```

## 4. 자주 나오는 에러 메시지 해석표

| 에러 메시지 | 유형 | 빠른 해결 |
|------------|------|-----------|
| `Cannot find module` | D | import 경로 확인, pnpm install |
| `Type 'X' is not assignable to type 'Y'` | D | 타입 불일치, 타입 가드 추가 |
| `P2002 Unique constraint failed` | E | 중복 데이터, 409 처리 추가 |
| `P2025 Record not found` | E | 소프트 삭제 필터 확인 |
| `401 Unauthorized` | A | JWT 토큰 확인, 만료 여부 |
| `ECONNREFUSED` | E | Docker 컨테이너 실행 확인 |
| `window is not defined` | D | SSR 환경, browser 가드 추가 |

## 5. Cursor Hooks — 자동화 워크플로우 (2026년 신규)

<!-- R6 신규 추가: Cursor Hooks 기능 상세 설명 (2026년 최신 정보) -->

### 5.1 Cursor Hooks란

Cursor Hooks는 Composer(Agent) 동작의 특정 이벤트에 반응하여 자동으로 스크립트를 실행하는 기능이다. 2026년 성능이 **40배 향상**되어 이벤트 처리가 훨씬 빠르다.

```
저장 위치: .cursor/hooks/ (bash/Node/Python 스크립트)
```

### 5.2 4가지 Hook 유형

| Hook | 실행 시점 | 주요 용도 |
|------|----------|-----------|
| `onPreEdit` | Composer 편집 적용 **전** | 편집 거부, 사전 검증 |
| `onPostEdit` | Composer 편집 커밋 **후** | 린트, 포맷, 알림 |
| `onPreCommit` | 에이전트 Git 커밋 스테이징 **전** | 커밋 검증, 메시지 수정 |
| `onApprove` | Composer diff 승인 클릭 **시** | 승인 후 자동 빌드 |

### 5.3 실전 Hooks 예시

**onPostEdit — 자동 린트 실행**

```bash
# .cursor/hooks/post-edit.sh
#!/bin/bash

# Composer가 파일을 수정한 후 자동으로 ESLint + Prettier 실행
echo "Running lint and format after Cursor edit..."
cd apps/backend && pnpm lint --fix
cd apps/frontend && pnpm lint --fix

echo "Lint complete."
```

**onPreCommit — 빌드 검증**

```bash
# .cursor/hooks/pre-commit.sh
#!/bin/bash

# 에이전트 Git 커밋 전 빌드 검증
echo "Running pre-commit build check..."
pnpm build

if [ $? -ne 0 ]; then
  echo "Build failed. Blocking commit."
  exit 1  # exit 1로 커밋 차단 가능
fi

echo "Build passed."
```

**onApprove — Swagger 문서 자동 업데이트**

```javascript
// .cursor/hooks/on-approve.js
const { execSync } = require('child_process');

// Composer diff 승인 시 Swagger 스펙 자동 생성
try {
  execSync('cd apps/backend && pnpm generate:swagger', { stdio: 'inherit' });
  console.log('Swagger spec updated.');
} catch (err) {
  console.error('Swagger generation failed:', err.message);
}
```

### 5.4 Hooks 설정 방법

```bash
# hooks 폴더 생성
mkdir -p .cursor/hooks

# 스크립트 작성 후 실행 권한 부여
chmod +x .cursor/hooks/post-edit.sh
chmod +x .cursor/hooks/pre-commit.sh

# Cursor Settings → Features → Hooks → Enable
```

> **활용 팁**: `onPreEdit`에서 `exit 1`을 반환하면 편집 자체를 거부할 수 있다. 이를 이용해 보안 파일(`.env`, `secrets/`)에 대한 Agent 편집을 차단할 수 있다.
