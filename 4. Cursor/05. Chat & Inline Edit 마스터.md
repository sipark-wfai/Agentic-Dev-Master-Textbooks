# 05. Chat & Inline Edit 마스터

> **학습 목표**
> - Chat(Cmd+L)으로 코드를 질문하고, Apply로 직접 적용하는 방법을 익힌다
> - Inline Edit(Cmd+K)으로 빠르게 특정 코드를 수정하는 방법을 익힌다
> - Chat vs Inline Edit 선택 기준을 명확히 이해한다
> - 멀티 게시판 프로젝트에 적용하는 실전 시나리오 10가지를 습득한다

---

## 1. Chat (Cmd+L) 완전 가이드

### 1.1 Chat 패널 구조

`Cmd+L`을 누르면 에디터 우측에 Chat 패널이 열린다.

```
┌─────────────────────────────────┐
│ Cursor Chat                  ✕  │
├─────────────────────────────────┤
│ [모델 선택: claude-sonnet-4-5 ▼]│
├─────────────────────────────────┤
│                                 │
│ [대화 내용]                     │
│                                 │
│ AI: 여기에 코드가 표시됩니다.    │
│ ┌─────────────────────────┐    │
│ │ 코드 블록               │    │
│ └─────────────────────────┘    │
│              [Apply] [Copy]     │
│                                 │
├─────────────────────────────────┤
│ @ # 메시지 입력...         [↑]  │
└─────────────────────────────────┘
```

### 1.2 코드 수정 없이 질문하기

Chat에서 코드에 대해 질문하면 AI가 설명해준다. 에디터 내용은 변경되지 않는다.

```
질문 유형별 예시:

[이해] "이 컴포넌트에서 JWT 토큰은 어디서 관리되나?"
[분석] "@Files src/auth/auth.service.ts 이 파일에서 
       보안 취약점이 있으면 알려줘"
[비교] "findOne과 findUnique의 차이가 뭐야?"
[설명] "이 에러가 왜 발생하는지 설명해줘"
[리뷰] "@Files src/post/ 이 폴더의 코드를 리뷰해줘"
```

### 1.3 Apply 버튼으로 코드 적용

AI가 코드 변경을 제안하면 Apply 버튼이 나타난다.

```
1. 질문: "findAll에 검색 기능을 추가해줘"
2. AI: 변경된 코드를 코드 블록으로 표시
3. [Apply] 클릭 → 에디터에서 해당 파일이 열리며 diff 표시
4. 변경 내용 확인
5. [Accept All] 또는 [Reject All] 선택
   또는 각 변경 사항 개별 수락/거절
```

### 1.4 대화 맥락 이어가기

한 Chat 세션에서 이전 대화 맥락이 유지된다. 이를 활용하면 점진적으로 기능을 개선할 수 있다.

```
[대화 1] "PostService에 findAll 메서드를 추가해줘"
         → AI가 기본 findAll 생성, Apply

[대화 2] "방금 만든 findAll에 키워드 검색 기능을 추가해줘"
         → AI가 이전 코드를 기억하고 검색 기능 추가

[대화 3] "검색 결과를 관련도 순으로 정렬해줘"
         → AI가 누적된 변경사항을 이해하고 정렬 추가

[대화 4] "이 findAll을 위한 단위 테스트를 작성해줘"
         → AI가 지금까지 만든 findAll 전체를 이해하고 테스트 작성
```

### 1.5 New Chat vs Continue Chat

```
Continue Chat (현재 채팅 유지):
✓ 이전 맥락이 필요한 경우
✓ 하나의 기능을 점진적으로 개선할 때
✗ 이전 대화가 많아 응답이 느려질 때
✗ 완전히 새로운 작업을 시작할 때

New Chat (Cmd+N 또는 [+] 버튼):
✓ 완전히 다른 주제/기능 시작 시
✓ 이전 대화가 오염되었을 때 (잘못된 가정)
✓ 응답 속도가 느려질 때
✓ 컨텍스트 창이 꽉 찼을 때 (AI가 알려줌)
```

## 2. Inline Edit (Cmd+K) 완전 가이드

### 2.1 Inline Edit의 3가지 모드

**모드 1: 커서 위치에 코드 추가 (선택 없이)**

```typescript
// 커서를 이 위치에 놓고 Cmd+K
function createPost(dto: CreatePostDto) {
  // [커서 위치]
}
// → "에러 처리와 Prisma 트랜잭션을 추가해줘"
// → AI가 해당 위치에 코드를 삽입
```

**모드 2: 선택 영역 수정**

```typescript
// 이 코드를 드래그 선택 후 Cmd+K
const posts = await prisma.post.findMany({
  where: { boardId },
});
// → "페이지네이션을 추가하고 소프트 삭제 필터를 적용해줘"
// → AI가 선택 영역을 새 코드로 교체
```

**모드 3: 터미널에서 명령어 생성**

```bash
# 터미널에서 Cmd+K
# → "PostgreSQL 데이터베이스를 생성하는 Docker 명령어를 알려줘"
# → AI가 터미널 명령어를 제안
docker run -d \
  --name multi-board-db \
  -e POSTGRES_USER=board_user \
  -e POSTGRES_PASSWORD=secure_password \
  -e POSTGRES_DB=multi_board \
  -p 5432:5432 \
  postgres:16
```

### 2.2 Accept/Reject 처리

```
Cmd+K 실행 후 변경 사항이 표시됨:
- 초록색: 추가된 코드
- 빨간색: 삭제된 코드

수락: Cmd+Enter (또는 [Accept] 버튼)
거절: Cmd+Backspace (또는 [Reject] 버튼)
수정 후 재실행: 다시 Cmd+K
```

### 2.3 새 파일 생성

```
빈 에디터 탭에서 Cmd+K:
"SvelteKit의 게시글 목록 페이지 컴포넌트를 만들어줘.
@Files apps/frontend/src/lib/types.ts 타입을 사용해야 해."

→ AI가 전체 파일 내용을 생성
→ Cmd+Enter로 수락
```

## 3. Chat vs Inline Edit 선택 기준표

| 상황 | 권장 도구 | 이유 |
|------|-----------|------|
| 코드에 대해 질문만 할 때 | Chat | 에디터 변경 없이 설명 |
| 한 파일의 특정 코드 수정 | Inline Edit (Cmd+K) | 빠르고 컨텍스트 명확 |
| 여러 번 대화하며 점진적 개선 | Chat | 대화 맥락 유지 |
| 새 파일 전체 생성 | Inline Edit (Cmd+K) | 파일 전체를 직접 생성 |
| 여러 파일에 걸친 변경 | Agent (Cmd+I) | 멀티파일 자율 편집 |
| 에러 메시지 분석 | Chat | 에러 컨텍스트 제공 가능 |
| 코드 리뷰 요청 | Chat | 설명+제안 형식 |
| 터미널 명령어 생성 | Inline Edit (터미널에서 Cmd+K) | 터미널 컨텍스트 |
| 리팩터링 (특정 블록) | Inline Edit (Cmd+K) | 선택 영역 직접 수정 |
| 테스트 코드 생성 | Chat | 전체 테스트 전략 논의 가능 |

## 4. @멘션으로 컨텍스트 추가

Chat에서 @를 입력하면 다양한 컨텍스트를 포함할 수 있다.

```
@Files src/auth/auth.service.ts    → 특정 파일 참조
@Files src/post/                   → 폴더 전체 참조
@Codebase                          → 전체 코드베이스 검색
@Docs https://nestjs.com           → 외부 문서 참조
@Web CORS NestJS 설정              → 실시간 웹 검색
@Git                               → 최근 커밋 참조
```

### 4.1 효과적인 @멘션 조합

```
[단순 수정]
"@Files src/post/post.service.ts
findAll에 검색 기능을 추가해줘"

[여러 파일 참조]
"@Files src/post/post.service.ts
@Files src/post/dto/
PostService의 모든 메서드에서 PaginationDto를 사용하도록 수정해줘"

[문서 참조]
"@Docs https://docs.nestjs.com/techniques/file-upload
Multer로 이미지 업로드 기능을 PostController에 추가해줘"

[최근 변경 기반]
"@Git 최근 커밋에서 변경된 auth 관련 코드를 리뷰해줘"
```

## 5. 실전 시나리오 10가지

### 시나리오 1: TypeScript 에러 수정 (Chat)

```
상황: TypeScript 타입 에러 발생

에러 메시지를 Chat에 붙여넣기:
"다음 TypeScript 에러를 수정해줘:
Type 'string | null' is not assignable to type 'string'.
  Type 'null' is not assignable to type 'string'. ts(2322)

@Files src/post/post.service.ts"

→ AI가 에러 원인 분석 후 수정 코드 제안
→ Apply로 적용
```

### 시나리오 2: DTO 유효성 검사 추가 (Cmd+K)

```
상황: CreatePostDto에 유효성 검사가 없음

1. CreatePostDto 전체 선택
2. Cmd+K
3. "class-validator 데코레이터를 추가해줘.
   title: 2~100자, content: 10자 이상, boardId: UUID 형식"
4. 변경 내용 확인 후 Accept
```

결과:
```typescript
import { IsString, IsUUID, MaxLength, MinLength } from 'class-validator';

export class CreatePostDto {
  @IsString()
  @MinLength(2, { message: '제목은 2자 이상이어야 합니다' })
  @MaxLength(100, { message: '제목은 100자를 초과할 수 없습니다' })
  title: string;

  @IsString()
  @MinLength(10, { message: '내용은 10자 이상이어야 합니다' })
  content: string;

  @IsUUID('4', { message: '올바른 게시판 ID를 입력해주세요' })
  boardId: string;
}
```

### 시나리오 3: 코드 설명 요청 (Chat)

```
상황: 팀원이 작성한 Prisma 미들웨어를 이해해야 함

1. Cmd+L로 Chat 열기
2. "@Files src/prisma/prisma.service.ts
   이 파일에서 소프트 삭제 미들웨어가 어떻게 작동하는지 설명해줘.
   주니어 개발자도 이해할 수 있게 쉽게 설명해줘."
```

### 시나리오 4: 단위 테스트 생성 (Chat)

```
상황: PostService.findAll에 대한 테스트 작성 필요

"@Files src/post/post.service.ts
findAll 메서드에 대한 Jest 단위 테스트를 작성해줘.
다음 케이스를 포함해:
1. 정상적으로 게시글 목록 반환
2. 빈 목록 반환 (게시글 없을 때)
3. 삭제된 게시글 제외 확인
4. 페이지네이션 동작 확인"
```

### 시나리오 5: Prisma 쿼리 최적화 (Cmd+K)

```
상황: N+1 쿼리 발생하는 코드 수정

1. 문제 코드 선택:
   const posts = await prisma.post.findMany();
   // 반복문에서 author 조회 → N+1 발생
   
2. Cmd+K → "N+1 쿼리를 제거하고 include로 최적화해줘"

결과:
const posts = await prisma.post.findMany({
  include: {
    author: { select: { id: true, name: true, email: true } },
    board: { select: { id: true, name: true } },
    _count: { select: { comments: true } },
  },
});
```

### 시나리오 6: SvelteKit 로그인 폼 생성 (Cmd+K)

```
상황: 빈 파일에서 로그인 폼 컴포넌트 생성

1. 새 파일 src/routes/auth/login/+page.svelte 생성
2. Cmd+K
3. "SvelteKit 로그인 폼 컴포넌트를 만들어줘.
   이메일/비밀번호 입력, 로그인 버튼, 에러 메시지 표시.
   Tailwind CSS 스타일 적용.
   @Files src/lib/api/auth.ts API 함수 사용."
```

### 시나리오 7: 에러 로그 분석 (Chat)

```
상황: 배포 후 에러 로그 발생

에러 로그를 Chat에 붙여넣기:
```

## 6. Chat에서 Apply 워크플로우 심화

### 6.1 Apply와 Diff 보기

Apply 후 에디터에서 diff가 표시된다.

```
초록색 배경: 새로 추가된 코드
빨간색 배경: 삭제될 코드

개별 변경 수락/거절:
- 각 변경 블록 옆의 [✓] 또는 [✗] 아이콘 클릭
- 또는 [Accept All] / [Reject All] 버튼

일부만 수락:
- 원하는 변경 블록만 [✓] 클릭
- 나머지는 [✗] 클릭
```

### 6.2 Apply 후 추가 수정

Apply한 코드가 완전하지 않다면 Chat에서 이어서 요청한다.

```
[1차 Apply]
"PostController에 게시글 목록 API를 추가해줘"

[2차 수정]
"방금 추가한 findAll API에 @ApiOperation 데코레이터를 추가해줘"

[3차 수정]
"Swagger 문서에서 응답 스키마도 보이도록 @ApiResponse를 추가해줘"
```

## 7. 멀티 게시판 프로젝트 실전 예시

### 7.1 인증 모듈 Chat으로 점진적 구현

```
대화 1:
"@Files apps/backend/src/auth/
JWT 로그인 기능의 기본 구조를 만들어줘.
AuthService, AuthController, JwtStrategy 파일이 필요해"

대화 2 (Apply 후):
"방금 만든 AuthService에 refresh token 기능을 추가해줘.
refresh token은 7일 유효기간으로 DB에 저장해야 해"

대화 3 (Apply 후):
"로그아웃 시 refresh token을 무효화하는 로직을 추가해줘"

대화 4 (Apply 후):
"이 인증 모듈 전체에 대한 e2e 테스트를 작성해줘"
```

### 7.2 게시판 타입별 분기 처리 Cmd+K로 수정

```typescript
// 기존 코드 (분기 없음)
async createPost(dto: CreatePostDto) {
  return this.prisma.post.create({ data: dto });
}

// 이 코드 선택 후 Cmd+K
// "게시판 타입에 따라 다른 유효성 검사를 적용해줘:
//  GALLERY: image 필드 필수
//  FILE: fileUrl 필드 필수
//  POLL: options 배열(2개 이상) 필수
//  나머지: 기본 title + content"

// 결과: 
async createPost(dto: CreatePostDto) {
  const board = await this.boardService.findOne(dto.boardId);
  
  switch (board.type) {
    case BoardType.GALLERY:
      if (!dto.imageUrls?.length) {
        throw new BadRequestException('갤러리 게시글에는 이미지가 필수입니다');
      }
      break;
    case BoardType.FILE:
      if (!dto.fileUrls?.length) {
        throw new BadRequestException('자료실 게시글에는 파일 첨부가 필수입니다');
      }
      break;
    case BoardType.POLL:
      if (!dto.pollOptions || dto.pollOptions.length < 2) {
        throw new BadRequestException('투표 게시글에는 2개 이상의 선택지가 필요합니다');
      }
      break;
  }
  
  return this.prisma.post.create({ data: dto });
}
```

## 8. Chat & Inline Edit 고급 팁

### 8.1 멀티모달 활용 (이미지 붙여넣기)

Chat에 스크린샷이나 다이어그램을 붙여넣으면 AI가 이미지를 이해하고 코드를 생성한다.

```
활용 예시:
- Figma 디자인 스크린샷 → SvelteKit 컴포넌트 생성
- ERD 다이어그램 → Prisma 스키마 생성
- 에러 화면 스크린샷 → 에러 원인 분석
- 와이어프레임 → HTML/CSS 코드 생성
```

### 8.2 코드 블록을 Chat으로 드래그

에디터에서 코드를 선택하고 Chat 패널로 드래그하면 해당 코드가 자동으로 포함된다.

### 8.3 Chat 히스토리 관리

```
Cmd+Shift+P → "Cursor: Chat History" → 이전 대화 세션 확인
중요한 대화는 Notepad로 저장
오래된 대화는 삭제하여 속도 유지
```
