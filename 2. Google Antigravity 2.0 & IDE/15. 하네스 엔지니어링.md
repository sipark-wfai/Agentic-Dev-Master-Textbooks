# 15. 하네스 엔지니어링 — 안전하고 제어 가능한 에이전트 설계

> **학습 목표**
> - 하네스 엔지니어링의 개념과 필요성을 이해한다
> - 에이전트 가드레일(Guardrails)을 설계하고 구현한다
> - Human-in-the-Loop(HitL) 체크포인트를 설정한다
> - 권한 제어와 비용 관리를 통해 안전한 에이전트 환경을 만든다

---

## 1. 하네스 엔지니어링이란

하네스(Harness)는 에이전트를 안전하고 예측 가능하게 제어하기 위한 설계 체계다. 강력한 에이전트일수록 잘못 설계된 하네스는 큰 피해를 가져올 수 있다.

```
하네스 엔지니어링의 3계층:

1. 방어 계층 (Defense)
   - 위험한 명령 차단 (DROP TABLE, rm -rf 등)
   - 파일 접근 범위 제한
   - 네트워크 접근 제한

2. 제어 계층 (Control)
   - Human-in-the-Loop 체크포인트
   - 에이전트 타임아웃 설정
   - 병렬 실행 수 제한

3. 가시성 계층 (Visibility)
   - 모든 에이전트 작업 로깅
   - 비용 모니터링
   - 알림 설정
```

## 2. 가드레일 설계

### 2.1 위험 명령 차단

```json
// antigravity settings.json (공식 설정 파일)
{
  "guardrails": {
    "blockedCommands": [
      "DROP TABLE",
      "DROP DATABASE",
      "DELETE FROM",
      "TRUNCATE",
      "rm -rf /",
      "chmod 777",
      "sudo rm"
    ],
    "requireApproval": [
      "git push --force",
      "npx prisma migrate reset",
      "docker system prune"
    ]
  }
}
```

### 2.2 파일 접근 제한

```json
{
  "sandbox": {
    "fileSystem": {
      "workspaceDir": "/projects/boardhub",
      "deniedPaths": [
        "**/.env",
        "**/.env.*",
        "**/.ssh/**",
        "**/.aws/**",
        "**/node_modules/.cache/**"
      ]
    }
  }
}
```

### 2.3 GEMINI.md에 가드레일 규칙 포함

```markdown
## 절대 금지 사항 (에이전트 하드 스톱)

- `DROP TABLE`, `DROP DATABASE`, `TRUNCATE` 실행 금지
- `DELETE FROM`으로 데이터를 물리적으로 삭제하는 것 금지
  (반드시 `deletedAt` 업데이트로 소프트 딜리트)
- `.env` 파일 읽기/수정 금지
- `git push --force` 실행 금지
- 프로덕션 DB에 직접 연결 금지
```

## 3. Human-in-the-Loop (HitL) 체크포인트

HitL은 에이전트가 고위험 작업을 수행하기 전에 인간의 승인을 요구하는 패턴이다.

### 3.1 HitL 설정

```json
{
  "humanInTheLoop": {
    "enabled": true,
    "triggers": [
      {
        "pattern": "git push",
        "message": "Git push를 실행하려 합니다. 계속하시겠습니까?",
        "timeout": 30
      },
      {
        "pattern": "npx prisma migrate",
        "message": "DB 마이그레이션을 실행하려 합니다. 확인하세요.",
        "timeout": 60
      },
      {
        "pattern": "docker push",
        "message": "컨테이너 이미지를 배포하려 합니다.",
        "timeout": 60
      }
    ]
  }
}
```

### 3.2 HitL 워크플로우

```
에이전트: "git push origin main을 실행하겠습니다"
        ↓
HitL 트리거 발동
        ↓
IDE 알림창: "Git push를 실행하려 합니다. 계속하시겠습니까? [승인] [거부]"
        ↓
개발자: [승인] 클릭
        ↓
에이전트: git push 실행
```

## 7. 팀 협업 하네스 설정

팀 전체가 동일한 하네스 설정을 사용하도록 Git으로 관리:

```bash
# 팀 공유 파일 (Git 커밋)
GEMINI.md                    # 에이전트 규칙 (가드레일 포함)

# 개인 설정 (.gitignore)
.env                         # API 키, DB 연결 정보
```

```json
// settings.json (팀 공유)
{
  "guardrails": {

  },

    "enabled": true
```
