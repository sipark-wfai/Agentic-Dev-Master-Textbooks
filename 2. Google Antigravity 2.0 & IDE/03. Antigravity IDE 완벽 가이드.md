# 03. Antigravity IDE 완벽 가이드 — 듀얼 엔진 뷰와 에이전트 협업 환경

> **학습 목표**
> - Antigravity IDE의 철학과 기존 VS Code 플러그인 방식의 차이를 이해한다
> - 듀얼 엔진 뷰(Dual-Engine View)의 구조와 활용법을 숙지한다
> - 에이전트 제안 시스템(Proposal Interface)의 모든 기능을 실습한다
> - 타임머신 롤백(Timemachine)으로 파일 이력을 복구하는 방법을 익힌다
> - IDE 권장 설정을 적용하여 최적의 개발 환경을 구성한다

## 1. IDE의 철학 — 에디터를 넘어선 에이전트 오케스트레이터

Antigravity IDE는 단순한 코드 에디터가 아니다. 에이전트와 인간이 하나의 화면에서 협업할 수 있도록 설계된 에이전트 오케스트레이터다.

기존 코드 에디터에서 AI를 사용하는 방식은 크게 두 가지였다:
1. 인라인 자동완성: 코드를 타이핑하는 동안 AI가 다음 줄을 제안
2. 채팅 패널: 에디터 옆 채팅창에서 AI와 대화하고 코드를 복사/붙여넣기

이 두 방식은 본질적으로 "AI가 제안하면 인간이 실행한다"는 구조다. 에이전트가 파일을 직접 수정하거나, 터미널 명령을 실행하거나, 결과를 검증하지 못한다.

Antigravity IDE는 이 패러다임을 뒤집는다:
- 에이전트가 파일을 직접 생성·수정한다 (Sandbox 내에서)
- 에이전트가 터미널 명령을 실행한다 (테스트, 빌드, 린트)
- 에이전트가 결과를 검증하고 오류를 자동 수정한다
- 인간은 최종 Proposal을 검토하고 수락/거부한다

## 2. 기존 VS Code 플러그인 방식의 3가지 한계

왜 Antigravity는 VS Code 플러그인 대신 독립적인 IDE를 선택했는가? 세 가지 근본적인 한계 때문이다.

### 한계 1: 맥락 격리 (Context Isolation)

VS Code 플러그인은 에디터가 열어 놓은 파일들의 내용만 볼 수 있다. 파일 탐색기를 통해 다른 파일을 열지 않으면 그 파일의 존재조차 모른다.

```
VS Code 플러그인의 맥락:
  열린 파일 탭 → AI가 볼 수 있는 범위
  닫힌 파일   → AI가 볼 수 없음
  DB 스키마   → AI가 알 수 없음 (MCP 없이)
  Git 이력    → AI가 알 수 없음
```

Antigravity IDE는 Desktop App의 MCP 서버들을 통해 프로젝트 전체, DB, Git, 외부 API의 맥락을 에이전트에게 제공한다.

### 한계 2: 제어권 부재 (No Control)

플러그인 방식에서 에이전트는 코드를 "제안"할 뿐, 실제로 실행할 수 없다.

```
플러그인 방식:
  AI: "이 코드를 실행하세요: npm run test"
  인간: 터미널 열기 → 입력 → 결과 확인 → AI에게 복사붙여넣기
  (이 루프가 무한 반복됨)

Antigravity IDE:
  AI → 샌드박스에서 npm run test 자동 실행 → 결과 분석 → 자동 수정
  (인간은 최종 Proposal만 검토)
```

### 한계 3: 복구 불가 (No Recovery)

플러그인이 잘못된 코드를 생성하면, Ctrl+Z로 되돌리거나 Git으로 복구해야 한다. 에이전트가 여러 파일을 동시에 수정했다면 각 파일을 개별적으로 되돌려야 한다.

Antigravity IDE의 타임머신(Timemachine) 기능은 트랜잭션 단위로 모든 변경을 기록하여 원클릭 복구를 가능하게 한다.

## 3. 듀얼 엔진 뷰 (Dual-Engine View)

IDE 화면은 크게 두 부분으로 나뉜다:

```
+--------------------------------------------------------------+
| 메뉴바: File | Edit | View | Go | Run | Agent | Help         |
+------------------------------+-------------------------------+
| 파일 탐색기                   |                               |
| ▼ boardhub                   |    에이전트 관리 패널           |
|   ▼ src                      |                               |
|     ▼ users                  | 탭: [Chat][Proposals][Artifacts]|
|       users.module.ts        |                               |
|       users.service.ts       | +---------------------------+ |
|       users.controller.ts    | | 채팅 인터페이스             | |
+------------------------------+ |                           | |
|                               | | > /code "users 모듈 구현" | |
|   코드 에디터                  | |                           | |
|   (VS Code 호환)               | | Gemini: 분석 중...        | |
|                               | | - 파일 읽기: schema.prisma| |
| import { Injectable } from   | | - 코드 생성: users.service| |
| '@nestjs/common';             | | - 테스트 실행: 2/5 통과   | |
|                               | +---------------------------+ |
| @Injectable()                 |                               |
| export class UsersService {  | 비용: 1,247 토큰 / $0.013   |
|   ...                         |                               |
| }                             |                               |
+------------------------------+-------------------------------+
| 상태바: Daemon: Connected | Sandbox: Running | Branch: main   |
+--------------------------------------------------------------+
```

### 3.1 좌측 패널 — 코드 에디터

VS Code와 완전히 호환된다. 기존 VS Code 익스텐션(ESLint, Prettier, GitLens 등)을 그대로 사용할 수 있다.

추가된 기능:
- 에이전트 작업 중 하이라이트: 에이전트가 현재 수정 중인 파일이 파일 탐색기에서 파란색으로 표시
- Proposal 표시: 에이전트가 변경을 제안한 파일에 마커 표시
- Timemachine 이력: 파일 우측 클릭 → "View Timemachine History"

### 3.2 우측 패널 — 에이전트 관리 패널

에이전트 관리 패널은 세 개의 탭으로 구성된다:

**탭 1: Chat (채팅)**
- 에이전트에게 지시를 내리는 채팅 인터페이스
- 슬래시 커맨드(/ask, /code, /review, /test 등) 지원
- 에이전트 작업 실시간 로그 스트리밍
- ReAct 루프의 각 단계(추론, 행동, 관측)를 시각화

**탭 2: Proposals (제안 목록)**
- 에이전트가 발행한 모든 Proposal 카드 목록
- 상태별 필터: Pending / Accepted / Rejected / Partial
- 일괄 Accept / 일괄 Reject 기능

**탭 3: Artifacts (산출물)**
- 에이전트 작업의 모든 산출물 타임라인
- 파일 변경, 테스트 결과, 스크린샷, 로그
- 특정 Artifact를 클릭하면 해당 내용을 에디터에서 열기

## 4. 에이전트 제안 시스템 (Proposal Interface) 완전 분석

Proposal Interface는 Antigravity 2.0의 핵심 안전장치다.

### 4.1 Proposal 카드 구조

```
+------------------------------------------------------------+
|  PROPOSAL #47                        [2026-06-01 14:32]    |
|  에이전트 ID: agent-xyz789                                   |
|  작업: "users 모듈의 CRUD API 구현"                           |
|------------------------------------------------------------|
|  변경 사항 요약:                                              |
|  - 신규 생성: src/users/users.service.ts     (+89줄)        |
|  - 신규 생성: src/users/users.controller.ts  (+67줄)        |
|  - 신규 생성: src/users/dto/create-user.dto.ts (+34줄)      |
|  - 수정:     src/users/users.module.ts       (+8줄, -2줄)   |
|  - 신규 생성: src/users/users.service.spec.ts (+112줄)      |
|------------------------------------------------------------|
|  테스트 결과: 8/8 통과 OK | 커버리지: 94%                    |
|  린트: 오류 없음 OK | TypeScript: 오류 없음 OK               |
|------------------------------------------------------------|
|  [Accept All]  [Reject All]  [Selective]  [Diff View]      |
+------------------------------------------------------------+
```

### 4.2 Accept 옵션들

**Accept All (전체 수락)**:
- 모든 파일 변경을 한 번에 실제 파일 시스템에 반영
- 타임머신에 이 시점이 스냅샷으로 저장됨
- 가장 빠른 방법이지만 검토를 건너뜀

**Reject All (전체 거부)**:
- 모든 변경을 폐기
- 에이전트에게 거부 이유를 입력하면 재시도 지시 가능
- 샌드박스는 이전 상태로 복원됨

**Selective Accept (선택적 수락)**:
- 파일별로 개별 수락/거부 결정
- 예: users.service.ts는 수락, users.spec.ts는 거부

**Diff View (변경 내역 보기)**:
- VS Code 스타일의 사이드 바이 사이드 diff
- 추가된 줄: 초록색, 삭제된 줄: 빨간색
- 특정 줄만 수락하는 "Hunk Accept" 기능 제공

### 4.3 Proposal 처리 전략

실무에서 효율적인 Proposal 처리 전략:

| 상황 | 권장 처리 방법 |
|------|--------------|
| 테스트 모두 통과 + 린트 오류 없음 | Accept All |
| 테스트 일부 실패 | Reject → 이유 입력 → 재시도 |
| 코드는 맞지만 스타일 문제 | Selective (스타일 관련만 Reject) |
| 대규모 변경 (50+ 파일) | Diff View로 중요 파일 먼저 검토 |
| 이해가 어려운 코드 | /ask로 설명 요청 후 결정 |

## 5. 타임머신 롤백 (Timemachine) — 트랜잭션 기반 파일 이력 관리

타임머신은 모든 Proposal Accept 시점을 스냅샷으로 저장하여 원클릭 복구를 가능하게 한다.

### 5.1 타임머신이 기록하는 이벤트

```
타임머신 타임라인 예시:
──────────────────────────────────────────────────────
T+0:00  [PROJECT_INIT] 프로젝트 초기화
T+0:35  [PROPOSAL_ACCEPT] #1 "DB 스키마 생성" (3 파일)
T+1:12  [PROPOSAL_ACCEPT] #2 "users 모듈 구현" (5 파일)
T+2:08  [MANUAL_EDIT] src/users/users.service.ts 수동 편집
T+2:45  [PROPOSAL_ACCEPT] #3 "auth 모듈 구현" (8 파일)
T+3:30  [PROPOSAL_ACCEPT] #4 "posts 모듈 구현" (7 파일) ← 현재
──────────────────────────────────────────────────────
```

### 5.2 타임머신 사용법

IDE에서:
```
우측 패널 → Artifacts 탭 → "Timemachine" 버튼
또는
파일 탐색기에서 파일 우측 클릭 → "View Timemachine History"
```

CLI에서:
```bash
# 타임머신 이력 목록
agy timemachine list

# 특정 스냅샷으로 롤백
agy timemachine restore --snapshot T_1_12

# 특정 파일만 특정 시점으로 복구
agy timemachine restore --file src/users/users.service.ts --snapshot T_0_35
```

### 5.3 Git과의 차이점

| 구분 | Git | Timemachine |
|------|-----|------------|
| 저장 단위 | 커밋 (수동) | Proposal Accept (자동) |
| 저장 시점 | 개발자가 결정 | 에이전트 작업 완료 시 자동 |
| 복구 방법 | git checkout | 원클릭 |
| 브랜치 | 있음 | 없음 (선형) |
| 협업 | 있음 (push/pull) | 없음 (로컬 전용) |
| 용도 | 버전 관리, 협업 | 에이전트 작업 안전망 |

타임머신은 Git을 대체하지 않는다. Git은 계속 사용하면서, 에이전트 작업의 세분화된 복구 수단으로 활용한다.

## 6. 실시간 비용 게이지

```
상태바 비용 표시:
토큰: 12,847 / 200,000 | 비용: $0.134 | 예상 총비용: $0.31
```

비용 게이지 상세 창:
```
+---------------------------------------+
| 현재 세션 비용 상세                     |
|---------------------------------------|
| 입력 토큰:   9,234 토큰 (플랜 한도 내 사용) |
| 출력 토큰:   3,613 토큰 (플랜 한도 내 사용) |
| 컨텍스트:   37.4%  (74,800/200,000)   |
```

## 7. 에이전트 작업 중 실시간 하이라이트

에이전트가 작업 중일 때 IDE는 다양한 시각적 피드백을 제공한다:

파일 탐색기 하이라이트:
- 에이전트가 현재 읽고 있는 파일: 파란색 점
- 에이전트가 현재 수정 중인 파일: 주황색 점
- Proposal 대기 중인 파일: 보라색 점

채팅 패널 실시간 스트리밍:
```
> /code "posts 모듈 구현 — 갤러리 게시판 포함"

[에이전트 실행 중...]
  REASON: posts 모듈의 현재 구조를 파악해야 합니다
  ACT:    filesystem-mcp로 src/posts/ 폴더 읽기
  OBSERVE: 현재 posts 폴더가 없음. 새로 생성 필요
  REASON: Prisma 스키마의 Post 모델 확인 필요
  ACT:    prisma/schema.prisma 읽기
  OBSERVE: Post 모델 확인, boardType 필드 발견
  REASON: 게시판 유형별 DTO를 분리 설계
  ACT:    파일 생성 중... (1/8) → src/posts/posts.module.ts
  ACT:    파일 생성 중... (2/8) → src/posts/posts.service.ts
  ...
  ACT:    npm run test:e2e 실행
  OBSERVE: 12/12 테스트 통과

[완료] Proposal #52 생성됨
```

## 8. IDE 컨텍스트 지시어

에이전트에게 지시할 때 특정 파일이나 폴더를 맥락으로 포함하려면 @ 지시어를 사용한다.

```
# 특정 파일을 맥락에 포함
/review @src/posts/posts.service.ts

# 특정 폴더 전체를 맥락에 포함
/code "이 폴더의 모든 서비스에 logging 인터셉터를 추가해" @src/

# 여러 파일 지정
/ask "이 두 파일의 의존성 관계를 설명해"
     @src/users/users.service.ts
     @src/auth/auth.service.ts
```

## 11. 멀티 게시판 프로젝트에서 IDE 활용 예시

BoardHub 프로젝트에서 실제로 IDE를 어떻게 활용하는지 보자.

### 11.1 프로젝트 열기

```bash
cd ~/projects/boardhub
antigravity-ide .
```

### 11.2 첫 번째 에이전트 지시

IDE 채팅창:
```
/ask "이 프로젝트의 구조를 파악하고, 현재 구현된 기능과
      아직 구현되지 않은 기능을 목록으로 정리해줘"
```

에이전트 응답:
```
프로젝트 구조를 분석했습니다.

현재 구현된 기능:
OK prisma/schema.prisma - DB 스키마 (8종 게시판 모델 포함)
OK src/app.module.ts - 앱 모듈 기본 구성
OK src/auth/ - 인증 모듈 (JWT 기반)

아직 구현되지 않은 기능:
NO src/users/ - 사용자 관리 모듈
NO src/boards/ - 게시판 관리 모듈
NO src/posts/ - 게시글 CRUD
NO src/comments/ - 댓글 CRUD
NO src/files/ - 파일 업로드
NO Frontend (SvelteKit) - 전혀 시작 안 됨

권장 순서: users → boards → posts → comments → files → frontend
```

### 11.3 모듈 구현 지시

```
/code "src/users/ 모듈을 완전히 구현해줘.
       @prisma/schema.prisma 의 User 모델을 기반으로,
       다음을 포함해야 해:
       - UsersService (CRUD + 소프트 딜리트)
       - UsersController (REST API)
       - CreateUserDto, UpdateUserDto (class-validator)
       - 단위 테스트 (Vitest, 커버리지 90% 이상)"
```

### 11.4 결과 검증 및 Proposal 처리

에이전트 작업 완료 후 Proposal 카드가 표시되면:

1. Diff View를 열어 users.service.ts의 소프트 딜리트 구현 확인
2. 테스트 결과 (9/9 통과) 확인
3. Accept All 클릭

타임머신에 스냅샷이 자동 저장된다.

## 12. VS Code 익스텐션 마이그레이션 가이드

기존에 VS Code를 사용하고 있었다면 Antigravity IDE로 마이그레이션할 때 익스텐션 호환성을 확인해야 한다.

호환되는 익스텐션 (대부분의 VS Code 마켓플레이스 익스텐션):
```
ESLint                (dbaeumer.vscode-eslint)
Prettier              (esbenp.prettier-vscode)
GitLens               (eamodio.gitlens)
Prisma                (Prisma.prisma)
Svelte for VS Code    (svelte.svelte-vscode)
Error Lens            (usernamehw.errorlens)
Thunder Client        (rangav.vscode-thunder-client)
```

호환되지 않는 익스텐션 (다른 AI 코파일럿):
```
GitHub Copilot        → Antigravity로 대체
Tabnine               → Antigravity로 대체
Codeium               → Antigravity로 대체
```

마이그레이션:
```bash
# VS Code 설정 파일을 Antigravity IDE로 복사
cp ~/.vscode/settings.json ~/.config/antigravity-ide/settings.json

# 익스텐션 목록 내보내기 (VS Code에서)
code --list-extensions > extensions.txt

# Antigravity IDE에서 설치
cat extensions.txt | xargs -I {} antigravity-ide --install-extension {}
```

## 체크리스트

이 편을 완료한 후 다음을 확인한다:

- [ ] 기존 VS Code 플러그인 방식의 3가지 한계를 설명할 수 있다
- [ ] 듀얼 엔진 뷰의 좌측/우측 패널 역할을 이해한다
- [ ] Proposal 카드의 4가지 처리 방법(Accept/Reject/Selective/Diff)을 실습했다
- [ ] 타임머신 롤백으로 특정 시점의 파일을 복구해봤다
- [ ] 비용 게이지에서 현재 세션의 토큰 사용량을 확인했다
- [ ] @ 지시어로 특정 파일을 맥락에 포함하여 지시해봤다
- [ ] settings.json 권장 설정을 IDE에 적용했다
- [ ] VS Code 익스텐션을 Antigravity IDE에 마이그레이션했다
