# 06. MCP(Model Context Protocol) 완벽 가이드 — 에이전트의 눈과 귀를 연결하는 법

> **학습 목표**
> - MCP가 없을 때 발생하는 환각(Hallucination) 문제를 이해한다
> - MCP 아키텍처와 데이터 흐름을 파악한다
> - 핵심 MCP 서버(PostgreSQL, Git, 파일 시스템, 웹 검색)를 설정하고 활용한다
> - 멀티 게시판 PostgreSQL 데이터베이스를 MCP로 연동한다
> - MCP 서버 디버깅 방법을 익힌다

## 1. MCP가 없을 때의 문제 — 환각(Hallucination)

### 1.1 환각 사례: DB 스키마 없이 코드 생성

에이전트에게 MCP 없이 코드를 생성하면 어떤 문제가 발생하는지 보자.

```
개발자: "users 테이블에서 이메일로 사용자를 찾는 쿼리를 작성해줘"

에이전트 (MCP 없음):
async findByEmail(email: string) {
  return await this.prisma.user.findUnique({
    where: { email },
    select: {
      id: true,
      email: true,
      username: true,    ← 실제 스키마에 없는 필드
      avatar: true,      ← 실제 스키마에 없는 필드
      createdAt: true,
    }
  });
}

실제 User 모델:
model User {
  id        Int    @id @default(autoincrement())
  email     String @unique
  nickname  String    ← 'username'이 아닌 'nickname'
  profile   String?   ← 'avatar'가 아닌 'profile'
  createdAt DateTime
}
```

에이전트는 실제 DB 스키마를 모르기 때문에 추측으로 코드를 작성한다. 이것이 환각이다. 이 코드는 TypeScript 컴파일은 통과하지만, 런타임에서 Prisma 오류가 발생한다.

### 1.2 환각 사례: Git 이력 없이 코드 수정

```
개발자: "authentication 모듈에서 최근에 추가된 기능이 뭔가?"

에이전트 (Git MCP 없음):
"죄송합니다. 최근 변경 이력을 알 수 없습니다. 현재 파일 내용을 기반으로
 설명하겠습니다..."

에이전트 (Git MCP 있음):
"3일 전 커밋(a3f9c2d)에서 refresh token 순환 갱신 기능이 추가되었습니다.
 변경된 파일: auth.service.ts (+87줄), auth.controller.ts (+23줄)
 커밋 메시지: 'feat: JWT refresh token rotation 구현'"
```

MCP는 에이전트에게 실세계의 정보를 실시간으로 제공함으로써 환각을 방지한다.

## 2. MCP 아키텍처

### 2.1 전체 데이터 흐름

```
사용자 지시
    |
    v
Gemini 3.5 Flash (AI 모델)
    |
    | "postgres-mcp를 사용해서 users 테이블 구조 조회"
    v
Antigravity Desktop App (MCP Host)
    |
    | MCP 프로토콜 (JSON-RPC over stdio/HTTP)
    v
MCP Server (postgres-mcp)
    |
    | SQL: SELECT column_name, data_type FROM information_schema.columns...
    v
PostgreSQL 16 (실제 DB)
    |
    v
쿼리 결과 반환
    |
    v
MCP Server → Desktop App → Gemini 3.5 Flash
    |
    | 실제 스키마 정보를 바탕으로 코드 생성
    v
정확한 코드 생성 (환각 없음)
```

### 2.2 MCP 프로토콜이란

MCP(Model Context Protocol)는 Anthropic이 2024년 오픈소스로 공개한 표준 프로토콜이다. Google은 Antigravity에 MCP를 채택하여 서드파티 서버와의 호환성을 보장한다.

MCP의 핵심 개념:

| 개념 | 설명 |
|------|------|
| Host | MCP 클라이언트 측. Antigravity Desktop App이 Host |
| Server | 실제 시스템과 통신하는 서버. postgres-mcp, git-mcp 등 |
| Tool | 에이전트가 호출할 수 있는 함수. query_database, list_commits 등 |
| Resource | 에이전트가 읽을 수 있는 데이터. 파일, DB 레코드 등 |

## 4. 핵심 MCP 서버 실습

### 4.1 postgres-mcp: PostgreSQL 16 스키마 실시간 조회

**설치 및 설정:**

```bash
# 1. PostgreSQL 16 실행 확인
docker run -d \
  --name boardhub-postgres \
  -e POSTGRES_DB=boardhub_db \
  -e POSTGRES_USER=boardhub_user \
  -e POSTGRES_PASSWORD=securepassword \
  -p 5432:5432 \
  postgres:16-alpine

# 2. MCP 설정 추가
agy mcp add postgres-mcp \
  --connection "postgresql://boardhub_user:securepassword@localhost:5432/boardhub_db"

# 3. MCP 서버 재시작
agy mcp restart postgres-mcp

# 4. 연결 확인
agy mcp status postgres-mcp
```

**MCP 활성화 후 에이전트 활용:**

```
/ask "현재 데이터베이스에서 users 테이블의 정확한 컬럼 목록을 알려줘"

에이전트 응답 (postgres-mcp 사용):
postgres-mcp를 통해 조회한 결과:

Table: users
- id: SERIAL PRIMARY KEY
- email: VARCHAR(255) UNIQUE NOT NULL
- nickname: VARCHAR(100) NOT NULL
- password_hash: VARCHAR(255) NOT NULL
- role: user_role (ENUM: 'ADMIN', 'MODERATOR', 'USER') DEFAULT 'USER'
- profile: TEXT
- is_active: BOOLEAN DEFAULT true
- created_at: TIMESTAMPTZ DEFAULT NOW()
- updated_at: TIMESTAMPTZ DEFAULT NOW()
- deleted_at: TIMESTAMPTZ (소프트 딜리트)
```

**postgres-mcp가 제공하는 Tool 목록:**

| Tool | 설명 |
|------|------|
| list_tables | 모든 테이블 목록 조회 |
| describe_table | 특정 테이블의 컬럼, 인덱스, 제약조건 조회 |
| query_database | SELECT 쿼리 실행 (읽기 전용) |
| list_indexes | 인덱스 목록 조회 |
| list_foreign_keys | 외래 키 관계 조회 |

## 5. 멀티 게시판 PostgreSQL 연동 전체 실습

BoardHub 프로젝트에 postgres-mcp를 연동하고 활용하는 전체 과정이다.

### 5.1 Docker로 PostgreSQL 16 실행

```bash
# docker-compose.yml (개발 환경)
cat > docker-compose.dev.yml << 'EOF'
# version 필드 제거 (Docker Compose v2에서 deprecated) <!-- R3 수정 -->
services:
  postgres:
    image: postgres:16-alpine
    container_name: boardhub-postgres
    environment:
      POSTGRES_DB: boardhub_db
      POSTGRES_USER: boardhub_user
      POSTGRES_PASSWORD: dev_password_2026
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U boardhub_user -d boardhub_db"]
      interval: 5s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:
EOF

# 실행
docker-compose -f docker-compose.dev.yml up -d

# 연결 확인
docker exec boardhub-postgres psql -U boardhub_user -d boardhub_db -c "SELECT version();"
```

### 5.4 MCP 연동 후 코드 생성 품질 비교

```
# postgres-mcp 활성화 상태에서:
/code "posts 테이블 기반으로 PostsService.findAll을 구현해줘"

에이전트가 postgres-mcp로 실제 스키마를 확인 후 생성한 코드:
async findAll(boardId: number, page: number, limit: number) {
  return await this.prisma.post.findMany({
    where: {
      boardId,
      deletedAt: null,  // ← 실제 스키마의 deleted_at 확인
    },
    select: {
      id: true,
      title: true,
      content: true,
      viewCount: true,       // ← 실제 필드명 확인
      commentCount: true,    // ← 실제 필드명 확인
      boardType: true,       // ← 실제 필드명 확인
      author: {
        select: {
          id: true,
          nickname: true,    // ← 'username' 아닌 'nickname' (실제 확인)
          profile: true,     // ← 'avatar' 아닌 'profile' (실제 확인)
        }
      },
      createdAt: true,
    },
    skip: (page - 1) * limit,
    take: limit,
    orderBy: { createdAt: 'desc' }
  });
}
```

## 6. MCP 서버 디버깅 방법

### 6.1 MCP 서버 상태 확인

```bash
# 전체 MCP 서버 상태
agy mcp list

# → [running]  git-mcp (저장소: /projects/boardhub)
# → [error]    brave-search-mcp (오류: API 키 없음)
# → [stopped]  filesystem-mcp

# 특정 서버 상태 상세 확인

# → 마지막 쿼리: 2026-06-01 14:32:00
# → 오류 수: 0
```

### 6.2 MCP 서버 로그 확인

```bash
# 실시간 로그
agy mcp logs postgres-mcp --follow

# 최근 50줄
agy mcp logs postgres-mcp --tail 50

# 로그 파일 직접 확인
tail -f ~/.gemini/logs/mcp-postgres.log  # 주의: 로그 경로 공식 미확인 <!-- R3 수정 -->
```

### 6.3 MCP 연결 테스트

```bash
# postgres-mcp 연결 테스트
agy mcp test postgres-mcp
# → 연결 성공: boardhub_db (PostgreSQL 16.2)
# → 테이블 수: 7
# → 응답 시간: 12ms
```

### 6.4 일반적인 MCP 오류 해결

| 오류 | 원인 | 해결 |
|------|------|------|
| Connection refused (5432) | PostgreSQL 미실행 | docker-compose up |
| Authentication failed | DB 비밀번호 오류 | DATABASE_URL 재확인 |
| Module not found | npx 패키지 미설치 | npx cache 클리어 |
| Permission denied | 파일 접근 권한 | filesystem-mcp 경로 확인 |
| API key invalid | Brave API 키 오류 | API 키 재발급 |

