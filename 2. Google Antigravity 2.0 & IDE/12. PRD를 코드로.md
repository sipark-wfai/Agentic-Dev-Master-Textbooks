## 2. 마일스톤 분할 전략

### 2.1 왜 마일스톤을 분할하는가

에이전트에게 "전체 BoardHub를 구현해줘" 라고 지시하면:
- 컨텍스트 윈도우가 중간에 고갈될 수 있음
- 실패 시 어디서 문제가 생겼는지 파악 어려움
- 중간 검토 불가능 (블랙박스)

마일스톤 분할의 이점:
- 각 마일스톤 완료 후 검토 가능
- 실패 시 해당 마일스톤만 재시도
- 컨텍스트 윈도우 관리 용이
- 타임머신 스냅샷 포인트 생성

### 2.2 BoardHub 마일스톤 계획

```
마일스톤 1: 데이터베이스 스키마 (이 편에서 실습)
  - Prisma schema.prisma 작성
  - 초기 마이그레이션 실행
  - 완료 기준: npx prisma migrate dev 성공, 모든 테이블 생성
```

## 3. 에이전트 지시문 작성 패턴

### 3.1 좋은 지시문의 5가지 요소

1. **명확한 범위**: 어떤 파일/폴더를 수정할지
2. **구체적인 입력**: 참조할 문서 (@파일경로)
3. **명확한 완료 기준**: 어떻게 성공을 판단할지
4. **예외 처리 지시**: 오류 발생 시 처리 방법
5. **금지 사항**: 하지 말아야 할 것

### 3.2 지시문 안티패턴 vs 좋은 패턴

**안티패턴 1: 모호한 범위**
```
# 나쁨
/code "게시판 관련 코드를 작성해줘"

# 좋음
/code "src/boards/boards.module.ts, boards.service.ts, boards.controller.ts를
       생성하고 다음 명세를 구현해줘:
       - 게시판 목록 조회 (GET /api/boards)
       - 게시판 상세 조회 (GET /api/boards/:id)
       - 게시판 생성 (POST /api/boards, Admin만)
       @docs/api/boards.md 참조"
```

**안티패턴 2: 완료 기준 없음**
```
# 나쁨
/code "users 모듈 구현해줘"

# 좋음
/code "users 모듈을 구현하고 다음 완료 기준을 확인해줘:
       1. npx tsc --noEmit 오류 없음
       2. npm run test:users 8/8 통과
       3. Swagger에서 /api/users 엔드포인트 접근 가능"
```

**안티패턴 3: 너무 큰 작업 단위**
```
# 나쁨 (컨텍스트 폭발)
agy agent run "전체 백엔드 API를 구현해줘"

# 좋음 (마일스톤 분할)
agy agent run "마일스톤 1: prisma/schema.prisma만 작성해줘. 
              다른 파일은 건드리지 마."
```

### 4.3 에이전트가 생성한 schema.prisma 검토

에이전트가 Proposal을 발행하면 Diff View로 검토한다:

```prisma
// apps/backend/prisma/schema.prisma (에이전트 생성본)

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

enum UserRole {
  ADMIN
  MODERATOR
  USER
}

enum BoardType {
  GENERAL
  GALLERY
  VIDEO
  QNA
  NOTICE
  FAQ
  PRIVATE
  FREE
}

model User {
  id           Int       @id @default(autoincrement())
  email        String    @unique @db.VarChar(255)
  nickname     String    @db.VarChar(100)
  passwordHash String    @map("password_hash")
  role         UserRole  @default(USER)
  profile      String?
  isActive     Boolean   @default(true) @map("is_active")
  createdAt    DateTime  @default(now()) @map("created_at")
  updatedAt    DateTime  @updatedAt @map("updated_at")
  deletedAt    DateTime? @map("deleted_at")

  posts         Post[]
  comments      Comment[]
  files         File[]
  postLikes     PostLike[]
  refreshTokens RefreshToken[]

  @@map("users")
}

model Board {
  id          Int       @id @default(autoincrement())
  name        String    @db.VarChar(50)
  type        BoardType
  description String?   @db.VarChar(500)
  isActive    Boolean   @default(true) @map("is_active")
  sortOrder   Int       @default(0) @map("sort_order")
  settings    Json?
  createdAt   DateTime  @default(now()) @map("created_at")
  updatedAt   DateTime  @updatedAt @map("updated_at")

  posts Post[]

  @@map("boards")
}

model Post {
  id               Int       @id @default(autoincrement())
  boardId          Int       @map("board_id")
  authorId         Int?      @map("author_id")
  title            String    @db.VarChar(200)
  content          String
  boardType        BoardType @map("board_type")
  isAnonymous      Boolean   @default(false) @map("is_anonymous")
  isPinned         Boolean   @default(false) @map("is_pinned")
  viewCount        Int       @default(0) @map("view_count")
  commentCount     Int       @default(0) @map("comment_count")
  likeCount        Int       @default(0) @map("like_count")
  isAnswered       Boolean?  @map("is_answered")
  acceptedAnswerId Int?      @map("accepted_answer_id")
  createdAt        DateTime  @default(now()) @map("created_at")
  updatedAt        DateTime  @updatedAt @map("updated_at")
  deletedAt        DateTime? @map("deleted_at")

  board    Board    @relation(fields: [boardId], references: [id])
  author   User?    @relation(fields: [authorId], references: [id])
  comments Comment[]
  files    File[]
  likes    PostLike[]

  @@index([boardId])
  @@index([authorId])
  @@index([deletedAt])
  @@map("posts")
}

model Comment {
  id        Int       @id @default(autoincrement())
  postId    Int       @map("post_id")
  authorId  Int?      @map("author_id")
  parentId  Int?      @map("parent_id")
  content   String    @db.VarChar(2000)
  likeCount Int       @default(0) @map("like_count")
  createdAt DateTime  @default(now()) @map("created_at")
  updatedAt DateTime  @updatedAt @map("updated_at")
  deletedAt DateTime? @map("deleted_at")

  post    Post      @relation(fields: [postId], references: [id])
  author  User?     @relation(fields: [authorId], references: [id])
  parent  Comment?  @relation("CommentReplies", fields: [parentId], references: [id])
  replies Comment[] @relation("CommentReplies")

  @@index([postId])
  @@index([parentId])
  @@map("comments")
}

model File {
  id               Int       @id @default(autoincrement())
  postId           Int?      @map("post_id")
  uploaderId       Int       @map("uploader_id")
  originalName     String    @map("original_name") @db.VarChar(255)
  storedPath       String    @map("stored_path")
  mimeType         String    @map("mime_type")
  fileSize         Int       @map("file_size")
  thumbnailSmPath  String?   @map("thumbnail_sm_path")
  thumbnailMdPath  String?   @map("thumbnail_md_path")
  thumbnailLgPath  String?   @map("thumbnail_lg_path")
  compressionRatio Int?      @map("compression_ratio")
  createdAt        DateTime  @default(now()) @map("created_at")
  deletedAt        DateTime? @map("deleted_at")

  post     Post? @relation(fields: [postId], references: [id])
  uploader User  @relation(fields: [uploaderId], references: [id])

  @@index([postId])
  @@map("files")
}

model PostLike {
  id        Int      @id @default(autoincrement())
  postId    Int      @map("post_id")
  userId    Int      @map("user_id")
  createdAt DateTime @default(now()) @map("created_at")

  post Post @relation(fields: [postId], references: [id])
  user User @relation(fields: [userId], references: [id])

  @@unique([postId, userId])
  @@map("post_likes")
}

model RefreshToken {
  id        Int      @id @default(autoincrement())
  userId    Int      @map("user_id")
  token     String   @unique
  isRevoked Boolean  @default(false) @map("is_revoked")
  expiresAt DateTime @map("expires_at")
  createdAt DateTime @default(now()) @map("created_at")

  user User @relation(fields: [userId], references: [id])

  @@map("refresh_tokens")
}
```

## 6. Proposal 검토 실전 가이드

### 6.1 대규모 Proposal 검토 순서

마일스톤 2가 완료되면 많은 파일이 변경된다. 효율적인 검토 순서:

```
1단계: 빌드/테스트 결과 먼저 확인
  → Proposal 카드 하단의 테스트 결과 확인
  → 오류가 있으면 Reject 후 재시도 (Accept 전에 확인)

2단계: 핵심 파일 Diff View 검토 (우선순위 순)
  → prisma.service.ts (소프트 딜리트 미들웨어)
  → jwt.strategy.ts (JWT 검증 로직)
  → auth.service.ts (login, refresh 로직)
  → auth.controller.ts (엔드포인트 경로)

3단계: 테스트 파일 확인
  → auth.service.spec.ts (테스트 케이스 커버리지)

4단계: Accept All 또는 Selective Accept
```

### 6.2 Proposal 검토 체크포인트

```
auth.service.ts 검토 포인트:
[ ] bcrypt.compare 사용 (평문 비교 금지)
```
