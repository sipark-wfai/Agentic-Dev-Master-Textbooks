# 14. 실전 완성 멀티 게시판 구현 — BoardHub 전체 시스템 완성

> **학습 목표**
> - pnpm 모노레포 구조로 BoardHub 프로젝트를 설정한다
> - SvelteKit + NestJS 풀스택을 에이전트로 완전 구현한다
> - Docker Compose로 개발 환경을 구성한다
> - 8종 게시판 전체 기능을 동작하는 상태로 완성한다

---

## 1. 프로젝트 구조 설정

### 1.1 pnpm 모노레포 초기화

```bash
# 프로젝트 디렉터리 생성
mkdir boardhub && cd boardhub
git init

# pnpm 모노레포 설정
cat > pnpm-workspace.yaml << 'EOF'
packages:
  - 'apps/*'
  - 'packages/*'
EOF

cat > package.json << 'EOF'
{
  "name": "boardhub",
  "private": true,
  "scripts": {
    "dev": "pnpm --parallel run dev",
    "build": "pnpm --recursive run build",
    "test": "pnpm --recursive run test",
    "lint": "pnpm --recursive run lint"
  }
}
EOF

# 앱 디렉터리 생성
mkdir -p apps/backend apps/frontend packages/shared
```

### 1.2 GEMINI.md 작성

```bash
cat > GEMINI.md << 'EOF'
# BoardHub — Gemini 에이전트 규칙서

## 기술 스택
- Frontend: SvelteKit 2.x + TypeScript
- Backend: NestJS 11.x + TypeScript
- DB: PostgreSQL 16 + Prisma v5
- 패키지 관리: pnpm 9.x (npm, yarn 금지)

## 절대 금지
- TypeScript `any` 타입 사용 금지
- Prisma `$queryRaw` 사용 금지
- `console.log` 사용 금지 (Logger 서비스 사용)
- `.env` 파일을 Git 커밋 금지
- DELETE 직접 실행 금지 (소프트 딜리트 정책)

## 필수 규칙
- TypeScript strict 모드를 항상 사용한다
- 모든 DB 조작은 Prisma ORM을 통해서만 한다
- 모든 API 엔드포인트에 Swagger 데코레이터를 추가한다
- 성공 응답: { success: true, data: T, meta: PageMeta | null }
- 에러 응답: { success: false, message, code, statusCode }
- 인증 필요 API는 JwtAuthGuard를 적용한다
- 모든 서비스 메서드에 한국어 JSDoc 주석을 작성한다

## 권장 패턴
- SvelteKit server-side load 함수를 클라이언트 fetch보다 우선 사용
- class-validator + class-transformer를 유효성 검증에 사용
- 테스트 파일은 구현 파일 옆에 위치 (*.spec.ts)
- 컴포넌트 파일명은 PascalCase 사용
EOF
```

## 2. Docker Compose 개발 환경

### 2.1 Docker Compose 설정

```yaml
# docker-compose.yml
version: '3.9'

services:
  postgres:
    image: postgres:16-alpine
    container_name: boardhub-postgres
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-boardhub_user}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-boardhub_pass}
      POSTGRES_DB: ${POSTGRES_DB:-boardhub_db}
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER:-boardhub_user}"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    container_name: boardhub-redis
    ports:
      - "6379:6379"

volumes:
  postgres_data:
```

```bash
# 개발 환경 시작
docker-compose up -d
docker-compose ps
```

## 3. 에이전트로 전체 구현

### 3.1 구현 순서

```bash
# 1단계: 백엔드 초기화
agy agent run "NestJS 백엔드 앱을 초기화해줘.
  apps/backend/ 폴더에 NestJS 11.x 프로젝트 생성.
  pnpm 사용, TypeScript strict 모드, Swagger 설정 포함"
  # --file GEMINI.md

# 2단계: Prisma 스키마 + 마이그레이션
agy agent run "BoardHub ERD를 기반으로 Prisma 스키마를 작성하고
  초기 마이그레이션을 실행해줘"
  # --file docs/erd.md --file apps/backend/prisma/schema.prisma

# 3단계: 인증 모듈
agy agent run "JWT 인증 시스템을 구현해줘.
  회원가입, 로그인, 토큰 갱신, 로그아웃 API"
  # --file GEMINI.md --file apps/backend/prisma/schema.prisma

# 4단계: 게시판 모듈
agy agent run "8종 게시판(GENERAL, GALLERY, VIDEO, QNA, NOTICE, FAQ, PRIVATE, ANONYMOUS)
  CRUD API를 구현해줘. 타입별 처리 로직 포함"
  # --file GEMINI.md --file apps/backend/prisma/schema.prisma

# 5단계: SvelteKit 프론트엔드
agy agent run "SvelteKit 2.x 프론트엔드를 구현해줘.
  apps/frontend/ 폴더. 게시판 목록, 게시글 목록/상세/작성 페이지"
  # --file GEMINI.md
```

## 4. 핵심 구현 검증

### 4.1 API 동작 확인

```bash
# Docker Compose 환경에서 백엔드 실행
cd apps/backend
pnpm run start:dev

# API 테스트
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"Test1234!","nickname":"테스터"}'

# → { "success": true, "data": { "userId": 1 } }

# Swagger UI 확인
open http://localhost:3000/api/docs
```

### 4.2 게시판별 동작 확인

```bash
# 갤러리 게시글 작성 (이미지 첨부 테스트)
curl -X POST http://localhost:3000/api/boards/2/posts \
  -H "Authorization: Bearer {jwt_token}" \
  -F "title=첫 갤러리 게시글" \
  -F "images=@test-image.jpg"
```
