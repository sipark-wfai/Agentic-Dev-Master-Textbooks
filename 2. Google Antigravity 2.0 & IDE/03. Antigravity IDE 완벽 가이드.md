> **R6 수정**: Timemachine 기능 완전 삭제. gRPC 세부 구현 내용 삭제(공식 미확인). 듀얼 엔진 뷰 및 에이전트 관리 패널 설명 유지(공식 확인). Proposal Interface → 변경사항 검토(Diff View) 방식으로 재기술.

## 1. IDE 기본 구조 — 듀얼 엔진 뷰

Antigravity IDE는 VS Code 아키텍처를 기반으로 하지만, 에이전트 협업을 위해 핵심 구조가 재설계되었다. 가장 큰 특징은 **듀얼 엔진 뷰(Dual-Engine View)**다.

```
┌──────────────────────────────────────────────────────────────────┐
│                      Antigravity IDE                              │
│  ┌──────────────────────────┐  ┌───────────────────────────────┐ │
│  │    에디터 엔진 (좌측)     │  │   에이전트 관리 패널 (우측)    │ │
│  │                          │  │                               │ │
│  │  [코드 에디터]            │  │  ┌─────────────────────────┐  │ │
│  │  *.svelte                │  │  │ 채팅 인터페이스          │  │ │
│  │  *.ts                   │  │  │ /ask /code /review       │  │ │
│  │  *.prisma               │  │  └─────────────────────────┘  │ │
│  │                          │  │                               │ │
│  │  [탐색기]                 │  │  ┌─────────────────────────┐  │ │
│  │  [소스 제어]              │  │  │ 에이전트 작업 현황       │  │ │
│  │  [디버거]                │  │  │ [running] agent-abc123   │  │ │
│  │  [확장]                  │  │  └─────────────────────────┘  │ │
│  │                          │  │                               │ │
│  │                          │  │  ┌─────────────────────────┐  │ │
│  │                          │  │  │ 변경사항 검토 (Diff)     │  │ │
│  │                          │  │  │ [수락] [거부]            │  │ │
│  │                          │  │  └─────────────────────────┘  │ │
│  └──────────────────────────┘  └───────────────────────────────┘ │
│  하단 상태바: Daemon: Connected | Sandbox: Ready | 비용 게이지     │
└──────────────────────────────────────────────────────────────────┘
```

### 1.1 에디터 엔진 (좌측 패널)

VS Code와 완전히 동일한 에디터 경험을 제공한다:
- Svelte, TypeScript, Prisma 언어 서버 내장
- Git 소스 제어 통합
- ESLint, Prettier 자동 포맷팅
- 기존 VS Code 확장(extension) 대부분 호환

### 1.2 에이전트 관리 패널 (우측 패널)

에이전트와 상호작용하는 공간이다:
- **채팅 인터페이스**: 슬래시 커맨드(/ask, /code, /review 등)로 에이전트 지시
- **에이전트 작업 현황**: 실행 중인 에이전트 상태, 진행률
- **변경사항 검토**: 에이전트가 생성한 변경사항을 Diff View로 확인하고 수락/거부

---

## 2. 에이전트 관리 패널 상세

### 2.1 채팅 인터페이스

에이전트와 대화하는 주요 인터페이스다. 슬래시 커맨드를 입력하여 에이전트 동작을 제어한다.

```
[채팅 입력창]
/ask "현재 posts 모듈의 구현 상태를 분석해줘" @src/posts/

에이전트 응답:
posts 모듈을 분석했습니다.
현재 구현 상태:
- PostsController: 4개 엔드포인트 (GET, POST, PUT, DELETE)
- PostsService: CRUD 메서드 구현됨
- 누락: 갤러리 타입 이미지 업로드 처리
- 누락: 단위 테스트 (커버리지 0%)
```

### 2.2 에이전트 작업 현황

실행 중인 에이전트의 상태를 실시간으로 표시한다:

```
실행 중인 에이전트:
┌──────────────────────────────────────────────────────┐
│  agent-abc123  [running]  3m 24s                      │
│  "posts 모듈 GALLERY 타입 이미지 처리 구현"           │
│  ▶ 현재 단계: Prisma 스키마 분석 중...                │
│  [중지] [로그 보기]                                    │
├──────────────────────────────────────────────────────┤
│  agent-xyz789  [waiting]  큐 대기                     │
│  "단위 테스트 생성"                                    │
└──────────────────────────────────────────────────────┘
```

### 2.3 변경사항 검토 (Diff View)

에이전트가 파일을 수정하거나 새 파일을 생성하면 변경사항이 표시된다. 개발자는 Diff View로 내용을 확인한 후 적용 여부를 결정한다.

```
변경사항 검토:
┌──────────────────────────────────────────────────────┐
│  📄 src/posts/posts.service.ts                        │
│  수정: +45줄 / -3줄                                   │
│  [Diff View] [수락] [거부]                            │
├──────────────────────────────────────────────────────┤
│  📄 prisma/schema.prisma                              │
│  수정: +12줄 / -0줄                                   │
│  [Diff View] [수락] [거부]                            │
└──────────────────────────────────────────────────────┘
```

**수락**: 변경사항이 실제 파일에 반영된다
**거부**: 변경사항이 버려지고 파일은 원래 상태를 유지한다
**Diff View**: 에디터에서 변경 전후를 나란히 비교한다

## 5. 실전 워크플로우 — BoardHub 구현 시나리오

### 5.1 일반적인 작업 흐름

```
1. IDE 좌측 탐색기에서 작업 대상 파일 확인
2. 에이전트 패널 채팅에서 작업 지시
   /code "posts 모듈에 GALLERY 타입 이미지 업로드 기능을 추가해"
         @src/posts/ @prisma/schema.prisma
3. 에이전트가 작업하는 동안 에디터에서 다른 코드 검토
4. 에이전트 작업 완료 후 변경사항 검토 패널 확인
5. Diff View로 각 파일의 변경사항을 검토
6. 올바른 변경사항은 수락, 잘못된 것은 거부
7. 수락 후 IDE 터미널에서 테스트 실행 확인
```

### 5.2 컨텍스트 지시어(@) 활용

에이전트에게 특정 파일이나 폴더를 참고하도록 지시할 수 있다:

```
@src/posts/posts.service.ts     → 특정 파일
@src/posts/                     → 폴더 전체
@prisma/schema.prisma           → Prisma 스키마
@GEMINI.md                      → 규칙 파일
@docs/api-spec.md               → API 명세
```

예시:
```
/fix "이 두 파일 사이의 타입 불일치를 수정해줘"
     @src/posts/posts.service.ts
     @src/posts/dto/create-post.dto.ts
```
