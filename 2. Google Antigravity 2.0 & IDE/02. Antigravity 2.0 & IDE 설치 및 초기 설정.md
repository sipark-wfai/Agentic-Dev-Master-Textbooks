# 02. Antigravity 2.0 & IDE 설치 및 초기 설정 — macOS · Windows 환경 구성 완벽 가이드

> **학습 목표**
> - macOS와 Windows 각 환경에서 Antigravity 2.0을 완벽하게 설치한다
> - Gemini API 키를 발급받고 Desktop App에 연동한다
> - Antigravity IDE와 Desktop App의 연결을 검증한다
> - 첫 번째 에이전트 실행 (Hello World)을 성공시킨다
> - 설치 과정에서 자주 발생하는 오류 5가지를 해결할 수 있다

## 1. 사전 요구사항

설치를 시작하기 전에 다음 소프트웨어가 설치되어 있어야 한다.

### 1.1 공통 요구사항

| 소프트웨어 | 최소 버전 | 권장 버전 | 비고 |
|-----------|---------|---------|-----|
| Node.js | 20.x LTS | 22.x LTS | nvm 사용 권장 |
| Git | 2.40 | 2.45+ | - |
| Docker Desktop | 4.28 | 4.30+ | 샌드박스 실행에 필수 |
| pnpm | 9.x | 9.x | npm/yarn 대신 사용 |

### 1.2 macOS 추가 요구사항

| 항목 | 요구사항 |
|------|---------|
| macOS 버전 | 13 Ventura 이상 |
| Apple Silicon (M1/M2/M3/M4) | 완전 지원 (Native ARM 빌드) |
| Intel Mac | 지원 (Rosetta 필요) |
| 메모리 | 최소 16GB (권장 32GB) |
| 디스크 여유 공간 | 최소 20GB |
| 가상화 | 가상화 기술 활성화 필요 |

### 1.3 Windows 추가 요구사항

| 항목 | 요구사항 |
|------|---------|
| Windows 버전 | Windows 11 22H2 이상 |
| WSL2 | 필수 (Ubuntu 22.04 LTS 권장) |
| 메모리 | 최소 16GB (권장 32GB) |
| 디스크 여유 공간 | 최소 25GB |
| Hyper-V | 활성화 필요 |

### 1.4 사전 설치 확인

```bash
# 설치 전 환경 확인 (macOS/Linux)
node --version    # v22.x.x 이상
git --version     # git version 2.4x.x 이상
docker --version  # Docker version 4.3x.x 이상
pnpm --version    # 9.x.x 이상

# Docker Desktop이 실행 중인지 확인
docker ps         # 오류 없이 실행되면 정상
```

Node.js가 없다면:

```bash
# macOS에서 nvm으로 Node.js 설치
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.zshrc
nvm install 22
nvm use 22
nvm alias default 22
```

## 2. macOS 설치 가이드

### 2.1 Desktop App 설치

**Step 1**: Google AI Studio 다운로드 페이지에서 Desktop App을 다운로드한다

```
URL: https://antigravity.google  <!-- R3 수정: 정확한 다운로드 URL은 공식 사이트 참고 -- 원문 URL 공식 미확인 -->
파일명: Antigravity-2.0-Desktop-arm64.dmg  (Apple Silicon)
        Antigravity-2.0-Desktop-x64.dmg    (Intel Mac)
파일 크기: 약 420MB
```

**Step 2**: DMG 파일을 열고 Applications 폴더로 드래그한다

**Step 3**: Gatekeeper 보안 설정 해제

Apple Silicon Mac에서는 처음 실행 시 '개발자를 확인할 수 없습니다' 오류가 발생할 수 있다:

```bash
# 방법 1: 터미널에서 Gatekeeper 제외 등록
xattr -d com.apple.quarantine /Applications/Antigravity.app

# 방법 2: 시스템 환경설정 → 보안 및 개인정보 보호
# → '확인 없이 열기' 버튼 클릭
```

**Step 4**: 처음 실행

```
Applications 폴더에서 Antigravity 앱을 더블클릭

초기 실행 시 다음 단계가 자동으로 진행됨:
1. 로컬 에이전트 데몬 설치 (launchd 서비스 등록)
2. 가상화 리소스 초기화 (Docker 컨테이너 준비)
3. Alpine Linux 샌드박스 이미지 다운로드 (약 150MB)
4. MCP 서버 기본 패키지 설치

소요 시간: 약 3~8분 (인터넷 속도에 따라 다름)
```

**Step 5**: 메뉴바에 Antigravity 아이콘 확인

```
macOS 메뉴바 상단 우측에 Antigravity 아이콘(▲)이 표시되면 정상
아이콘 클릭 시 상태 메뉴 표시:
  ● Daemon: Running
  ● Sandbox: Ready
  ● API: Not Connected (아직 API 키 미설정)
```

### 2.2 IDE 설치 (macOS)

**Step 1**: IDE 다운로드

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
```

## 5. Desktop App과 IDE 연동 설정

Desktop App과 IDE는 gRPC를 통해 통신한다. 기본적으로 자동 연결되지만, 수동 설정이 필요한 경우가 있다.

### 5.1 연동 설정

```json
{
  "antigravity.daemon.host": "localhost",
  "antigravity.daemon.port": 7432  <!-- R3 수정: 포트 번호 7432 공식 미확인 -->,
  "antigravity.daemon.tlsEnabled": false,
  "antigravity.daemon.autoReconnect": true,
  "antigravity.daemon.reconnectIntervalMs": 3000
}
```

### 5.2 연동 상태 확인

IDE 하단 상태바에서:
```
● Antigravity Daemon: Connected    ← 초록색: 정상
● Antigravity Daemon: Connecting   ← 노란색: 연결 중
● Antigravity Daemon: Disconnected ← 빨간색: 연결 실패
```

연결 실패 시:
```bash
# 데몬 재시작
agy daemon restart

# 또는 Desktop App을 종료하고 재시작
pkill -f antigravity-daemon  # macOS/Linux
```

## 7. 자주 겪는 초기 오류 5가지와 해결법

### 오류 1: 'Cannot connect to Docker daemon'

**증상**: `agy status` 실행 시 Sandbox 상태가 'Error: Docker not running'

**원인**: Docker Desktop이 실행되지 않은 상태

**해결**:
```bash
# macOS: Docker Desktop 앱 실행
open /Applications/Docker.app

# 실행 확인 (약 30초 대기 후)
docker ps
agy status
```

**예방**: 로그인 시 Docker Desktop 자동 시작 설정
```
Docker Desktop → Settings → General
→ 'Start Docker Desktop when you sign in' 체크
```

### 오류 2: 'Gemini API key invalid or expired'

**증상**: `agy status` 실행 시 Gemini 상태가 'Error: 401 Unauthorized'

**원인**: API 키 오타, 만료, 또는 프로젝트 결제 미설정

**해결**:
```bash
# 1. Google AI Studio에서 API 키 재확인
# 2. API 키 재설정
agy config set gemini.apiKey "AIzaSy..."

# 3. 연결 테스트
agy status
```

결제 관련 오류라면 Google Cloud Console에서 결제 계정을 활성화해야 한다.

### 오류 3: 'Port 7432 already in use'

**증상**: Desktop App 시작 시 'Address already in use: 7432'

**원인**: 이전 데몬 프로세스가 좀비 상태로 남아 있음

**해결**:
```bash
# macOS/Linux
lsof -i :7432
kill -9 $(lsof -t -i:7432)
agy daemon start

# Windows (PowerShell)
netstat -ano | findstr :7432
taskkill /PID [pid번호] /F
```

### 오류 4: 'WSL2 kernel not found' (Windows 전용)

**증상**: Windows에서 Desktop App 시작 시 WSL2 관련 오류

**원인**: WSL2 커널이 업데이트되지 않음

**해결**:
```powershell
# PowerShell 관리자 권한으로 실행
wsl --update
wsl --set-default-version 2
wsl --shutdown
# 이후 Docker Desktop 재시작
```

### 오류 5: 'Sandbox image pull failed'

**증상**: 첫 실행 시 샌드박스 이미지 다운로드 실패

**원인**: 방화벽, 프록시, 또는 네트워크 문제

**해결**:
```bash
# 1. 네트워크 확인
ping gcr.io

# 2. 수동으로 이미지 풀
docker pull gcr.io/antigravity-sandbox/alpine-base:2.0  <!-- R3 수정: 이미지 경로 공식 미확인 — 창작 가능성 있음 -->

# 3. 이미지 풀 후 데몬 재시작
agy daemon restart
```

## 8. 첫 번째 Hello World 실습

설치가 완료되었다면 첫 번째 에이전트 작업을 실행해보자.

### 8.1 프로젝트 준비

```bash
# 실습용 프로젝트 디렉터리 생성
mkdir ~/boardhub-test
cd ~/boardhub-test
git init

# GEMINI.md 생성 (간단한 버전)
cat > GEMINI.md << 'EOF'
# BoardHub 테스트 프로젝트

@must 한국어로 주석을 작성한다
@must TypeScript를 사용한다
@prefer 함수는 단일 책임 원칙을 따른다
EOF

echo '프로젝트 준비 완료'
```

### 8.2 첫 번째 에이전트 실행 (CLI 방식)

```bash
# 에이전트에게 첫 번째 작업 지시
agy agent run "TypeScript로 간단한 hello.ts 파일을 만들어줘."
  # 인사말을 받아서 콘솔에 출력하는 greet 함수를 포함하고,
  # main 함수에서 '안녕하세요, Antigravity!'를 출력해

# 에이전트 실행 상태 확인
agy agent list
# → [running] agent-abc123: TypeScript로 간단한 hello.ts...

# 작업 완료 대기
agy agent wait agent-abc123

# 완료 후 Proposal 목록 확인
agy proposal list
```

### 8.3 IDE에서 Proposal 확인 및 수락

```
IDE에서 에이전트 패널을 확인하면:

┌─────────────────────────────────────────┐
```

```typescript
// hello.ts (에이전트가 생성한 파일)

/**
 * 인사말을 받아서 콘솔에 출력하는 함수
 * @param name - 인사할 대상의 이름
 */

  console.log(`안녕하세요, ${name}!`);
}

/**
 * 메인 실행 함수
 */
function main(): void {
  greet("Antigravity");
}

main();
```

### 8.4 첫 번째 IDE 채팅 사용

IDE 에이전트 패널의 채팅창에서:

```
/ask "이 hello.ts 파일에 테스트를 추가하려면 어떤 프레임워크를 사용하는 게 좋을까?"
```

Gemini 3.5가 응답:
```
이 프로젝트에는 Vitest를 권장합니다. 이유는 다음과 같습니다:

1. TypeScript를 기본 지원합니다 (별도 설정 불필요)
2. Jest와 API가 호환되어 학습 곡선이 낮습니다
3. 속도가 빠릅니다 (ES 모듈 네이티브 지원)
```

이것이 `/ask` 명령어의 특성이다 — 코드를 수정하지 않고 질문/상담만 한다.

이제 실제 테스트를 생성하려면:

```
/test "hello.ts의 greet 함수에 대한 단위 테스트를 Vitest로 작성해"
```
