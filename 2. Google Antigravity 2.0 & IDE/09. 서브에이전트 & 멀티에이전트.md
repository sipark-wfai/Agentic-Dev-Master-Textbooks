# 09. 서브에이전트 & 멀티에이전트 — 에이전트 팀을 구성하고 조율하는 법

> **학습 목표**
> - 단일 에이전트의 한계와 멀티에이전트의 필요성을 이해한다
> - 오케스트레이터-워커 패턴을 설계할 수 있다
> - 직렬 vs 병렬 실행의 선택 기준을 파악한다
> - 파일 충돌을 방지하는 설정을 적용한다
> - 멀티 게시판 8종을 에이전트별로 분배하여 병렬 구현한다

## 1. 단일 에이전트의 한계

대형 프로젝트를 단일 에이전트로 처리하면 다음 문제가 발생한다:

### 1.1 컨텍스트 윈도우 고갈

```
단일 에이전트가 BoardHub 전체를 구현할 때:

초기: GEMINI.md + PRD + ERD = 18,000 토큰
작업 누적:
  users 모듈:    12,000 토큰
  boards 모듈:   10,000 토큰
  posts 모듈:    25,000 토큰
  comments 모듈: 15,000 토큰
총계: 80,000 토큰 → posts까지는 가능하지만
  files + frontend 추가 시 200,000 토큰 한계 위험
```

### 1.2 처리 시간의 선형 증가

```
단일 에이전트 순차 실행:     85분
멀티에이전트 병렬 실행:     45분 (47% 단축)
```

---

## 2. 오케스트레이터-워커 패턴

Antigravity의 멀티에이전트는 오케스트레이터-워커 패턴으로 동작한다 (공식 확인).

```
오케스트레이터 에이전트
    ├── 전체 작업 분석
    ├── 서브에이전트 생성 및 지시
    └── 결과 통합

워커 에이전트들
    ├── Agent-1: users + auth 모듈
    ├── Agent-2: boards + posts 모듈
    └── Agent-3: files 모듈
```

### 2.1 오케스트레이터 실행

```bash
# 오케스트레이터가 전체 작업을 분배하도록 지시
agy agent run "다음 작업을 서브에이전트로 분배하여 병렬 실행해줘:
  1. users 모듈 + auth 모듈 구현
  2. boards 모듈 + posts 모듈 구현
  3. files 모듈 구현
  각 에이전트는 GEMINI.md 규칙을 따르고,
  prisma/schema.prisma를 기반으로 구현해줘"
```

---

## 3. 병렬 서브에이전트 실행

병렬 서브에이전트는 공식 확인된 기능이다.

```bash
# 서브에이전트 1: users + auth 모듈
agy agent run "users 모듈과 auth 모듈을 구현해줘.
  JWT 인증 포함. GEMINI.md 규칙 준수." &
AGENT_1=$!

# 서브에이전트 2: boards + posts 모듈
agy agent run "boards 모듈과 posts 모듈을 구현해줘.
  8종 게시판 타입 처리 포함. GEMINI.md 규칙 준수." &
AGENT_2=$!

# 서브에이전트 3: files 모듈
agy agent run "files 모듈을 구현해줘.
  이미지/동영상 업로드 처리. GEMINI.md 규칙 준수." &
AGENT_3=$!

# 모든 에이전트 완료 대기
wait $AGENT_1 $AGENT_2 $AGENT_3
echo "모든 서브에이전트 작업 완료"
```

### 3.1 에이전트 목록 모니터링

```bash
# 실행 중인 모든 에이전트 확인
agy agent list
# → [running] agent-001: "users + auth 모듈 구현" (5m 12s)
# → [running] agent-002: "boards + posts 모듈 구현" (5m 12s)
# → [running] agent-003: "files 모듈 구현" (5m 12s)

# 특정 에이전트 로그 확인
agy logs agent-001 --follow

# IDE /agents 슬래시 커맨드로 모니터링 (공식 확인)
/agents
```

## 4. 직렬 vs 병렬 실행 선택 기준

### 4.1 직렬 실행이 필요한 경우

```bash
# 의존성이 있는 작업: 직렬 실행
# 1. Prisma 스키마 먼저 완성
agy agent run "prisma/schema.prisma를 완성해줘. 모든 모델 포함"
agy agent wait  # 완료 대기

# 2. 스키마 기반으로 마이그레이션
agy agent run "완성된 스키마로 migration을 생성해줘"
agy agent wait

# 3. 마이그레이션 기반으로 서비스 구현
agy agent run "마이그레이션이 완료된 상태에서 서비스 코드를 구현해줘"
```

### 4.2 병렬 실행이 가능한 경우

```
서로 다른 파일/모듈을 수정:
  Agent-1: src/users/  (겹치지 않음)
  Agent-2: src/boards/ (겹치지 않음)
  → 병렬 실행 안전

같은 파일을 수정:
  Agent-1: src/app.module.ts
  Agent-2: src/app.module.ts
  → 충돌 위험! 직렬 실행 권장
```

## 5. 파일 충돌 방지

여러 에이전트가 동시에 같은 파일을 수정하면 충돌이 발생한다.

### 5.1 충돌 방지 설정

공유 파일(`app.module.ts`, `prisma/schema.prisma` 등)을 건드리는 작업은 에이전트별로 명확히 분리한다:

```bash
# 에이전트 지시문에서 파일 범위 명시
agy agent run "src/users/ 폴더만 수정해줘.
  app.module.ts와 prisma/schema.prisma는 건드리지 마.
  나중에 별도로 통합할 예정이야"
```

```json
// settings.json에서 공유 파일 잠금 설정
// (설정 키 이름은 공식 문서 확인 권장)
{
  "multiAgent": {
    "protectedFiles": [
      "prisma/schema.prisma",
      "src/app.module.ts",
      "package.json"
    ]
  }
}
```

> **참고**: `multiAgentGate` 같은 구체적 설정 키 이름은 공식 문서에서 확인되지 않았다. 위 예시는 개념적 설명이며, 실제 설정 키는 공식 문서를 참고하라.

### 5.2 충돌 발생 시 해결

```bash
# 충돌하는 에이전트 중 하나 중지
agy agent stop agent-002

# Git으로 충돌 해결
git diff HEAD
git checkout -- src/app.module.ts  # 원래 상태로 복구

# 한 에이전트 결과 수락 후 다른 에이전트 재실행
agy agent run "이미 반영된 users 모듈을 고려하여
  boards 모듈을 app.module.ts에 추가해줘"
```

## 6. 실전 시나리오 — I/O 2026 93 에이전트 데모

Google I/O 2026에서 93개의 에이전트가 OS를 빌드한 데모가 공개되었다. 이 원리를 BoardHub에 적용하면:

```
BoardHub 병렬 구현 시나리오:

Phase 1 (기반 구조, 직렬):
  → Prisma 스키마 확정
  → Migration 실행

Phase 2 (모듈 구현, 병렬):
  Agent-A: auth + users (JWT, 회원 관리)
  Agent-B: boards + categories (게시판 설정)
  Agent-C: files (이미지/동영상 업로드)

Phase 3 (posts + frontend, 병렬):
  Agent-D: posts 모듈 (8종 게시판 게시글)
  Agent-E: SvelteKit 프론트엔드

Phase 4 (통합, 직렬):
  → 모듈 통합 (app.module.ts)
  → E2E 테스트
  → 배포
```
