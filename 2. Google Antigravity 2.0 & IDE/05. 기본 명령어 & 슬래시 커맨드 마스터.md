## 1. agy CLI 명령어 완전 정리

agy CLI는 Go 언어로 빌드된 단일 실행 바이너리(single binary)로, 터미널과 CI/CD 파이프라인에서 Antigravity의 모든 기능을 제어한다.

### 1.1 시스템 상태 관련 명령어

```bash
# 버전 확인
agy --version
# → Antigravity CLI v2.0.x (darwin/arm64)

# 전체 시스템 상태 확인
agy status
# → Daemon: Running | Sandbox: Ready | Gemini: Connected

# 상태 상세 출력
agy status --verbose

# 지원 모델 목록 조회 (v1.0.5+)
agy models
# → gemini-3.5-flash (default)
# → gemini-3.5-pro
# → ...

# 도움말
agy help
agy help agent    # 특정 명령어 도움말
```

### 1.2 에이전트 실행 관련 명령어

```bash
# 에이전트 실행 (기본)
agy agent run "지시사항"

# 에이전트 실행 (특정 파일 첨부)
agy agent run "이 파일을 리뷰해줘" --file src/users/users.service.ts

# 에이전트 실행 (여러 파일 첨부)
agy agent run "이 두 파일의 의존성 문제를 해결해줘" \
  --file src/users/users.service.ts \
  --file src/auth/auth.service.ts

# 에이전트 실행 (비대화형 모드 — CI/CD용)
agy agent run "테스트 실패 원인을 찾아 수정해줘" --non-interactive

# 에이전트 실행 (타임아웃 설정)
agy agent run "전체 프로젝트 테스트 실행 및 수정" --timeout 600

# 실행 중인 에이전트 목록
agy agent list
# → [running] agent-abc123: "users 모듈 구현" (2m 34s)
# → [waiting] agent-xyz789: "posts 모듈 구현" (큐 대기)

# 특정 에이전트 상태 확인
agy agent status agent-abc123

# 에이전트 작업 완료 대기
agy agent wait agent-abc123
agy agent wait agent-abc123 --timeout 300

# 에이전트 강제 중지
agy agent stop agent-abc123

# 에이전트 실행 로그 확인
agy logs agent-abc123
agy logs agent-abc123 --follow    # 실시간 스트리밍
agy logs agent-abc123 --tail 50   # 최근 50줄
```

### 1.3 MCP 관련 명령어

```bash
# MCP 서버 목록 확인
agy mcp list
# → [active] postgres-mcp
# → [active] filesystem-mcp
# → [active] git-mcp

# MCP 서버 추가
agy mcp add postgres-mcp

# MCP 서버 재시작
agy mcp restart postgres-mcp

# MCP 서버 로그
agy mcp logs postgres-mcp --tail 20
```

### 1.4 스킬 관련 명령어

```bash
# 스킬 목록 확인
agy skill list

# 스킬 설치
agy skill install image-optimizer
agy skill install video-thumbnailer

# 스킬 제거
agy skill remove image-optimizer

# 스킬 테스트
agy skill test image-optimizer
```

### 1.5 업데이트 및 기타

```bash
# CLI 업데이트
agy update

# 설정 조회/변경
agy config get gemini.model
agy config set gemini.apiKey "AIzaSy..."

# 전체 로그 확인 (오류 레벨)
agy logs --level error --tail 50

# 로그 파일 직접 확인
cat ~/.gemini/antigravity-cli/log/cli-*.log
```

## 2. IDE 슬래시 커맨드 완전 정리

IDE 채팅창에서 슬래시(/)로 시작하는 커맨드를 입력하면 에이전트에게 특정 유형의 작업을 지시할 수 있다.

### 2.1 탐색/질문 커맨드

```bash
/ask "현재 posts 모듈의 구현 상태를 분석해줘"
# → 코드를 수정하지 않고 분석/답변만 반환

/ask "이 PRD에서 기술적으로 구현이 어려운 부분이 있는가?" @docs/prd.md

/ask "현재 TypeScript 설정이 올바른가?" @tsconfig.json
```

**특징**: 코드를 수정하지 않음. 질문·탐색·분석에 사용.

### 2.2 코드 생성 커맨드

```bash
/code "users 모듈의 CRUD 서비스를 구현해줘"

/code "이 인터페이스를 기반으로 DTO 클래스를 만들어줘" @src/posts/interfaces/post.interface.ts

/code "Docker Compose 파일을 생성해줘. PostgreSQL 16, Redis 7 포함"
```

**특징**: 새 파일 생성 또는 기존 파일 수정. 변경사항은 Diff View에서 검토 후 적용.

### 2.3 수정/픽스 커맨드

```bash
/fix "이 파일의 TypeScript 타입 오류를 수정해줘" @src/users/users.service.ts

/fix "npx tsc --noEmit를 실행하고 모든 오류를 수정해줘"

/fix "이 함수가 undefined를 반환하는 버그를 찾아서 수정해줘"
```

### 2.4 테스트 커맨드

```bash
/test "users 서비스의 단위 테스트를 Vitest로 작성해줘" @src/users/users.service.ts

/test "GALLERY 게시판의 이미지 업로드 로직을 테스트해줘"
```

### 2.5 리뷰 커맨드

```bash
/review "이 PR의 변경사항을 검토해줘. 보안 취약점과 타입 안전성을 중점으로"
         @src/auth/ @src/users/

/review "이 코드가 GEMINI.md 규칙을 모두 따르는지 확인해줘" @src/posts/
```

### 2.6 기타 유용한 커맨드

```bash
# 컨텍스트 압축 (토큰 초과 시)
/compact

# 현재 적용 중인 GEMINI.md 규칙 확인
/memory

# 현재 프로젝트 파일 목록 탐색
/ls src/posts/

# 목표 설정 (스케줄링)
/goal "오늘 중으로 posts 모듈 CRUD + 단위 테스트 완성"

# 에이전트 실행 중인 작업 목록 확인
/agents
```

## 3. 컨텍스트 지시어(@) 완전 가이드

컨텍스트 지시어는 에이전트에게 특정 파일이나 폴더를 참고하도록 명시적으로 지시한다.

### 3.1 기본 사용법

```bash
# 파일 하나 참조
/fix "이 파일의 버그를 수정해줘" @src/posts/posts.service.ts

# 폴더 전체 참조
/review "이 폴더의 코드를 검토해줘" @src/auth/

# 여러 파일 동시 참조
/fix "이 두 파일의 타입 불일치를 해결해줘"
     @src/posts/posts.service.ts
     @src/posts/dto/create-post.dto.ts

# GEMINI.md 규칙 포함
/code "게시판 목록 API를 구현해줘" @GEMINI.md @src/boards/
```

### 3.2 언제 @ 지시어를 써야 하나?

| 상황 | 사용 예 |
|------|---------|
| 특정 파일 버그 수정 | `@src/posts/posts.service.ts` |
| 모듈 전체 리뷰 | `@src/auth/` |
| API 명세 기반 구현 | `@docs/api-spec.md` |
| DB 스키마 기반 작업 | `@prisma/schema.prisma` |
| 규칙 재확인 | `@GEMINI.md` |

## 4. 실전 시나리오 10가지

### 시나리오 1: 새 모듈 구현

```bash
# CLI로 실행
agy agent run "GEMINI.md 규칙을 따라서 posts 모듈 전체를 구현해줘.
  게시글 CRUD + 페이지네이션 + 소프트 딜리트 포함"

# 또는 IDE에서
/code "posts 모듈 전체를 구현해줘" @GEMINI.md @prisma/schema.prisma
```

### 시나리오 2: 버그 수정

```bash
/fix "이 서비스에서 findOne이 null을 반환할 때 
      NotFoundException 대신 undefined를 반환하는 버그 수정"
     @src/users/users.service.ts
```

### 시나리오 3: 테스트 일괄 생성

```bash
agy agent run "src/posts/ 폴더의 모든 서비스 파일에 대한 
  단위 테스트를 Vitest로 작성해줘. 커버리지 90% 이상 목표"
```

### 시나리오 4: TypeScript 오류 일괄 수정

```bash
agy agent run "npx tsc --noEmit를 실행하고 나오는 모든 오류를 수정해줘. 
  오류가 없을 때까지 반복해줘. 최대 3번까지 시도"
```

### 시나리오 5: 코드 리뷰 + 수정

```bash
/review "이 인증 모듈을 OWASP Top 10 기준으로 보안 검토해줘" @src/auth/
# 검토 결과 확인 후
/fix "방금 리뷰에서 발견된 보안 이슈를 모두 수정해줘"
```

### 시나리오 6: API 명세서 기반 구현

```bash
/code "이 API 명세서를 기반으로 NestJS 컨트롤러와 서비스를 구현해줘"
      @docs/api-spec.md @GEMINI.md
```

### 시나리오 7: 리팩터링

```bash
/fix "이 파일이 300줄을 초과합니다. GEMINI.md 규칙에 따라 기능별로 분리해줘"
     @src/posts/posts.service.ts @GEMINI.md
```

### 시나리오 8: Docker Compose 설정

```bash
/code "개발 환경용 Docker Compose 파일을 만들어줘.
  PostgreSQL 16, Redis 7 포함. 환경 변수는 .env에서 읽어야 함"
```

### 시나리오 9: CI/CD 통합

```bash
# GitHub Actions 워크플로우
agy agent run "GitHub Actions 워크플로우 파일을 만들어줘.
  main 브랜치 push 시 테스트 실행 + 빌드 검증 수행" --non-interactive
```

### 시나리오 10: 프로젝트 문서화

```bash
/code "이 프로젝트의 README.md를 한국어로 작성해줘.
  설치 방법, 환경 변수 목록, API 엔드포인트 목록 포함"
      @GEMINI.md @docs/
```

## 5. 비용 최소화 전략

| 전략 | 설명 | 절감 효과 |
|------|------|---------|
| 파일 최소 첨부 | @ 지시어로 필요한 파일만 | 30-50% 절감 |
| /ask vs /code 구분 | 탐색은 /ask, 구현만 /code | 20-30% 절감 |
| /compact 정기 실행 | 70% 이상 시 즉시 실행 | 10-20% 절감 |
| 마일스톤 분할 | 큰 작업을 작은 단위로 | 과금 사고 방지 |
