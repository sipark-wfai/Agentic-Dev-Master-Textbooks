# 09. 서브에이전트 & 멀티에이전트 — 에이전트 팀을 구성하고 조율하는 법

> **학습 목표**
> - 단일 에이전트의 한계와 멀티에이전트의 필요성을 이해한다
> - 오케스트레이터-워커 패턴을 설계할 수 있다
> - 직렬 vs 병렬 실행의 선택 기준을 파악한다
> - 파일 충돌 방지를 위한 multiAgentGate 설정을 적용한다
> - 멀티 게시판 8종을 에이전트별로 분배하여 병렬 구현한다

---

## 1. 단일 에이전트의 한계

대형 프로젝트를 단일 에이전트로 처리하면 다음 문제가 발생한다:

### 1.1 컨텍스트 윈도우 고갈

```
단일 에이전트가 BoardHub 전체를 구현할 때:

초기 컨텍스트 사용량:
  GEMINI.md       :  3,000 토큰
  PRD 문서         :  5,000 토큰
  ERD + API 명세   : 10,000 토큰
  소계             : 18,000 토큰

작업 진행 중 누적:
  users 모듈 코드  : 12,000 토큰
  boards 모듈 코드 : 10,000 토큰
  posts 모듈 코드  : 25,000 토큰
  comments 모듈    : 15,000 토큰
  소계             : 62,000 토큰

총계: 80,000 토큰 → 200,000 토큰 한계의 40%

→ posts까지는 괜찮지만 files + frontend 추가 시 한계 초과 위험
```

### 1.2 처리 시간의 선형 증가

```
단일 에이전트 순차 실행:
  users 모듈:    15분
  boards 모듈:   10분
  posts 모듈:    25분
  comments 모듈: 20분
  files 모듈:    15분
  총 소요:       85분

멀티에이전트 병렬 실행:
  Agent-1 (users + boards): 25분
  Agent-2 (posts + comments): 45분  ← 가장 긴 시간
  Agent-3 (files):           15분
  총 소요:                   45분  ← 47% 단축
```

### 1.3 단일 장애점 (Single Point of Failure)

단일 에이전트가 중간에 실패하면 처음부터 재시작해야 한다. 멀티에이전트는 실패한 에이전트만 재시작하면 된다.

## 2. 오케스트레이터-워커 패턴

### 2.1 패턴 개요

멀티에이전트 아키텍처의 표준 패턴이다.

```
오케스트레이터-워커 패턴:

+------------------------------------------+
|          오케스트레이터 에이전트           |
|  - 전체 계획 수립                          |
|  - 작업 분배                              |
|  - 워커 에이전트 생성                      |
|  - 결과 수집 및 통합                       |
+------------------------------------------+
      |              |               |
      v              v               v
+----------+   +----------+   +----------+
| Worker-1 |   | Worker-2 |   | Worker-3 |
| users 모듈|   | posts 모듈|   | frontend |
+----------+   +----------+   +----------+
```

### 2.2 오케스트레이터 프롬프트 설계

오케스트레이터 에이전트에게 전달하는 지시문의 예시:

```
agy agent run "
당신은 BoardHub 프로젝트의 오케스트레이터입니다.

**임무**: 다음 4개의 서브에이전트를 생성하고 조율하여
         BoardHub 백엔드 API를 완성하세요.

**서브에이전트 분배**:

[Agent-A: 인증 & 사용자]
  범위: src/auth/, src/users/
  작업:
    1. JWT 인증 모듈 (access + refresh token)
    2. 사용자 CRUD + 소프트 딜리트
    3. RBAC 권한 시스템 (ADMIN, MODERATOR, USER)
  완료 기준: 단위 테스트 100% 통과

[Agent-B: 게시판 & 게시글]
  범위: src/boards/, src/posts/
  작업:
    1. 게시판 설정 관리 (8종 타입 지원)
    2. 게시글 CRUD (타입별 검증 포함)
    3. 게시글 조회수, 좋아요 기능
  완료 기준: 단위 테스트 100% 통과

[Agent-C: 댓글 & 파일]
  범위: src/comments/, src/files/
  작업:
    1. 댓글 CRUD + 대댓글
    2. 파일 업로드 (이미지, 동영상)
    3. image-optimizer, video-thumbnailer 스킬 연동
  완료 기준: 단위 테스트 100% 통과

[Agent-D: 통합 & E2E 테스트]
  선행 조건: Agent-A, B, C 모두 완료
  범위: test/
  작업:
    1. API 통합 테스트 작성
    2. E2E 시나리오 테스트 (사용자 → 게시판 → 게시글 → 댓글)
    3. 성능 테스트 (동시 100명 시나리오)
  완료 기준: 모든 테스트 통과

**충돌 방지 규칙**:
  - prisma/schema.prisma는 Agent-A가 먼저 작업 완료 후 다른 에이전트가 수정
  - 각 에이전트는 자신의 범위 외 파일 수정 금지
"
```

## 3. 직렬 vs 병렬 실행 선택 기준

### 3.1 직렬 실행이 적합한 경우

```
직렬 실행 (순차 처리):

[단계 1] → [단계 2] → [단계 3]

언제 사용?
- 단계 간 의존성이 있을 때
  예: DB 스키마 완성 → API 구현 → 프론트엔드 구현
- 이전 결과를 다음 단계에서 참조할 때
- 파일 충돌이 불가피할 때 (prisma/schema.prisma)
```

```bash
# 직렬 실행 예시
agy agent run "1단계: prisma/schema.prisma 완성 (users, boards, posts 모델)"
agy agent wait --all  # 완료 대기

agy agent run "2단계: Prisma 마이그레이션 실행 및 API 구현"
agy agent wait --all

agy agent run "3단계: SvelteKit 프론트엔드 구현 (API 연동)"
agy agent wait --all
```

### 3.2 병렬 실행이 적합한 경우

```
병렬 실행 (동시 처리):

[작업 A] ─┐
[작업 B] ─┤→ 결과 통합
[작업 C] ─┘

언제 사용?
- 작업 간 의존성이 없을 때
- 같은 파일을 수정하지 않을 때
- 처리 시간을 최소화해야 할 때
```

```bash
# 병렬 실행 예시
# 각 명령을 백그라운드(&)로 실행
agy agent run "users 모듈 구현" --scope "apps/backend/src/users/" &
agy agent run "boards 모듈 구현" --scope "apps/backend/src/boards/" &
agy agent run "files 모듈 구현" --scope "apps/backend/src/files/" &

# 모든 에이전트 완료 대기
agy agent wait --all
```

### 3.3 의존성 그래프 기반 스케줄링

```
BoardHub 구현 의존성 그래프:

[prisma/schema.prisma] ← 모든 것의 기반
         |
    ┌────┴────┐
    v         v
[auth/]   [users/]
    |         |
    └────┬────┘
         |
    ┌────┴─────────────┐
    v         v         v
[boards/]  [posts/]  [comments/]
               |         |
               └────┬────┘
                    v
                [files/]
                    |
                    v
              [frontend/]
                    |
                    v
           [E2E 테스트]
```

이 그래프를 기반으로 병렬화 계획:

```
Phase 1 (직렬): schema.prisma 완성
Phase 2 (병렬): auth + users (의존성 없음)
Phase 3 (병렬): boards + posts + comments (Phase 2 완료 후)
Phase 4 (직렬): files (boards, posts 필요)
Phase 5 (직렬): frontend (모든 API 완성 후)
Phase 6 (직렬): E2E 테스트
```

## 4. 병렬 에이전트 파일 충돌 방지

### 4.1 multiAgentGate 설정

```json
// .agents/config.json
{
  "multiAgentGate": {
    "enabled": true,
    "strategy": "mutex",
    "conflictPolicy": "queue",
    "lockTimeout": 30000,
    "mutexFiles": [
      "prisma/schema.prisma",
      "prisma/migrations/",
      "pnpm-workspace.yaml",
      "pnpm-lock.yaml",
      ".env",
      ".env.local",
      "GEMINI.md",
      "apps/backend/src/app.module.ts"
    ],
    "agentScopes": {
      "agent-auth": ["apps/backend/src/auth/**"],
      "agent-users": ["apps/backend/src/users/**"],
      "agent-posts": ["apps/backend/src/posts/**", "apps/backend/src/boards/**"],
      "agent-comments": ["apps/backend/src/comments/**"],
      "agent-files": ["apps/backend/src/files/**"],
      "agent-frontend": ["apps/frontend/src/**"]
    }
  }
}
```

### 4.2 파일 잠금 동작 방식

```
시나리오: Agent-A와 Agent-B가 모두 app.module.ts를 수정하려 함

1. Agent-A가 먼저 app.module.ts 잠금 요청
   → 잠금 획득, 작업 시작

2. Agent-B가 app.module.ts 잠금 요청
   → 잠금 대기 (Queue에 추가)
   → lockTimeout(30초) 내에 Agent-A 완료 기다림

3. Agent-A 작업 완료 → 잠금 해제
   → Agent-B 잠금 획득, 작업 시작

4. Agent-B 작업 완료
   → 두 에이전트의 변경사항이 충돌 없이 통합됨
```

## 5. 실전: 멀티 게시판 8종 병렬 구현

BoardHub의 8종 게시판을 멀티에이전트로 병렬 구현하는 전체 과정이다.

### 5.1 사전 준비

```bash
# 1. 기반 작업 완료 확인
agy agent run "prisma/schema.prisma를 완성해줘. 다음 모델이 포함되어야 함:
              User, Board, Post, Comment, File, Category
              BoardType enum: GENERAL, GALLERY, VIDEO, QNA, NOTICE, FAQ, PRIVATE, FREE"
agy agent wait --all

# 2. Prisma 마이그레이션 실행
agy agent run "npx prisma migrate dev --name init_all_tables 실행"
agy agent wait --all

# 3. 기반 모듈 완성 (직렬)
agy agent run "공통 모듈 생성: src/common/ (filters, guards, interceptors, decorators, pipes)"
agy agent wait --all
agy agent run "prisma.service.ts 완성 (소프트 딜리트 미들웨어 포함)"
agy agent wait --all
agy agent run "auth 모듈 완성 (JWT, guards)"
agy agent wait --all
agy agent run "users 모듈 완성"
agy agent wait --all
```

### 5.2 8종 게시판 병렬 구현

```bash
# 각 게시판 타입별 서비스 레이어 병렬 구현
echo "=== Phase 3: 게시판/게시글 병렬 구현 시작 ==="

# 에이전트 1: boards 모듈
agy agent run "boards 모듈 구현 — 게시판 CRUD, 8종 타입 설정 관리
              --scope apps/backend/src/boards/" &

# 에이전트 2: 일반/갤러리/동영상 게시판
agy agent run "posts 모듈의 GENERAL, GALLERY, VIDEO 타입 처리 구현
              @prisma/schema.prisma 기반으로 타입별 검증 로직 포함
              --scope apps/backend/src/posts/" &

# 에이전트 3: Q&A/공지/FAQ 게시판
agy agent run "posts 모듈의 QNA, NOTICE, FAQ 타입 처리 구현
              QNA: 답변 채택 기능, NOTICE: ADMIN 전용 작성
              FAQ: 카테고리 분류 기능 포함
              --scope apps/backend/src/posts/qna-notice-faq/" &

# 에이전트 4: 비공개 문의/자유 게시판
agy agent run "posts 모듈의 PRIVATE, FREE 타입 처리 구현
              PRIVATE: 작성자+ADMIN만 열람, FREE: 익명 작성 가능
              --scope apps/backend/src/posts/private-free/" &

# 모든 에이전트 완료 대기
agy agent wait --all
echo "=== Phase 3 완료 ==="

# Phase 4: 댓글 + 파일 병렬
agy agent run "comments 모듈 구현 (대댓글 지원, Q&A 답변 채택)" &
agy agent run "files 모듈 구현 (image-optimizer, video-thumbnailer 스킬 연동)" &
agy agent wait --all
echo "=== Phase 4 완료 ==="
```

### 5.3 결과 통합 및 검증

```bash
# Phase 5: 통합 테스트
agy agent run "전체 백엔드 빌드 및 E2E 테스트 실행.
              실패하는 테스트가 있으면 원인을 파악하고 수정해줘"
agy agent wait --all --timeout 600

# Proposal 전체 확인 후 Accept
agy proposal list
agy proposal accept --all
```

## 7. 멀티에이전트 비용 관리

병렬 에이전트는 비용도 병렬로 발생한다. 효율적인 비용 관리가 필요하다.

### 7.1 비용 최적화 전략

```
전략 1: 컨텍스트 최소화
  - 각 에이전트에게 최소한의 컨텍스트만 제공
  - @파일경로 지시어로 필요한 파일만 포함

전략 2: 작업 단위 적절히 분할
  - 너무 큰 작업: 컨텍스트 폭발 → 비용 증가
  - 너무 작은 작업: 오버헤드 → 비효율
  - 적정 크기: 단일 모듈 (100-300줄 규모)

전략 3: 동시 에이전트 수 제한
  - 기본값: 최대 3개 동시 에이전트
  - 조정: agy config set multiAgent.maxConcurrent 5

전략 4: 월별 예산 설정
  - agy config set cost.monthlyBudgetUSD 100
  - 80% 도달 시 경고 알림
```

### 7.2 비용 추적

```bash
# 이번 달 비용 확인
agy cost summary
# → 이번 달: $23.45 / $100.00 한도
# → 에이전트별 비용:
# →   agent-auth:     $3.20
# →   agent-users:    $2.80
# →   agent-posts:    $8.50
# →   agent-comments: $4.10
# →   agent-files:    $4.85

# 특정 작업 세션 비용 확인
agy cost session agent-posts-session-20260601
```

## 8. 실습: 오케스트레이터 에이전트로 전체 백엔드 구현

다음 단일 명령어로 오케스트레이터가 전체 BoardHub 백엔드를 자동으로 계획하고 구현한다:

```bash
agy agent run "
당신은 BoardHub 프로젝트의 시니어 개발자 역할을 맡은 오케스트레이터입니다.

**목표**: NestJS 11 기반 BoardHub 백엔드 API 완전 구현

**제약**:
@GEMINI.md 의 모든 규칙을 준수
@prisma/schema.prisma 의 모델 구조를 기반으로 구현
테스트 커버리지 90% 이상 필수

**구현 계획**:
다음 단계를 직접 계획하고 서브에이전트를 생성하여 실행하세요.
단계 간 의존성을 분석하여 병렬 실행 가능한 단계를 최대한 병렬화하세요.

결과 보고서를 IMPLEMENTATION_REPORT.md로 작성하세요.
" --orchestrator --timeout 1800
```

이 명령어 하나로:
1. 오케스트레이터가 단계별 계획 수립
2. 의존성 분석 후 병렬화 계획
3. 서브에이전트들 순차/병렬 실행
4. 결과 통합 및 검증
5. 최종 보고서 생성

전 과정이 자동으로 진행된다.

## 9. 오케스트레이터 프롬프트 설계 고급 패턴

### 9.1 반복 시도 패턴

에이전트가 실패할 경우 자동으로 재시도하도록 설계한다:

```bash
agy agent run "
목표: src/posts/posts.service.ts의 단위 테스트 커버리지 90% 달성

단계:
1. 현재 테스트 커버리지 확인 (npm run test:cov)
2. 커버리지가 90% 미만이면 누락된 테스트 케이스 식별
3. 테스트 코드 보완
4. 다시 커버리지 확인
5. 90% 이상이 될 때까지 2~4를 최대 3회 반복

완료 기준: npm run test:cov → posts 모듈 커버리지 90% 이상
" --scope "apps/backend/src/posts/ apps/backend/test/"
```

### 9.2 조건부 분기 패턴

에이전트가 상황에 따라 다른 경로를 선택하도록 한다:

```bash
agy agent run "
1. 먼저 현재 코드베이스에서 TypeScript 오류가 있는지 확인 (npx tsc --noEmit)
2. 오류가 있으면: 오류를 모두 수정한 후 3번으로 진행
3. 오류가 없으면: 코드 리뷰를 수행하고 개선점을 제안
4. 개선점이 있으면: 자동으로 수정 적용
5. REVIEW_REPORT.md에 작업 결과 기록
"
```

### 9.3 체인 패턴 (파이프라인)

작업 결과를 다음 작업의 입력으로 전달한다:

```bash
# 단계 1: 분석
agy agent run "posts 모듈의 현재 구현 상태를 분석하고
              ANALYSIS.md에 기록해줘 (미구현 기능, 버그, 개선점)" 
agy agent wait --all

# 단계 2: ANALYSIS.md를 기반으로 구현
agy agent run "ANALYSIS.md의 분석 결과를 기반으로
              가장 중요한 미구현 기능 3개를 구현해줘" @ANALYSIS.md
agy agent wait --all

# 단계 3: 검증
agy agent run "ANALYSIS.md에서 구현하기로 한 3개 기능이
              올바르게 구현되었는지 테스트로 검증해줘" @ANALYSIS.md
```

## 10. 멀티에이전트 디버깅

### 10.1 에이전트별 로그 분리 확인

여러 에이전트가 동시에 실행될 때 로그가 섞이지 않도록 에이전트 ID로 필터링한다:

```bash
# 실행 중인 모든 에이전트 확인
agy agent list
# → [running] agent-auth-001 (3m 12s)
# → [running] agent-posts-002 (1m 45s)
# → [completed] agent-users-003

# 특정 에이전트 로그만 확인
agy logs agent-posts-002 --follow

# 특정 에이전트 비용 확인
agy cost agent agent-auth-001
```

### 10.2 병렬 실행 진행 상황 모니터링

```bash
# 모든 에이전트 상태를 한눈에 확인
watch -n 5 'agy agent list --format table'

# 실시간 출력 예시:
# ID              STATUS    DURATION  COST    SCOPE
# agent-auth-001  running   3m 12s    $0.45   src/auth/
# agent-posts-002 running   1m 45s    $0.23   src/posts/
# agent-users-003 completed 8m 30s    $1.20   src/users/
```

### 10.3 에이전트 작업 충돌 감지

```bash
# 충돌 이벤트 로그 확인
agy logs --filter "MUTEX_CONFLICT" --tail 20

# 충돌이 발생한 파일 목록
agy mcp list --conflicts
```
