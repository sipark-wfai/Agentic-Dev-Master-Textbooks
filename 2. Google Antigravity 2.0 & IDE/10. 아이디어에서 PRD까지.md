# 10. 아이디어에서 PRD까지 — 에이전트 친화적 기획서 작성 완벽 가이드

> **학습 목표**
> - 에이전트 친화적 PRD(Product Requirements Document)의 특징을 이해한다
> - /ask 명령어로 아이디어를 구조화된 PRD로 발전시키는 과정을 실습한다
> - PRD의 필수 구성 요소를 모두 갖춘 문서를 작성할 수 있다
> - BoardHub 멀티 게시판 허브의 완전한 PRD를 완성한다

---

## 1. 에이전트 친화적 PRD란

### 1.1 일반 PRD vs 에이전트 친화적 PRD

**일반 PRD (전통 방식):**
```
"사용자가 게시판을 이용할 수 있어야 합니다.
 게시글 작성, 수정, 삭제 기능이 필요합니다."
```

에이전트가 이걸 받으면 "게시판"이 몇 종인지, 삭제가 물리적인지 소프트인지, 기술 스택이 무엇인지 모두 추측으로 결정한다.

**에이전트 친화적 PRD:**
```
## FR-001 게시글 작성
- 대상: 인증된 사용자 (role: USER 이상)
- 입력: title(최대 200자), content(HTML), boardType
- 갤러리 타입: image 파일 1~10개 필수 첨부
- 처리: content-filter로 금지어 검사
- 출력: { success: true, data: { postId, boardType, createdAt } }
- 오류: 400(유효성 실패), 401(비인증), 403(권한 없음)
```

에이전트가 이 PRD를 받으면 즉시 구현 가능하다.

### 1.2 에이전트 친화적 PRD의 5가지 특징

1. **기능 ID 체계**: 모든 기능에 FR-001, FR-002 형식의 고유 ID 부여
2. **입출력 명세**: 함수처럼 입력/출력/오류 코드가 명확
3. **수치화된 제약**: "많은 댓글" → "최대 1,000개/게시글"
4. **기술 스택 명시**: 에이전트가 추측하지 않아도 됨
5. **금지 사항 명시**: 절대 하지 말아야 할 것들

## 2. /ask로 아이디어 → PRD 구조화

```
/ask "나는 8종 게시판(일반, 갤러리, 동영상, Q&A, 공지, FAQ, 비공개문의, 자유)을
      하나의 플랫폼에서 통합 관리하는 서비스를 만들고 싶어.
      이 아이디어를 에이전트 친화적 PRD 형식으로 구조화해줘.
      기술 스택: SvelteKit + NestJS + PostgreSQL + Prisma"

에이전트 응답:
BoardHub PRD 초안을 작성하겠습니다.

## 서비스 개요
- 서비스명: BoardHub
- 목적: 8종 게시판 통합 플랫폼
...

## 핵심 기능 요구사항 (FR)
FR-001 회원가입/로그인
FR-002 게시판 목록 조회
FR-003 게시글 작성 (타입별 처리)
...
```

### 2.1 PRD 단계별 구체화

```
1단계: 아이디어 → 개요
/ask "이 아이디어의 핵심 가치와 타겟 사용자를 정의해줘"

2단계: 기능 목록화
/ask "필요한 기능을 FR-001부터 번호로 정리해줘"

3단계: 우선순위
/ask "각 기능의 개발 우선순위를 Must/Should/Nice로 분류해줘"

4단계: 기술 검증
/ask "이 PRD에서 기술적으로 구현이 어려운 부분이 있는가?"
```

## 3. BoardHub PRD 핵심 구성

### 3.1 필수 섹션

```markdown
# BoardHub PRD v1.0

## 1. 서비스 개요
- 서비스명, 목적, 핵심 가치
- 타겟 사용자
- 성공 지표 (KPI)

## 2. 기술 스택
| 레이어 | 기술 | 버전 |
|-------|------|-----|
| Frontend | SvelteKit | 2.x |
| Backend | NestJS | 11.x |
| DB | PostgreSQL 16 + Prisma v5 | - |

## 3. 사용자 역할
| 역할 | 권한 |
|------|------|
| ANONYMOUS | 공개 게시글 읽기 |
| USER | 게시글 작성, 댓글 |
| ADMIN | 전체 관리 |

## 4. 기능 요구사항 (FR)
### FR-001 회원가입
### FR-002 로그인/로그아웃
...

## 5. 비기능 요구사항 (NFR)
- 응답시간: API 95th percentile < 200ms
- 파일 업로드: 이미지 5MB, 동영상 100MB 제한
- 동시 접속: 최대 1,000명
```

### 3.2 게시판 타입별 FR 예시

```markdown
## FR-011 GALLERY 게시글 작성
- 대상: 인증된 사용자
- 전제조건: boardType = 'GALLERY'
- 입력:
  - title: string (1~200자, 필수)
  - content: string (HTML, 최대 10,000자, 선택)
  - images: File[] (1~10개, 각 최대 5MB, 필수)
  - allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp', 'image/gif']
- 처리:
  - image-optimizer 스킬: 원본 저장 + WebP 변환 + 썸네일(320x200) 생성
- 출력: { success: true, data: { postId, images: [{url, thumbnailUrl}] } }
- 오류: 400(이미지 미첨부), 413(파일 크기 초과)
```

## 4. PRD 품질 검증

에이전트를 사용해 PRD를 자가 검증할 수 있다:

```
/ask "이 PRD의 품질을 다음 기준으로 평가해줘:
  1. 모든 기능에 FR 번호가 있는가?
  2. 입출력 명세가 구체적인가?
  3. 기술 스택이 명시되어 있는가?
  4. 비기능 요구사항이 수치화되어 있는가?
  5. 에러 케이스가 정의되어 있는가?"
  @docs/prd.md
```

### 4.1 PRD 품질 체크리스트

```
[ ] 서비스 개요가 1문장으로 요약 가능하다
[ ] 모든 기능에 FR-XXX 번호가 있다
[ ] 각 FR에 입력/출력/오류 코드가 명시되어 있다
[ ] 기술 스택과 버전이 명시되어 있다
[ ] 사용자 역할과 권한이 정의되어 있다
[ ] 파일 크기, 응답시간 등 수치가 있다
[ ] 금지 사항이 명시되어 있다
[ ] 8종 게시판 각각의 특수 처리가 정의되어 있다
```

## 5. PRD → GEMINI.md 연결

완성된 PRD에서 GEMINI.md 규칙을 자동 생성할 수 있다:

```
/ask "이 PRD를 기반으로 GEMINI.md 규칙을 작성해줘.
  특히 파일 업로드 제한, 인증 방식, API 응답 형식을 중심으로"
  @docs/prd.md
```
