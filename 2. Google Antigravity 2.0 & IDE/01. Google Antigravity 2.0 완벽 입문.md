## 1. 소프트웨어 개발의 패러다임 전환

### 1.1 코파일럿 시대 (2021–2024)

2021년 GitHub Copilot이 등장했을 때 개발자들은 환호했다. 자동완성이 단순한 키워드 수준을 넘어 함수 전체를 제안해 주었기 때문이다. 이후 수많은 코파일럿형 도구들이 쏟아졌다.

그러나 코파일럿 시대의 도구들은 본질적으로 **"매우 똑똑한 자동완성기"**에 불과했다. 개발자가 코드를 한 줄씩 입력하면, AI가 다음 줄을 제안하는 방식이다. 의사결정권은 언제나 인간에게 있었고, AI는 보조자 역할에 머물렀다.

```
코파일럿 패러다임:
  인간 → [코드 입력] → AI 제안 → 인간 수락/거부 → 반복
  (인간이 루프를 주도, AI는 한 줄씩 반응)
```

코파일럿 시대의 3가지 한계:
1. **컨텍스트 단절**: 파일 하나만 보고 제안하므로, 프로젝트 전체 구조를 이해하지 못한다
2. **실행 불가**: 코드를 제안할 뿐, 실제로 실행·테스트·배포하지 못한다
3. **기억 없음**: 세션이 끊기면 이전 대화와 결정을 기억하지 못한다

### 1.2 에이전트 시대 (2025–현재)

2025년을 기점으로 개발 도구의 패러다임이 근본적으로 바뀌었다. 단순히 "더 잘 제안하는" AI가 아니라, **"스스로 계획하고, 실행하고, 검증하는"** AI 에이전트가 등장한 것이다.

에이전트 패러다임에서 AI는:
- 사용자의 지시를 받아 **스스로 계획**을 수립한다
- 도구(파일 읽기·쓰기, 명령어 실행, API 호출 등)를 **자율적으로 사용**한다
- 실행 결과를 **관측하고 다음 행동을 수정**한다
- 목표를 달성할 때까지 **루프를 지속**한다

```
에이전트 패러다임:
  인간 → [목표 지시] → AI 계획 → AI 실행 → AI 관측 → AI 수정 → ... → 결과 보고
  (AI가 루프를 주도, 인간은 목표와 최종 검토만)
```

### 1.3 코파일럿 vs 에이전트 비교표

| 구분 | 코파일럿 (예: GitHub Copilot) | 에이전트 (예: Google Antigravity 2.0) |
|------|-------------------------------|--------------------------------------|
| 역할 | 스마트 자동완성기 | 자율 실행 파트너 |
| 컨텍스트 범위 | 현재 파일 + 열린 탭 | 전체 프로젝트 + 외부 시스템(DB, Git, API) |
| 실행 능력 | 없음 (제안만) | 있음 (파일 수정, 명령 실행, 테스트, 배포) |
| 계획 수립 | 없음 | 있음 (단계별 마일스톤 자동 분할) |
| 오류 처리 | 없음 | 있음 (오류 감지 → 자동 수정 → 재시도) |
| 메모리 | 없음 | 있음 (GEMINI.md로 규칙 영속화) |
| 비용 단위 | 토큰/월정액 | 월정액 플랜 기반 |
| 인간 개입 시점 | 매 줄마다 | 목표 설정 + 결과 검토 |
| 안전장치 | 없음 | Sandbox 격리 + Human-in-the-Loop |

## 2. Google Antigravity 2.0의 탄생

### 2.1 역사와 배경

**2025년 11월**: Google Antigravity v1.0 비공개 베타 출시. 초기에는 Google 내부 개발자들만 사용했으며, VS Code 익스텐션 형태로 배포되었다. 이 버전에서는 기본적인 코드 생성과 파일 수정 기능만 제공되었다.

**2026년 5월 Google I/O**: **Google Antigravity 2.0** 정식 발표. 가장 큰 변화는 3-tier 아키텍처의 도입이었다. Desktop App(백엔드 엔진) + Antigravity IDE(프론트엔드 에디터) + CLI(`agy` 명령어)가 분리되어 독립적으로 동작하면서도 유기적으로 연결되는 구조가 탄생했다. 내부 AI 엔진도 Gemini 3.5로 업그레이드되었다.

**2026년 6월 18일**: Gemini CLI(소비자용) 서비스 종료. Antigravity CLI(`agy`)로의 전환이 공식화되었다.

### 2.2 왜 3-tier 구조인가?

기존 VS Code 익스텐션 방식(v1.0)의 문제점:
- IDE가 닫히면 에이전트 작업도 중단된다
- 에이전트가 IDE 프로세스와 같은 메모리 공간을 공유하여 격리가 불가능하다
- CI/CD 파이프라인에서 사용하려면 GUI가 필요하다

2.0의 해결책:
- **Desktop App**: 항상 백그라운드에서 실행되는 데몬 프로세스. IDE를 닫아도 에이전트 작업이 계속된다
- **IDE**: 에디터와 에이전트 관리를 하나의 화면에서 처리하는 전용 인터페이스
- **CLI**: GUI 없이 터미널과 CI/CD에서 에이전트를 제어할 수 있는 경량 도구

## 3. 3대 구성 요소 상세 개요

### 3.1 Antigravity 2.0 Desktop App (백엔드 엔진)

Desktop App은 Antigravity 에코시스템의 심장부다. 사용자가 직접 조작하는 UI는 없지만, 모든 지능적 처리가 여기서 이루어진다.

**주요 역할:**

1. **로컬 에이전트 데몬 (Local Agent Daemon) 실행**
   - 백그라운드에서 항상 실행되는 서비스 프로세스
   - Gemini 3.5 Flash API와의 통신을 담당
   - 에이전트 작업 큐(Task Queue) 관리

2. **보안 샌드박스 (Secure Sandbox) 호스팅**
   - macOS: `sandbox-exec` 기반 격리 (공식 확인)
   - Linux: `nsjail` 기반 격리 (공식 확인)
   - 에이전트가 실행하는 모든 코드는 이 안에서 격리 실행됨

3. **MCP 서버 관리**
   - Model Context Protocol 서버들의 생명주기 관리
   - PostgreSQL, Git, 파일 시스템, 웹 검색 등 외부 시스템 연동

4. **Agent Skills 관리**
   - 온디맨드 스킬 패키지 로딩/언로딩

5. **멀티에이전트 오케스트레이션**
   - 여러 에이전트를 병렬로 실행하고 결과를 통합

### 3.2 Antigravity IDE (프론트엔드 에디터)

VS Code 아키텍처를 기반으로 한 포크(Fork)이지만, 에이전트 협업을 위해 근본적으로 재설계된 에디터다.

**핵심 기능:**

- **듀얼 엔진 뷰 (Dual-Engine View)**:
  - 좌측 패널: 고성능 코드 에디터 (VS Code 완전 호환)
  - 우측 패널: 에이전트 관리 패널 (채팅, 작업 현황, 변경사항 검토)

- **에이전트 변경사항 검토**:
  - 에이전트가 생성한 코드 변경사항을 Diff View로 확인
  - 변경사항 수락/거부 선택 가능

- **실시간 비용 게이지**:
  - 현재 작업에 사용된 토큰 수와 예상 비용 실시간 표시

### 3.3 Antigravity CLI (`agy` 명령어)

Go 언어로 빌드된 단일 실행 바이너리(single binary). 터미널에서 Antigravity의 모든 기능을 제어할 수 있다.

```bash
# 자주 사용하는 agy 명령어
agy --version              # 버전 확인
agy status                 # 데몬 상태 확인
agy models                 # 지원 모델 목록 조회 (v1.0.5+)
agy agent run "지시사항"   # 에이전트 실행
agy agent list             # 실행 중인 에이전트 목록
agy agent stop [id]        # 특정 에이전트 중지
agy skill install [이름]   # 스킬 설치
agy skill list             # 설치된 스킬 목록
agy mcp add [설정]         # MCP 서버 추가
agy logs [에이전트-id]     # 에이전트 로그 확인
agy update                 # CLI 업데이트
```

**Antigravity CLI와 Desktop App은 동일한 에이전트 코어(runtime)를 사용한다.** CLI로 실행한 에이전트와 Desktop App에서 실행한 에이전트는 같은 엔진 위에서 동작한다.

CI/CD 파이프라인 예시:
```yaml
# GitHub Actions에서 Antigravity 사용
- name: Run Antigravity Agent
  run: |
    agy agent run "테스트 코드가 실패하는 모듈을 찾아 수정하고, PR 설명을 업데이트하라"
    agy agent wait --timeout 300
```

## 5. 핵심 개념 심층 이해

### 5.1 ReAct 루프 — 에이전트의 사고 방식

Antigravity 에이전트는 **ReAct(Reason + Act)** 패턴으로 동작한다. 이는 인공지능 에이전트가 복잡한 문제를 해결하는 방법론으로, 추론(Reason)과 행동(Act)을 반복하여 목표에 도달한다.

```
ReAct 루프 (단일 사이클):

1. REASON (추론)
   "현재 상황을 파악한다. users 테이블이 없으므로
    먼저 Prisma 스키마를 확인해야 한다"
        ↓
2. ACT (행동)
   filesystem-mcp를 사용해 prisma/schema.prisma 읽기
        ↓
3. OBSERVE (관측)
   "User 모델이 정의되어 있지만 migration이
    실행되지 않았음을 확인"
        ↓
4. REASON (재추론)
   "npx prisma migrate dev를 실행해야 한다"
        ↓
5. ACT (행동)
   샌드박스에서 npx prisma migrate dev 실행
        ↓
6. OBSERVE (관측)
   "마이그레이션 성공. users 테이블 생성 완료"
        ↓
7. 목표 달성 → 결과 보고
```

### 5.2 Artifacts 시스템 — 블랙박스 문제 해결

초기 AI 에이전트의 가장 큰 문제는 **블랙박스**였다. 에이전트가 무엇을 했는지 알 수 없었고, 결과물을 추적하기 어려웠다.

Antigravity 2.0의 Artifacts 시스템은 이 문제를 해결한다. 에이전트가 생성하는 모든 산출물이 시각적 카드로 추적된다:

| Artifact 유형 | 설명 | 예시 |
|--------------|------|------|
| CODE | 생성/수정된 코드 파일 | `src/users/users.service.ts` |
| SCHEMA | DB 스키마 변경 | `prisma/schema.prisma` |
| TEST | 테스트 코드 | `src/users/users.spec.ts` |
| SCREENSHOT | UI 스크린샷 | 컴포넌트 렌더링 결과 |
| LOG | 실행 로그 | 서버 시작 로그, 테스트 결과 |
| MIGRATION | DB 마이그레이션 파일 | `20260601_add_users_table.sql` |

IDE의 Artifacts 패널에서 에이전트 작업의 전체 타임라인을 볼 수 있다.

### 5.3 Secure Sandbox — 안전한 실행 환경

에이전트가 실행하는 모든 코드는 OS 네이티브 격리 기술로 보호된 샌드박스 안에서 실행된다:
- **macOS**: `sandbox-exec` 기반 격리 (공식 확인)
- **Linux**: `nsjail` 기반 격리 (공식 확인)

에이전트가 실수를 하더라도 샌드박스 격리 덕분에 호스트 시스템은 보호된다. 인간이 항상 에이전트 작업 결과를 검토하고 적용 여부를 결정한다.

### 5.4 GEMINI.md — 에이전트의 헌법

GEMINI.md는 프로젝트 루트에 위치하는 텍스트 파일로, 에이전트가 따라야 할 규칙을 정의한다. Claude Code의 CLAUDE.md에 해당하는 개념이다.

GEMINI.md는 일반 Markdown 형식으로 작성하며, 규칙을 명확한 문장으로 표현한다:

```markdown
# 멀티 게시판 허브 — Gemini 규칙서

## 필수 규칙
- TypeScript strict 모드를 반드시 사용한다
- 모든 DB 조작은 Prisma ORM을 통해서만 한다
- 직접 SQL 쿼리(Prisma $queryRaw) 사용을 금지한다
- SvelteKit server-side load 함수를 클라이언트 fetch보다 우선 사용한다
```

## 6. 예제 프로젝트 소개 — 멀티 게시판 허브

이 시리즈 전체에서 사용할 실습 프로젝트는 **멀티 게시판 허브**다.

### 6.1 프로젝트 개요

**서비스명**: BoardHub (보드허브)
**목적**: 여러 종류의 게시판을 하나의 서비스에서 통합 관리

**8종 게시판:**
| 유형 | 설명 | 특이사항 |
|------|------|---------|
| 일반 게시판 | 텍스트 중심 자유 게시판 | 기본형 |
| 갤러리 게시판 | 이미지 중심 게시판 | 썸네일 자동 생성 |
| 동영상 게시판 | 동영상 공유 게시판 | 동영상 썸네일 추출 |
| Q&A 게시판 | 질문/답변 구조 | 채택된 답변 표시 |
| 공지 게시판 | 운영진 공지사항 | 관리자 전용 작성 |
| FAQ 게시판 | 자주 묻는 질문 | 카테고리 분류 |
| 비공개 문의 | 1:1 문의 게시판 | 작성자+관리자만 열람 |
| 자유 게시판 | 제한 없는 자유 게시판 | 익명 작성 가능 |

### 6.2 기술 스택

```
Frontend:  SvelteKit 2.x (TypeScript)
Backend:   NestJS 11.x (TypeScript)
Database:  PostgreSQL 16 + Prisma v5
Auth:      JWT (Access Token + Refresh Token)
Storage:   로컬 파일 시스템 (추후 S3 연동)
Deploy:    Docker Compose (개발) → Vercel+Railway (배포)
```
