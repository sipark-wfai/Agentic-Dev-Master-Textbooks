## 잔존/신규 발견 오류

### 🔴 심각
| 항목 | 원문 내용 | 실제 사실 | 위치 |
|------|----------|----------|------|
| `findUnique` where에 `deletedAt` 조건 추가 | `findUnique({ where: { id, deletedAt: null } })` | Prisma의 `findUnique`는 `@unique` 또는 `@@unique` 필드만 where 조건으로 허용. `deletedAt`은 unique 컬럼이 아니므로 TypeScript 컴파일 오류 발생. `findFirst`로 교체하거나 별도 조회 후 deletedAt 확인 필요 | 3.3절 board.service.ts |

### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| $extends 내 `this` 참조 | `(this as any).update(...)` / `(this as any).updateMany(...)` | Prisma $extends Query Extension 콜백 내에서 `this`로 같은 모델을 재귀 호출하는 것은 공식 권장 패턴이 아님. `query(args)` 파라미터 활용 또는 별도 PrismaClient 사용이 안전 | 6절 PrismaService |
| RolesGuard 숫자 계층 방식 | `roleHierarchy: { SUPER_ADMIN: 4, BOARD_ADMIN: 3, USER: 2, GUEST: 1 }` | 기능적으로 작동하나 NestJS 공식 RBAC 예제와 다른 커스텀 구현. 계층 방식이 더 직관적이나 "커스텀 구현" 명시 권장 | 4.1절 RolesGuard |

- ERD → Prisma 스키마 변환 원칙 정확
