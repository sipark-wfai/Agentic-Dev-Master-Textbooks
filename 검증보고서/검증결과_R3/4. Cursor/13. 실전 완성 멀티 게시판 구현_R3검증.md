### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| localStorage에 accessToken 저장 | `localStorage.setItem('accessToken', accessToken)` | 보안 모범 사례상 Access Token을 localStorage에 저장하면 XSS 공격에 취약. 교육 목적이라도 "실제 프로덕션에서는 httpOnly 쿠키 권장" 주석 필수 | 2.1절 authStore, 125·135·149번째 줄 |
| FileUploadDropzone에서 localStorage 직접 참조 | `localStorage.getItem('accessToken')` | 컴포넌트에서 localStorage 직접 접근 대신 authStore 사용이 SvelteKit 권장 패턴 | 2.4절 FileUploadDropzone, 475번째 줄 |
| Svelte 4 이벤트 핸들러 문법 | `on:submit|preventDefault`, `on:click` | SvelteKit v2(Svelte 4) 기준 현재 정확. Svelte 5(Runes 모드)에서는 `onsubmit`, `onclick` 방식으로 변경됨. 버전 명시 권장 | 2.3절 PostList 등 |
| 파일 업로드 시 토큰 헤더 방식 | fetch에 Authorization Bearer 헤더 수동 추가 | 토큰이 만료된 경우 처리 로직 없음. 실제 구현에서는 자동 갱신(refresh) 로직 필요. 교육 목적으로는 허용 가능하나 주석 권장 | 2.4절 |

### 🟢 확인됨 (정확)
- Docker Compose version 필드 제거 정확 (R1 수정 완료)
- pnpm workspace 모노레포 구조 정확
- SvelteKit 동적 라우팅 `[board_id]`, `[post_id]` 파일 기반 라우팅 정확
- `+page.server.ts` / `+page.svelte` 분리 패턴 정확
- `error()` 헬퍼 함수 SvelteKit 에러 처리 정확
- `derived` 스토어 사용 정확
- `browser` 가드 사용 (`$app/environment`) 정확
- NestJS `memoryStorage()` Multer 설정 정확
- Refresh Token 쿠키 전송 (`credentials: 'include'`) 패턴 정확 (보안상 올바른 방식)
- CORS `credentials: true` 설정 정확
