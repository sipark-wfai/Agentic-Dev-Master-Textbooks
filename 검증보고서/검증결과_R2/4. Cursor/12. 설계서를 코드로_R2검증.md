### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| $extends 내 `this` 참조 | `(this as any).update(...)` | 06편과 동일 문제: $extends Query Extension 내에서 같은 모델을 `this`로 재귀 호출하는 방식은 Prisma 공식 권장 패턴이 아님. 실제로 동작할 수 있으나 안정성 불확실 | 6절 |
| RolesGuard 역할 계층 | `SUPER_ADMIN:4, BOARD_ADMIN:3, USER:2, GUEST:1` 숫자 계층 방식 | 기능적으로는 작동하나, NestJS 공식 RBAC 예제는 배열 방식(`requiredRoles.some(role => user.role === role)`)을 사용. 계층 방식은 커스텀 구현으로 유효하지만 공식 방식과 다름 | 4.1절 |
| `findUnique` where에 deletedAt 조건 | `findUnique({ where: { id, deletedAt: null } })` | Prisma의 `findUnique`는 `@unique` 또는 `@@unique` 필드만 where에 허용. `deletedAt: null`을 추가하면 TypeScript 에러 발생. `findFirst`를 사용해야 함 | 3.3절 |
