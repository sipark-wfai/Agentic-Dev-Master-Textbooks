### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| localStorage에 accessToken 저장 | `localStorage.setItem('accessToken', accessToken)` | 보안 모범 사례상 Access Token을 localStorage에 저장하면 XSS 공격에 취약. httpOnly 쿠키 사용 권장. 교재가 교육 목적임을 감안해도 보안 주의 주석 필요 | 2.1절 |
| Refresh Token 전송 방식 | `credentials: 'include'` (쿠키로 전송) | Refresh Token을 쿠키로 전송하는 것은 올바른 보안 패턴. Access Token은 localStorage 대신 메모리 또는 쿠키 사용 권고 | 2.1절 |
| API 클라이언트 내 localStorage 직접 참조 | `localStorage.getItem('accessToken')` (FileUploadDropzone 컴포넌트) | 컴포넌트에서 localStorage 직접 접근 대신 authStore를 사용하는 것이 SvelteKit 패턴에 맞음 | 2.4절 |
| SvelteKit 이벤트 핸들러 | `on:submit`, `on:click` 등 Svelte 4 문법 | SvelteKit v2는 Svelte 4 기반으로 이 문법이 현재 유효하나, Svelte 5에서는 `onsubmit`, `onclick` (runes) 방식으로 변경될 예정 | 2.3절 |

### 🟢 확인됨
- Docker Compose version 필드 제거 정확 (R1 수정 반영)
- pnpm workspace 모노레포 구조 정확
- SvelteKit 동적 라우팅 `[board_id]`, `[post_id]` 파일 기반 라우팅 정확
- `+page.server.ts` / `+page.svelte` 분리 패턴 정확
- `error()` 헬퍼 함수 SvelteKit 에러 처리 정확
- `derived` 스토어 사용 정확
- `browser` 가드 사용 (`$app/environment`) 정확
- NestJS `memoryStorage()` Multer 설정 정확
- CORS `credentials: true` 설정 정확
