## 검증 요약
Hooks의 개념(PreToolUse, PostToolUse, Notification, Stop)과 exit code 체계(0/1/2)는 정확하다. 그러나 Hook 스크립트에서 변수 전달 방식에 일관성 문제가 있다. 일부 예시는 `${file}` 직접 치환을 사용하고, 다른 예시는 stdin JSON 파싱을 사용하는데 실제 Claude Code Hooks는 stdin JSON 방식이 공식이다. `${file}`, `${command}` 직접 치환은 실제로 동작하지 않을 수 있다.

## 발견된 할루시네이션 / 오류

### 🔴 심각 (사실과 명백히 다름)
| 항목 | 원문 내용 | 실제 사실 | 위치 |
|------|----------|----------|------|
| ${file} 직접 치환 | `"command": ".claude/hooks/auto-lint.sh \"${file}\""` | Claude Code Hooks는 tool_input을 stdin JSON으로 전달함. `${file}` 변수 직접 치환은 지원되지 않음 | 섹션 4, 6 전반 |
| ${command} 직접 치환 | `".claude/hooks/human-approval.sh \"${command}\" PreToolUse"` | 마찬가지로 stdin JSON 방식이 실제 동작 방식. `${command}` 직접 치환 미지원 | 섹션 6 |

### 🟡 주의 (불확실하거나 오해 소지)
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| 협업 크레딧 오타 | "Calude Sonnet 4.6" | "Claude Sonnet 4.6"의 오타 | 메타 헤더 |
| Notification 이벤트 | "특정 조건이 충족될 때 발생하는 Hook" | Notification 이벤트의 구체적 트리거 조건이 불명확하게 설명됨 | 섹션 2.3 |
| 비용 제어 Hook | `CLAUDE_CONTEXT_TOKENS`, `CLAUDE_MAX_TOKENS` 환경변수 | 이 환경변수들이 실제 Claude Code에서 제공되는지 불확실 | 13편 내용이나 일부 관련 |
| Hook 3의 ${file} 혼용 | Prettier Hook에서 `${file}` 사용 | stdin 파싱 없이 `${file}` 직접 사용 - 실제 동작 불가 | 섹션 4 Hook3 |

### 🟢 확인됨 (정확한 정보)
- PreToolUse, PostToolUse, Notification, Stop 이벤트 유형 (정확)
- exit code 0(성공), 1(경고), 2(차단) 체계 (정확)
- `.claude/settings.json` Hooks 설정 파일 위치 (정확)
- matcher 패턴 (Write, Bash, 정규식) (정확)
- stdin JSON 파싱 방식 (Hook 1에서 올바르게 설명) (정확)
- PreToolUse exit 2로 도구 실행 차단 가능 (정확)
- PostToolUse로 파일 저장 후 자동 린팅 패턴 (개념적으로 정확)
- Stop 이벤트 활용법 (정확)

## 개선 권고사항
1. 메타 헤더의 "Calude"를 "Claude"로 수정
2. 모든 Hook 예시에서 `${file}`, `${command}` 직접 치환 방식을 stdin JSON 파싱 방식으로 통일
3. 섹션 6의 전체 settings.json에서 변수 치환 방식 전면 수정
4. 각 Hook 스크립트에 stdin 파싱 코드 패턴을 일관되게 적용
5. Hook 3(Prettier)과 Hook 4(테스트), Hook 5(.env 보호) 등의 스크립트도 stdin 파싱 방식으로 수정
