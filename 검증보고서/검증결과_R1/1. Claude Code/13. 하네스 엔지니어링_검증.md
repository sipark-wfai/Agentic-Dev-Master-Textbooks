# 13. 하네스 엔지니어링 할루시네이션 검증 보고서

**검증일**: 2026-06-05
**원본 파일**: 13. 하네스 엔지니어링.md
**전체 할루시네이션 위험도**: 중간

## 검증 요약
하네스 엔지니어링 개념과 4대 구성 요소(가드레일, 파일 접근 제한, 권한 제어, 비용 제어)가 개념적으로 정확하다. 그러나 `.claude/settings.json`의 `permissions`, `limits` 섹션이 실제 Claude Code에서 지원되는지 검증이 필요하다. Hook 스크립트에서 `${command}`, `${file}` 직접 치환 방식도 06편과 동일한 문제가 반복된다.

## 발견된 할루시네이션 / 오류

### 🔴 심각 (사실과 명백히 다름)
| 항목 | 원문 내용 | 실제 사실 | 위치 |
|------|----------|----------|------|
| settings.json permissions 섹션 | `"permissions": {"allow": [...], "deny": [...]}` | Claude Code `.claude/settings.json`에 `permissions.allow/deny` 구조가 실제로 지원되는지 공식 문서에서 확인 필요. 현재 공식 지원 여부 불명확 | 섹션 2.2, 3 |
| settings.json limits 섹션 | `"limits": {"maxFilesPerSession": 100, ...}` | `limits` 섹션은 실제 Claude Code settings.json 공식 스펙에 없는 것으로 보임 | 섹션 3 |
| ${command} 직접 치환 | `".claude/hooks/human-approval.sh \"${command}\" PreToolUse"` | 06편과 동일하게 `${command}` 직접 치환이 Claude Code Hooks에서 지원되지 않음. stdin JSON 파싱 방식 사용 필요 | 섹션 2.3, 3 |

### 🟡 주의 (불확실하거나 오해 소지)
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| 협업 크레딧 오타 | "Calude Sonnet 4.6" | "Claude Sonnet 4.6"의 오타 | 메타 헤더 |
| CLAUDE_CONTEXT_TOKENS 환경변수 | `CLAUDE_CONTEXT_TOKENS="${CLAUDE_CONTEXT_TOKENS:-0}"` | Claude Code가 이 환경변수를 실제로 Hook에 제공하는지 불확실 | 섹션 2.4 |
| CLAUDE_MAX_TOKENS 환경변수 | `CLAUDE_MAX_TOKENS="${CLAUDE_MAX_TOKENS:-200000}"` | 동일하게 불확실 | 섹션 2.4 |
| ${file} 직접 치환 | Hook 명령어에서 `"${file}"` 사용 | stdin JSON 파싱 방식이 올바름 | 섹션 3 |

### 🟢 확인됨 (정확한 정보)
- 하네스 엔지니어링 개념 (비결정론적 에이전트를 결정론적으로 제어) (정확)
- 프롬프트 엔지니어링 vs 하네스 엔지니어링 비교표 (개념 정확)
- PreToolUse exit 2로 차단하는 패턴 (정확)
- Hooks 이벤트 유형 (PreToolUse, PostToolUse, Stop) (정확)
- any 타입 감지 패턴 (`grep -c ": any"`) (정확)
- 보안 키워드 감지 패턴 (정확)
- 하네스 성숙도 모델 Level 0~5 (개념 정확)
- 역할별 하네스 설계 전략 (개념 정확)
- chmod +x 권한 설정 (정확)

## 개선 권고사항
1. 메타 헤더의 "Calude"를 "Claude"로 수정
2. `permissions` 및 `limits` 섹션의 실제 Claude Code 지원 여부 검증 후 지원되지 않으면 제거하거나 대안 제시
3. 모든 Hook 명령어에서 `${command}`, `${file}` 직접 치환을 stdin JSON 파싱 방식으로 수정
4. `CLAUDE_CONTEXT_TOKENS`, `CLAUDE_MAX_TOKENS` 환경변수 지원 여부 검증
