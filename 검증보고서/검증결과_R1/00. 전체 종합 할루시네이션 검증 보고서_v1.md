## 2. 섹션별 핵심 발견 사항

### 🔴 2섹션: Google Antigravity 2.0 & IDE — 위험도 매우 높음 (4.25/10)

**가장 심각한 문제**: 교재 전체가 **실제로 존재하지 않는 제품**을 기반으로 작성됨.

- "Google Antigravity 2.0"이라는 제품은 존재하지 않음
- 실제 Google의 AI 코딩 CLI 도구는 **Gemini CLI** (명령어: `gemini`)
- 교재에 등장하는 `ag` 명령어, `Antigravity IDE`, 다운로드 URL (`ai.google.dev/antigravity/*`), Proposal System, Timemachine, Skills 레지스트리 등 **모두 허구**
- "Gemini 3.5" 모델명도 존재하지 않음 (실제: Gemini 2.5 Pro)
- PRD 작성법, NestJS/SvelteKit 코드 등 일반 개발 내용은 정확하지만, 도구 자체가 허구이므로 교재로서의 신뢰도 치명적

**권고**: 해당 섹션 전체를 실제 **Gemini CLI** 기반으로 전면 재작성 필요

### 🟡 1섹션: Claude Code — 위험도 중간 (7.9/10)

**주요 발견 오류:**
- 메타데이터 오타: `"Calude Sonnet 4.6"` → `"Claude Sonnet 4.6"` (전편 공통)
- 존재하지 않는 CLI 옵션: `--headless`, `--timeout`, `/status`, `/bug` 슬래시 커맨드 등 (04편)
- MCP 설정 파일 경로 혼재: Claude Desktop용 `claude_desktop_config.json`과 CLI용 `.claude/settings.json` (05편)
- Hooks 예시에서 stdin JSON 파싱 방법과 `${file}`, `${command}` 직접 치환 방식 혼용 (06편)
- `pnpm --filter` 문법 오류 (10, 12편)
- Docker Compose `version` 필드 deprecated (05, 10, 12편)
- 모델명 불확실: `claude-opus-4-5` 등이 실제 모델 ID와 일치하는지 미확인 (다수 편)

**강점**: CLAUDE.md 개념 체계, MCP 핵심 개념, PRD 작성 방법론, 오케스트레이터-워커 패턴은 정확

## 4. 우선순위별 수정 권고사항

### 🚨 즉시 수정 (Critical)
1. **2섹션 전체 재작성**: "Google Antigravity 2.0"은 허구 제품. 실제 Gemini CLI 기반으로 전면 재작성 필요
2. **Prisma `$use()` → `$extends()`**: 1~4섹션 전반에 걸쳐 deprecated API 교체
3. **Docker Compose `version` 필드 제거**: 현재 Compose V2 표준에 맞게 수정

### ⚠️ 우선 수정 (High)
4. **Claude Code 존재하지 않는 명령어 제거**: `/status`, `/bug`, `--headless`, `--timeout` 등
5. **MCP 설정 파일 경로 통일**: Claude Code CLI 기준 `.claude/settings.json` 명확화
6. **Cursor 캐시 경로 수정**: 14편의 위험한 전체 삭제 안내 수정

### 📝 권장 수정 (Medium)
7. **모델명 검증**: `claude-opus-4-5`, `claude-sonnet-4-5` 등 Anthropic 공식 명칭과 대조
8. **가격/수치 정보 면책**: 변동 가능 수치에 공식 페이지 링크 및 주의 문구 추가
9. **메타데이터 오타 수정**: "Calude Sonnet 4.6" (1섹션 전편)
10. **GitHub Actions 버전 업데이트**: `pnpm/action-setup@v3` → v4 등

## 5. 연구 활용 권고

본 검증 결과는 **AI 생성 교육 콘텐츠의 할루시네이션 패턴 연구**에 다음과 같이 활용 가능하다:

1. **유형 분류**: 존재하지 않는 제품명 생성, 명령어 조작, deprecated API 사용, 가격 허위 기재 등 유형별 패턴 분석
2. **심각도 스펙트럼**: 2섹션(전면 허구) ~ 3,4섹션(부분 오류)의 스펙트럼 제시
3. **도메인 의존성**: 일반 개발 방법론(PRD, 설계서, NestJS)은 정확하나, 특정 신규 도구(Antigravity, 신규 CLI)에서 할루시네이션 집중 발생
4. **검증 어려움**: 빠르게 변화하는 AI 도구의 특성상 모델명, 가격, 기능이 자주 바뀌어 검증 자체가 도전적
5. **패턴 인사이트**: AI가 실제 존재하는 Gemini CLI를 기반으로 "Google Antigravity"라는 브랜딩을 창작한 것으로 보이며, 이는 AI가 유사 제품을 혼합하여 새로운 허구 제품을 만드는 전형적인 할루시네이션 패턴
