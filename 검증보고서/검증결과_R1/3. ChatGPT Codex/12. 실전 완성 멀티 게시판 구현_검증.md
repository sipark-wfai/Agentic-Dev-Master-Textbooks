# 12. 실전 완성 멀티 게시판 구현 할루시네이션 검증 보고서

**검증일**: 2026-06-05
**원본 파일**: 12. 실전 완성 멀티 게시판 구현.md
**전체 할루시네이션 위험도**: 중간

## 검증 요약

12편은 SvelteKit + NestJS + PostgreSQL 16 기반 풀스택 구현을 다루는 실전 편이다. 코드 예시 품질은 높으나, Prisma $use() deprecated 이슈가 여기서도 등장하며 docker-compose 버전 표기 문제도 발견되었다.

## 발견된 할루시네이션 / 오류

### 🔴 심각
| 항목 | 원문 내용 | 실제 사실 | 위치 |
|------|----------|----------|------|
| Prisma $use() | PrismaService에서 $use() 사용 언급 (10편, 11편 연속) | Prisma v5 공식 권장은 $extends() 방식. $use()는 deprecated 예정 | PrismaModule 참조 부분 |
| docker-compose version | version: '3.9' | Docker Compose v2부터 version 필드가 선택적이며, 최신 docker-compose에서는 version 키가 obsolete로 처리됨 | docker-compose.yml |

### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| SvelteKit locals.user | if (locals.user) { throw redirect(302, '/') } | locals에 user를 설정하는 hooks.server.ts 코드가 없어 동작 여부 불명확 | +page.server.ts (로그인 페이지) |
| 쿠키 전달 방식 | credentials: 'include' 사용 | SvelteKit에서 fetch는 동일 도메인 쿠키를 자동 전송하므로 credentials 설정 방식이 다를 수 있음 | 로그인 Form Action |
| ThrottlerModule | 분당 100 요청 제한 | @nestjs/throttler 설정에서 ttl 단위가 밀리초(60000ms)인지 초(60s)인지 버전마다 다름. v4+에서는 ms 단위 | AppModule |

### 🟢 확인됨
- SvelteKit auth 스토어 구현 (writable, derived 패턴) 정확성
- +layout.server.ts에서 /api/v1/auth/me 호출로 사용자 정보 로드 방식
- NestJS main.ts 설정 (cookieParser, enableCors, setGlobalPrefix, ValidationPipe)
- 게시판 타입별 컴포넌트 분기 처리 (GALLERY는 GalleryCard, 나머지는 PostCard)
- Docker Compose PostgreSQL 16 헬스체크 설정

## 개선 권고사항

1. Prisma $use()를 $extends()로 업데이트 (확정 오류)
2. docker-compose.yml에서 version 키 제거 권고 (최신 Docker Compose 방식)
3. hooks.server.ts 구현 코드 추가 (locals.user 설정을 위해 필수)
4. ThrottlerModule ttl 단위 명시 (ms vs 초)
