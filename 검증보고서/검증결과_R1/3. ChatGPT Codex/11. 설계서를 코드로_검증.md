# 11. 설계서를 코드로 할루시네이션 검증 보고서

**검증일**: 2026-06-05
**원본 파일**: 11. 설계서를 코드로.md
**전체 할루시네이션 위험도**: 중간

## 검증 요약

11편은 ERD에서 Prisma 스키마 생성, API 명세서에서 NestJS 모듈 생성, 설계-구현 불일치 탐지를 다루는 실전 코드 중심 편이다. Prisma $use() deprecated 이슈와 타입 안전성 문제가 발견되었다.

## 발견된 할루시네이션 / 오류

### 🔴 심각
| 항목 | 원문 내용 | 실제 사실 | 위치 |
|------|----------|----------|------|
| Prisma $use() deprecated | PrismaService에서 this.$use() 사용 | Prisma v5에서 $use() 미들웨어 방식은 deprecated 예정이며, $extends()를 사용한 쿼리 확장이 공식 권장 방식. 교재의 주요 패턴이 구식 API 사용 | PrismaService 코드 3절 |

### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| softDelete 메서드 타입 | keyof PrismaClient 사용, delegate.update: Function | Function 타입은 any와 유사한 안전성 문제. 타입 안전한 구현이 더 적절 | PrismaService softDelete 메서드 |
| UserService.create 반환 타입 | Omit | password를 런타임에 구조 분해로 제거하는 방식은 타입 레벨에서 완전하지 않음 | UserService 코드 |
| OptionalJwtGuard 언급 | OptionalJwtGuard 사용 | NestJS에서 OptionalJwtGuard는 커스텀 구현이 필요하나 구현 코드가 없음 | PostController 코드 |

### 🟢 확인됨
- Prisma 스키마 전체 구조 (모델, 인덱스, Enum, 관계) 정확성
- NestJS 모듈 파일 구조 (module, controller, service, dto, spec)
- @@map() 활용으로 테이블명 snake_case 지정
- PostController의 ApiTags, ApiOperation 등 Swagger 데코레이터 사용
- CreatePostDto class-validator 데코레이터 사용

## 개선 권고사항

1. PrismaService의 $use()를 $extends() 방식으로 업데이트 (확정 오류 — 구식 API)
2. softDelete 메서드의 타입 안전성 강화
3. OptionalJwtGuard 구현 코드 추가 또는 참조 링크 제공

## 전체 신뢰도 점수
- **점수**: 7/10
- **근거**: Prisma $use() deprecated 이슈가 핵심 PrismaService 구현에 영향을 미치며, 이를 그대로 따라 구현 시 향후 버전 업그레이드 시 문제 발생. 그 외 NestJS 코드는 대체로 정확.
