## 검증 요약

08편은 에이전트 친화적 PRD 작성법을 다루는 편이다. 방법론과 형식 중심 내용으로 사실 오류가 거의 없으며, PRD 예시는 실용적이고 명확하다.

## 발견된 할루시네이션 / 오류

### 🔴 심각
해당 없음

### 🟡 주의
| 항목 | 원문 내용 | 실제 사실/우려사항 | 위치 |
|------|----------|------------------|------|
| 비밀번호 규칙 정규식 | @Matches(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])/) | 특수문자 목록이 제한적이며 실제 서비스에서는 더 넓은 범위의 특수문자 허용이 필요할 수 있음 | AUTH-001 실패 케이스 |
| 로그인 실패 잠금 | "5회 연속 실패: 429, 5분 잠금" | Redis 없이는 구현이 복잡. 방법 명시 없이 스펙만 제시함 | AUTH-002 |
| 비기능 요구사항 성능 | "동시 접속자: 1,000명 (v1.0 목표)" | 학습용 프로젝트에서 동시 1000명은 현실적이지 않으나, 교육 목적으로는 이해 가능 | 비기능 요구사항 |

### 🟢 확인됨
- 에이전트 친화적 PRD의 특징 (기능 ID, JSON 형식, 수치 기반 성공 기준)
- 기능 ID 형식 (AUTH-001, BOARD-001 등) 활용의 유효성
- docs/ 폴더에 PRD 배치 후 AGENTS.md에서 참조하는 패턴
- 권한 매트릭스 표 형식의 명확성
- HTTP 상태 코드 분류 (400, 401, 403, 404, 409, 429) 정확성

## 개선 권고사항

1. 로그인 실패 잠금 구현 방법 (Redis 활용)을 간략히 언급
2. 비기능 요구사항 수치에 "학습용 예시" 표기 권고
