# 02. Codex 환경 설정 완벽 가이드 — ChatGPT 구독·GitHub 연동·첫 태스크

> **학습 목표**
> - ChatGPT Codex를 사용하기 위한 계정과 구독 요건을 확인한다
> - GitHub 계정을 Codex와 안전하게 연동하는 방법을 익힌다
> - 첫 번째 태스크를 실행하고 PR 결과를 확인한다
> - 요금제별 기능 차이를 이해하고 자신에게 맞는 플랜을 선택한다
> - 초기 설정에서 자주 발생하는 오류 5가지를 해결한다

---

## 1. 시작 전 요건 확인

ChatGPT Codex를 사용하려면 다음이 필요하다.

| 요건 | 내용 |
|------|------|
| ChatGPT 계정 | OpenAI 계정 (openai.com) |
| 구독 플랜 | Plus($20/월), Pro($200/월), 또는 Team |
| GitHub 계정 | github.com 계정 |
| 인터넷 연결 | 안정적인 인터넷 연결 |
| 브라우저 | Chrome, Firefox, Safari 최신 버전 |

### 1.1 구독 플랜 확인 방법

1. chatgpt.com에 로그인한다
2. 좌측 하단의 프로필 아이콘을 클릭한다
3. "My Plan" 또는 "구독 관리"를 선택한다
4. 현재 구독 상태를 확인한다

무료 플랜(Free)이라면 Codex 탭이 표시되지 않거나 기능이 잠겨 있다. 이 경우 Plus 이상으로 업그레이드해야 한다.

### 2.1 플랜 선택 기준

**Plus 추천 대상**
- 개인 개발자, 프리랜서
- 사이드 프로젝트 진행 중
- Codex를 처음 시작하는 경우

**Pro 추천 대상**
- 전문 개발자, 빠른 처리 속도가 필요한 경우
- 복잡한 프로젝트를 자주 처리하는 경우
- o3 모델의 고급 추론 능력이 필요한 경우

**Team 추천 대상**
- 개발팀 전체가 함께 사용하는 경우
- 공유 AGENTS.md와 태스크 히스토리 관리가 필요한 경우

## 3. ChatGPT 계정 설정

### 3.1 계정 생성

이미 계정이 있다면 이 단계를 건너뛴다.

1. chat.openai.com 또는 chatgpt.com 접속
2. "Sign Up" 클릭
3. 이메일 주소 입력 또는 Google/Apple/Microsoft 계정으로 가입
4. 이메일 인증 완료
5. 이름, 생년월일 입력
6. 전화번호 인증 (선택 사항이지만 권장)

### 3.2 Plus 구독 업그레이드

1. 로그인 후 좌측 사이드바 하단 "Upgrade to Plus" 클릭
2. 결제 정보 입력 (신용카드 또는 PayPal)
3. 구독 완료 확인

구독 완료 후 페이지를 새로고침하면 사이드바에 "Codex" 항목이 나타난다.

## 5. GitHub 연동 절차

이 단계가 가장 중요하다. GitHub 연동이 완료되어야 Codex가 레포지토리에서 작업할 수 있다.

### 5.1 GitHub OAuth 연결

```
Codex 대시보드 → 설정(⚙️) → "GitHub 계정 연결" 클릭
→ GitHub 로그인 페이지로 리다이렉트
→ OpenAI ChatGPT가 요청하는 권한 확인
→ "Authorize openai" 클릭
→ ChatGPT로 돌아오며 연결 완료
```

### 5.2 권한 범위(Scope) 설명

Codex가 GitHub에서 요청하는 권한은 다음과 같다.

```
✅ repo: 레포지토리 읽기/쓰기
   - 코드 파일 읽기
   - 브랜치 생성
   - 커밋 및 Push
   - PR 생성

✅ read:user: 사용자 정보 읽기
   - 사용자 이름, 이메일 (인증용)

✅ read:org: 조직 정보 읽기
   - 조직 소속 레포 접근 여부 확인

❌ delete_repo: 레포지토리 삭제 (요청하지 않음)
❌ admin:org: 조직 관리 권한 (요청하지 않음)
```

Codex는 레포지토리를 삭제하거나 조직 설정을 변경하는 권한을 요청하지 않는다. 안전한 범위에서만 작업한다.

### 5.3 특정 레포지토리만 허용하기 (권장)

GitHub App 방식으로 연동하면 접근을 허용할 레포지토리를 개별 선택할 수 있다.

```
GitHub → Settings → Applications → OpenAI ChatGPT
→ "Repository access" 섹션
→ "Only select repositories" 선택
→ 허용할 레포지토리 체크 (예: board-hub)
→ "Save" 클릭
```

이렇게 하면 Codex가 허용된 레포지토리만 접근할 수 있어 보안이 강화된다.

### 5.4 GitHub 연동 확인

연동이 완료되면 Codex 대시보드의 레포지토리 선택 드롭다운에 연결된 레포지토리 목록이 나타난다.

## 6. 학습용 레포지토리 설정

### 6.1 board-hub 레포지토리 생성

```
GitHub → New repository

Repository name: board-hub
Description: 멀티 게시판 허브 - SvelteKit + NestJS + PostgreSQL 16
Visibility: Private (비공개 권장)
Initialize: ✅ Add a README file
.gitignore: Node
License: MIT

→ "Create repository" 클릭
```

### 6.2 초기 파일 구조 생성

레포지토리를 로컬에 클론하고 기본 구조를 생성한다.

```bash
# 로컬 클론
git clone https://github.com/[username]/board-hub.git
cd board-hub

# 기본 디렉토리 구조 생성
mkdir -p apps/frontend apps/backend packages/shared docs

# pnpm workspace 설정
cat > pnpm-workspace.yaml << 'EOF'
packages:
  - 'apps/*'
  - 'packages/*'
EOF

# root package.json 생성
cat > package.json << 'EOF'
{
  "name": "board-hub",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "build": "pnpm -r build",
    "test": "pnpm -r test",
    "lint": "pnpm -r lint"
  },
  "devDependencies": {
    "typescript": "^5.4.0"
  }
}
EOF

# 커밋 및 Push
git add .
git commit -m "chore: initialize monorepo structure"
git push origin main
```

### 6.3 AGENTS.md 임시 생성

03편에서 자세히 다루지만, 지금은 최소한의 AGENTS.md를 추가한다.

```bash
cat > AGENTS.md << 'EOF'
# AGENTS.md

## 프로젝트 개요
board-hub: 8종 게시판을 지원하는 커뮤니티 플랫폼

## 기술 스택
- 프론트엔드: SvelteKit 2.x (TypeScript)
- 백엔드: NestJS 10.x (TypeScript)
- DB: PostgreSQL 16 + Prisma v5
- 패키지 매니저: pnpm

## 기본 규칙
- TypeScript strict 모드 사용
- 모든 함수에 JSDoc 주석 필수
- 테스트 없는 PR은 올리지 않음

## 명령어
- 빌드: pnpm build
- 테스트: pnpm test
- 린트: pnpm lint
EOF

git add AGENTS.md
git commit -m "docs: add AGENTS.md"
git push origin main
```

## 7. 첫 번째 태스크 실행

환경 설정이 완료되었다. 이제 첫 번째 태스크를 실행해본다.

### 7.1 Hello World 수준의 첫 태스크

```
Codex 대시보드에서:

1. 레포지토리 선택: board-hub
2. 태스크 입력창에 다음을 입력:

"apps/backend 디렉토리에 NestJS 프로젝트를 초기화해줘.
 패키지 매니저는 pnpm을 사용하고,
 apps/backend/README.md 파일에 프로젝트 설명을 추가해줘.
 빌드가 성공하는지 확인해줘."

3. 모델 선택: o4-mini (기본값)
4. "실행" 버튼 클릭
```

### 7.2 태스크 실행 과정 모니터링

태스크를 실행하면 Codex 대시보드에 진행 상황이 표시된다.

```
[태스크 실행 로그 예시]

▶ 태스크 시작: 2025-06-05 14:30:00
  ✓ 레포지토리 클론: board-hub
  ✓ AGENTS.md 로드
  ✓ 브랜치 생성: codex/init-nestjs-backend
  ⟳ NestJS 프로젝트 초기화 중...
    - npm install -g @nestjs/cli && nest new apps/backend 실행
    - 의존성 설치 중 (약 2분 소요)
  ✓ apps/backend/README.md 작성
  ⟳ 빌드 테스트 중...
    - pnpm build 실행
  ✓ 빌드 성공
  ✓ PR 생성: #1 feat: initialize NestJS backend
▶ 태스크 완료: 2025-06-05 14:34:23 (4분 23초)
```

### 7.3 PR 결과 확인

태스크가 완료되면 GitHub에 PR이 생성된다.

```
GitHub → board-hub → Pull requests

PR #1: feat: initialize NestJS backend
Branch: codex/init-nestjs-backend → main
Author: Codex (OpenAI)

변경된 파일:
  + apps/backend/package.json
  + apps/backend/src/app.module.ts
  + apps/backend/src/app.controller.ts
  + apps/backend/src/app.service.ts
  + apps/backend/src/main.ts
  + apps/backend/README.md
  + apps/backend/tsconfig.json
  + apps/backend/nest-cli.json
```

PR 설명에는 태스크 내용, 실행한 명령어, 빌드 결과가 포함된다.

### 7.4 PR 검토 및 머지

```
1. PR 페이지에서 "Files changed" 탭 클릭
2. 변경된 파일을 하나씩 확인
3. 의도한 대로 구현되었으면 "Review changes" → "Approve"
4. "Merge pull request" 클릭
```

## 8. 태스크 결과 확인 상세 가이드

### 8.1 Codex 대시보드에서 확인

```
태스크 목록 → 완료된 태스크 클릭
→ 태스크 상세 페이지:
  - 태스크 설명
  - 실행 시간
  - 생성된 PR 링크
  - 실행 로그 (펼쳐보기 가능)
  - 오류 메시지 (실패한 경우)
```

### 8.2 GitHub에서 PR Diff 분석

PR의 변경 사항을 분석하는 방법이다.

```
PR 페이지 → Files changed 탭

각 파일에서:
- 초록색 줄: 추가된 코드
- 빨간색 줄: 삭제된 코드
- 회색 줄: 변경 없음 (컨텍스트)

파일별 리뷰:
  - 논리적 오류 확인
  - 타입 안전성 확인
  - 코딩 컨벤션 준수 여부
  - AGENTS.md 규칙 준수 여부
```

### 8.3 코멘트로 수정 요청

PR을 검토하다 수정이 필요한 부분이 있으면:

```
방법 1: PR 코멘트
→ 해당 줄 옆의 "+" 버튼 클릭
→ 코멘트 입력: "이 함수는 async여야 합니다"
→ Codex가 코멘트를 읽고 수정 태스크를 다시 실행

방법 2: 새 태스크 입력
→ Codex 대시보드에서 새 태스크:
  "PR #1의 app.service.ts에서 getHello() 함수를 async로 변경해줘"
```

## 10. 자주 겪는 초기 오류 5가지

### 오류 1: "Codex 탭이 보이지 않음"

**증상**: 사이드바나 메뉴에 Codex 옵션이 없음

**원인**: 무료 계정이거나, 구독이 활성화되지 않은 상태

**해결**:
```
1. chatgpt.com → 좌측 하단 프로필 → "My Plan" 확인
2. Plus 미가입 상태라면 "Upgrade to Plus" 클릭
3. 결제 완료 후 페이지 새로고침 (Ctrl+Shift+R)
4. 여전히 보이지 않으면 로그아웃 후 재로그인
```

### 오류 2: "GitHub 연동 실패 — Authentication required"

**증상**: GitHub OAuth 연결 시도 후 "인증 실패" 또는 빈 레포 목록

**원인**: GitHub 계정의 2FA 설정, 또는 OAuth 앱 권한 부여 실패

**해결**:
```
1. GitHub → Settings → Applications → Authorized OAuth Apps 확인
2. "OpenAI ChatGPT" 앱이 목록에 있는지 확인
3. 없다면 Codex 대시보드에서 "GitHub 재연결" 클릭
4. GitHub 2FA가 활성화된 경우: 인증 앱 또는 SMS 코드 입력 필요
```

### 오류 3: "태스크 실패 — Repository not found"

**증상**: 태스크 실행 시 "레포지토리를 찾을 수 없음" 오류

**원인**: GitHub App의 레포지토리 접근 권한이 설정되지 않음

**해결**:
```
GitHub → Settings → Applications → GitHub Apps
→ "OpenAI ChatGPT" → "Configure"
→ Repository access → "Only select repositories"
→ board-hub 레포 선택
→ "Save" 클릭
→ Codex에서 레포지토리 선택 목록 새로고침
```

### 오류 4: "태스크 실패 — Build error"

**증상**: 빌드 명령어 실행 중 오류로 태스크 실패

**원인**: AGENTS.md의 빌드 명령어가 잘못되었거나, package.json에 스크립트가 없음

**해결**:
```
1. AGENTS.md의 빌드 명령어 확인:
   - pnpm build (pnpm 사용 시)
   - npm run build (npm 사용 시)

2. root package.json에 scripts 확인:
   {
     "scripts": {
       "build": "pnpm -r build",
       "test": "pnpm -r test",
       "lint": "pnpm -r lint"
     }
   }

3. 수정 후 Push하고 태스크 재실행
```

### 오류 5: "태스크 큐 한도 초과"

**증상**: "Monthly limit reached" 또는 태스크 실행 불가 메시지

**원인**: Plus 플랜의 월간 태스크 한도 초과

**해결**:
```
방법 1: 다음 달까지 대기
방법 2: Pro 플랜으로 업그레이드 (한도 없음)
방법 3: 태스크 범위를 줄여 효율적으로 사용
  - 하나의 태스크에 너무 많은 작업을 넣지 않음
  - 핵심 기능만 먼저 구현하고 나머지는 나중에
```

## 11. GitHub App 권한 세부 설정 가이드

보안을 위해 Codex에 부여하는 GitHub 권한을 최소화하는 방법이다.

### 11.1 현재 권한 확인

```
GitHub → Settings → Integrations → GitHub Apps
→ "OpenAI ChatGPT" 클릭 → "Configure"
→ Permissions & events 섹션 확인
```

### 11.2 권한별 필요성

```
✅ 반드시 필요한 권한:
  - Contents (read & write): 파일 읽기·수정
  - Pull requests (read & write): PR 생성·수정
  - Metadata (read): 레포 메타데이터

✅ 이슈 연동 시 필요:
  - Issues (read & write): 이슈 읽기·상태 변경

⚠️ 신중히 부여:
  - Actions (read & write): GitHub Actions 트리거
  - Secrets (read): 환경 변수 읽기

❌ 부여 불필요:
  - Administration: 레포 설정 변경
  - Deployments: 배포 관리
```

### 11.3 레포지토리 범위 제한

```
GitHub Apps 설정 → Repository access
→ "Only select repositories" 선택
→ 허용할 레포만 선택

⚠️ "All repositories"는 피한다.
  모든 레포에 접근 권한을 주면 보안 위험이 높아진다.
```

## 13. 개발 환경 연동 심화 설정

### 13.1 GitHub 알림 최적화

Codex가 생성한 PR을 빠르게 알림 받으려면 GitHub 알림을 설정한다.

```
GitHub → Settings → Notifications

Participating and @mentions:
  ✅ Email
  ✅ Web and Mobile

Pull Request reviews:
  ✅ Email
  ✅ Web and Mobile

Codex PR 알림을 별도 이메일 필터로 분류:
  보낸 사람: notifications@github.com
  제목 포함: [board-hub] codex/
```

### 13.2 Slack 알림 연동 (선택)

팀이 Slack을 사용한다면 GitHub-Slack 연동으로 PR 알림을 Slack에서 받을 수 있다.

```
Slack → Apps → GitHub 앱 추가
/github subscribe board-hub/board-hub pulls

이후 Codex가 PR을 올릴 때마다 Slack 채널에 알림이 온다.
```

### 13.3 브랜치 보호 규칙 설정

Codex PR이 검토 없이 main에 직접 머지되지 않도록 브랜치를 보호한다.

```
GitHub → board-hub → Settings → Branches → Add rule

Branch name pattern: main
✅ Require a pull request before merging
  ✅ Require approvals: 1
✅ Require status checks to pass before merging
✅ Require branches to be up to date before merging
✅ Do not allow bypassing the above settings

→ "Save changes" 클릭
```

이 설정으로 Codex가 올린 PR도 반드시 리뷰어의 승인이 필요하다.
