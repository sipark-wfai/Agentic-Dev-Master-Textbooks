## 2. 20가지 오류 시나리오 완전 해결

### 오류 01: GitHub 연동 실패 (권한 오류)

**증상**
```
Codex 태스크 실행 시:
"Error: Repository not found or access denied"
또는 레포지토리 드롭다운이 비어있음
```

**원인**
- GitHub OAuth 토큰 만료
- GitHub App 레포지토리 접근 권한 미설정
- 조직 레포지토리에 접근 시 조직 승인 없음

**해결**
```
1. Codex 대시보드 → 설정 → "GitHub 재연결"
2. GitHub OAuth 재인증 (Authorize 클릭)
3. GitHub → Settings → Applications → OpenAI ChatGPT
   → Repository access → 레포지토리 체크
4. 조직 레포의 경우: 조직 Settings → OAuth Apps → Approve
```

**예방**
```
AGENTS.md에 명시:
"이 레포지토리는 GitHub App에서 접근이 허용되어야 한다.
접근 허용 경로: GitHub → Settings → Applications"
```

### 오류 02: AGENTS.md 미적용

**증상**
```
Codex가 다음을 하지 않음:
- pnpm 대신 npm 사용
- any 타입 사용
- 잘못된 브랜치명 사용
- 코딩 컨벤션 무시
```

**원인**
- AGENTS.md 파일이 레포 루트에 없음 (서브 폴더에만 있음)
- AGENTS.md 파일이 GitHub에 Push되지 않음
- 파일명 오타 (agents.md, AGENT.md 등)

**해결**
```bash
# 파일 위치 확인
ls -la | grep -i agents

# 올바른 위치 확인
cat AGENTS.md  # 루트에서 실행

# 없다면 생성 및 Push
git add AGENTS.md
git commit -m "docs: add AGENTS.md"
git push origin main
```

**예방**
```
PR 생성 전 체크리스트에 추가:
[ ] AGENTS.md가 레포 루트에 존재하는가?

[ ] GitHub에 Push되어 있는가?
```

### 오류 03: 태스크 실패 — 빌드 오류

**증상**
```
태스크 로그:
✗ 빌드 실패

오류 내용:
src/auth/auth.service.ts:45:12 - error TS2345:
Argument of type 'string | undefined' is not assignable 
to parameter of type 'string'.
```

**원인**
- TypeScript strict 모드에서 undefined 처리 미흡
- 환경 변수가 undefined일 수 있는 경우 체크 누락
- 모듈 의존성 누락

**해결 태스크**
```
"PR #[번호]의 빌드가 실패했어.

오류:
src/auth/auth.service.ts:45:12 - error TS2345:
Argument of type 'string | undefined' is not assignable to parameter of type 'string'.

process.env.JWT_SECRET이 undefined일 수 있어.
다음 방법으로 수정해줘:

방법: ConfigService를 사용하여 타입 안전하게 가져오기
const secret = this.configService.get<string>('JWT_SECRET');
if (!secret) throw new Error('JWT_SECRET is not defined');

apps/backend/src/auth/auth.service.ts만 수정해줘."
```

**예방**
```markdown
## 환경 변수 규칙 (AGENTS.md)

환경 변수는 반드시 ConfigService를 통해 접근한다:
const value = this.configService.get<string>('KEY');
if (!value) throw new Error('KEY environment variable is not set');

process.env.KEY 직접 접근 금지.
```

### 오류 04: 태스크 실패 — 테스트 오류

**증상**
```
태스크 로그:
✗ 테스트 실패

FAIL src/auth/auth.service.spec.ts
  ✕ 정상 로그인: accessToken을 반환한다

  ● AuthService › login › 정상 로그인: accessToken을 반환한다
    Expected: "jwt-token"
    Received: undefined
```

**원인**
- Mock 설정이 잘못됨
- 비동기 처리 누락 (await 없음)
- 테스트 환경 변수 미설정

**해결 태스크**
```
"PR #[번호]의 테스트가 실패하고 있어.

오류:
Expected: 'jwt-token'
Received: undefined

auth.service.spec.ts에서 JwtService.signAsync가 올바르게 Mock되지 않은 것 같아.

현재 Mock:
jwtService.signAsync = jest.fn();  // 반환값 없음

올바른 Mock:
jwtService.signAsync = jest.fn().mockResolvedValue('jwt-token');

auth.service.spec.ts의 JwtService Mock을 수정해줘."
```

**예방**
```
테스트 작성 규칙 (AGENTS.md):
- Mock은 반드시 반환값을 설정한다
  jest.fn().mockResolvedValue(value) (비동기)
  jest.fn().mockReturnValue(value) (동기)
- 테스트 후 Mock 초기화: afterEach(() => jest.clearAllMocks())
```

### 오류 09: TypeScript 타입 오류 누적

**증상**
```
빌드 오류 수십 개:
error TS2345: Argument of type ...
error TS2339: Property 'x' does not exist on type ...
error TS7006: Parameter 'e' implicitly has an 'any' type.
```

**원인**
- Codex가 이전 타입 오류를 수정하지 않고 계속 코드 추가
- tsconfig.json의 strict 모드가 처음부터 활성화되지 않음

**해결 태스크**
```
"apps/backend에 TypeScript 타입 오류가 누적되어 있어.
pnpm -r exec tsc --noEmit 실행 시 오류가 다수 발생해.

단계별로 수정해줘:
1. pnpm -r exec tsc --noEmit 실행하여 전체 오류 목록 확인
2. Critical 오류 (any 타입, 타입 불일치)부터 수정
3. 모든 오류 해결 후 pnpm build 성공 확인

수정 방향:
- implicit any → 구체적 타입 명시
- undefined 가능성 → 옵셔널 체이닝 또는 nullish coalescing
- 타입 불일치 → 타입 가드 또는 명시적 타입 지정"
```

### 오류 10: NestJS DI(의존성 주입) 오류

**증상**
```
Nest.js 앱 시작 실패:
Nest can't resolve dependencies of the PostService (?).
Please make sure that the argument PrismaService at index [0] 
is available in the PostModule context.
```

**원인**
- PrismaModule이 PostModule에 import되지 않음
- 글로벌 모듈(@Global) 설정 누락
- 순환 의존성

**해결**
```typescript
// 방법 1: PostModule에 PrismaModule import 추가
@Module({
  imports: [PrismaModule],  // ← 추가
  controllers: [PostController],
  providers: [PostService],
})
export class PostModule {}

// 방법 2: PrismaModule을 @Global로 설정 (권장)
@Global()
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}
// 이후 다른 모듈에서 imports 없이 PrismaService 주입 가능
```

**해결 태스크**
```
"NestJS DI 오류가 발생해.

오류: Nest can't resolve dependencies of PostService at index [0]

PrismaModule이 @Global() 데코레이터가 없어서
다른 모듈에서 PrismaService를 주입받지 못하고 있어.

apps/backend/src/prisma/prisma.module.ts에
@Global() 데코레이터를 추가해줘.
그리고 모든 다른 모듈에서 불필요하게 추가된 imports: [PrismaModule]을 제거해줘."
```

### 오류 11: SvelteKit SSR 빌드 실패

**증상**
```
pnpm build 실패:
TypeError: Cannot read properties of undefined (reading 'user')
    at +layout.svelte:15:28
```

**원인**
- 클라이언트 전용 코드가 SSR에서 실행됨
- localStorage, window 같은 브라우저 API 서버에서 접근
- 스토어 초기화 시점 문제

**해결**
```svelte
<!-- 브라우저 전용 코드 -->
<script lang="ts">
  import { browser } from '$app/environment';
  
  // SSR에서 실행 안 됨
  $: if (browser) {
    localStorage.setItem('key', 'value');
  }
  
  // 또는 onMount 사용
  import { onMount } from 'svelte';
  onMount(() => {
    // 브라우저에서만 실행
    localStorage.setItem('key', 'value');
  });
</script>
```

**해결 태스크**
```
"SvelteKit 빌드가 실패해.

오류: Cannot read properties of undefined (reading 'user')
위치: +layout.svelte:15

SSR 환경에서 data.user가 초기화되기 전에 접근하는 것 같아.
$app/environment의 browser를 사용하여
클라이언트에서만 실행되도록 수정해줘."
```

### 오류 12: CORS 설정 오류

**증상**
```
브라우저 콘솔:
Access to fetch at 'http://localhost:3000/api/v1/auth/login' 
from origin 'http://localhost:5173' has been blocked by CORS policy
```

**원인**
- NestJS CORS 설정에 프론트엔드 URL이 포함되지 않음
- credentials: true 누락
- 허용 메서드에 OPTIONS 누락

**해결**
```typescript
// main.ts
app.enableCors({
  origin: ['http://localhost:5173', 'https://board-hub.vercel.app'],
  credentials: true,  // 쿠키 전송 필수
  methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
  allowedHeaders: ['Content-Type', 'Authorization'],
});
```

**해결 태스크**
```
"CORS 오류가 발생해.
http://localhost:5173에서 http://localhost:3000/api/v1 접근 불가.

apps/backend/src/main.ts의 enableCors 설정을 다음으로 수정해줘:
- origin: ['http://localhost:5173', process.env.FRONTEND_URL]
- credentials: true
- methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
- allowedHeaders: Content-Type, Authorization"
```

### 오류 13: 환각 — 존재하지 않는 API 사용

**증상**
```
빌드 오류:
Module '"sharp"' has no exported member 'fromBuffer'.
또는
Property 'toWebP' does not exist on type 'Sharp'.
```

**원인**
- Codex가 존재하지 않는 API 또는 메서드를 사용함
- 오래된 버전의 API 사용
- 다른 라이브러리의 API를 혼동

**해결**
```
공식 문서를 참조하도록 태스크에 명시:

"sharp 라이브러리의 공식 API 문서를 참조해줘:
https://sharp.pixelplumbing.com/api-input

현재 코드의 fromBuffer() 메서드는 존재하지 않아.
올바른 메서드는 sharp(buffer)로 호출하는 방식이야.
sharp() 생성자를 사용하여 이미지를 로드하고 처리해줘."
```

**예방**
```
AGENTS.md에 주요 라이브러리 버전 명시:
## 라이브러리 버전 (AGENTS.md)

- sharp: 0.33.x (공식 문서: https://sharp.pixelplumbing.com)
- 버전 명시 없이 최신 API를 사용하지 않는다
- 불확실한 API는 공식 npm 패키지 문서를 확인 후 사용
```

### 오류 14: PR 충돌 (동시 태스크)

**증상**
```
PR 머지 시:
This branch has conflicts that must be resolved
Conflicting files:
  apps/backend/src/post/post.service.ts
  prisma/schema.prisma
```

**원인**
- 두 태스크가 같은 파일을 동시에 수정
- 스키마 파일을 두 태스크에서 동시에 변경

**해결**
```
1. PR A를 먼저 머지
2. PR B의 브랜치를 develop으로 rebase:
   git checkout codex/feat-pinned
   git rebase develop
   (충돌 해결)
   git push --force-with-lease

또는 Codex에게 충돌 해결 요청:
"PR #16의 브랜치가 develop과 충돌나고 있어.
develop을 rebase하고 충돌을 해결해줘.
충돌 파일:
- apps/backend/src/post/post.service.ts
  post.service.ts는 PR #16의 변경사항을 유지해줘."
```

**예방**
```
같은 파일을 수정하는 태스크는 절대 병렬 실행하지 않는다.
태스크 시작 전 "어떤 파일을 수정하는가?"를 먼저 파악한다.
```

### 오류 19: PostgreSQL 연결 실패 (테스트 DB)

**증상**
```
pnpm prisma migrate dev 실패:
Error: P1001: Can't reach database server at `localhost:5432`
```

**원인**
- DATABASE_URL 환경 변수 미설정
- PostgreSQL 사용자 또는 DB 미존재
- 포트 충돌

**해결**
```bash
# PostgreSQL 상태 확인
pg_lsclusters
service postgresql status

# 사용자 및 DB 생성
psql -U postgres << 'EOF'
CREATE USER boardhub WITH PASSWORD 'boardhub_password';
CREATE DATABASE board_hub OWNER boardhub;
CREATE DATABASE board_hub_test OWNER boardhub;
GRANT ALL PRIVILEGES ON DATABASE board_hub TO boardhub;
GRANT ALL PRIVILEGES ON DATABASE board_hub_test TO boardhub;
EOF

# 연결 테스트
psql -U boardhub -d board_hub -c "SELECT 1;"
```

## 3. GitHub Issue로 버그 리포트 → Codex 자동 전달

### 3.1 이슈 → 태스크 자동화 패턴

```
1. 사용자가 버그 발견
2. GitHub Issue 생성 (이슈 템플릿 사용)
3. 이슈에 'codex-ready' 레이블 추가
4. 개발자가 Codex 태스크 입력:
   "Issue #[번호]를 읽고 버그를 수정해줘.
    Closes #[번호]"
5. Codex가 이슈 내용을 읽고 수정 후 PR 생성
6. PR 리뷰 → 머지 → 이슈 자동 Close
```

### 3.2 버그 이슈 최적화 작성법

```markdown
## 버그: [간단한 설명]

### 환경
- 발생 버전: 1.0.0
- 발생 경로: POST /api/v1/files/upload

### 재현 방법
1. 로그인한 상태에서
2. 갤러리 게시판에서 이미지 업로드
3. 응답의 thumbnailUrl 확인

### 현재 동작
thumbnailUrl: null

### 기대 동작
thumbnailUrl: "/uploads/thumbs/uuid.jpg"

### 원인 추정
apps/backend/src/file/file.service.ts의 generateThumbnail() 함수에서
await 없이 호출되는 것으로 추정

### 관련 파일
- apps/backend/src/file/file.service.ts
- apps/backend/src/post/post.service.ts

### Codex 힌트
await this.fileService.generateThumbnail(fileId)로
수정하면 해결될 것으로 예상.
회귀 테스트를 반드시 추가해줘.
```

## 4. 트러블슈팅 빠른 참조 카드

```
증상                              → 해결 방향
────────────────────────────────────────────────────
레포 목록 비어있음                → GitHub App 권한 설정
AGENTS.md 무시됨                 → 파일 위치·Push 확인
빌드 실패 (TS 오류)              → tsc --noEmit로 오류 확인 후 재태스크
테스트 실패 (Mock 오류)          → Mock 반환값 설정 확인
태스크 타임아웃                  → 태스크 범위 분할
환경 변수 오류                   → .env.test 또는 AGENTS.md에 명시
패키지 설치 실패                 → peer dep 확인, pnpm install --force
Prisma 마이그레이션 충돌         → 스키마 변경 태스크 순차 실행
DI 오류                          → PrismaModule @Global() 확인
CORS 오류                        → enableCors origin + credentials
환각 (존재하지 않는 API)         → 공식 문서 URL을 태스크에 명시
PR 충돌                          → 동시 실행 방지, rebase로 해결
브랜치 보호 실패                 → codex/ 브랜치로 Push 후 PR
요금 초과                        → Pro 업그레이드 또는 대기
자동 머지 위험                   → 브랜치 보호 규칙 설정
```
