## 1. 에이전트 친화적 PRD란

PRD(Product Requirements Document)는 제품의 기능과 요구사항을 정의하는 문서다. 전통적인 PRD는 사람이 읽기 위해 작성되었다. 개발팀이 이해하고 구현하기 위한 문서다.

에이전트 친화적 PRD는 사람과 AI 에이전트 모두가 정확하게 파싱할 수 있도록 작성된다.

### 1.1 일반 PRD vs 에이전트 친화적 PRD

```
[일반 PRD]
"사용자는 로그인할 수 있어야 합니다. 로그인 화면은 직관적이어야 하고,
오류 메시지는 친절해야 합니다."

[에이전트 친화적 PRD]
## AUTH-001: 이메일/비밀번호 로그인

**입력**
- email: string (RFC 5321 이메일 형식)
- password: string (8자 이상)

**성공 응답** (200 OK)
- accessToken: JWT (만료: 15분)
- 응답 헤더: Set-Cookie (HttpOnly, Secure, SameSite=Strict)

**실패 응답**
- 이메일 형식 오류: 400 Bad Request
- 이메일 미존재: 401 Unauthorized ("이메일 또는 비밀번호가 올바르지 않습니다")
- 비밀번호 불일치: 401 Unauthorized ("이메일 또는 비밀번호가 올바르지 않습니다")
- 5회 연속 실패: 429 Too Many Requests (5분 잠금)

**비기능 요구사항**
- 응답 시간: 500ms 이하
- 비밀번호 로그 기록 금지
```

두 번째 PRD를 보면 Codex가 정확히 무엇을 구현해야 하는지, 어떤 오류 처리가 필요한지, 성능 기준이 무엇인지 즉시 파악할 수 있다.

### 1.2 에이전트 친화적 PRD의 특징

```
1. 기능 ID: 고유한 식별자 (AUTH-001, BOARD-003 등)
2. 구체적인 입력/출력: JSON 형식으로 명시
3. 성공/실패 케이스: HTTP 상태 코드와 오류 메시지 포함
4. 수치 기반 성공 기준: "빠르게" 대신 "500ms 이하"
5. 엣지 케이스 명시: 경계값, 예외 상황 포함
6. 기술 제약 명시: 사용할 라이브러리, 보안 요건 등
```

Codex가 아닌 일반 ChatGPT 대화에서 PRD 작성을 도움받는다.

### 2.1 PRD 작성 프롬프트

```
ChatGPT에게:

"멀티 게시판 허브 서비스의 에이전트 친화적 PRD를 작성해줘.

[서비스 개요]
8종 게시판(일반·갤러리·동영상·Q&A·공지·FAQ·비공개문의·자유)을 지원하는 커뮤니티 플랫폼

[기술 스택]
- 백엔드: NestJS 10.x + TypeScript strict
- DB: PostgreSQL 16 + Prisma v5
- 프론트엔드: SvelteKit 2.x
- 인증: JWT (HttpOnly 쿠키)

[사용자 역할]
- ADMIN: 관리자
- USER: 가입 사용자
- GUEST: 비로그인

[기능 도메인]
1. 인증 (AUTH-001~005)
2. 게시판 관리 (BOARD-001~005)
3. 게시물 (POST-001~010)
4. 댓글 (COMMENT-001~005)
5. 파일 업로드 (FILE-001~003)

각 기능을 기능 ID, 설명, API 스펙(HTTP 메서드/경로/요청/응답), 
성공 기준, 실패 케이스로 구체적으로 작성해줘.
ChatGPT Codex AI 에이전트가 이 문서만 보고 구현할 수 있을 정도로 명확하게."
```

### 2.2 PRD 섹션별 추가 질문

초안이 나왔다면 각 섹션을 보완하는 추가 질문을 한다:

```
"AUTH 섹션에서 소셜 로그인(Google OAuth)도 추가해줘.
AUTH-006으로 ID를 부여하고 OAuth 플로우를 상세히 명시해줘."

"POST 섹션에서 게시물 검색 기능을 추가해줘.
전문 검색(Full-text search) PostgreSQL 기능을 사용하는 방향으로."

"비기능 요구사항을 더 구체화해줘.
응답 시간, 동시 접속자 수, 파일 크기 제한 등을 수치로 명시해줘."
```

## 3. PRD 필수 구성 요소

### 3.1 문서 헤더

```markdown
# Board Hub PRD (Product Requirements Document)

**버전**: 1.0.0
**작성일**: 2025-06-05
**최종 수정**: 2025-06-05
**작성자**: [팀명]
**상태**: Draft | Review | Approved

## 문서 목적
이 문서는 ChatGPT Codex AI 에이전트와 개발팀이 board-hub 서비스를
구현하기 위한 기능 명세를 정의한다.

## Codex 사용 지침
에이전트는 이 문서를 기반으로 구현을 진행하며,
명세가 불명확한 경우 보수적으로 해석한다.
명세에 없는 기능을 임의로 추가하지 않는다.
```

### 3.2 사용자 역할 정의

```markdown
## 사용자 역할

| 역할 | 코드 | 설명 |
|------|------|------|
| 관리자 | ADMIN | 모든 기능 접근, 사용자·게시판 관리 |
| 일반 사용자 | USER | 회원가입·로그인, 게시물·댓글 CRUD |
| 비로그인 사용자 | GUEST | 공개 게시물 읽기만 가능 |

### 권한 매트릭스

| 작업 | GUEST | USER | ADMIN |
|------|-------|------|-------|
| 공개 게시물 읽기 | ✅ | ✅ | ✅ |
| 게시물 작성 | ❌ | ✅ | ✅ |
| 본인 게시물 수정 | ❌ | ✅ | ✅ |
| 타인 게시물 수정 | ❌ | ❌ | ✅ |
| 게시물 삭제 | ❌ | 본인만 | ✅ |
| 게시판 생성 | ❌ | ❌ | ✅ |
| 사용자 관리 | ❌ | ❌ | ✅ |
| 공지 작성 | ❌ | ❌ | ✅ |
| 비공개문의 읽기 | ❌ | 본인만 | ✅ |
```

### 3.3 기능 명세 템플릿

```markdown
## [기능-ID]: [기능 이름]

**우선순위**: P0 | P1 | P2
**담당**: 백엔드 | 프론트엔드 | 풀스택
**의존성**: [의존하는 기능 ID 목록]

### 설명
[기능에 대한 2~3줄 설명]

### API 명세

**요청**
- Method: GET | POST | PUT | PATCH | DELETE
- Path: /api/v1/[path]
- 인증: 필요 | 불필요 | ADMIN 전용
- Headers: Content-Type: application/json
- Request Body:
  ```json
  {
    "field1": "string (설명)",
    "field2": "number (설명)"
  }
  ```

**응답 (성공)**
- Status: 200 OK | 201 Created
- Body:
  ```json
  {
    "field1": "string",
    "field2": "number"
  }
  ```

**응답 (실패)**
| 상황 | 상태 코드 | 메시지 |
|------|----------|--------|
| [실패 상황 1] | 400 | "[오류 메시지]" |
| [실패 상황 2] | 401 | "[오류 메시지]" |

### 성공 기준 (테스트 케이스)
- [ ] [정상 케이스]: [입력] → [예상 응답]
- [ ] [실패 케이스 1]: [입력] → [예상 오류]
- [ ] [실패 케이스 2]: [입력] → [예상 오류]

### 비기능 요구사항
- 응답 시간: [N]ms 이하
- 보안: [보안 요구사항]
```

## 4. 멀티 게시판 허브 전체 PRD

```markdown
# Board Hub PRD v1.0

**버전**: 1.0.0  
**작성일**: 2025-06-05  
**상태**: Approved

---

## 프로젝트 개요

board-hub는 8종 게시판을 지원하는 커뮤니티 플랫폼이다.

### 게시판 종류
| 타입 코드 | 이름 | 특징 |
|----------|------|------|
| GENERAL | 일반 | 텍스트 중심 |
| GALLERY | 갤러리 | 이미지 + 썸네일 |
| VIDEO | 동영상 | 비디오 + HLS |
| QNA | Q&A | 질문·답변·채택 |
| NOTICE | 공지 | ADMIN 전용 작성, 고정 |
| FAQ | FAQ | 카테고리·태그 |
| PRIVATE | 비공개문의 | 작성자·ADMIN만 열람 |
| FREE | 자유 | 익명 선택 가능 |

---

## 인증 (AUTH)

### AUTH-001: 회원가입

**우선순위**: P0

**API**
- POST /api/v1/auth/register
- 인증: 불필요

**요청**
```json
{
  "email": "string (이메일 형식, 최대 255자)",
  "password": "string (8자 이상, 대소문자+숫자+특수문자 포함)",
  "username": "string (2~20자, 한글·영문·숫자·언더스코어)"
}
```

**응답 (201 Created)**
```json
{
  "message": "회원가입이 완료되었습니다",
  "user": {
    "id": 1,
    "email": "user@example.com",
    "username": "홍길동",
    "role": "USER",
    "createdAt": "2025-06-05T00:00:00.000Z"
  }
}
```

**실패 케이스**
| 상황 | 코드 | 메시지 |
|------|------|--------|
| 이메일 형식 오류 | 400 | "올바른 이메일 형식이 아닙니다" |
| 비밀번호 규칙 미충족 | 400 | "비밀번호는 8자 이상, 대소문자·숫자·특수문자 포함" |
| 이메일 중복 | 409 | "이미 사용 중인 이메일입니다" |
| 사용자명 중복 | 409 | "이미 사용 중인 사용자명입니다" |

**성공 기준**
- 정상 회원가입 → 201 + user 객체 반환
- 중복 이메일 → 409 반환
- 비밀번호 규칙 위반 → 400 반환
- 비밀번호는 응답에 포함되지 않음

**보안**
- bcrypt salt rounds 12로 비밀번호 해싱
- 비밀번호 평문 로그 기록 절대 금지

---

### AUTH-002: 로그인

**우선순위**: P0

**API**
- POST /api/v1/auth/login
- 인증: 불필요

**요청**
```json
{
  "email": "string",
  "password": "string"
}
```

**응답 (200 OK)**
```json
{
  "message": "로그인되었습니다",
  "user": {
    "id": 1,
    "email": "user@example.com",
    "username": "홍길동",
    "role": "USER"
  }
}
```
- Set-Cookie: access_token=JWT; HttpOnly; Secure; SameSite=Strict; Max-Age=900

**실패 케이스**
| 상황 | 코드 | 메시지 |
|------|------|--------|
| 이메일 미존재 | 401 | "이메일 또는 비밀번호가 올바르지 않습니다" |
| 비밀번호 불일치 | 401 | "이메일 또는 비밀번호가 올바르지 않습니다" |
| 5회 연속 실패 | 429 | "5분 후 다시 시도해주세요" |

**성공 기준**
- 올바른 자격증명 → 200 + HttpOnly 쿠키 설정
- 잘못된 자격증명 → 401 (이메일/비밀번호 구분 없는 메시지)
- 연속 실패 잠금 → 429

**성능**: 응답 시간 500ms 이하

---

### AUTH-003: 로그아웃

**우선순위**: P0

**API**
- POST /api/v1/auth/logout
- 인증: 필요 (JWT)

**응답 (200 OK)**
```json
{ "message": "로그아웃되었습니다" }
```

### AUTH-005: 비밀번호 변경

**우선순위**: P1

**API**
- PATCH /api/v1/auth/password
- 인증: 필요 (JWT)

**실패 케이스**

|------|------|--------|
| 현재 비밀번호 불일치 | 401 | "현재 비밀번호가 올바르지 않습니다" |
| 새 비밀번호 규칙 미충족 | 400 | "비밀번호 규칙을 충족하지 않습니다" |

## 게시판 관리 (BOARD)

### BOARD-001: 게시판 목록 조회

**우선순위**: P0

**API**
- GET /api/v1/boards
- 인증: 불필요

**응답 (200 OK)**
```json
{
  "boards": [
    {
      "id": 1,
      "name": "자유게시판",
      "type": "FREE",
      "description": "자유롭게 이야기하는 공간",
      "postCount": 142,
      "isActive": true
    }
  ]
}
```

---

### BOARD-002: 게시판 단건 조회

**API**
- GET /api/v1/boards/:boardId
- 인증: 불필요

**실패 케이스**
- 미존재 boardId: 404 "게시판을 찾을 수 없습니다"
- 비활성 게시판: 404 "게시판을 찾을 수 없습니다"

---

### BOARD-003: 게시판 생성 (ADMIN)

**우선순위**: P0

**API**
- POST /api/v1/boards
- 인증: ADMIN 전용

**요청**
```json
{
  "name": "string (최대 50자)",
  "type": "GENERAL|GALLERY|VIDEO|QNA|NOTICE|FAQ|PRIVATE|FREE",
  "description": "string (최대 200자, 선택)"
}
```

**실패 케이스**
| 상황 | 코드 | 메시지 |
|------|------|--------|
| 권한 없음 (USER) | 403 | "권한이 없습니다" |
| 이름 중복 | 409 | "이미 존재하는 게시판 이름입니다" |
| 잘못된 type | 400 | "올바른 게시판 타입이 아닙니다" |

---

## 게시물 (POST)

### POST-001: 게시물 목록 조회

**우선순위**: P0

**API**
- GET /api/v1/boards/:boardId/posts
- 인증: 불필요 (PRIVATE 게시판 제외)
- Query: page (기본 1), limit (기본 20, 최대 100), sort (createdAt|viewCount)

**응답 (200 OK)**
```json
{
  "posts": [
    {
      "id": 1,
      "title": "게시물 제목",
      "author": { "id": 1, "username": "홍길동" },
      "viewCount": 42,
      "commentCount": 5,
      "isPinned": false,
      "isAnonymous": false,
      "thumbnailUrl": "/uploads/thumbs/uuid.jpg",
      "createdAt": "2025-06-05T00:00:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 142,
    "totalPages": 8
  }
}
```

**게시판 타입별 특수 동작**
- PRIVATE: 비로그인 → 403. 로그인 사용자 → 본인 글만 내용 표시
- FREE: isAnonymous=true이면 author.username → "익명"
- NOTICE: isPinned=true인 게시물 항상 최상단
- GALLERY: thumbnailUrl 필수 응답

### POST-003: 게시물 작성

**우선순위**: P0

**API**
- POST /api/v1/posts
- 인증: USER 이상 (NOTICE는 ADMIN만)

**요청 (multipart/form-data)**
```
boardId: number
title: string (1~200자)

```

**성공 응답 (201 Created)**
```json
{
  "id": 1,
  "title": "게시물 제목",
  "content": "내용",
  "boardId": 1,
  "author": { "id": 1, "username": "홍길동" },
  "files": [],
  "createdAt": "2025-06-05T00:00:00.000Z"
}
```

**실패 케이스**
| 상황 | 코드 | 메시지 |
|------|------|--------|
| 미인증 | 401 | "로그인이 필요합니다" |
| NOTICE 게시판에 USER가 작성 | 403 | "공지 게시판은 관리자만 작성할 수 있습니다" |
| 제목 길이 초과 | 400 | "제목은 200자 이하여야 합니다" |
| 파일 10개 초과 | 400 | "파일은 최대 10개까지 첨부 가능합니다" |

## 6. PRD 품질 자가 검증 체크리스트 20항목

```
기본 구조
[ ] 01. 문서 버전과 상태(Draft/Review/Approved)가 명시되어 있다
[ ] 02. 프로젝트 개요가 2~3문장으로 명확하게 기술되어 있다
[ ] 03. 게시판 종류가 타입 코드와 함께 표로 정리되어 있다
[ ] 04. 사용자 역할이 명확하게 정의되어 있다
[ ] 05. 권한 매트릭스 표가 있다

기능 명세
[ ] 06. 모든 기능에 고유 ID가 부여되어 있다 (AUTH-001 형식)
[ ] 07. 모든 API에 HTTP 메서드와 경로가 명시되어 있다
[ ] 08. 요청 Body가 JSON 형식으로 명시되어 있다 (타입 포함)
[ ] 09. 성공 응답이 실제 JSON 예시와 함께 명시되어 있다
[ ] 10. 실패 케이스가 HTTP 상태 코드와 오류 메시지와 함께 명시되어 있다

성공 기준
[ ] 11. 각 기능에 테스트 가능한 성공 기준이 있다
[ ] 12. "잘 동작해야 한다" 같은 모호한 기준이 없다
[ ] 13. 수치 기반 성능 기준이 있다 (응답 시간 등)
[ ] 14. 엣지 케이스가 명시되어 있다

보안
[ ] 15. 각 API의 인증 요구사항이 명시되어 있다
[ ] 16. 비밀번호 처리 방법이 명시되어 있다
[ ] 17. XSS, SQL 인젝션 방지 방법이 언급되어 있다

비기능 요구사항
[ ] 18. 성능 목표가 수치로 명시되어 있다
[ ] 19. 보안 요구사항 섹션이 있다
[ ] 20. 가용성 및 접근성 요구사항이 있다
```
