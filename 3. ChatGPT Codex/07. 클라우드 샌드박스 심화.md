> **학습 목표**
> - OpenAI 클라우드 Ubuntu 22.04 샌드박스의 구조와 특성을 이해한다
> - 사전 설치된 도구 목록을 파악하고 추가 패키지 설치 방법을 익힌다
> - 환경 변수, 네트워크 접근 범위, 실행 시간 제한을 이해한다

## 1. OpenAI 클라우드 샌드박스 개요

ChatGPT Codex가 태스크를 실행하는 환경은 **OpenAI가 관리하는 클라우드의 격리된 Ubuntu 22.04 컨테이너**다. 각 태스크마다 새로운 샌드박스가 생성되고, 태스크 완료 후 삭제된다.

### 1.1 샌드박스 생명주기

```
태스크 시작
    │
    ▼
샌드박스 생성
(Ubuntu 22.04 컨테이너 초기화)
    │
    ▼
GitHub 레포지토리 클론
    │
    ▼
AGENTS.md 읽기
    │
    ▼
패키지 설치 (필요한 경우)
    │
    ▼
코드 실행·수정
    │
    ▼
빌드·테스트 실행
    │
    ▼
Git 커밋·Push
    │
    ▼
PR 생성
    │
    ▼
샌드박스 삭제
(모든 임시 파일 제거)
```

### 1.2 샌드박스 격리 수준

각 태스크의 샌드박스는 완전히 격리된다.

```
태스크 A 샌드박스               태스크 B 샌드박스
┌──────────────────┐           ┌──────────────────┐
│ 레포 클론        │           │ 레포 클론        │
│ /workspace/repo  │           │ /workspace/repo  │
│                  │           │                  │
│ 파일 시스템 독립  │           │ 파일 시스템 독립  │
│ 네트워크 독립     │           │ 네트워크 독립     │
│ 프로세스 독립     │           │ 프로세스 독립     │
└──────────────────┘           └──────────────────┘
       │                              │
       │ (공유 없음)                   │
       └──────────────────────────────┘
```

두 태스크가 동시에 실행되더라도 서로의 파일이나 프로세스에 영향을 주지 않는다.

## 3. 패키지 설치 방법

### 3.1 npm/pnpm 패키지 설치

태스크에서 새 npm 패키지가 필요한 경우, Codex가 자동으로 설치한다.

```bash
# 샌드박스 내 자동 실행 예시
cd /workspace/board-hub
pnpm install  # 기존 package.json 의존성 설치

# 새 패키지 추가 (태스크에서 명시한 경우)
cd apps/backend
pnpm add sharp       # 이미지 처리
pnpm add @nestjs/jwt # JWT
pnpm add -D @types/multer  # 타입 정의 (개발 의존성)
```

### 3.2 태스크에서 패키지 명시하기

필요한 패키지를 명시적으로 지정하면 에이전트가 정확한 패키지를 설치한다.

```
"이미지 썸네일 생성 기능을 구현해줘.

[필요한 패키지]
- sharp@latest (이미지 리사이즈)
- @types/sharp (TypeScript 타입)

위 패키지를 apps/backend에 설치 후 구현을 시작해줘."
```

### 3.3 시스템 패키지 설치 (apt)

특정 시스템 도구가 필요한 경우:

```bash
# 샌드박스는 root 권한으로 실행되므로 sudo 없이 apt-get 사용 가능
apt-get install -y ffmpeg     # 동영상 처리
apt-get install -y imagemagick  # 이미지 처리
apt-get install -y postgresql  # PostgreSQL 서버
```

태스크 지시문에서:
```
"동영상 스트리밍 기능을 구현해줘.
ffmpeg가 필요하다. 샌드박스에 설치 후 진행해줘."
```

## 4. 파일 시스템 구조

### 4.1 샌드박스 내 파일 시스템

```
/workspace/
├── [레포이름]/          ← GitHub에서 클론된 레포
│   ├── AGENTS.md
│   ├── apps/
│   └── ...
/tmp/                    ← 임시 파일 (태스크 종료 시 삭제)
/home/user/             ← 홈 디렉토리
```

### 4.2 업로드 파일 처리

파일 업로드 기능을 개발할 때 샌드박스 내 임시 저장 경로를 고려해야 한다.

```bash
# 개발 환경에서 파일 저장 경로
/workspace/board-hub/uploads/originals/  # 원본 파일
/workspace/board-hub/uploads/thumbs/     # 썸네일
```

```markdown
## 파일 업로드 설정 (AGENTS.md)

### 로컬 개발 환경
파일 저장 경로: ./uploads/ (레포 루트 기준)
.gitignore에 /uploads/ 추가 필요

### 프로덕션 환경
파일 저장: AWS S3 또는 외부 스토리지
환경 변수: STORAGE_TYPE=local|s3
```

## 5. 환경 변수 설정

### 5.1 .env 파일 관리

샌드박스는 GitHub 레포지토리를 클론하므로, `.env` 파일이 `.gitignore`에 있으면 없는 상태로 시작한다.

**올바른 접근**:

```bash
# 레포에 .env.example 파일 포함
DATABASE_URL=postgresql://user:password@localhost:5432/board_hub
JWT_SECRET=your-jwt-secret-here
REDIS_URL=redis://localhost:6379
PORT=3000
```

AGENTS.md에 환경 변수 설정 방법을 명시:

```markdown
## 환경 변수 설정 (AGENTS.md)

### 테스트 실행 시
테스트 환경 변수는 .env.test 파일 또는 
jest.config.ts의 testEnvironment 설정으로 제공한다.

테스트용 기본값:
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/board_hub_test
JWT_SECRET=test-secret-key-minimum-32-characters
REDIS_URL=redis://localhost:6379

### 빌드 시
빌드에는 실제 DB 연결이 불필요하므로 더미 값 사용 가능:
DATABASE_URL=postgresql://dummy:dummy@localhost:5432/dummy
JWT_SECRET=build-time-dummy-secret-key-32chars
```

### 5.2 GitHub Secrets 활용

Codex 샌드박스에서 실제 외부 서비스 연결이 필요한 경우, GitHub Secrets를 통해 환경 변수를 제공한다.

```yaml
# .github/workflows/ci.yml
env:
  DATABASE_URL: ${{ secrets.DATABASE_URL_TEST }}
  JWT_SECRET: ${{ secrets.JWT_SECRET_TEST }}
```

단, GitHub Actions CI와 Codex 샌드박스는 별개의 환경이다. Codex 샌드박스에 직접 Secrets를 주입하는 방법은 현재(2025.06) 제한적이므로, 테스트는 로컬 PostgreSQL을 샌드박스 내에서 실행하는 방식을 사용한다.

```typescript
// 이메일 발송 서비스 Mock 예시
jest.mock('../mail/mail.service', () => ({
  MailService: jest.fn().mockImplementation(() => ({
    sendVerificationEmail: jest.fn().mockResolvedValue(undefined),
    sendPasswordResetEmail: jest.fn().mockResolvedValue(undefined),
  })),
}));
```

```markdown
## 외부 서비스 Mock (AGENTS.md)

- MailService: 이메일 발송
- S3Service: 파일 업로드
- SmsService: SMS 발송
외부 서비스에 실제로 요청을 보내는 테스트 작성 금지.

## 7. 샌드박스 실행 시간 제한

### 7.1 타임아웃 기준

Codex 태스크에는 최대 실행 시간 제한이 있다. 2025.06 기준으로 태스크당 약 **30분**의 실행 시간이 제공된다. (OpenAI 정책에 따라 변경될 수 있다)

### 7.2 시간 초과 방지 전략

**전략 1: 태스크 분할**

30분 안에 완료되지 않을 것 같으면 태스크를 분할한다.

```
❌ 너무 큰 태스크:
"백엔드 전체 (auth, board, post, comment, file) 구현"
→ 30분 초과 가능

✅ 적절한 크기:
"auth 모듈만 구현"
"board 모듈만 구현"
"post 모듈만 구현"
→ 각각 10~15분 완료 가능
```

**전략 2: 의존성 미리 설치 안내**

```
"의존성 설치 시간을 줄이기 위해 package.json에 이미 다음 패키지가 
포함되어 있다고 가정하고 작업해줘.
실제 pnpm install은 실행하지 않아도 된다 (이미 완료됨)."
```

**전략 3: 테스트 범위 조정**

```
"이번 태스크에서는 핵심 단위 테스트 5개만 작성해줘.
E2E 테스트는 별도 태스크로 작성할 예정이야."
```

## 8. 데이터베이스 설정 (샌드박스 내)

### 8.1 샌드박스에서 PostgreSQL 실행하기

Codex 샌드박스 내에서 PostgreSQL을 직접 실행하여 테스트할 수 있다.

태스크 지시문:
```
"테스트 전에 샌드박스 내에서 PostgreSQL을 시작하고
테스트용 데이터베이스를 생성해줘.

명령어:
service postgresql start  # 샌드박스는 root 권한으로 실행되므로 sudo 불필요
createdb -U postgres board_hub_test
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/board_hub_test"
```

AGENTS.md에 명시:
```markdown
## 테스트 데이터베이스 설정 (AGENTS.md)

### 샌드박스 내 PostgreSQL 사용

테스트 실행 전:
1. service postgresql start (또는 pg_ctlcluster 16 main start)
2. psql -U postgres -c "CREATE DATABASE board_hub_test;"
3. DATABASE_URL을 설정하고 pnpm prisma migrate deploy 실행

테스트용 환경 변수:
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/board_hub_test
JWT_SECRET=test-secret-key-must-be-32-chars-minimum
PORT=3001
```

### 8.2 board-hub PostgreSQL 16 테스트 DB 전체 설정

**AGENTS.md에 추가할 테스트 DB 설정**:

```markdown
## PostgreSQL 16 테스트 환경 (AGENTS.md)

### 샌드박스 초기화 스크립트

```bash
#!/bin/bash
# test-db-setup.sh

# PostgreSQL 서비스 시작
pg_ctlcluster 16 main start 2>/dev/null || service postgresql start

# 테스트 DB 생성 (이미 있으면 무시)
psql -U postgres -tc "SELECT 1 FROM pg_database WHERE datname='board_hub_test'" | \
  grep -q 1 || psql -U postgres -c "CREATE DATABASE board_hub_test;"

# Prisma 마이그레이션 실행
cd apps/backend
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/board_hub_test \
  pnpm prisma migrate deploy

echo "테스트 DB 준비 완료"
```

### jest.config.ts 설정

```typescript
// apps/backend/jest.config.ts
export default {
  moduleFileExtensions: ['js', 'json', 'ts'],
  rootDir: 'src',
  testRegex: '.*\\.spec\\.ts$',
  transform: {
    '^.+\\.(t|j)s$': 'ts-jest',
  },
  globalSetup: './test/global-setup.ts',
  testEnvironment: 'node',
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/$1',
  },
};
```

### test/global-setup.ts

```typescript
import { execSync } from 'child_process';

export default async function globalSetup() {
  process.env.DATABASE_URL = 
    'postgresql://postgres:postgres@localhost:5432/board_hub_test';
  process.env.JWT_SECRET = 'test-secret-key-minimum-32-chars';
  
  // PostgreSQL 시작
  try {
    execSync('pg_ctlcluster 16 main start', { stdio: 'ignore' });
  } catch {
    // 이미 실행 중
  }
  
  // DB 생성 및 마이그레이션
  execSync('pnpm prisma migrate deploy', { 
    cwd: process.cwd(),
    env: { ...process.env }
  });
}
```
```

### 8.3 Prisma 마이그레이션 샌드박스 전략

```markdown
## Prisma 마이그레이션 전략 (AGENTS.md)

### 개발 환경 (로컬)
pnpm prisma migrate dev --name [migration-name]
→ 새 마이그레이션 파일 생성 + DB 적용

### 샌드박스 환경 (CI/Codex)
pnpm prisma migrate deploy
→ 기존 마이그레이션 파일만 적용 (새 생성 없음)

### 마이그레이션 파일 위치
prisma/migrations/[타임스탬프]_[이름]/migration.sql

### 주의
샌드박스에서 prisma migrate dev를 실행하면 새 마이그레이션이
생성되어 레포에 포함된다. 의도된 스키마 변경인지 확인 필요.

## 9. 샌드박스 vs 로컬 환경 차이 극복

### 9.1 주요 차이점

```
┌─────────────────────┬──────────────────┬──────────────────┐
│       항목           │    로컬 환경      │  Codex 샌드박스  │
├─────────────────────┼──────────────────┼──────────────────┤

### 9.2 파일 경로 문제

Windows 로컬 환경에서 작성된 코드에 `\` 경로 구분자가 있으면 샌드박스에서 오류가 발생한다.

```typescript
// ❌ Windows 경로 (샌드박스에서 오류)
const uploadDir = 'uploads\\originals';

// ✅ cross-platform (path.join 사용)
import * as path from 'path';
const uploadDir = path.join('uploads', 'originals');
```

AGENTS.md에 명시:
```markdown
## 파일 경로 규칙 (AGENTS.md)

파일 경로는 반드시 path.join() 또는 path.resolve()를 사용한다.
직접 경로 문자열 조합 금지 (Windows ↔ Linux 호환성 문제).
```

### 9.3 줄 끝 문자 (CRLF vs LF)

Windows에서 개발하면 줄 끝이 CRLF(\r\n)이고, 샌드박스(Linux)는 LF(\n)를 사용한다.

```bash
# .gitattributes 설정으로 자동 변환
* text=auto eol=lf
*.sh text eol=lf
```

### 9.4 case-sensitive 파일 시스템

macOS는 기본적으로 대소문자를 구분하지 않지만, Linux(샌드박스)는 구분한다.

```typescript
// ❌ macOS에서는 동작, Linux(샌드박스)에서는 오류
import { UserService } from './userService';  // 실제 파일명: user.service.ts

// ✅ 정확한 파일명 사용
import { UserService } from './user.service';
```

## 11. 실전: board-hub PostgreSQL 16 완전 설정

### 11.1 docker-compose.yml 작성 (로컬 개발용)

```yaml
# docker-compose.yml
services:
  postgres:
    image: postgres:16-alpine
    container_name: board-hub-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: boardhub
      POSTGRES_PASSWORD: boardhub_password
      POSTGRES_DB: board_hub
    volumes:
      - postgres_data:/var/lib/postgresql/data
      - ./docker/postgres/init.sql:/docker-entrypoint-initdb.d/init.sql
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U boardhub -d board_hub"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    container_name: board-hub-redis
    restart: unless-stopped
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

volumes:
  postgres_data:
  redis_data:
```
