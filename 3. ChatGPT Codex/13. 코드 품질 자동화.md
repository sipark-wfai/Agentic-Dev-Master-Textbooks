## 1. Codex를 품질 자동화 도구로 활용하기

### 2.2 실제 생성될 테스트 코드 예시

```typescript
// apps/backend/src/auth/auth.service.spec.ts

import { Test, TestingModule } from '@nestjs/testing';
import { ConflictException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import { AuthService } from './auth.service';
import { UserService } from '../user/user.service';

describe('AuthService', () => {
  let service: AuthService;
  let userService: jest.Mocked<UserService>;
  let jwtService: jest.Mocked<JwtService>;

  const mockUser = {
    id: 1,
    email: 'test@example.com',
    password: '$2b$12$hashedpassword',
    username: '테스트유저',
    role: 'USER' as const,
    createdAt: new Date(),
    updatedAt: new Date(),
    deletedAt: null,
  };

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      providers: [
        AuthService,
        {
          provide: UserService,
          useValue: {
            create: jest.fn(),
            findByEmailWithPassword: jest.fn(),
            findById: jest.fn(),
          },
        },
        {
          provide: JwtService,
          useValue: {
            signAsync: jest.fn(),
          },
        },
      ],
    }).compile();

    service = module.get<AuthService>(AuthService);
    userService = module.get(UserService);
    jwtService = module.get(JwtService);
  });

  afterEach(() => {
    jest.clearAllMocks();
  });

  describe('register', () => {
    it('정상 회원가입: User 객체를 반환한다 (password 제외)', async () => {
      const { password, ...userWithoutPassword } = mockUser;
      userService.create.mockResolvedValue(userWithoutPassword);

      const result = await service.register({
        email: 'test@example.com',
        password: 'Test1234!',
        username: '테스트유저',
      });

      expect(result.user).toEqual(userWithoutPassword);
      expect(result.user).not.toHaveProperty('password');
      expect(userService.create).toHaveBeenCalledWith(
        'test@example.com',
        'Test1234!',
        '테스트유저',
      );
    });

    it('이메일 중복: ConflictException을 발생시킨다', async () => {
      userService.create.mockRejectedValue(
        new ConflictException('이미 사용 중인 이메일입니다'),
      );

      await expect(
        service.register({
          email: 'existing@example.com',
          password: 'Test1234!',
          username: '새유저',
        }),
      ).rejects.toThrow(ConflictException);
    });
  });

  describe('validateUser', () => {
    it('올바른 자격증명: User 객체를 반환한다', async () => {
      userService.findByEmailWithPassword.mockResolvedValue(mockUser);
      jest.spyOn(bcrypt, 'compare').mockResolvedValue(true as never);

      const result = await service.validateUser(
        'test@example.com',
        'Test1234!',
      );

      expect(result).not.toBeNull();
      expect(result).not.toHaveProperty('password');
    });

    it('이메일 미존재: null을 반환한다', async () => {
      userService.findByEmailWithPassword.mockResolvedValue(null);

      const result = await service.validateUser(
        'nonexistent@example.com',
        'Test1234!',
      );

      expect(result).toBeNull();
    });

    it('비밀번호 불일치: null을 반환한다', async () => {
      userService.findByEmailWithPassword.mockResolvedValue(mockUser);
      jest.spyOn(bcrypt, 'compare').mockResolvedValue(false as never);

      const result = await service.validateUser(
        'test@example.com',
        'WrongPassword!',
      );

      expect(result).toBeNull();
    });
  });

  describe('login', () => {
    it('정상 로그인: accessToken을 포함한 응답을 반환한다', async () => {
      const { password, ...userWithoutPassword } = mockUser;
      jwtService.signAsync.mockResolvedValue('jwt-token');

      const result = await service.login(userWithoutPassword);

      expect(result.accessToken).toBe('jwt-token');
      expect(jwtService.signAsync).toHaveBeenCalledWith({
        sub: mockUser.id,
        email: mockUser.email,
        role: mockUser.role,
      });
    });
  });
});
```

## 5. 코드 리뷰 자동화

### 5.1 PR 자동 리뷰 태스크

```
"PR #[번호]의 코드를 리뷰해줘.

[리뷰 관점]

1. TypeScript 타입 안전성 (Critical)
   - any 타입 사용 여부
   - 타입 단언(!!)의 적절성
   - 타입 가드 필요 여부

2. 보안 (Critical)
   - SQL 인젝션 가능성 (Prisma.$queryRaw 오용)
   - 인증/인가 누락
   - 민감 데이터 로깅

3. NestJS 패턴 (Warning)
   - Controller→Service→Repository 레이어 준수
   - Exception 클래스 올바른 사용
   - DTO 검증 완전성

4. Prisma 패턴 (Warning)
   - N+1 쿼리 문제 (select/include 사용 확인)
   - 트랜잭션 누락 (여러 쿼리가 원자적이어야 하는 경우)

5. 성능 (Info)
   - 불필요한 데이터 로드
   - 인덱스 미사용 쿼리

[보고 형식]
파일명:줄번호 | 심각도 | 문제 | 권장 해결책

코드는 수정하지 말고 리뷰만 제출해줘.
GitHub PR 코멘트로 각 줄에 직접 달아줘."
```

### 5.2 보안 취약점 스캔 태스크

```
"apps/backend/src/ 전체의 보안 취약점을 스캔해줘.

[스캔 항목]
1. 인증 누락: JwtGuard가 없는 POST/PATCH/DELETE 엔드포인트
2. 인가 누락: ADMIN 전용 기능에 RolesGuard 없음
3. SQL 인젝션: Prisma.$queryRaw 사용 시 Prisma.sql 태그 미사용
4. XSS: 사용자 입력을 HTML로 직접 렌더링
5. 민감 데이터: 비밀번호, JWT 등을 Logger.log로 출력
6. IDOR: 본인 확인 없이 타인 리소스 수정 가능
7. Rate Limiting: 인증 엔드포인트에 제한 없음
8. 파일 업로드: MIME 타입 검증 미흡

[발견 시 조치]
Critical 항목은 즉시 수정하고 PR 생성.
Warning 이하는 리포트만 작성."
```

## 6. 리팩터링 태스크

### 6.1 중복 코드 제거

```
"apps/backend/src/post/post.service.ts와
apps/backend/src/comment/comment.service.ts에
중복되는 권한 확인 로직이 있어.

[중복 패턴]
두 서비스 모두 '본인 또는 ADMIN'을 확인하는 코드:
if (resource.authorId !== userId && userRole !== 'ADMIN') {
  throw new ForbiddenException('...');
}

[리팩터링]
1. apps/backend/src/common/utils/auth.util.ts 파일 생성
2. checkOwnerOrAdmin(authorId, userId, role) 유틸 함수 작성
3. post.service.ts, comment.service.ts에서 유틸 함수 사용
4. 기존 테스트 모두 통과 유지

중복이 있는 다른 패턴도 동일하게 처리해줘.
기능 변경은 없어야 함."
```

### 6.2 타입 강화 리팩터링

```
"apps/backend/src/ 전체에서 타입 안전성을 강화해줘.

[문제 패턴]
1. 암시적 any: (item: any) => ... 형식의 함수
2. 타입 단언 남용: as SomeType
3. 반환 타입 미명시: async function getUser() { return ... }

[수정 방향]
1. 암시적 any → 구체적 타입 또는 unknown + 타입 가드
2. 타입 단언 → 타입 가드 함수로 교체
3. 모든 public 메서드에 반환 타입 명시

[검증]
pnpm -r exec tsc --noEmit 후 에러 없어야 함
기존 테스트 모두 통과 유지"
```

## 7. GitHub Actions CI/CD 파이프라인

### 7.1 완전한 CI 파이프라인

```yaml
# .github/workflows/ci.yml
name: CI Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

env:
  NODE_VERSION: '20'
  PNPM_VERSION: '9'

jobs:
  # ==================== 변경 감지 ====================
  detect-changes:
    runs-on: ubuntu-latest
    outputs:
      backend: ${{ steps.filter.outputs.backend }}
      frontend: ${{ steps.filter.outputs.frontend }}
      shared: ${{ steps.filter.outputs.shared }}
    steps:
      - uses: actions/checkout@v4
      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            backend:
              - 'apps/backend/**'
              - 'prisma/**'
              - 'packages/shared/**'
            frontend:
              - 'apps/frontend/**'
              - 'packages/shared/**'
            shared:
              - 'packages/shared/**'

  # ==================== 백엔드 CI ====================
  backend-ci:
    needs: detect-changes
    if: needs.detect-changes.outputs.backend == 'true' || github.event_name == 'push'
    runs-on: ubuntu-latest

    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: board_hub_test
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
        ports:
          - 5432:5432

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v3
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Type check
        run: pnpm -r --filter backend exec tsc --noEmit

      - name: Lint
        run: pnpm --filter backend lint

      - name: Prisma generate
        run: pnpm --filter backend prisma generate
        env:
          DATABASE_URL: postgresql://postgres:postgres@localhost:5432/board_hub_test

      - name: Run migrations
        run: pnpm --filter backend prisma migrate deploy
        env:
          DATABASE_URL: postgresql://postgres:postgres@localhost:5432/board_hub_test

      - name: Build
        run: pnpm --filter backend build

      - name: Unit tests
        run: pnpm --filter backend test --coverage
        env:
          DATABASE_URL: postgresql://postgres:postgres@localhost:5432/board_hub_test
          JWT_SECRET: test-secret-key-32-characters-min

      - name: E2E tests
        run: pnpm --filter backend test:e2e
        env:
          DATABASE_URL: postgresql://postgres:postgres@localhost:5432/board_hub_test
          JWT_SECRET: test-secret-key-32-characters-min
          PORT: 3001

      - name: Upload coverage
        uses: codecov/codecov-action@v4
        with:
          files: ./apps/backend/coverage/lcov.info
          flags: backend
          token: ${{ secrets.CODECOV_TOKEN }}

  # ==================== 프론트엔드 CI ====================
  frontend-ci:
    needs: detect-changes
    if: needs.detect-changes.outputs.frontend == 'true' || github.event_name == 'push'
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v3
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Type check
        run: pnpm --filter frontend check

      - name: Lint
        run: pnpm --filter frontend lint

      - name: Build
        run: pnpm --filter frontend build

  # ==================== 보안 스캔 ====================
  security-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run npm audit
        run: pnpm audit --audit-level=high
        continue-on-error: true

      - name: OWASP Dependency Check
        uses: dependency-check/Dependency-Check_Action@main
        with:
          project: 'board-hub'
          path: '.'
          format: 'HTML'
        continue-on-error: true
```

### 7.2 자동 배포 파이프라인

```yaml
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    branches: [ main ]

jobs:
  deploy-backend:
    runs-on: ubuntu-latest
    needs: [backend-ci]  # CI 통과 후에만 배포
    
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to Render
        uses: johnbeynon/render-deploy-action@v0.0.8
        with:
          service-id: ${{ secrets.RENDER_SERVICE_ID }}
          api-key: ${{ secrets.RENDER_API_KEY }}

  deploy-frontend:
    runs-on: ubuntu-latest
```

```
월간 루틴:
문서화 업데이트 (API.md, README.md)

접근성 검사
```
