### 마일스톤 2: 인증 모듈

**태스크 2-1: 회원가입**

```
"GitHub Issue #5를 해결해줘.

docs/PRD.md의 AUTH-001을 읽고 회원가입 기능을 구현해줘.

[구현 위치]
apps/backend/src/auth/ 및 apps/backend/src/user/

[파일 구성]
- auth/auth.module.ts
- auth/auth.controller.ts
- auth/auth.service.ts
- auth/dto/register.dto.ts
- user/user.module.ts
- user/user.service.ts
- user/user.repository.ts (선택)

[register.dto.ts]
class RegisterDto {
  @IsEmail() @MaxLength(255)
  email: string;
  
  @IsString() @MinLength(8)
  @Matches(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])/, {
    message: '비밀번호는 대소문자, 숫자, 특수문자를 포함해야 합니다'
  })
  password: string;
  
  @IsString() @MinLength(2) @MaxLength(20)
  @Matches(/^[a-zA-Z0-9가-힣_]+$/)
  username: string;
}

[AuthService.register]
1. 이메일 중복 확인
2. 사용자명 중복 확인
3. bcrypt.hash(password, 12) 해싱
4. User 생성 (role: USER 기본값)
5. 비밀번호 제외하고 응답

[성공 기준]
- 정상 회원가입 → 201 + user 객체 (password 제외)
- 이메일 중복 → 409
- 비밀번호 규칙 위반 → 400
- 단위 테스트: register() 메서드 3개 이상
- 빌드 + 테스트 통과
- Closes #5"
```

## 4. PR 검토·승인·머지 프로세스

### 4.1 PR 검토 순서

```
1. CI 통과 여부 확인
   - GitHub Actions 빌드·테스트 통과 ✅
   - 린트 오류 없음 ✅

2. 변경 파일 스캔 (5분)
   - 의도된 파일만 수정되었는가?
   - 불필요한 파일 변경은 없는가?

3. 핵심 로직 리뷰 (10분)
   - 비즈니스 로직이 PRD와 일치하는가?
   - 보안 취약점이 없는가?
   - 에러 처리가 적절한가?

4. 테스트 리뷰 (5분)
   - 테스트가 실제 동작을 검증하는가?
   - 성공 케이스와 실패 케이스가 모두 있는가?

5. 승인 또는 수정 요청
   - 승인 → Merge
   - 수정 → 코멘트 작성 → Codex 재태스크
```

### 4.2 수정 요청 시 재태스크 패턴

```
PR 코멘트에서 발견한 문제:
"line 45: bcrypt.compare가 await 없이 호출됨"

Codex 재태스크:
"PR #6의 auth.service.ts line 45에서
await 없이 bcrypt.compare를 호출하고 있어.
async 함수 내에서 await bcrypt.compare(...)로 수정해줘.
다른 파일은 수정하지 않는다."
```

### 4.3 머지 전략

```
Squash and Merge (권장):
- 여러 커밋을 하나로 합쳐서 clean한 히스토리 유지
- 커밋 메시지: "feat: [기능명] (#PR번호)"

Merge Commit:
- 모든 커밋을 보존
- 이력 추적이 중요한 경우

Rebase and Merge:
- 리베이스로 선형 히스토리 유지
- 충돌 해결이 복잡할 수 있음
```

## 7. 자주 발생하는 PRD → 코드 전환 실수

### 실수 1: PRD와 다른 API 경로 사용

```
PRD: POST /api/v1/auth/login
Codex 구현: POST /auth/login (api/v1 prefix 누락)

→ 방지: AGENTS.md에 "모든 API에 /api/v1 prefix 포함" 명시
→ 수정 태스크: "auth 컨트롤러의 경로에 /api/v1 prefix가 빠져 있어. 수정해줘."
```

### 실수 2: 응답 형식 불일치

```
PRD 응답: { user: { id, email, username, role } }
Codex 구현: { id, email, username, role } (user 래퍼 없음)

→ 방지: PRD에 응답 예시를 정확히 작성
→ 수정 태스크: "응답을 { user: {...} } 형식으로 감싸줘"
```

### 실수 3: 실패 케이스 누락

```
PRD: 5회 연속 실패 시 429 반환
Codex 구현: 5회 제한 없이 무한 시도 가능

→ 방지: 성공 기준에 실패 케이스를 테스트로 명시
→ 수정 태스크: "로그인 5회 연속 실패 시 429 반환 기능을 추가해줘"
```
