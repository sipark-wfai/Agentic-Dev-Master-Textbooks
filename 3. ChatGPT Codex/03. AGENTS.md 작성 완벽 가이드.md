# 03. AGENTS.md 작성 완벽 가이드 — Codex 에이전트의 헌법 만들기

> **학습 목표**
> - AGENTS.md의 역할과 중요성을 이해한다
> - Codex가 AGENTS.md를 읽고 활용하는 방식을 파악한다
> - 멀티 게시판 프로젝트를 위한 완성도 높은 AGENTS.md를 작성한다
> - 잘못 작성된 AGENTS.md와 올바른 AGENTS.md의 차이를 구별한다
> - 모노레포 환경에서 서브 디렉토리 AGENTS.md를 활용한다

---

## 1. AGENTS.md란 무엇인가

AGENTS.md는 **레포지토리 루트에 배치하는 에이전트 행동 지침서**다. Codex가 태스크를 시작할 때 가장 먼저 읽는 파일이며, 프로젝트의 기술 스택, 코딩 규칙, 빌드 명령어, 브랜치 전략 등을 정의한다.

비유하자면, AGENTS.md는 새로 입사한 개발자에게 주는 **온보딩 문서**다. "우리 팀은 TypeScript strict 모드를 씁니다", "PR 제목은 [feat/fix/refactor]로 시작해야 합니다", "빌드는 pnpm build로 합니다" 같은 정보가 담긴다.

Codex는 AGENTS.md가 없어도 작동하지만, 결과물의 품질이 크게 떨어진다. 마치 규칙을 모르는 신입 개발자가 코드를 짜는 것과 같다.

### 1.1 다른 에이전트 도구와의 비교

```
┌──────────────────┬────────────────┬─────────────────┐
│   에이전트 도구   │   규칙 파일명   │      위치        │
├──────────────────┼────────────────┼─────────────────┤
│ ChatGPT Codex    │ AGENTS.md      │ 레포 루트        │
│ Claude Code      │ CLAUDE.md      │ 레포 루트        │
│ Google Antigrav  │ GEMINI.md      │ 레포 루트        │
│ GitHub Copilot   │ .github/copilot-instructions.md│ .github 폴더    │
└──────────────────┴────────────────┴─────────────────┘
```

모두 비슷한 개념이지만 파일명과 문법이 다르다. Codex는 반드시 `AGENTS.md`를 읽는다.

### 1.2 Codex가 AGENTS.md를 읽는 시점

```
태스크 시작
    ↓
레포지토리 클론
    ↓
루트 AGENTS.md 읽기          ← 여기서 읽음
    ↓
서브 디렉토리 AGENTS.md 읽기  ← 해당 경로 작업 시
    ↓
태스크 실행 (규칙 적용됨)
    ↓
PR 생성
```

## 2. AGENTS.md 필수 섹션 구성

AGENTS.md는 자유 형식의 마크다운이지만, 다음 섹션이 반드시 포함되어야 한다.

### 2.1 프로젝트 개요 섹션

에이전트가 이 프로젝트가 무엇인지 즉시 파악할 수 있도록 간결하게 설명한다.

```markdown
## 프로젝트 개요
board-hub는 8종 게시판(일반·갤러리·동영상·Q&A·공지·FAQ·비공개문의·자유)을
지원하는 커뮤니티 플랫폼이다.

주요 기능:
- 사용자 인증 (JWT, 소셜 로그인)
- 게시판별 맞춤 기능 (썸네일, 동영상 스트리밍, 익명 등)
- 역할 기반 접근 제어 (ADMIN, USER, GUEST)
- 파일 업로드 (이미지, 동영상)
```

**잘못된 예시**:
```markdown
## 프로젝트
게시판 프로젝트입니다.
```

**올바른 예시**: 기능, 사용자 역할, 핵심 특징을 구체적으로 명시한다.

### 2.2 기술 스택 섹션

사용하는 모든 기술과 버전을 명시한다. 버전이 없으면 에이전트가 오래된 버전을 사용할 수 있다.

```markdown
## 기술 스택

### 프론트엔드
- SvelteKit 2.x (TypeScript strict)
- TailwindCSS 3.x
- Vite 5.x (번들러)

### 백엔드

- Passport.js 0.7.x (JWT 인증)
- class-validator 0.14.x
- class-transformer 0.5.x

### 데이터베이스

### 인프라 및 도구
```

### 2.3 코딩 컨벤션 섹션

코드 스타일과 규칙을 상세히 명시한다. 규칙이 많을수록 에이전트 결과물이 일관성을 갖는다.

```markdown
## 코딩 컨벤션

### TypeScript 규칙
- strict 모드 필수 (tsconfig.json의 "strict": true)
- any 타입 절대 금지 (eslint: @typescript-eslint/no-explicit-any: error)
- unknown 타입은 타입 가드와 함께 사용
- 모든 함수 매개변수와 반환 타입 명시

### 명명 규칙
- 변수·함수: camelCase (예: getUserById)
- 클래스: PascalCase (예: UserService)
- 상수: UPPER_SNAKE_CASE (예: MAX_FILE_SIZE)
- 파일명: kebab-case (예: user-service.ts)
- 데이터베이스 컬럼: snake_case (예: created_at)

### 함수 작성 규칙
- 모든 public 함수에 JSDoc 주석 필수
- 함수 길이 50줄 이하 권장
- 매개변수 3개 이상이면 객체로 묶기

### 비동기 처리
- async/await 사용 (Promise.then 체이닝 금지)
- 에러 처리: try-catch 또는 NestJS Exception Filter

### 금지 사항
- console.log 사용 금지 (Logger 서비스 사용)
- any 타입 사용 금지
- 하드코딩된 비밀번호, 토큰, URL 금지
- TODO 주석 없이 커밋 금지
```

### 2.7 금지 사항 섹션

명확한 금지 사항이 있으면 에이전트가 잘못된 패턴을 사용하지 않는다.

```markdown
## 절대 금지 사항

### 코드
- any 타입 사용 금지 → unknown + 타입 가드 사용
- console.log 사용 금지 → NestJS Logger 또는 winston 사용
- 하드코딩된 자격증명 금지 (비밀번호, API 키, JWT 시크릿)
- 테스트 없는 새 기능 구현 금지
- main 브랜치 직접 Push 금지

### 패턴
- Prisma.$queryRaw 사용 시 반드시 Prisma.sql 태그 사용 (SQL 인젝션 방지)
- 사용자 입력을 HTML에 직접 렌더링 금지 (XSS 방지)
- JWT 토큰을 LocalStorage에 저장 금지 (HttpOnly 쿠키 사용)
- 비밀번호 평문 저장 금지 (bcrypt 사용)

### 의존성
- 라이선스 불명확한 패키지 설치 금지
- deprecated 패키지 신규 설치 금지
```

```markdown
## 프로젝트 개요

board-hub는 8종 게시판(일반·갤러리·동영상·Q&A·공지·FAQ·비공개문의·자유)을
지원하는 커뮤니티 플랫폼이다.

### 게시판 종류
- 일반(GENERAL): 텍스트 중심 게시물
- 갤러리(GALLERY): 이미지 중심, 썸네일 자동 생성
- 동영상(VIDEO): 비디오 업로드·HLS 스트리밍
- Q&A(QNA): 질문·답변·채택(accepted_answer) 기능
- 공지(NOTICE): ADMIN만 작성, 상단 고정 가능
- FAQ(FAQ): 카테고리·태그 필터링
- 비공개문의(PRIVATE): 작성자·ADMIN만 열람
- 자유(FREE): 익명 선택 가능

### 사용자 역할
- ADMIN: 모든 게시판 관리, 사용자 관리
- USER: 가입 사용자, 게시물·댓글 작성 가능
- GUEST: 비로그인 사용자, 공개 게시물 읽기만 가능

## 코딩 컨벤션

### TypeScript
- strict 모드 필수
- any 타입 절대 금지
- 모든 함수 반환 타입 명시
- interface 우선 사용 (type은 유니온·교차 타입에만)

### 명명 규칙
- 변수·함수: camelCase
- 클래스·인터페이스·Enum: PascalCase
- 상수: UPPER_SNAKE_CASE
- 파일명: kebab-case
- DB 컬럼: snake_case

### NestJS 패턴
- Controller → Service → Repository 레이어 구분
- DTO에 class-validator 데코레이터 필수
- 모든 엔드포인트에 Swagger 데코레이터(@ApiOperation 등) 추가
- Guard, Interceptor, Filter는 모듈별 분리

### Prisma 패턴
- 트랜잭션: prisma.$transaction 사용
- Raw Query: Prisma.sql 태그 필수
- Soft Delete: deletedAt 컬럼 활용

### SvelteKit 패턴
- 서버사이드 로직: +page.server.ts (load, actions)
- 클라이언트 전용: +page.svelte
- API 통신: fetch (서버사이드) 또는 SvelteKit 내장 fetch
- 상태 관리: Svelte stores (writable, readable, derived)
```

## 5. 잘못 쓴 vs 올바른 AGENTS.md 비교

### 비교 1: 기술 스택 명세

**잘못된 예시** (버전 없음):
```markdown
## 기술 스택
- React
- Node.js
- MySQL
```

**올바른 예시** (버전 명시):
```markdown
## 기술 스택
- SvelteKit 2.x (TypeScript strict)
- NestJS 10.x
- PostgreSQL 16 + Prisma v5
- pnpm 9.x
```

버전이 없으면 에이전트가 최신 버전을 사용하거나 오래된 버전을 사용하여 호환성 문제가 발생한다.

### 비교 2: 빌드 명령어

**잘못된 예시** (명령어 없음):
```markdown
## 개발 환경
npm으로 개발합니다.
```

**올바른 예시** (명확한 명령어):
```markdown
## 명령어
- 설치: pnpm install
- 빌드: pnpm build (성공 여부 확인 필수)
- 테스트: pnpm test (실패 시 수정 후 재실행)
- 린트: pnpm lint
```

명령어가 없으면 에이전트가 npm 또는 yarn을 무작위로 사용하거나, 빌드 검증 없이 PR을 올릴 수 있다.

### 비교 3: 코딩 규칙

**잘못된 예시** (모호한 규칙):
```markdown
## 규칙
코드를 깔끔하게 작성해주세요.
```

**올바른 예시** (구체적인 규칙):
```markdown
## 코딩 규칙
- any 타입 절대 금지 (ESLint 오류로 처리됨)
- 모든 함수에 반환 타입 명시
- 함수명: 동사 + 명사 패턴 (getUserById, createPost)
- console.log 금지, Logger.log() 사용
```

### 비교 4: 금지 사항

**잘못된 예시** (금지 사항 없음):
```markdown
보안을 신경써서 개발해주세요.
```

**올바른 예시** (명확한 금지 목록):
```markdown
## 절대 금지
- 비밀번호 평문 저장 (bcrypt 필수)
```

## 7. AGENTS.md 작성 팁

### 7.1 구체적일수록 좋다

애매한 설명보다 구체적인 규칙이 훨씬 효과적이다.

```
❌ "보안에 신경쓰세요"
✅ "비밀번호는 bcrypt salt rounds 12로 해싱하고, JWT는 HttpOnly Secure 쿠키에 저장하세요"

❌ "깔끔한 코드를 작성하세요"
✅ "함수는 50줄 이하, 매개변수는 3개 이하, JSDoc 주석 필수"
```

### 7.2 예시를 포함한다

규칙에 예시가 있으면 에이전트가 의도를 더 잘 파악한다.

```markdown
## 에러 메시지 형식

에러 메시지는 다음 형식을 따른다:

올바른 예:
throw new NotFoundException('게시물을 찾을 수 없습니다');
throw new BadRequestException('제목은 100자 이하여야 합니다');

잘못된 예:
throw new Error('error');
throw new Error('not found');
```

### 7.3 AGENTS.md를 살아있는 문서로 유지한다

프로젝트가 진행되면서 AGENTS.md도 업데이트한다.

- 새 패키지를 추가하면 기술 스택 섹션을 업데이트한다
- 새 코딩 규칙이 생기면 추가한다
- 반복되는 실수 패턴을 발견하면 금지 사항에 추가한다

### 7.4 Codex에게 AGENTS.md 작성을 도움받는다

아이러니하게도 Codex 자신에게 AGENTS.md 초안 작성을 요청할 수 있다.

```
ChatGPT (일반 대화)에서:

기술 스택:
- 프론트엔드: SvelteKit 2.x
- 백엔드: NestJS 10.x
- DB: PostgreSQL 16 + Prisma v5
- 패키지 매니저: pnpm

프로젝트: 멀티 게시판 허브

ChatGPT Codex 에이전트가 이 파일을 읽고 일관된 코드를 생성할 수 있도록
```
