## 1. 고수의 작업 루틴

초보자와 고수를 가르는 가장 큰 차이는 **세션을 어떻게 설계하느냐**다. 고수는 에이전트를 시작하기 전에 이미 절반의 작업을 끝낸다.

### 1.1 고수의 하루 작업 루틴

```
[오전 - 설계 시간]
1. 오늘 구현할 기능을 CLAUDE.md에 TODO로 추가
2. 관련 PRD/ERD 섹션을 확인하고 불명확한 부분 해소
3. 구현할 파일 목록과 순서를 미리 정리

[오후 - 구현 시간]
4. Git 체크포인트 커밋 (작업 시작 전)
5. 명확한 지시문으로 Claude Code 실행
6. 에이전트 작업 중 병렬로 코드 리뷰 진행
7. 생성된 코드 검토 후 테스트 실행
8. 다음 마일스톤 계획 수립

[저녁 - 정리 시간]
9. /cost (API 사용자) 또는 /stats (Pro/Max 구독자)로 오늘 사용량 확인 <!-- R5: /cost는 API 사용자, /stats는 구독자 -->
10. CLAUDE.md 업데이트 (발견된 패턴, 새 규칙)
11. Git 커밋으로 마무리
```

### 1.2 마일스톤 관리 전략

```markdown

## 2. 토큰 비용 최소화 전략

### 2.1 컨텍스트 슬림화 기법

**기법 1: 필요한 파일만 참조**

```
나쁜 예 (토큰 낭비):
> @src/ 전체를 분석하고 posts 모듈을 개선해줘

좋은 예 (토큰 절약):
> @src/posts/posts.service.ts 와 @prisma/schema.prisma 만 읽고

**기법 2: 작업 범위 명시적 제한**

```
"최소한의 변경만 해줘. 필요한 파일 외에는 수정하지 않는다."
"새 파일 생성 없이 기존 파일만 수정해줘."
```

**기법 3: 요약 요청 활용**

```

```

cat > scripts/pr-review.sh << 'ENDSCRIPT'
#!/bin/bash
# GitHub Actions 또는 로컬에서 PR 코드 리뷰

CHANGED_FILES=$(git diff --name-only origin/main...HEAD | grep -E "\.(ts|svelte)$")

if [ -z "$CHANGED_FILES" ]; then
  echo "변경된 TypeScript/Svelte 파일이 없습니다."
  exit 0
fi

echo "변경된 파일: $CHANGED_FILES"
echo ""

claude --print \  # R3 수정: --headless 옵션 제거 (Claude Code CLI에 미존재). --print 단독 사용
  "다음 파일들을 PR 코드 리뷰해줘:
   $CHANGED_FILES

   1. CLAUDE.md 규칙 위반 여부 (any 타입, console.log 등)
   2. 보안 취약점 (SQL Injection, XSS, 인증 누락)
   3. 성능 이슈 (N+1 쿼리, 불필요한 전체 조회)
   4. 에러 처리 누락
   5. 테스트 커버리지 부족
   
   각 항목을 Severity(critical/major/minor)와 함께 JSON 형식으로 출력해줘." \
> pr-review-$(date '+%Y%m%d-%H%M').json

echo "리뷰 완료: pr-review-*.json 파일 확인"
ENDSCRIPT
chmod +x scripts/pr-review.sh

## 4. Claude Code 확장 활용

### 4.1 GitHub Actions + Claude Code Headless Mode

```yaml
# .github/workflows/claude-review.yml
name: Claude Code Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  code-review:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # 전체 히스토리 필요
      
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      
      - name: Install Claude Code
        run: npm install -g @anthropic-ai/claude-code
      
      - name: Get Changed Files
        id: changed-files
        run: |
          CHANGED=$(git diff --name-only origin/${{ github.base_ref }}...HEAD | \
            grep -E "\.(ts|svelte)$" | head -20 || echo "")
          echo "files=$CHANGED" >> $GITHUB_OUTPUT
      
      - name: Claude Code Review
        if: steps.changed-files.outputs.files != ''
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          REVIEW=$(claude --print --model claude-haiku-4-5 \  # R6: claude-haiku-4-5 (2026년 기준 최신 Haiku)
            "다음 변경된 파일들을 간략히 리뷰해줘:
             ${{ steps.changed-files.outputs.files }}
             
             critical 이슈만 보고해줘 (보안, 런타임 오류 가능성)
             형식: [파일명]: [이슈 설명]")
          
          echo "$REVIEW"
          
          # PR 코멘트로 추가
          gh pr comment ${{ github.event.pull_request.number }} \
            --body "## Claude Code 자동 리뷰\n\n$REVIEW"
        env:
          GH_TOKEN: ${{ github.token }}
```

### 5.1 Anthropic API 직접 활용

Claude Code를 넘어서 Anthropic API를 직접 활용하면 더 세밀한 제어가 가능하다.

```typescript
// Anthropic API 직접 사용 예시
import Anthropic from '@anthropic-ai/sdk';

const anthropic = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY,
});

// 스트리밍 응답
const stream = await anthropic.messages.stream({
  model: 'claude-sonnet-4-6',
  max_tokens: 4096,
  system: '당신은 NestJS 전문가입니다.',
  messages: [{
    role: 'user',
    content: '게시글 CRUD 서비스를 작성해줘'
  }]
});

for await (const chunk of stream) {
  if (chunk.type === 'content_block_delta') {
    process.stdout.write(chunk.delta.text);
  }
}
```

## 6. 고수가 쓰는 숨겨진 팁 모음

### 팁 0: Dynamic Workflows (ultracode) 활용

대규모 작업을 매우 빠르게 처리해야 할 때 `ultracode` 키워드를 사용한다.<!-- R6: 트리거 키워드 ultracode 확인됨 -->

```
> ultracode로 NestJS 전체 백엔드 API를 병렬로 구현해줘.
  목표: 8종 게시판 CRUD + 인증 + 파일 업로드
```

Dynamic Workflows는 수백 개의 서브에이전트를 자동으로 생성하여 대규모 작업을 분산 처리한다. **연구 프리뷰** 기능이므로 프로덕션 핵심 작업에는 신중히 적용한다.

### 팁 1: 에이전트에게 "먼저 계획을 보여줘"

```
> 파일 업로드 모듈을 구현하기 전에
  어떤 파일을 어떤 순서로 만들 것인지 계획만 먼저 보여줘.
  (코드 작성은 아직 하지 않는다)

[계획 확인 후]
> 계획이 좋다. 이제 그 순서대로 구현해줘.
```

이 방법으로 에이전트가 잘못된 방향으로 진행하는 것을 사전에 차단한다.

### 팁 2: 기대값 명시

```
> PostsService.findAll 메서드를 구현해줘.
  완성된 코드는 다음 테스트를 모두 통과해야 해:
  
  1. findAll({boardId: 'uuid'}) 호출 시 posts 배열 반환
  2. page=2, limit=10 일 때 11번째부터 20번째 항목 반환
  3. INQUIRY 게시판에서 비인증 사용자 호출 시 ForbiddenException
```

테스트 케이스를 먼저 보여주면 에이전트가 그 기준에 맞게 구현한다.

### 팁 3: 제약을 명시적으로 부여

```
> 다음 제약 안에서 파일 업로드를 구현해줘:
  - 새 npm 패키지 설치 금지 (기존 Multer만 사용)
  - 파일 저장 경로: uploads/{year}/{month}/{uuid}.{ext}
  - 이미지 썸네일 생성: sharp 라이브러리 사용 (이미 설치됨)
  - 동영상 업로드: 검증만, 썸네일 생성 없음
  - 파일 업로드 후 DB에 반드시 저장 (files 테이블)
```

### 팁 4: 단계별 확인

```
긴 작업을 한 번에 요청하지 않는다.

나쁜 예:
> 게시판 전체를 구현해줘 (너무 광범위)

좋은 예:
> 1단계: PostsModule 파일 구조만 생성해줘 (빈 파일들)
  완료됐으면 알려줘, 그러면 2단계를 지시하겠다.

> 2단계: create 메서드만 구현해줘.
  완료됐으면 알려줘.

> 3단계: findAll 메서드를 구현해줘...
```

### 팁 5: 실패한 구현을 재사용

```
> 방금 구현한 PostsService.findAll이 제대로 동작하지 않아.
  다음 오류가 발생했어:
  
  [오류 메시지 전체 복사붙여넣기]
  
  이 오류를 분석하고 최소한의 변경으로 수정해줘.
  (다시 처음부터 작성하지 않는다)
```

## 7. 이 시리즈를 완주한 당신에게

### 7.1 당신이 이제 할 수 있는 것들

15편을 모두 완주했다면 다음을 할 수 있다.

- Claude Code를 설치하고 프로젝트에 바로 적용할 수 있다
- CLAUDE.md로 에이전트가 팀 규칙을 따르도록 제어할 수 있다
- MCP로 실제 DB에 연결하여 환각 없이 코드를 생성할 수 있다
- Hooks로 코드 품질을 자동으로 검증할 수 있다
- 멀티에이전트로 대규모 프로젝트를 병렬로 개발할 수 있다
- PRD와 설계서를 작성하여 에이전트가 정확하게 구현하게 할 수 있다
- 하네스로 에이전트를 안전하게 제어할 수 있다
- 오류 발생 시 체계적으로 진단하고 복구할 수 있다
- 팀 협업 환경에서 Claude Code를 활용할 수 있다

### 7.2 앞으로 계속 성장하는 방법

**매일 하기**:
```
- 실제 프로젝트에 Claude Code 적용
- CLAUDE.md를 발견된 패턴으로 지속 개선
- /cost로 비용 효율성 추적
```

**매주 하기**:
```
- 생성된 코드 품질 회고 (잘 된 것, 못 된 것)
- 트러블슈팅 사례 기록 (팀 공유)
- 새로운 Claude Code 기능 업데이트 확인
```

**매월 하기**:
```
- 에이전트 사용으로 절약된 시간 측정
- CLAUDE.md 전체 리뷰 및 정제
- 다음 분기 Claude Code 활용 계획 수립
```

## 부록: 빠른 참조 카드

### 자주 쓰는 명령어

```bash
# 세션 시작
claude                      # 대화형 시작
claude "지시사항"            # 일회성 실행
claude --resume             # 이전 세션 재개
claude --model claude-haiku-4-5 "단순작업"  # 모델 지정 (Haiku: 빠르고 저렴)

# 세션 내 슬래시 커맨드
/cost      # 사용량 확인
/compact   # 히스토리 압축
/clear     # 히스토리 초기화
/memory    # CLAUDE.md 조회
/help      # 도움말

# 컨텍스트 지시어
@파일경로    # 특정 파일 참조
@폴더경로/   # 폴더 전체 참조
```

### 자주 쓰는 프롬프트 패턴

```
[기능 구현]
@CLAUDE.md 와 @docs/PRD.md 를 읽고
{파일명}에 {기능}을 구현해줘.
완료 조건: {측정 가능한 기준}

[오류 수정]
@{오류_파일} 에서 다음 오류가 발생했어:
{오류 메시지}
근본 원인을 분석하고 최소한의 변경으로 수정해줘.

[코드 리뷰]
@{파일명} 을 CLAUDE.md 규칙에 맞게 검토하고
any 타입, console.log, 보안 이슈를 찾아줘.

[계획 수립]
{작업}을 구현하기 전에 파일 목록과 순서를 계획해줘.
코드는 아직 작성하지 않는다.
```
