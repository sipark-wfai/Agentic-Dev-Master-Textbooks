## 1. Hooks 개념: 에이전트 행동을 제어하는 트리거

Hooks는 Claude Code 에이전트가 특정 행동(파일 저장, 명령어 실행 등)을 하기 전후에 자동으로 실행되는 스크립트다. 인간 개발자가 에이전트를 감시하지 않아도 자동으로 품질을 검사하고, 위험한 행동을 차단하고, 알림을 보낼 수 있다.

### 1.1 Hooks의 역할

```
에이전트가 행동하기 전/후에 자동 실행

PreToolUse Hook               에이전트 행동              PostToolUse Hook
     |                              |                            |
     v                              v                            v
[검증/차단]    -->    [파일 쓰기/명령어 실행]    -->    [린팅/포맷/테스트]
```

### 1.2 Hooks가 없으면 어떤 일이 생기는가

- 에이전트가 코드를 작성해도 ESLint/TypeScript 검사가 실행되지 않는다
- DROP TABLE 같은 위험한 SQL을 자동으로 실행할 수 있다
- .env 파일이 실수로 수정돼도 알 수 없다
- 테스트 없이 기능이 완료됐다고 보고될 수 있다

### 1.3 Hooks가 있으면

- 파일 저장 즉시 자동 린팅 및 포맷팅
- 위험한 SQL 패턴 감지 시 인간 승인 요청
- 중요 파일 수정 시 로그 기록 및 경고
- 커밋 전 자동 타입 검사 및 테스트 실행

## 2. Hooks 이벤트 유형 완전 정리

### 2.1 PreToolUse

도구가 실행되기 직전에 실행되는 Hook이다.

**특징**:
- exit code 2를 반환하면 해당 도구 실행을 차단한다
- 위험한 행동을 방지하는 데 사용한다
- 실행 취소가 불가능한 작업 전에 검증한다

**활용 케이스**:
- DROP TABLE 구문 감지 및 차단
- 특정 파일 수정 전 인간 승인 요청
- 프로덕션 환경 감지 및 경고

### 2.2 PostToolUse

도구가 실행된 직후에 실행되는 Hook이다.

**특징**:
- 실행 결과를 바탕으로 추가 작업을 수행한다
- 코드 품질 자동 검사에 주로 사용한다
- exit code가 에이전트 흐름에 영향을 줄 수 있다

**활용 케이스**:
- 파일 저장 후 ESLint/Prettier 자동 실행
- TypeScript 컴파일 확인
- 테스트 자동 실행

### 2.3 Notification
<!-- R3 수정: Notification 이벤트는 Claude Code 버전에 따라 지원 여부가 다를 수 있음. /help hooks 또는 공식 문서에서 지원 이벤트 목록 확인 권장 -->

특정 조건이 충족될 때 발생하는 Hook이다.

**활용 케이스**:
- 에이전트가 오래 실행될 때 슬랙 알림
- 오류 발생 시 이메일 발송
- 중요 파일 변경 시 알림

### 2.4 Stop

에이전트가 응답을 완료할 때 실행되는 Hook이다.

**활용 케이스**:
- 작업 완료 요약 로그
- 완료 통보 알림
- 사용한 토큰 비용 기록

## 3. .claude/settings.json 구조와 Hooks 설정 문법

### 3.1 기본 구조

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "도구 이름 또는 패턴",
        "hooks": [
          {
            "type": "command",
            "command": "실행할 쉘 명령어"
          }
        ]
      }
    ],
    "PostToolUse": [...],
    "Notification": [...],
    "Stop": [...]
  }
}
```

### 3.2 matcher 패턴

matcher는 어떤 도구 실행에 Hook을 적용할지 결정한다.

```json
"matcher": "Write"         // Write 도구에만 적용
"matcher": "Bash"          // Bash 도구에만 적용
"matcher": ".*"            // 모든 도구에 적용 (정규식)
"matcher": "Write|Edit"    // Write 또는 Edit 도구에 적용
```

### 3.3 Hook 명령어에서 사용 가능한 데이터

Claude Code Hooks는 실행 시 tool_name, tool_input 등의 데이터를 **JSON 형태로 stdin에 전달**한다. Hook 스크립트에서 stdin을 파싱하여 파일 경로, 실행 명령어 등의 정보를 얻는다.

```bash
#!/bin/bash
# stdin에서 JSON 데이터 파싱 예시

# stdin 전체 읽기
INPUT=$(cat)

# tool_name 추출
TOOL=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_name',''))")

# 파일 경로 추출 (Write/Edit 도구의 경우)
FILE=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('path',''))")

# 실행 명령어 추출 (Bash 도구의 경우)
CMD=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('command',''))")
```

> **주의**: `${file}`, `${command}` 같은 셸 변수 직접 치환 방식은 동작하지 않는다. 반드시 위와 같이 stdin JSON을 파싱하여 데이터를 읽어야 한다.

### 3.4 exit code 의미

| exit code | 의미 | 에이전트 동작 |
|-----------|------|--------------|
| 0 | 성공 | 계속 진행 |
| 1 | 경고 | 결과를 컨텍스트에 추가하고 계속 |
| 2 | 차단 | 도구 실행을 취소하고 에이전트에게 차단 사유 전달 |

## 4. 실전 Hooks 예시 10가지

### Hook 1: 파일 저장 시 ESLint 자동 실행

TypeScript/JavaScript 파일이 저장될 때마다 ESLint를 실행하고, 오류가 있으면 에이전트에게 알린다.

```bash
#!/bin/bash
# .claude/hooks/auto-lint.sh
# stdin에서 JSON 데이터 파싱
INPUT=$(cat)
FILE=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('path',''))")

if [[ "$FILE" =~ \.(ts|tsx|js|jsx)$ ]]; then
  npx eslint --fix "$FILE" 2>&1 && echo 'ESLint 통과' || (echo 'ESLint 오류 발견:'; npx eslint "$FILE" 2>&1; exit 1)
fi
```

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/auto-lint.sh"
          }
        ]
      }
    ]
  }
}
```

**동작 설명**:
1. Claude Code가 Hook 실행 시 JSON을 stdin으로 전달하며, 스크립트에서 파일 경로를 파싱한다
2. TypeScript/JavaScript 파일이 저장되면 ESLint를 자동 실행한다
3. `--fix` 옵션으로 자동 수정 가능한 문제는 즉시 수정한다
4. 자동 수정 불가능한 문제가 있으면 exit code 1을 반환하여 에이전트에게 알린다

### Hook 2: DROP TABLE 구문 감지 시 인간 승인 요청

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "# stdin에서 JSON 파싱하여 command 추출 후 DROP 패턴 감지\n# 실제 구현 시 .claude/hooks/dangerous-sql-guard.sh 스크립트로 분리 권장\nINPUT=$(cat); CMD=$(echo \"$INPUT\" | python3 -c \"import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('command',''))\"); if echo \"$CMD\" | grep -iE '(DROP\\s+TABLE|DROP\\s+DATABASE|TRUNCATE)' > /dev/null 2>&1; then echo '위험: DROP TABLE/TRUNCATE 명령어가 감지됐습니다.'; exit 2; fi"
          }
        ]
      }
    ]
  }
}
```

**동작 설명**:
1. Bash 명령어 실행 전 `DROP TABLE`, `DROP DATABASE`, `TRUNCATE` 패턴을 감지한다
2. 감지되면 터미널에 경고 메시지를 출력하고 인간의 확인을 요청한다
3. "승인"을 입력하지 않으면 exit code 2를 반환하여 명령어 실행을 차단한다

### Hook 5: .env 파일 편집 시 경고 및 기록

```bash
# .claude/hooks/env-guard.sh
#!/bin/bash
INPUT=$(cat)
FILE=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('path',''))")
TOOL=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_name',''))")

if [[ "$FILE" == *".env"* ]] && [[ "$FILE" != *".env.example"* ]]; then
  TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
  
  # 경고 로그 기록
  echo "[$TIMESTAMP] 경고: .env 파일 수정 - $FILE (도구: $TOOL)" >> .claude/security.log
  
  # 에이전트에게 경고
  echo "경고: .env 파일($FILE)이 수정됐습니다."
  echo "환경 변수 변경은 주의가 필요합니다."
  echo "변경 내용이 .env.example에도 반영돼야 하는지 확인하세요."
  
  # .env 파일을 직접 쓰기 시도하면 차단 (PreToolUse에서)
  if [ "$TOOL" = "Write" ]; then
    echo "직접 .env 파일 쓰기는 허용되지 않습니다."
    echo ".env.example을 업데이트하고 직접 편집하세요."
    exit 2
  fi
fi
```

### Hook 7: 커밋 전 TypeScript 타입 검사

```bash
# .claude/hooks/typecheck.sh
#!/bin/bash
INPUT=$(cat)
FILE=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('path',''))")

# TypeScript 파일이 변경됐을 때만 실행
if echo "$FILE" | grep -E "\.(ts|tsx)$" > /dev/null; then
  # 프론트엔드 파일
  if echo "$FILE" | grep "apps/frontend" > /dev/null; then
    echo "프론트엔드 TypeScript 타입 검사 중..."
    cd apps/frontend && npx svelte-check --tsconfig ./tsconfig.json 2>&1
    RESULT=$?
  # 백엔드 파일
  elif echo "$FILE" | grep "apps/backend" > /dev/null; then
    echo "백엔드 TypeScript 타입 검사 중..."
    cd apps/backend && npx tsc --noEmit 2>&1
    RESULT=$?
  fi
  
  if [ "${RESULT:-0}" -ne 0 ]; then
    echo "TypeScript 타입 오류 발견!"
    exit 1
  fi
  
  echo "TypeScript 타입 검사 통과"
fi
```

### Hook 8: 보안 키워드 평문 저장 차단

```bash
# .claude/hooks/security-scan.sh
#!/bin/bash
INPUT=$(cat)
FILE=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('path',''))")

# 체크할 파일 확장자
if ! echo "$FILE" | grep -E "\.(ts|tsx|js|jsx|svelte|json|env)$" > /dev/null; then
  exit 0
fi

# .env.example은 제외
if [[ "$FILE" == *".env.example"* ]]; then
  exit 0
fi

# 보안 키워드 패턴 검사
DANGEROUS_PATTERNS=(
  "password\s*=\s*['\"][^'\"]{3,}['\"]"
  "secret\s*=\s*['\"][^'\"]{8,}['\"]"
  "api_key\s*=\s*['\"][^'\"]{8,}['\"]"
  "private_key\s*=\s*['\"][^'\"]{8,}['\"]"
  "sk-ant-api"
  "ghp_[a-zA-Z0-9]+"
)

FOUND=0
for pattern in "${DANGEROUS_PATTERNS[@]}"; do
  if grep -iE "$pattern" "$FILE" > /dev/null 2>&1; then
    echo "보안 경고: $FILE 에서 잠재적인 비밀키 패턴 발견!"
    echo "패턴: $pattern"
    FOUND=1
  fi
done

if [ $FOUND -eq 1 ]; then
  echo "환경 변수 사용을 권장합니다. process.env.VARIABLE_NAME"
  exit 2  # 차단
fi
```

### Hook 10: 빌드 실패 시 슬랙 알림

```bash
# .claude/hooks/build-notify.sh
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('command',''))")
RESULT=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_result',{}).get('exit_code',0))")

SLACK_WEBHOOK="${SLACK_WEBHOOK_URL}"

if [ -z "$SLACK_WEBHOOK" ]; then
  exit 0
fi

if echo "$COMMAND" | grep -E "(build|compile|tsc)" > /dev/null; then
  if [ "$RESULT" -ne 0 ]; then
    PROJECT=$(basename "$PWD")
    TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
    
    curl -s -X POST "$SLACK_WEBHOOK" \
      -H 'Content-Type: application/json' \
      -d "{
        \"text\": \"빌드 실패 알림\",
        \"attachments\": [{
          \"color\": \"danger\",
          \"fields\": [
            {\"title\": \"프로젝트\", \"value\": \"$PROJECT\", \"short\": true},
            {\"title\": \"시간\", \"value\": \"$TIMESTAMP\", \"short\": true},
            {\"title\": \"명령어\", \"value\": \"$COMMAND\"}
          ]
        }]
      }"
    
    echo "슬랙 알림 전송 완료"
  fi
fi
```

## 5. Hook 실행 결과 코드로 에이전트 흐름 제어

### 5.1 exit code 활용 전략

```bash
#!/bin/bash
# .claude/hooks/smart-validator.sh
INPUT=$(cat)
FILE=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('tool_input',{}).get('path',''))")

# 타입스크립트 파일이 아니면 통과
if ! echo "$FILE" | grep -E "\.(ts|tsx)$" > /dev/null; then
  exit 0  # 통과
fi

# any 타입 사용 여부 확인
ANY_COUNT=$(grep -c ": any" "$FILE" 2>/dev/null || echo 0)

if [ "$ANY_COUNT" -gt 5 ]; then
  echo "오류: any 타입이 ${ANY_COUNT}개 발견됐습니다."
  echo "any 타입을 proper 타입으로 교체해주세요."
  exit 2  # 차단: 에이전트에게 수정 요청
  
elif [ "$ANY_COUNT" -gt 0 ]; then
  echo "경고: any 타입이 ${ANY_COUNT}개 발견됐습니다."
  echo "가능하면 proper 타입으로 교체를 권장합니다."
  exit 1  # 경고: 계속 진행하지만 에이전트가 인식
fi

exit 0  # 성공: 문제 없음
```

### 5.2 에이전트와의 상호작용

exit code 1을 반환하면 Claude Code는 Hook의 출력 메시지를 컨텍스트에 포함하여 수정을 시도한다.

```
[에이전트 작동 예시]

에이전트: posts.service.ts 파일을 수정합니다...
PostToolUse Hook 실행...
경고: any 타입이 2개 발견됐습니다.

에이전트 (자동 수정):
any 타입을 발견했습니다. 올바른 타입으로 교체합니다...

수정 전:
  async findPosts(options: any) {...}

수정 후:
  async findPosts(options: FindPostsOptions) {...}
```

### 7.1 Hook 수동 테스트

```bash
# Hook 스크립트를 직접 실행하여 동작 확인
```
