## 1. Claude Code 명령어 체계 전체 지도

Claude Code의 명령어는 크게 세 가지로 나뉜다.

```
Claude Code 명령어 체계
+------------------------------------------+
|  1. CLI 옵션                              |
|     터미널에서 claude 명령어와 함께 사용  |
|     예: claude --model claude-3-5-sonnet  |
+------------------------------------------+
|  2. 슬래시 커맨드                         |
|     대화형 세션 안에서 /로 시작            |
|     예: /help, /clear, /cost             |
+------------------------------------------+
|  3. 컨텍스트 지시어                        |
|     대화 중 파일/폴더를 참조할 때 사용     |
|     예: @src/auth/auth.service.ts         |
+------------------------------------------+
```

## 2. CLI 옵션 완전 정리

### 2.1 기본 실행 모드

```bash
# 대화형 세션 시작 (현재 폴더가 작업 폴더)
claude

# 특정 폴더를 작업 폴더로 지정하여 시작
claude /path/to/project

# 일회성 명령 실행 후 종료
claude "게시판 목록 API를 만들어줘"

# 파이프로 입력 받기
echo "현재 폴더의 파일 목록을 알려줘" | claude
```

### 2.2 출력 및 형식 옵션

```bash
# 응답을 stdout으로 출력 (대화형 UI 없이)
claude --print "users 테이블의 Prisma 스키마를 작성해줘"

# JSON 형식으로 출력 (스크립트에서 파싱 용도)
claude --print --output-format json "현재 프로젝트 구조를 JSON으로 요약해줘"

# 응답만 출력 (메타 정보 제외)
claude --print --silent "TypeScript 타입 오류를 고쳐줘"
```

### 2.3 모델 선택 옵션

```bash
# 특정 모델 지정
claude --model claude-opus-4-6 "복잡한 아키텍처 설계를 도와줘"
claude --model claude-sonnet-4-6 "간단한 함수를 작성해줘"

# 현재 사용 중인 모델 확인
claude --version
# 모델은 --model 옵션으로 직접 지정한다
```

**모델 선택 가이드**:

| 모델 | 적합한 작업 | 비용 |
|------|-------------|------|
| claude-opus-4-6 | 복잡한 아키텍처 설계, 어려운 버그 분석 | 높음 |<!-- R3 수정: 모델명은 Anthropic 릴리즈 정책에 따라 변경될 수 있음. 최신 모델명은 공식 문서 확인 -->
| claude-sonnet-4-6 | 일반 기능 구현, 코드 리뷰 | 중간 |
| claude-haiku-4-6 | 단순 자동완성, 빠른 질의 | 낮음 |

### 2.4 세션 관리 옵션

```bash
# 이전 세션 재개 (가장 최근 세션)
claude --resume

# 특정 세션 ID로 재개
claude --resume SESSION_ID

# 이전 세션 재개 (가장 최근 세션)
claude --resume

# 이전 대화 없이 새 세션 시작 (기본값)
claude --no-resume
```

### 2.5 비대화형(CI/CD) 모드

```bash
# 비대화형 모드: --print 옵션으로 입력 대기 없이 결과를 출력
claude --print "모든 TypeScript 오류를 수정해줘"

# CI/CD 파이프라인에서 활용 예시
# .github/workflows/code-review.yml
# - name: Claude Code Review
#   run: |
#     claude --print "이 PR의 코드를 리뷰하고 문제점을 JSON으로 알려줘"
```

### 2.6 기타 유용한 옵션

```bash
# 도움말 출력
claude --help

# 버전 확인
claude --version

# 허용 도구 제한 (보안을 위해)
claude --allowedTools "Read,Write,Edit" "파일만 읽고 쓸 수 있게 제한된 세션"
# 허용할 도구 이름을 쉼표로 구분하여 지정한다. 사용 가능한 도구: Read, Write, Edit, Bash, WebSearch 등

# 특정 도구 비활성화
claude --disallowedTools "Bash" "쉘 명령어 실행을 금지한 세션"
```

## 3. 슬래시 커맨드 완전 정리

슬래시 커맨드는 대화형 세션 안에서 `/` 로 시작하여 에이전트의 동작을 제어한다.

### 3.1 /help — 도움말

```
> /help
```

사용 가능한 모든 슬래시 커맨드 목록과 설명을 출력한다.

```
> /help compact
```

특정 커맨드의 상세 사용법을 출력한다.

### 3.2 /clear — 대화 히스토리 초기화

```
> /clear
```

현재 세션의 대화 히스토리를 초기화한다. 컨텍스트가 오염됐거나, 새로운 작업을 시작할 때 사용한다.

**언제 사용하는가**:
- 에이전트가 이전 대화의 잘못된 가정을 계속 반복할 때
- 완전히 다른 주제로 전환할 때
- 컨텍스트 윈도우가 거의 가득 찼을 때

### 3.3 /compact — 히스토리 압축

```
> /compact
```

대화 히스토리를 요약하여 토큰 사용량을 줄인다. `/clear`와 달리 대화 맥락은 유지된다.

**동작 방식**: Claude가 지금까지의 대화를 핵심만 추려 요약 버전으로 교체한다. 작업 진행 상황은 유지되면서 토큰을 절약할 수 있다.

```
> /compact
히스토리가 압축됐습니다.
압축 전: 15,432 토큰
압축 후: 2,841 토큰
절약: 12,591 토큰
```

### 3.4 /cost — 토큰 사용량 및 비용 확인

```
> /cost
```

현재 세션에서 사용한 토큰과 예상 비용을 출력한다.

```
현재 세션 사용량:
- 입력 토큰: 24,532
- 출력 토큰: 8,741
- 총 토큰: 33,273
- 예상 비용: $0.24 (claude-sonnet-4-6 기준)
```

### 3.5 /memory — 현재 메모리 내용 조회

```
# 현재 로드된 메모리(CLAUDE.md) 내용 확인
> /memory
```

/memory 커맨드는 현재 로드된 메모리 내용을 조회하는 용도다. CLAUDE.md 파일을 수정하려면 에디터에서 직접 편집한다. 세션 재시작 후 변경된 내용이 반영된다.

### 3.6 /review — 현재 코드 품질 검토
<!-- R3 수정: /review 커맨드는 Claude Code 버전에 따라 지원 여부가 다를 수 있음. /help로 실제 사용 가능한 커맨드 목록 확인 권장 -->

```
> /review
```

현재 작업 중인 파일 또는 최근 변경된 파일의 코드 품질을 검토한다.

```
> /review @src/posts/posts.service.ts
```

특정 파일을 지정하여 검토한다.

### 3.7 /vim — vim 키바인딩 모드
<!-- R3 수정: /vim 커맨드는 Claude Code 버전에 따라 지원 여부가 다를 수 있음. /help로 확인 권장 -->

```
> /vim
```

vim 키바인딩을 활성화한다. vim에 익숙한 개발자를 위한 기능이다.

활성화 후:
- `i` — 입력 모드
- `Esc` — 노멀 모드
- `dd` — 현재 줄 삭제
- `yy` — 현재 줄 복사

비활성화:
```
> /vim off
```

### 3.9 그 외 주요 슬래시 커맨드

```
# 사용 중인 모델 변경
> /model claude-opus-4-6

# 허가 설정 확인
> /permissions
```

## 4. 컨텍스트 지시어 활용법

컨텍스트 지시어는 대화 중 특정 파일이나 폴더를 에이전트의 컨텍스트에 명시적으로 포함시키는 방법이다.

### 4.1 @파일경로 — 특정 파일을 컨텍스트에 포함

```
# 단일 파일 참조
> @prisma/schema.prisma 를 참고해서 Post 모델에 viewCount 필드를 추가해줘

# 여러 파일 동시 참조
> @src/posts/posts.service.ts 와 @src/posts/posts.controller.ts 를 비교해서
  서비스와 컨트롤러 간 역할 분리가 올바른지 검토해줘

# 설정 파일 참조
> @tsconfig.json 설정을 확인하고 strict 모드가 활성화됐는지 알려줘
```

### 4.2 @폴더경로 — 폴더 전체를 컨텍스트에 포함

```
# 폴더 전체 탐색
> @src/auth/ 폴더의 전체 구조를 분석하고 보안 취약점이 있는지 검토해줘

# 여러 폴더 참조
> @src/posts/ 와 @src/comments/ 를 참고해서 
  두 모듈의 일관성을 확인해줘
```

### 4.3 @ 지시어 사용 시 주의사항

```
# 주의: 너무 큰 폴더를 한 번에 참조하면 컨텍스트 초과
> @src/  (src 전체 - 수백 개 파일이면 컨텍스트 초과 가능)

# 권장: 작업에 필요한 파일/폴더만 지정
> @src/posts/posts.service.ts 와 @prisma/schema.prisma 만 참고해서
  게시글 목록 쿼리를 최적화해줘
```

## 5. 멀티라인 입력 방법

### 5.1 Shift+Enter로 줄바꿈

대화 입력창에서 `Shift+Enter`를 누르면 줄바꿈이 되어 멀티라인 입력이 가능하다.

```
> 다음 요구사항에 따라 PostDTO를 작성해줘:
  1. title: 문자열, 필수, 최소 2자 최대 100자
  2. content: 문자열, 필수, 최소 10자
  3. boardId: UUID 형식
  4. isAnonymous: boolean, 기본값 false
  5. tags: 문자열 배열, 최대 10개
```

### 5.2 파일을 직접 첨부

```bash
# 파일 내용을 인라인으로 전달 (bash heredoc 활용)
cat << 'EOF' | claude
다음 코드에서 버그를 찾아줘:

function calculateDiscount(price, rate) {
  return price * rate / 100;
}

console.log(calculateDiscount(10000, 10)); // 예상: 1000, 실제: ?
EOF
```

### 5.3 파일 경로로 입력

```bash
# 파일 내용을 입력으로 사용
claude < requirements.txt

# 긴 프롬프트를 파일로 저장하고 실행
claude "$(cat long_prompt.txt)"
```

  3. Post에 viewCount Int 기본값 0 추가

## 7. 고급 활용 패턴

### 7.1 파이프라인 조합

```bash
# 여러 명령어를 파이프로 연결
git diff HEAD~1 | claude --print "이 diff를 검토하고 문제점을 알려줘"

# 파일 목록을 입력으로 전달
find src -name "*.spec.ts" | claude --print "테스트 파일 목록을 분석해서 커버리지 부족한 모듈을 알려줘"
```

### 7.2 스크립트에서 활용

```bash
#!/bin/bash
# auto-review.sh: 매 커밋 전 자동 코드 리뷰

CHANGED_FILES=$(git diff --cached --name-only --diff-filter=ACM | grep -E "\.(ts|svelte)$")

if [ -n "$CHANGED_FILES" ]; then
  echo "변경된 파일을 리뷰합니다..."
  
  REVIEW=$(claude --print \
    "다음 파일들을 검토해줘: $CHANGED_FILES
     any 타입, console.log, 하드코딩된 값이 있으면 알려줘. JSON 형식으로.")
  
  # 심각한 문제가 있으면 커밋 차단
  if echo "$REVIEW" | grep -q '"severity":"critical"'; then
    echo "심각한 문제 발견! 커밋을 중단합니다."
    echo "$REVIEW"
    exit 1
  fi
fi
```

### 7.3 세션 재개 활용

긴 작업을 중단했다가 다시 시작할 때 세션을 재개하면 이전 컨텍스트를 그대로 이어받을 수 있다.

```bash
# 나중에 세션 재개 (가장 최근 세션)
claude --resume
# 또는 특정 세션 ID로 재개
claude --resume sess_abc123
```

## 8. 단축키 및 조작 팁

### 대화형 세션 내 단축키

| 단축키 | 동작 |
|--------|------|
| `Ctrl+C` | 현재 에이전트 작업 중단 |
| `Ctrl+D` | 세션 종료 |
| `Ctrl+L` | 터미널 화면 클리어 |
| `Up 화살표` | 이전 입력 불러오기 |
| `Tab` | 자동완성 (파일 경로 등) |
| `Shift+Enter` | 줄바꿈 (엔터 없이) |
| `Esc` | 현재 입력 취소 |

### 에이전트 작업 중 제어

```
작업 중 에이전트에게 추가 지시:
- 에이전트가 실행 중일 때 새 메시지를 입력하면 현재 작업에 추가 지시가 됨
- "멈춰" 또는 Ctrl+C로 즉시 중단 가능
- 중단 후 "방금 작업한 내용을 롤백해줘"로 되돌리기 가능
```

## 9. 자주 하는 실수와 해결법

### 실수 1: 컨텍스트 없이 광범위한 지시

```
# 나쁜 예
> 전체 프로젝트를 리팩터링해줘

# 좋은 예
> @src/posts/ 폴더의 파일들에서 any 타입을 모두 제거해줘
  변경 파일: posts.service.ts, posts.controller.ts만 수정해줘
```

### 실수 2: 너무 큰 컨텍스트

```
# 나쁜 예 (전체 src 폴더 - 수백 개 파일)
> @src/ 전체를 분석해줘

# 좋은 예
> @src/auth/auth.service.ts 와 @src/auth/auth.controller.ts 만 분석해줘
```

### 실수 3: 슬래시 커맨드를 너무 늦게 사용

```
# 토큰이 다 소진된 후 /compact 사용 -> 효과 제한적
# 권장: 대화가 길어지기 시작하면 중간중간 /compact 사용

# 작업 전 컨텍스트 확인
> /cost
```
