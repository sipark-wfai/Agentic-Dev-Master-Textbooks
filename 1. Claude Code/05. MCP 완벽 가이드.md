## 1. MCP란 무엇인가

MCP(Model Context Protocol)는 AI 모델과 외부 시스템(데이터베이스, API, 파일 시스템 등)을 연결하는 표준 프로토콜이다. Anthropic이 2024년에 오픈 소스로 공개했으며, 현재 많은 기업과 도구가 MCP를 지원한다.

MCP를 한 문장으로 정의하면: **"AI가 외부 세계와 소통하는 표준 인터페이스"** 다.

### 1.1 MCP가 해결하는 문제

MCP 없이 AI에게 데이터베이스 작업을 요청하면 다음과 같은 문제가 생긴다.

**문제 1: 환각(Hallucination)**

```
개발자: "users 테이블의 모든 컬럼을 알려줘"
AI (MCP 없음): "users 테이블에는 id, name, email, password, createdAt, 
               updatedAt 컬럼이 있습니다."

실제 users 테이블: id, email, hashedPassword, nickname, role, 
                   isActive, lastLoginAt, createdAt, updatedAt, deletedAt
```

AI가 존재하지 않는 `name` 컬럼을 만들고, `hashedPassword`를 `password`로 잘못 추측했다. 이를 기반으로 코드를 작성하면 런타임 오류가 발생한다.

**문제 2: 스키마 불일치**

```typescript
// AI가 생성한 코드 (실제 스키마와 다름)
const user = await prisma.user.findUnique({
  where: { id },
  select: { id: true, name: true, email: true }  // name은 존재하지 않음!
});
```

**문제 3: 버전 추측**

PostgreSQL 16의 새로운 기능(예: pg_walinspect, MERGE 문)을 모르고 구버전 방식으로 쿼리를 작성할 수 있다.

### 1.2 MCP가 있으면

```
개발자: "users 테이블의 모든 컬럼을 알려줘"
AI (MCP 연결): [실제 DB에 쿼리]
              "users 테이블의 컬럼:
               - id: UUID, PRIMARY KEY
               - email: VARCHAR(255), UNIQUE, NOT NULL
               - hashedPassword: VARCHAR, NOT NULL
               - nickname: VARCHAR(50), NOT NULL
               - role: ENUM('USER', 'ADMIN'), DEFAULT 'USER'
               ..."
```

실제 데이터베이스에서 스키마를 직접 읽어오기 때문에 환각이 발생하지 않는다.

## 2. MCP 아키텍처

```
+-------------------+     MCP 프로토콜     +-------------------+
|   Claude Code     |  <---------------->  |    MCP Host       |
|   (MCP Client)    |                      |   (mcpServers     |
|                   |                      |    config)        |
+-------------------+                      +--------+----------+
                                                    |
                              +---------------------+
                              |                     |
                    +---------v-------+   +---------v-------+
                    |  MCP Server 1   |   |  MCP Server 2   |
                    |  (PostgreSQL)   |   |  (Git)          |
                    +--------+--------+   +--------+--------+
                             |                     |
                    +--------v--------+   +--------v--------+
                    |  PostgreSQL 16  |   |  Git Repository |
                    |  (실제 DB)      |   |  (실제 저장소)  |
                    +-----------------+   +-----------------+
```

### 2.1 구성 요소 설명

- **MCP Client** (Claude Code): 도구 실행 요청을 보내는 주체
- **MCP Host**: 여러 MCP 서버를 관리하는 프로세스 (Claude Desktop 또는 Claude Code 자체)
- **MCP Server**: 특정 시스템(DB, Git 등)에 대한 도구를 제공하는 서버
- **실제 시스템**: PostgreSQL, Git, 파일 시스템 등 실제 데이터 소스

### 2.2 MCP 통신 방식

MCP는 JSON-RPC 2.0 프로토콜을 사용하며 두 가지 전송 방식을 지원한다.

| 전송 방식 | 설명 | 사용 케이스 |
|-----------|------|-------------|
| stdio | 표준 입출력으로 통신 | 로컬 서버 (DB, Git, 파일 시스템) |
| SSE (HTTP) | HTTP 서버-센트 이벤트 | 원격 서버, 웹 기반 서비스 |

## 3. MCP 서버 설정 파일 구조 및 등록 방법

MCP 서버는 Claude Code 설정 파일에 등록한다.

### 3.1 설정 파일 위치

Claude Code CLI와 Claude Desktop 앱은 서로 다른 별도의 프로그램이며, 각각 다른 설정 파일을 사용한다.

**Claude Code CLI 설정 파일 (이 교재 기준)**:
```bash
# 프로젝트별 설정 (권장)
.claude/settings.json

# 글로벌 설정
~/.claude/settings.json

# 파일이 없으면 생성
mkdir -p .claude
touch .claude/settings.json
```

**Claude Desktop 앱 설정 파일** (Claude Code CLI와 별개):
```bash
# macOS
~/Library/Application Support/Claude/claude_desktop_config.json

# Windows
%APPDATA%\Claude\claude_desktop_config.json
```

이 교재의 모든 MCP 설정 예시는 **Claude Code CLI** 기준으로 `.claude/settings.json`을 사용한다. Claude Desktop 앱에서 MCP를 설정할 경우에는 위의 `claude_desktop_config.json` 경로를 사용해야 한다.

### 3.2 기본 구조

```json
{
  "mcpServers": {
    "서버-이름": {
      "command": "실행 명령어",
      "args": ["인수1", "인수2"],
      "env": {
        "환경변수명": "값"
      }
    }
  }
}
```

### 3.3 Claude Code 프로젝트별 설정

프로젝트 루트의 `.claude/settings.json`에도 MCP 서버를 등록할 수 있다. 이 방법은 프로젝트별로 다른 MCP 설정을 유지할 때 유용하다.

```json
{
  "mcpServers": {
    "board-hub-db": {
      "command": "npx",
      <!-- R3 수정: 패키지명은 npm registry 기준 정확하나, 설치 전 최신 버전 확인 권장: npm info @modelcontextprotocol/server-postgres -->
      "args": ["-y", "@modelcontextprotocol/server-postgres", 
               "postgresql://boarduser:password@localhost:5432/board_hub"]
    }
  }

```

## 4. 핵심 MCP 서버 설치 및 설정

### 4.1 PostgreSQL MCP 서버

**역할**: Claude Code가 PostgreSQL 데이터베이스의 스키마를 조회하고, 쿼리를 실행할 수 있게 한다.

**설치 및 설정**:

```bash
# 테스트 실행 (npx로 자동 설치)
npx -y @modelcontextprotocol/server-postgres postgresql://localhost/board_hub
```

**config.json 설정**:

```json
{
  "mcpServers": {
    "board-hub-postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://boarduser:password@localhost:5432/board_hub"
      ]
    }
  }
}
```

**제공하는 도구**:
- `query`: SQL 쿼리 실행
- `list_tables`: 테이블 목록 조회
- `describe_table`: 특정 테이블 스키마 조회

**활용 예시**:

```
> board_hub 데이터베이스의 모든 테이블을 나열하고 각 테이블의 레코드 수를 알려줘

Claude Code가 실행하는 쿼리:
SELECT 
  schemaname,
  tablename,
  n_live_tup as row_count
FROM pg_stat_user_tables
ORDER BY n_live_tup DESC;
```

### 4.2 Git MCP 서버

**역할**: Claude Code가 Git 커밋 이력, 브랜치, diff를 직접 조회할 수 있게 한다.

**설치 및 설정**:

```json
{
  "mcpServers": {
    "board-hub-git": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-git",
        "--repository",
        "/path/to/board-hub"
      ]
    }
  }
}
```

**제공하는 도구**:
- `git_log`: 커밋 이력 조회
- `git_diff`: 변경사항 조회
- `git_status`: 현재 상태 확인
- `git_blame`: 특정 파일의 변경 이력
- `git_branch`: 브랜치 목록

**활용 예시**:

```
> 최근 5개 커밋을 보여주고, 각 커밋에서 변경된 파일 수를 알려줘

> 현재 브랜치와 main 브랜치의 차이를 분석하고 
  변경된 파일 목록을 보여줘
```

### 4.3 파일 시스템 MCP 서버

**역할**: Claude Code가 허용된 경로의 파일을 안전하게 읽고 쓸 수 있게 한다.

```json
{
  "mcpServers": {
    "board-hub-fs": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/path/to/board-hub"
      ]
    }
  }
}
```

**보안 특징**: 지정된 경로 밖의 파일은 접근 불가. 에이전트가 시스템 파일을 실수로 수정하는 것을 방지한다.

### 4.4 Brave Search MCP 서버

**역할**: Claude Code가 웹 검색을 수행하여 최신 정보를 참고할 수 있게 한다.

```bash
# Brave Search API 키 발급: https://api.search.brave.com
```

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "BSAxxxxxxxxxxxxxxxxxxxxxxx"
      }
    }
  }
}
```

**활용 예시**:

```
> NestJS 10에서 JWT 리프레시 토큰 구현하는 최신 방법을 검색하고
  우리 프로젝트에 적용해줘
```

## 5. 멀티 게시판 PostgreSQL 16에 MCP 연동 전체 실습

### 5.1 환경 준비

**Step 1**: Docker로 PostgreSQL 16 실행

```bash
# docker-compose.yml 생성
cat > docker-compose.yml << 'EOF'
services:
  postgres:
    image: postgres:16-alpine
    container_name: board_hub_db
    environment:
      POSTGRES_USER: boarduser
      POSTGRES_PASSWORD: boardpass
      POSTGRES_DB: board_hub
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
EOF

# PostgreSQL 시작
docker-compose up -d postgres

# 연결 확인
docker exec -it board_hub_db psql -U boarduser -d board_hub -c "\l"
```

**Step 2**: Prisma 스키마 기본 설정

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id             String    @id @default(uuid())
  email          String    @unique
  hashedPassword String
  nickname       String    @unique
  role           Role      @default(USER)
  isActive       Boolean   @default(true)
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt
  deletedAt      DateTime?
  
  posts    Post[]
  comments Comment[]
  
  @@map("users")
}

enum Role {
  USER
  ADMIN
}
```

**Step 3**: 마이그레이션 실행

```bash
# .env 설정
echo "DATABASE_URL=postgresql://boarduser:boardpass@localhost:5432/board_hub" > .env

# 초기 마이그레이션
npx prisma migrate dev --name init

# 확인
npx prisma migrate status
```

### 5.2 MCP 서버 설정

**Step 4**: .claude/settings.json 설정 (Claude Code CLI 기준)

```json
{
  "mcpServers": {
    "board-hub-postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://boarduser:boardpass@localhost:5432/board_hub"
      ]
    },
    "board-hub-git": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-git",
        "--repository",
        "/Users/username/projects/board-hub"
```

### 5.3 MCP 연동 실습

**Step 5**: Claude Code 실행 및 MCP 확인

```bash
cd /path/to/board-hub
claude

# MCP 서버 연결 확인
> /tools
```

```
사용 가능한 도구:

  - list_tables (테이블 목록)
  - describe_table (테이블 스키마)

MCP: board-hub-git
  - git_log (커밋 이력)

  - git_status (현재 상태)

  - Read (파일 읽기)
  - Write (파일 쓰기)
  - Bash (명령어 실행)
  ...
```

**Step 6**: 실제 스키마 기반 코드 생성

```
> board_hub 데이터베이스의 현재 스키마를 조회하고,
  users 테이블을 기반으로 UserService의 findById 메서드를 작성해줘
```

Claude Code가 MCP를 통해 실제 스키마를 읽고:

```typescript
// 생성된 코드 (실제 컬럼명 정확히 반영)
async findById(id: string): Promise<UserResponseDto> {
  const user = await this.prisma.user.findUnique({
    where: { id, deletedAt: null },
    select: {
      id: true,
      email: true,
      nickname: true,  // name이 아닌 nickname (실제 컬럼명)
      role: true,
      isActive: true,
      createdAt: true,
      // hashedPassword는 응답에서 제외
    },
  });
  
  if (!user) {
    throw new NotFoundException(`사용자를 찾을 수 없습니다: ${id}`);
  }
  
  return user;
}
```

**Step 7**: 데이터 검증 및 쿼리 최적화

```
> users 테이블에 현재 몇 명의 회원이 있고, 역할별 분포는 어떻게 돼?
  또한 최근 7일 내 가입한 회원 수도 알려줘.
```

MCP가 실제 DB에 쿼리를 실행하여 실제 데이터를 반환한다.

## 6. MCP 서버 디버깅 및 연결 오류 해결

### 6.1 MCP 서버 연결 확인

```bash
# MCP 서버 수동 테스트
npx -y @modelcontextprotocol/server-postgres \
  "postgresql://boarduser:boardpass@localhost:5432/board_hub" \
  --debug

# 출력 예시:
# MCP Server starting...
# Connected to PostgreSQL 16.2
# Available tools: query, list_tables, describe_table
```

### 6.2 자주 발생하는 MCP 오류

**오류 1: 연결 거부**

```
Error: MCP server 'board-hub-postgres' failed to start
Cause: connect ECONNREFUSED 127.0.0.1:5432
```

해결:
```bash
# PostgreSQL이 실행 중인지 확인
docker ps | grep postgres
# 실행 중이 아니면
docker-compose up -d postgres
```

**오류 2: 인증 실패**

```
Error: password authentication failed for user "boarduser"
```

해결:
```bash
# 연결 문자열 재확인
psql "postgresql://boarduser:boardpass@localhost:5432/board_hub" -c "\l"

# Docker 컨테이너 환경변수 확인
docker inspect board_hub_db | grep -A5 "Env"
```

**오류 3: MCP 서버 설정 파일 경로 오류**

```bash
# 설정 파일 위치 확인
ls -la .claude/
cat .claude/settings.json

# JSON 문법 오류 확인
python3 -c "import json; json.load(open('.claude/settings.json'))"
```

### 6.3 MCP 서버 로그 확인

```bash
# Claude Code의 MCP 관련 로그
~/.claude/logs/mcp_*.log

# 상세 로그 모드로 Claude Code 실행
CLAUDE_LOG_LEVEL=debug claude  # R3 수정: 이 환경변수의 Claude Code 공식 지원 여부 불확실. 동작하지 않을 경우 --debug 플래그 대신 claude --verbose 시도
```

## 7. MCP 서버 직접 만들기 기초

표준 MCP 서버가 지원하지 않는 시스템에 연결해야 할 경우 직접 MCP 서버를 만들 수 있다.

### 7.1 Node.js 기반 커스텀 MCP 서버 예시

다음은 멀티 게시판 허브의 게시판 통계를 제공하는 간단한 MCP 서버다.

```typescript
// mcp-board-stats/index.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

const server = new Server(
  {
    name: 'board-stats-server',
    version: '1.0.0',
  },
  {
    capabilities: {
      tools: {},
    },
  }
);

// 도구 목록 정의
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: 'get_board_stats',
        description: '게시판별 통계를 반환합니다 (게시글 수, 댓글 수, 오늘 작성 수)',
        inputSchema: {
          type: 'object',
          properties: {
            boardId: {
              type: 'string',
              description: '조회할 게시판 ID (없으면 전체)',
            },
          },
        },
      },
      {
        name: 'get_popular_posts',
        description: '조회수 기준 상위 게시글을 반환합니다',
        inputSchema: {
          type: 'object',
          properties: {
            limit: {
              type: 'number',
              description: '반환할 게시글 수 (기본값: 10)',
            },
          },
        },
      },
    ],
  };
});

// 도구 실행 처리
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  switch (request.params.name) {
    case 'get_board_stats': {
      const { boardId } = request.params.arguments as { boardId?: string };
      
      const stats = await prisma.board.findMany({
        where: boardId ? { id: boardId } : undefined,
        include: {
          _count: {
            select: {
              posts: true,
            },
          },
        },
      });
      
      return {
        content: [
          {
            type: 'text',
            text: JSON.stringify(stats, null, 2),
          },
        ],
      };
    }
    
    case 'get_popular_posts': {
      const { limit = 10 } = request.params.arguments as { limit?: number };
      
      const posts = await prisma.post.findMany({
        where: { deletedAt: null },
        orderBy: { viewCount: 'desc' },
        take: limit,
        select: {
          id: true,
          title: true,
          viewCount: true,
          board: { select: { name: true } },
          author: { select: { nickname: true } },
        },
      });
      
      return {
        content: [
          {
            type: 'text',
            text: JSON.stringify(posts, null, 2),
          },
        ],
      };
    }
    
    default:
      throw new Error(`알 수 없는 도구: ${request.params.name}`);
  }
});

// 서버 시작
async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
}

main().catch(console.error);
```

## 8. MCP 활용 실전 팁

### 8.1 스키마 기반 코드 생성의 위력

MCP 연동 전후의 차이를 직접 경험해보자.

**MCP 연동 전:**
```
> Post 모델에 대한 Prisma 쿼리를 작성해줘
[AI가 추측으로 작성, 실제 컬럼명과 다를 수 있음]
```

**MCP 연동 후:**
```
> board_hub의 posts 테이블 스키마를 조회한 후,
  게시글 목록 조회 쿼리를 작성해줘 (페이지네이션, 작성자 정보 포함)

[AI가 실제 스키마를 확인하고 정확한 컬럼명으로 쿼리 작성]
```

### 8.2 데이터 기반 의사결정

```
> 현재 DB에서 가장 오래된 마이그레이션과 최근 마이그레이션을 확인하고,
  스키마 변경 이력을 요약해줘.
  그리고 현재 스키마에서 인덱스가 없는 FK 컬럼을 찾아줘.
```

### 8.3 Git과 코드의 결합

```
> 최근 3일간의 커밋 이력을 확인하고,
  posts 모듈 관련 변경사항만 추출해줘.
  그리고 변경된 파일들의 현재 코드를 읽고
```

### 이 편에서 배운 내용

- MCP의 개념: AI와 외부 시스템을 연결하는 표준 프로토콜
- MCP 없이 발생하는 문제: 환각, 컬럼명 오류, 스키마 불일치
- MCP 아키텍처: Client -> Host -> Server -> 실제 시스템
- 핵심 MCP 서버: PostgreSQL, Git, 파일 시스템, Brave Search
- 전체 실습: PostgreSQL 16 + Docker + MCP 연동
- 커스텀 MCP 서버 제작 기초
