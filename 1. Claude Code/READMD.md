- **시리즈명**: Claude Code로 시작하는 에이전틱 개발 마스터
- **대상**: 대학생, 신입 개발자·기획자·디자이너
- **교재 수**: 총 15편
- **예제 프로젝트**: SvelteKit + NestJS + PostgreSQL 16 멀티 게시판
- **최종 수정**: 2026-06-05
- **작성**: 워크포스에이아이(WorkforceAI)
- **협업**: Calude Sonnet 4.6
- **문의 이메일**: sipark@workforceai.kr

---

**비즈니스 생산성을 위한 일분일초가 아쉬운 직장인을 위하여.**

많은 기업이 혁신을 위해 '클로드(Claude)'를 도입하지만, 정작 실무자들은 밀려드는 당장 업무를 처리하느라 새로운 툴을 학습할 물리적 시간이 부족합니다.

본 교재는 이러한 실무자들의 현실적인 페인 포인트(Pain Point)를 해결하기 위해 기획되었습니다.

Calude Sonnet 4.6으로 생성하였음을 밝히며, 교재가 잘못된 정보를 담고 있을 수 있습니다. 문의 주시기 바랍니다.

## 1. 시리즈 소개

### 왜 이 교재 시리즈인가

코딩을 처음 배운 대학생도, 현업에 막 발을 내딛은 신입 개발자도, 코드 한 줄 모르는 기획자와 디자이너도 — 이 시리즈는 그 모두를 위해 설계되었다.

기존의 AI 코딩 도구 교재들은 두 가지 극단 중 하나였다. 너무 얕아서 "이걸로 뭘 할 수 있나" 싶거나, 너무 깊어서 "이걸 다 읽으려면 몇 달이 걸리나" 싶은 것들이었다. 이 시리즈는 그 사이 어딘가가 아니라, **두 가지를 동시에** 충족한다. 각 교재는 이론과 실전을 함께 다루되, 읽고 나면 반드시 무언가를 직접 만들어볼 수 있는 실습으로 끝난다.

Claude Code는 Anthropic이 만든 에이전틱 코딩 도구다. 터미널에서 자연어로 목표를 말하면 AI 에이전트가 직접 파일을 읽고 코드를 작성하고 실행하고 디버깅까지 마친 뒤 결과를 가져온다. 이 시리즈는 Claude Code가 무엇인지 이해하는 것부터, 실제 상용 서비스 수준의 풀스택 프로젝트를 혼자 완성하는 것까지의 여정을 한 줄기로 안내한다.

### 이 시리즈로 최종적으로 할 수 있는 것

- 아이디어를 PRD와 설계서로 문서화하고, Claude Code에게 자율 구현을 맡길 수 있다.
- SvelteKit + NestJS + PostgreSQL 16 기반의 멀티 게시판 풀스택 서비스를 완성할 수 있다.
- MCP, Hooks, 서브에이전트 등 Claude Code의 고급 기능을 실무 수준으로 활용할 수 있다.
- 에이전트가 잘못된 방향으로 가지 않도록 CLAUDE.md와 하네스로 제어할 수 있다.
- 예상치 못한 오류 상황에서도 당황하지 않고 체계적으로 해결할 수 있다.

## 2. 대상 독자와 역할별 학습 경로

### 2.1 대상 독자 정의

이 시리즈는 세 가지 역할을 가진 독자를 동시에 고려하여 설계되었다. 각 역할마다 핵심적으로 읽어야 할 교재가 다르다.

| 역할 | 설명 | 핵심 목표 |
|------|------|---------|
| **개발자** (Developer) | 코드를 직접 작성하거나 검토하는 역할. 신입 개발자, CS 전공 대학생 포함. | Claude Code로 개발 생산성을 극대화하고 실전 풀스택 프로젝트를 완성한다. |
| **기획자** (Planner) | 서비스 기획, 요구사항 정의, PRD 작성을 담당하는 역할. 코딩 지식이 거의 없어도 된다. | 에이전트 친화적 기획서를 작성하여 개발 팀과의 협업 품질을 높인다. |
| **디자이너** (Designer) | UI/UX를 설계하고 디자인 가이드라인을 정의하는 역할. | 디자인 규칙을 에이전트가 이해할 수 있는 형식으로 작성하여 구현 품질을 통제한다. |

### 2.2 역할별 추천 학습 경로

#### 개발자 필수 경로 (전체 이수 권장)

```
01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11 → 12 → 13 → 14 → 15
```

처음부터 끝까지 순서대로 학습하는 것을 강력히 권장한다. 각 교재는 앞 교재의 개념을 전제하고 설계되었다.

#### 기획자 핵심 경로

```
01 → 03(CLAUDE.md 개념만) → 08 → 09 → 10 → 14(해당 시나리오만)
```

코드를 직접 다루지 않더라도 에이전트가 올바르게 구현하도록 기획서를 설계하는 능력을 갖추는 경로다. 교재 01은 필수이며, 교재 08·09는 기획자의 핵심이다.

#### 디자이너 핵심 경로

```
01 → 03(스타일 규칙 섹션 집중) → 08(UI 명세 섹션 집중) → 09(ERD 제외, 화면 흐름 섹션 집중) → 12(프론트엔드 섹션)
```

디자인 가이드라인을 CLAUDE.md와 style.md에 녹여내어 에이전트가 UI를 일관되게 구현하도록 통제하는 역량을 키우는 경로다.

#### 빠른 시작 경로 (맛보기 — 하루 완성)

```
01 → 02 → 04 → 10
```

이론보다 일단 돌아가는 것을 먼저 보고 싶은 독자를 위한 경로다. 4개 교재를 읽은 뒤 교재 10의 실습을 따라하면 Claude Code로 간단한 프로젝트를 구동해볼 수 있다. 이후 나머지 교재를 순서대로 학습한다.

## 4. 단계별 교재 상세 정의

### STAGE 1 — 이해 (교재 01)

#### 교재 01. Claude Code 완벽 입문 — 에이전트 퍼스트 패러다임과 에코시스템

**한 줄 소개**: Claude Code가 무엇인지, 왜 지금 이 도구를 배워야 하는지 이해한다.

**학습 목표**:
- 코파일럿(Copilot) 시대와 에이전트 퍼스트 시대의 차이를 설명할 수 있다.
- Claude Code의 핵심 구성 요소(CLI, CLAUDE.md, 샌드박스, MCP, Hooks)의 역할을 설명할 수 있다.
- 개발자·기획자·디자이너 각각의 관점에서 Claude Code가 어떤 가치를 주는지 이해한다.

**주요 내용**:
- 에이전트 퍼스트 패러다임의 정의와 코파일럿 모델과의 근본적 차이
- Claude Code CLI 아키텍처: 자율 루프(ReAct Loop), 도구 사용(Tool Use), 샌드박스 실행
- Claude Code 에코시스템 지도: CLAUDE.md · MCP · Hooks · 서브에이전트의 관계
- 역할별 가치: 개발자(생산성), 기획자(기획-개발 간극 해소), 디자이너(UI 일관성 통제)
- 이 시리즈의 예제 프로젝트 소개: 멀티 게시판 허브의 전체 설계 개요

**대상 독자**: 개발자·기획자·디자이너 전체
**선수 교재**: 없음
**예상 학습 시간**: 60~90분

**학습 목표**:
- macOS 또는 Windows 환경에 Claude Code를 오류 없이 설치할 수 있다.
- API 키를 발급·설정하고 첫 번째 명령어를 실행할 수 있다.
- VS Code 연동 환경을 구성하고 기본 작업 흐름을 이해한다.

**주요 내용**:

- VS Code 연동 설정 및 추천 익스텐션 목록
- 설치 검증 체크리스트 및 자주 겪는 초기 오류 해결법

**대상 독자**: 개발자 (기획자·디자이너는 선택)
**선수 교재**: 01
**예상 학습 시간**: 45~90분

### STAGE 3 — 핵심 설정과 도구 (교재 03~07)

#### 교재 03. CLAUDE.md 작성 완벽 가이드 — 에이전트의 헌법 설계하기

**한 줄 소개**: CLAUDE.md는 에이전트가 프로젝트에서 반드시 지키는 규칙서다. 잘 쓴 CLAUDE.md 하나가 수백 번의 교정 지시를 대신한다.

**학습 목표**:
- CLAUDE.md의 내부 동작 원리(AST 파싱, 시맨틱 청킹)를 이해한다.
- 프로젝트 상황에 맞는 CLAUDE.md를 직접 작성할 수 있다.
- 글로벌 CLAUDE.md와 프로젝트별 CLAUDE.md의 차이를 구분하고 올바르게 적용한다.

**주요 내용**:
- CLAUDE.md란 무엇인가: 에이전트 시스템 프롬프트와의 차이
- 동작 원리: Claude Code가 CLAUDE.md를 읽고 컨텍스트에 통합하는 방식
- 파일 위치와 우선순위: 글로벌(`~/.claude/CLAUDE.md`) vs 프로젝트 루트 vs 하위 폴더
- 핵심 섹션 구성법: 프로젝트 개요, 기술 스택, 아키텍처 규칙, 금지 사항, 빌드·테스트 명령어
- `@must` · `@avoid` · `@prefer` 어노테이션 활용 패턴
- 역할별 CLAUDE.md 작성 가이드: 개발자용, 기획자용, 디자이너용(style.md 분리)
- 멀티 게시판 프로젝트용 CLAUDE.md 전체 예시 (주석 포함)
- 잘못 작성된 CLAUDE.md vs 잘 작성된 CLAUDE.md 비교 사례

**대상 독자**: 개발자·기획자·디자이너 전체
**선수 교재**: 01·02
**예상 학습 시간**: 90~120분

#### 교재 04. 기본 명령어 & 슬래시 커맨드 마스터 — Claude Code를 자유자재로 조종하는 법

**한 줄 소개**: Claude Code의 모든 명령어와 슬래시 커맨드를 체계적으로 익혀 작업 효율을 극대화한다.

**학습 목표**:
- Claude Code CLI의 전체 명령어 체계를 이해하고 필요한 명령어를 즉시 꺼내 쓸 수 있다.
- 슬래시 커맨드(`/ask`, `/review`, `/compact` 등)의 용도와 차이를 구분하여 사용한다.
- 컨텍스트 지시어(`@파일`, `@폴더`, `@URL`)로 에이전트의 집중 범위를 정밀 제어한다.

**주요 내용**:
- Claude Code 명령어 체계 전체 지도: 세션 관리 / 컨텍스트 제어 / 에이전트 제어
- 핵심 슬래시 커맨드 완전 정리
  - `/ask`: 코드를 건드리지 않고 질문·상담만 하는 모드
  - `/review`: 현재 열린 코드의 품질 검토 요청
  - `/compact`: 긴 대화 히스토리를 압축하여 컨텍스트 윈도우를 절약
  - `/clear`: 대화 히스토리 초기화
  - `/memory`: CLAUDE.md 내용 실시간 조회 및 수정
  - `/cost`: 현재 세션의 토큰 사용량과 예상 비용 확인
- 컨텍스트 지시어 활용법: `@src/routes/board` `@schema.prisma` `@https://...`
- 멀티라인 입력과 파일 첨부 방법
- 대화 세션 저장·재개(`--resume`) 활용법
- 실전 시나리오별 명령어 조합 예시 10선

**대상 독자**: 개발자
**선수 교재**: 02
**예상 학습 시간**: 90~120분

#### 교재 05. MCP(Model Context Protocol) 완벽 가이드 — 에이전트의 눈과 귀를 연결하는 법

**한 줄 소개**: MCP는 에이전트가 데이터베이스, Git, 외부 API 등 실제 시스템을 직접 들여다볼 수 있게 하는 연결 규격이다.

**학습 목표**:
- MCP의 개념과 동작 원리를 이해하고, 에이전트 환각(Hallucination) 오류를 MCP로 어떻게 해소하는지 설명할 수 있다.
- `claude_desktop_config.json`에 MCP 서버를 등록하고 정상 작동을 검증할 수 있다.
- PostgreSQL MCP, Git MCP, Filesystem MCP 등 핵심 서버를 실전 프로젝트에 연결할 수 있다.

**주요 내용**:
- MCP란 무엇인가: "AI 전용 범용 어댑터"의 역할과 필요성
- MCP 없이 개발할 때 생기는 문제: 환각, 컬럼명 추측, 스키마 불일치
- MCP 아키텍처: 에이전트(Client) → MCP Host → MCP Server → 실제 시스템
- `claude_desktop_config.json` 기본 구조 및 서버 등록 방법
- 핵심 MCP 서버 설치 및 설정 실습
  - `@modelcontextprotocol/server-postgres`: PostgreSQL 스키마 실시간 조회
  - `@modelcontextprotocol/server-git`: Git 커밋 이력 및 브랜치 조회
  - `@modelcontextprotocol/server-filesystem`: 파일 시스템 안전 접근
  - `@modelcontextprotocol/server-brave-search`: 웹 검색 연동
- 멀티 게시판 프로젝트에 PostgreSQL MCP 연동하는 전체 실습
- MCP 서버 디버깅 및 연결 오류 해결 가이드

**대상 독자**: 개발자
**선수 교재**: 03·04
**예상 학습 시간**: 90~120분

#### 교재 06. Hooks 완벽 가이드 — 에이전트 행동을 자동 제어하는 트리거 설계

**한 줄 소개**: Hooks는 에이전트가 특정 행동(파일 편집, 명령어 실행 등)을 하기 전후에 자동으로 작동하는 트리거다. 이를 통해 코드 품질과 보안을 자동으로 강제할 수 있다.

**학습 목표**:
- Claude Code Hooks의 이벤트 유형과 실행 시점을 정확히 이해한다.
- `settings.json`에 Hooks를 설정하고, 실제로 작동하는 것을 확인할 수 있다.
- ESLint·Prettier 자동 실행, 보안 키워드 차단 등 실무에 바로 쓸 수 있는 Hooks를 작성한다.

**주요 내용**:
- Hooks 개념과 필요성: "에이전트가 코드를 저장하기 전에 자동으로 검사하는 관문"
- Hooks 이벤트 유형 완전 정리
  - `PreToolUse`: 에이전트가 도구를 사용하기 직전 실행
  - `PostToolUse`: 에이전트가 도구를 사용한 직후 실행
  - `Notification`: 특정 조건에서 알림 발송
  - `Stop`: 에이전트가 응답을 완료할 때 실행
- `settings.json` 구조와 Hooks 설정 문법
- 실전 Hooks 예시 10선
  - 파일 저장 시 ESLint 자동 실행 및 에러 시 차단
  - `DROP TABLE` 구문 감지 시 인간 승인 요청
  - Prettier 자동 포맷 강제
  - 테스트 파일 수정 시 자동 테스트 실행
  - 환경 변수 파일(`.env`) 편집 시 경고 및 기록
- Hook 실행 결과 코드(exit code)로 에이전트 흐름 제어하는 방법
- 멀티 게시판 프로젝트 적용 실습: Prisma 스키마 변경 감지 Hook 구현

**대상 독자**: 개발자
**선수 교재**: 04·05
**예상 학습 시간**: 90~120분

#### 교재 07. 서브에이전트 & 멀티에이전트 — 에이전트 팀을 구성하고 조율하는 법

**한 줄 소개**: 복잡한 프로젝트는 한 명의 에이전트가 혼자 처리하지 않는다. 여러 에이전트에게 역할을 나눠 병렬로 처리하면 속도와 품질이 동시에 올라간다.

**학습 목표**:
- 서브에이전트(Sub-agent)의 개념과 오케스트레이터-서브에이전트 패턴을 이해한다.
- `Task` 도구를 활용해 서브에이전트에게 독립적인 작업을 위임하는 방법을 실습한다.
- 병렬 에이전트 실행 시 발생하는 충돌 문제와 해결 방법을 이해한다.

**주요 내용**:
- 서브에이전트란 무엇인가: 오케스트레이터와 워커의 역할 분리
- `Task` 도구 사용법: 독립된 컨텍스트에서 서브에이전트 생성하기
- 직렬 vs 병렬 에이전트 실행 비교와 선택 기준
- 병렬 실행 시 주의사항: 파일 충돌(Race Condition) 방지 패턴
- 오케스트레이터 프롬프트 설계법: 서브에이전트에게 명확한 역할과 범위 부여
- 실전 멀티에이전트 시나리오
  - 백엔드 API 구현 에이전트 + 프론트엔드 컴포넌트 구현 에이전트 병렬 운영
  - 코드 리뷰 전담 에이전트 + 테스트 작성 전담 에이전트 분리
- 멀티 게시판 프로젝트 적용 실습: 8종 게시판을 에이전트별로 분배하여 병렬 구현

  - 인증 방식 및 에러 응답 규격 통일
  - 멀티 게시판 핵심 API 명세 완성 예시 (게시글 CRUD, 파일 업로드, 인증 등)

- 설계서 완성도 자가 검증 체크리스트

#### 교재 12. 실전 완성 — SvelteKit + NestJS + PostgreSQL 16 멀티 게시판 구현

**한 줄 소개**: 이 시리즈의 집대성. 디커플드 모노레포 구조의 풀스택 멀티 게시판 서비스를 Claude Code와 함께 완성한다.

- 8종 게시판(일반·갤러리·동영상·Q&A·공지·FAQ·비공개문의·자유)의 각 비즈니스 로직을 구현할 수 있다.
- 완성된 서비스를 로컬에서 구동하고 기본적인 배포 준비까지 마칠 수 있다.

**주요 내용**:
- 모노레포 구조 전체 설계 (`frontend/` + `backend/` + 공통 설정)

  - 인증 흐름 구현: 이메일 회원가입·로그인, 구글 OAuth 연동

  - 파일 업로드: Multer + S3 or 로컬 스토리지 이중 설정
  - Prisma v5 ORM 연동 및 트랜잭션 처리
- 데이터베이스 (PostgreSQL 16)

### STAGE 6 — 심화 & 문제 해결 (교재 13~15)

#### 교재 13. 하네스 엔지니어링 — 에이전트를 안전하게 제어하는 가드레일 설계

**한 줄 소개**: 에이전트는 강력하지만 방치하면 예상치 못한 방향으로 달린다. 하네스는 에이전트가 정해진 범위 안에서만 움직이도록 설계하는 제어 아키텍처다.

**학습 목표**:
- 프롬프트 엔지니어링과 하네스 엔지니어링의 차이를 이해하고 구분할 수 있다.
- `settings.json`과 CLAUDE.md를 조합하여 프로젝트 수준의 하네스를 구축할 수 있다.
- 비용·보안·파일 접근 범위를 코드 수준에서 강제하는 가드레일을 설계할 수 있다.

**주요 내용**:
- 하네스 엔지니어링의 정의: 비결정론적 에이전트를 결정론적 시스템으로 묶는 기술
- 프롬프트 엔지니어링 vs 하네스 엔지니어링 비교표
- 하네스의 4대 구성 요소
  - **가드레일 (Guardrails)**: CLAUDE.md의 `@must`·`@avoid` 규칙 강제 집행
  - **파일 접근 제한**: 허용 경로 화이트리스트 및 `.env`·결제 모듈 보호
  - **권한 제어**: 에이전트가 특정 명령어 실행 시 인간 승인을 요구하도록 Hook 설계
  - **비용 제어**: 최대 토큰 사용량 임계치 설정 및 세션 자동 중단 트리거
- `settings.json` 완전 레퍼런스: 허용 도구 목록, 금지 명령어, Hook 집합
- 역할별 하네스 설계 전략: 신입 개발자용(엄격) vs 숙련자용(유연)
- 멀티 게시판 프로젝트 하네스 설계 실습: 결제 관련 파일 보호 + DROP 구문 차단

**대상 독자**: 개발자
**선수 교재**: 05·06·10
**예상 학습 시간**: 90~120분

#### 교재 14. 트러블슈팅 완전 정복 — 상황별 오류 해결과 복합 시나리오 대응

**한 줄 소개**: 막히면 구글링하는 시대는 끝났다. 이 교재는 Claude Code 사용 중 마주치는 20가지 오류 시나리오를 유형별로 정리하고 단계별 해결법을 제시한다.

**학습 목표**:
- Claude Code 사용 중 자주 발생하는 오류를 유형별로 분류하고 원인을 진단할 수 있다.
- 컨텍스트 고갈, 무한 루프, 파일 충돌 등 복합 시나리오를 체계적으로 해결할 수 있다.
- 오류 재발 방지를 위해 CLAUDE.md와 Hooks에 규칙을 추가하는 방법을 안다.

**주요 내용**:
- 트러블슈팅 진단 프레임워크: 오류 유형 분류 (환경·컨텍스트·에이전트·코드)
- 시나리오별 해결 가이드 (총 20개 시나리오)

  **[환경 오류]**
  1. API 키 인증 실패 및 할당량 초과
  2. Node.js·npm 버전 충돌
  3. MCP 서버 연결 실패 (포트 충돌, 프로세스 미실행)
  4. PostgreSQL 연결 거부 (호스트·포트·인증 문제)

  **[컨텍스트 오류]**
  5. 컨텍스트 윈도우 고갈 (`/compact` 활용 전략)
  6. 에이전트가 이전 대화를 "기억하지 못함"
  7. CLAUDE.md가 적용되지 않는 경우
  8. `@파일` 지시어가 무시되는 경우

  **[에이전트 동작 오류]**
  9. 에이전트가 무한 루프에 빠진 경우 (강제 중단 방법)
  10. 에이전트가 잘못된 파일을 수정하는 경우
  11. 에이전트가 PRD를 무시하고 임의 구현하는 경우
  12. 서브에이전트 간 파일 충돌 (Race Condition)
  13. 에이전트가 존재하지 않는 라이브러리를 사용하는 경우 (환각)

  **[코드/빌드 오류]**
  14. TypeScript 타입 에러 누적
  15. Prisma 마이그레이션 충돌
  16. SvelteKit 빌드 실패 (SSR 관련)
  17. NestJS 의존성 주입(DI) 오류
  18. CORS 설정 오류 (프론트·백 연동 시)
  19. 환경 변수(`.env`) 누락으로 인한 런타임 오류
  20. Docker 컨테이너 내 권한 문제

- 오류 발생 후 CLAUDE.md·Hooks에 규칙 추가하는 예방 루프
- 비상 복구 절차: Git을 활용한 상태 복원 단계별 가이드

**대상 독자**: 개발자·기획자·디자이너 전체
**선수 교재**: 10
**예상 학습 시간**: 자율 (필요한 시나리오만 선택 학습)

## 5. 기술 스택 안내

이 시리즈 전체의 실전 예제는 다음 기술 스택을 기준으로 작성된다.

| 영역 | 기술 | 선정 이유 |
|------|------|---------|
| 프론트엔드 | SvelteKit | 컴파일러 기반으로 번들 크기가 작고 학습 곡선이 낮다. 가상 DOM 없이 순수 JS로 변환되어 성능이 우수하다. |
| 백엔드 | NestJS (TypeScript) | 강력한 모듈·의존성 주입 아키텍처로 대규모 프로젝트에서도 구조가 무너지지 않는다. Spring과 유사한 구조로 Java 경험자에게 친숙하다. |
| 데이터베이스 | PostgreSQL 16 | 관계형 무결성, 대용량 처리, JSON 지원을 동시에 갖춘 오픈소스 표준 DB다. |
| ORM | Prisma v5 | TypeScript 타입 안전성을 코드와 스키마 사이에서 완벽히 보장한다. 마이그레이션 관리가 직관적이다. |
| 구조 | 디커플드 모노레포 | 프론트엔드와 백엔드를 독립적으로 배포·확장하면서도 단일 저장소에서 관리한다. |
