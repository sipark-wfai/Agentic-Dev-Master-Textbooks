## 1. 하네스 엔지니어링이란

하네스 엔지니어링(Harness Engineering)은 비결정론적(non-deterministic)인 AI 에이전트를 결정론적(deterministic)인 소프트웨어 시스템처럼 동작하게 묶는 기술이다.

"하네스(harness)"는 원래 말을 제어하기 위해 마차에 연결하는 마구(馬具)를 의미한다. 에이전트는 강력하지만 예측 불가능할 수 있다. 하네스는 에이전트의 능력을 유지하면서 제어 가능한 범위 안에서 작동하게 만드는 구조다.

### 1.1 왜 하네스가 필요한가

LLM 기반 에이전트의 본질적 특성:
- **비결정성**: 같은 입력에도 다른 결과를 낼 수 있다
- **환각**: 없는 정보를 있다고 생성할 수 있다
- **범위 초과**: 요청 범위를 벗어난 파일을 수정할 수 있다
- **비용 미고려**: 컨텍스트 윈도우를 불필요하게 채울 수 있다

하네스는 이 특성들을 외부 제어 레이어로 보완한다.

### 1.2 프롬프트 엔지니어링 vs 하네스 엔지니어링

| 항목 | 프롬프트 엔지니어링 | 하네스 엔지니어링 |
|------|---------------------|-------------------|
| 제어 위치 | 에이전트 내부 (프롬프트 텍스트) | 에이전트 외부 (시스템 레이어) |
| 신뢰도 | 에이전트가 "따르기를 원함" | 물리적으로 강제됨 |
| 우회 가능성 | 에이전트가 무시할 수 있음 | 코드 레벨에서 차단됨 |
| 적용 방법 | CLAUDE.md, 시스템 프롬프트 | settings.json, Hooks, 파일 권한 |
| 주요 용도 | 코딩 스타일, 선호도 | 보안, 비용, 무결성 |

**결론**: 프롬프트 엔지니어링과 하네스 엔지니어링은 상호 보완적이다. 두 가지를 함께 사용해야 한다.

## 2. 하네스의 4대 구성 요소

### 2.1 가드레일 (Guardrails)

CLAUDE.md에 명시된 규칙을 Hook으로 강제하는 시스템이다. 에이전트가 CLAUDE.md를 "읽고 따르기를 원하는" 것에서 그치지 않고, 위반 시 자동으로 차단하거나 수정 요청한다.

```
가드레일 레이어:
[에이전트 코드 생성]
        |
        v
[PostToolUse Hook: code-quality-check.sh 실행]
        |
        v
any 타입 발견?  --YES--> exit 1 (에이전트에게 수정 요청)
        |
       NO
        v
console.log 발견?  --YES--> exit 1 (에이전트에게 수정 요청)
        |
       NO
        v
[코드 파일 저장 완료]
```

### 2.2 파일 접근 제한

에이전트가 작업할 수 있는 파일과 폴더를 화이트리스트로 제한한다.

```json
// .claude/settings.json
{
  "permissions": {
    "allow": [
      "apps/backend/src/**",
      "apps/frontend/src/**",
      "packages/shared/src/**",
      "prisma/schema.prisma",
      "docs/**"
    ],
    "deny": [
      ".env",
      ".env.*",
      "**/.env",
      "prisma/migrations/**",
      "*.key",
      "*.pem",
      "**/*.secret"
    ]
  }
}
```

### 2.3 권한 제어 (Human-in-the-Loop)

되돌릴 수 없는 작업 전에 인간의 승인을 요구하는 Hook이다.

```bash
# .claude/hooks/human-approval.sh
#!/bin/bash
COMMAND="${1}"
ACTION="${2}"  # PreToolUse | PostToolUse

# 되돌릴 수 없는 작업 목록
IRREVERSIBLE_PATTERNS=(
  "prisma migrate deploy"
  "prisma db push --force-reset"
  "docker rm"
  "rm -rf"
  "git push --force"
  "DROP TABLE"
  "DELETE FROM.*WHERE"
)

for pattern in "${IRREVERSIBLE_PATTERNS[@]}"; do
  if echo "$COMMAND" | grep -iE "$pattern" > /dev/null 2>&1; then
    echo ""
    echo "=========================================="
    echo "  인간 승인 필요: 되돌릴 수 없는 작업"
    echo "=========================================="
    echo "명령어: $COMMAND"
    echo ""
    echo "이 작업을 실행하려면 '승인'을 입력하세요."
    echo "(취소하려면 Enter 또는 '취소' 입력)"
    echo ""
    read -p "> " CONFIRM
    
    if [ "$CONFIRM" != "승인" ]; then
      echo "작업이 취소됐습니다."
      exit 2  # 에이전트 차단
    fi
    
    echo "승인됨. 작업을 진행합니다."
    break
  fi
done

exit 0
```

### 2.4 비용 제어

토큰 사용량을 모니터링하고 임계치 초과 시 자동으로 `/compact`를 실행하거나 경고한다.

```bash
# .claude/hooks/cost-control.sh
#!/bin/bash

# Claude Code가 제공하는 현재 컨텍스트 정보
CURRENT_TOKENS="${CLAUDE_CONTEXT_TOKENS:-0}"
MAX_TOKENS="${CLAUDE_MAX_TOKENS:-200000}"
WARNING_THRESHOLD=0.7  # 70% 사용 시 경고
CRITICAL_THRESHOLD=0.9  # 90% 사용 시 강제 compact

if [ "$CURRENT_TOKENS" -gt 0 ] && [ "$MAX_TOKENS" -gt 0 ]; then
  USAGE=$(echo "scale=2; $CURRENT_TOKENS / $MAX_TOKENS" | bc)
  
  if (( $(echo "$USAGE > $CRITICAL_THRESHOLD" | bc -l) )); then
    echo "경고: 컨텍스트 윈도우가 ${USAGE}% 사용됐습니다."
    echo "자동으로 /compact를 실행합니다..."
    # Claude Code에 /compact 지시 (exit code 1로 메시지 전달)
    exit 1
    
  elif (( $(echo "$USAGE > $WARNING_THRESHOLD" | bc -l) )); then
    echo "알림: 컨텍스트 윈도우가 ${USAGE}% 사용됐습니다."
    echo "/compact 실행을 고려하세요."
  fi
fi
```

### 4.3 프로덕션 배포 하네스

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/production-deployment-guard.sh \"${command}\""
          }
        ]
      }
    ]
  }
}
```

```bash
# .claude/hooks/production-deployment-guard.sh
#!/bin/bash
COMMAND="${1}"

# 프로덕션 환경에서는 모든 배포 명령 차단 (수동 확인 필수)
PROD_COMMANDS=(
  "kubectl"
  "helm"
  "docker push"
  "prisma migrate deploy"
  "git push"
  "npm publish"
  "pnpm publish"
)

for cmd in "${PROD_COMMANDS[@]}"; do
  if echo "$COMMAND" | grep -i "$cmd" > /dev/null 2>&1; then
    echo "프로덕션 배포 명령이 감지됐습니다: $COMMAND"
    echo "이 명령은 에이전트가 자동으로 실행할 수 없습니다."
    echo "직접 터미널에서 실행해주세요."
    exit 2
  fi
done
```

## 5. 멀티 게시판 프로젝트 하네스 설계 실습

### 5.1 하네스 설치 스크립트

```bash
#!/bin/bash
# .claude/install-harness.sh

echo "Board Hub 하네스 설치 중..."

# 디렉토리 생성
mkdir -p .claude/hooks
mkdir -p .claude/logs

# Hook 스크립트 생성 및 권한 설정
cat > .claude/hooks/auto-lint.sh << 'HOOKEOF'
#!/bin/bash
FILE="${1}"
if echo "$FILE" | grep -E "\.(ts|tsx|js|svelte)$" > /dev/null; then
  npx eslint --fix "$FILE" 2>&1 || exit 1
fi
HOOKEOF

cat > .claude/hooks/code-quality-check.sh << 'HOOKEOF'
#!/bin/bash
FILE="${1}"
if echo "$FILE" | grep -E "\.(ts|tsx)$" > /dev/null; then
  ISSUES=0
  
  # any 타입 검사
  ANY_COUNT=$(grep -c ": any" "$FILE" 2>/dev/null || echo 0)
  if [ "$ANY_COUNT" -gt 0 ]; then
    echo "코드 품질: any 타입 ${ANY_COUNT}개 발견 - 수정 필요"
    ISSUES=1
  fi
  
  # console.log 검사
  LOG_COUNT=$(grep -c "console\.log" "$FILE" 2>/dev/null || echo 0)
  if [ "$LOG_COUNT" -gt 0 ]; then
    echo "코드 품질: console.log ${LOG_COUNT}개 발견 - Logger 사용 권장"
    ISSUES=1
  fi
  
  exit $ISSUES
fi
HOOKEOF

chmod +x .claude/hooks/*.sh 2>/dev/null || true

echo "하네스 설치 완료!"
echo ""
echo "보호되는 항목:"
echo "  - any 타입 자동 감지 및 수정 요청"
echo "  - console.log 자동 감지"
echo "  - .env 파일 직접 수정 차단"
echo "  - 위험한 SQL 명령 인간 승인 필요"
echo "  - 보안 키워드 평문 저장 차단"
```

### 5.2 하네스 상태 확인

```bash
# 하네스 동작 테스트
echo "하네스 테스트 중..."

# 테스트 1: any 타입 감지
echo 'function test(x: any) { return x; }' > /tmp/test-any.ts
bash .claude/hooks/code-quality-check.sh "/tmp/test-any.ts"
echo "exit code: $? (1이어야 함)"

# 테스트 2: 보안 키워드 감지

# 테스트 3: Prisma DROP 차단
bash .claude/hooks/human-approval.sh "psql -c 'DROP TABLE users'" PreToolUse
echo "exit code: $? (2이어야 함, 수동 입력 없이)"
```

## 6. 하네스 엔지니어링 성숙도 모델

| 레벨 | 설명 | 구현 내용 |
|------|------|-----------|
| Level 0 | 무하네스 | 에이전트 제약 없이 자유 실행 |
| Level 1 | 기본 가드레일 | CLAUDE.md 규칙 + ESLint Hook |
| Level 2 | 파일 보호 | .env 보호 + 파일 접근 제한 |
| Level 3 | 인간 승인 | 위험한 명령어 승인 요청 |
| Level 4 | 자동 검증 | TypeScript 타입 검사 + 테스트 자동 실행 |
| Level 5 | 완전 통제 | 비용 제한 + 롤백 체계 + 감사 로그 |

멀티 게시판 허브 개발에서는 Level 3~4 수준의 하네스를 권장한다.
