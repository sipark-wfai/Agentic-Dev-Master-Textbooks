## 1. 에이전트 퍼스트 패러다임이란 무엇인가

소프트웨어 개발의 역사는 도구가 개발자의 의도를 얼마나 깊이 이해하느냐에 따라 계속 진화해 왔다. 텍스트 에디터에서 IDE로, IDE에서 코파일럿으로, 그리고 지금은 에이전트 퍼스트(Agent-First) 패러다임으로 전환이 일어나고 있다.

에이전트 퍼스트 패러다임은 "AI가 스스로 계획하고, 도구를 사용하며, 결과를 검토하고, 다음 행동을 결정한다"는 철학을 기반으로 한다. 개발자는 매 단계를 직접 지시하지 않고, 목표와 제약 조건만 제시한다. AI 에이전트가 나머지를 처리한다.

### 1.1 코파일럿 vs 에이전트 비교

| 구분 | 코파일럿(Copilot) 방식 | 에이전트(Agent) 방식 |
|------|------------------------|----------------------|
| 상호작용 단위 | 줄 단위 또는 함수 단위 자동완성 | 태스크 단위 자율 실행 |
| 사용자 역할 | 모든 결정을 인간이 내림 | 목표와 제약만 제시 |
| 컨텍스트 이해 | 현재 열린 파일에 한정 | 프로젝트 전체 구조 파악 |
| 도구 사용 | 없음 (코드 제안만) | 파일 읽기/쓰기, 명령어 실행, 검색 등 |
| 오류 처리 | 인간이 에러를 보고 재요청 | 에러를 스스로 감지하고 수정 시도 |
| 작업 범위 | 단일 파일, 단일 함수 | 멀티 파일, 멀티 모듈, 전체 기능 |
| 학습 곡선 | 낮음 (제안 수락/거절만 함) | 중간 (프롬프트 설계 능력 필요) |
| 생산성 향상 | 10~30% | 200~500% (복잡한 작업 기준, 사용자·작업 유형에 따라 편차 있음) |<!-- R3 수정: 검증 불가 수치에 면책 문구 추가 -->

코파일럿은 개발자가 키보드를 치는 속도를 높여주는 도구다. 반면 에이전트는 개발자가 키보드를 치지 않아도 작업을 완수한다. 이것이 패러다임 전환의 핵심이다.

### 1.2 왜 지금인가

2025년을 기점으로 LLM의 컨텍스트 윈도우가 수십만 토큰을 넘어섰고, 추론 능력이 시니어 개발자 수준에 근접했다. 동시에 MCP(Model Context Protocol) 같은 표준 인터페이스가 등장하여 AI가 실제 외부 시스템과 연결될 수 있게 됐다. 도구 사용(Tool Use) 능력이 성숙해지면서 에이전트가 단순한 텍스트 생성기가 아니라 실질적인 작업 수행자로 진화했다.

## 2. Claude Code란 무엇인가

Claude Code는 Anthropic이 개발한 CLI 기반 에이전틱 코딩 도구다. 터미널에서 `claude` 명령어 하나로 실행하면, Claude가 프로젝트 전체를 탐색하고, 파일을 읽고 쓰고, 명령어를 실행하고, 오류를 수정하는 전 과정을 자율적으로 수행한다.

핵심 특징을 정리하면 다음과 같다.

- **CLI 퍼스트**: GUI 없이 터미널에서 동작한다. CI/CD 파이프라인에 직접 통합 가능하다.
- **프로젝트 인식**: 프로젝트 루트의 CLAUDE.md를 읽어 컨텍스트를 자동으로 구성한다.
- **도구 사용**: 파일 시스템 접근, 쉘 명령어 실행, 웹 검색 등 다양한 도구를 활용한다.
- **MCP 연동**: 데이터베이스, Git, 외부 API 등과 실시간으로 연결된다.
- **Hooks 지원**: 에이전트의 행동 전후에 자동 실행되는 트리거를 설정할 수 있다.
- **멀티에이전트**: 여러 서브에이전트를 병렬로 실행하여 대규모 작업을 처리한다.

### 2.1 Claude Code의 위치

```
+--------------------------------------------------+
|              개발자 / 기획자                      |
|         (목표와 제약 조건 제시)                   |
+--------------------------------------------------+
                      |
                      v
+--------------------------------------------------+
|              Claude Code CLI                     |
|         (에이전틱 실행 엔진)                      |
+---------------+---------------+------------------+
|   CLAUDE.md   |     MCP       |     Hooks        |
|  (규칙/컨텍)  | (외부 연결)   |  (행동 제어)     |
+-------+-------+-------+-------+--------+---------+
        |               |                |
        v               v                v
+----------+  +------------------+  +----------+
|파일 시스템|  |DB/Git/API 등     |  | 스크립트 |
+----------+  +------------------+  +----------+
```

## 3. ReAct 루프: 에이전트의 자율 실행 원리

Claude Code는 ReAct(Reasoning + Acting) 패턴을 기반으로 작동한다. ReAct는 LLM이 추론(Reasoning)과 행동(Acting)을 교대로 수행하면서 목표를 달성하는 방식이다.

### 3.1 ReAct 루프 단계

```
+------------------------------------+
|        사용자 요청 입력             |
+------------------+-----------------+
                   |
          +--------v---------+
          |  1. 추론(Think)   |
          |  목표 분석,       |
          |  계획 수립        |
          +--------+---------+
                   |
          +--------v---------+
          |  2. 행동(Act)     |
          |  도구 실행:       |
          |  파일읽기/쓰기,   |
          |  명령어 실행 등   |
          +--------+---------+
                   |
          +--------v---------+
          |  3. 관측(Obs)     |
          |  실행 결과 확인   |
          |  오류 여부 판단   |
          +--------+---------+
                   |
          완료?    |
          +--------+------+
          |               |
         NO              YES
          |               v
          |     +------------------+
          |     |   결과 반환      |
          |     +------------------+
          |
          +---> 다시 1번(추론)으로
```

### 3.2 실제 ReAct 루프 예시

개발자가 "게시글 CRUD API를 만들어줘"라고 요청했을 때 Claude Code의 내부 처리 흐름은 다음과 같다.

**[추론 1]** 요청을 분석한다. CLAUDE.md를 읽어 기술 스택이 NestJS + Prisma + PostgreSQL임을 확인한다. 기존 모듈 구조를 파악하기 위해 src/ 폴더를 탐색한다.

**[행동 1]** `CLAUDE.md`, `src/app.module.ts`, `prisma/schema.prisma`를 읽는다.

**[관측 1]** 기존 스키마에 Post 모델이 없음을 확인한다. Auth 모듈이 이미 존재함을 확인한다.

**[추론 2]** Prisma 스키마에 Post 모델을 추가하고, NestJS Post 모듈을 생성해야 한다. 순서를 계획한다: 스키마 -> 마이그레이션 -> 모듈 -> 컨트롤러 -> 서비스 -> DTO.

**[행동 2]** `prisma/schema.prisma`에 Post 모델을 추가한다.

**[관측 2]** 파일이 성공적으로 수정됐다.

**[행동 3]** `npx prisma migrate dev --name add_post` 명령어를 실행한다.

**[관측 3]** 마이그레이션이 성공했다.

이 루프가 완료될 때까지 수십 번의 추론-행동-관측 사이클이 자동으로 반복된다.

## 4. Claude Code 에코시스템 구성 요소

Claude Code는 단독 도구가 아니라 여러 구성 요소가 유기적으로 연결된 에코시스템이다.

### 4.1 CLI (Command Line Interface)

터미널에서 `claude` 명령어로 실행하는 핵심 인터페이스다.

```bash
# 대화형 세션 시작
claude

# 프로젝트 폴더를 지정하여 시작
claude /path/to/project

# 일회성 명령 실행
claude "게시판 목록 API를 NestJS로 구현해줘"

# 이전 세션 이어서 진행
# R3 수정: --resume 플래그는 버전별 지원 여부 상이. 대화형 모드에서 /resume 슬래시 커맨드 사용 권장
claude --resume
```

### 4.2 CLAUDE.md

에이전트가 프로젝트에서 반드시 읽고 따르는 규칙서다. 인간으로 비유하면 신입 개발자에게 주는 온보딩 문서와 같다. 기술 스택, 코딩 컨벤션, 금지 사항, 빌드 명령어 등을 담는다.

```markdown
# 프로젝트: 멀티 게시판 허브

## 기술 스택
- 프론트엔드: SvelteKit 2.x
- 백엔드: NestJS 10.x
- DB: PostgreSQL 16 + Prisma v5
- 패키지 매니저: pnpm

## 절대 금지
- any 타입 사용 금지
- 하드코딩된 비밀키 금지
- console.log 프로덕션 코드에 사용 금지
```

### 4.3 MCP (Model Context Protocol)

AI와 외부 시스템을 연결하는 표준 프로토콜이다. PostgreSQL, Git, 파일 시스템, 웹 검색 등과 실시간으로 연결하여 에이전트가 실제 데이터를 기반으로 작업할 수 있게 한다.

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/board_hub"]
    }
  }
}
```

### 4.4 Hooks

에이전트가 특정 행동을 하기 전후에 자동 실행되는 트리거다. 파일 저장 시 린팅, 위험한 SQL 감지 시 인간 승인 요청, 테스트 자동 실행 등을 구현할 수 있다.

```json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "command",
        "command": "npx eslint --fix ${file}"
      }]
    }]
  }
}
```

### 4.5 서브에이전트 (Sub-agents)

하나의 오케스트레이터 에이전트가 여러 워커 에이전트를 생성하여 작업을 병렬로 처리한다. 8종 게시판을 동시에 구현할 때 각 게시판마다 독립된 에이전트를 배정하는 식으로 활용한다.

```
[오케스트레이터]
      |
      +-- [서브에이전트 1] 일반 게시판 API 구현
      +-- [서브에이전트 2] 갤러리 게시판 API 구현
      +-- [서브에이전트 3] Q&A 게시판 API 구현
      +-- [서브에이전트 4] 공지 게시판 API 구현
      (병렬 실행)
```

## 5. 역할별 가치: 누가 왜 배워야 하는가

### 5.1 개발자에게

생산성 극대화가 핵심 가치다. 반복적인 보일러플레이트 코드 작성, CRUD 구현, 테스트 작성 등 시간을 많이 소모하지만 창의성이 크게 필요 없는 작업을 에이전트에게 위임한다.

실제로 숙련된 Claude Code 사용자는 다음과 같은 생산성 향상을 경험한다.

- 신규 기능 구현 시간: 기존 대비 크게 단축 (사용자마다 다를 수 있음)
- 버그 수정 시간: 기존 대비 절반 가까이 단축 (에러 메시지 자동 분석) (사용자마다 다를 수 있음)
- 문서 작성 시간: 기존 대비 대폭 단축 (코드에서 자동 생성) (사용자마다 다를 수 있음)

주의: 에이전트가 생성한 코드는 반드시 검토해야 한다. 에이전트는 빠르지만, 비즈니스 로직의 정확성은 개발자가 확인해야 한다.

### 5.2 기획자에게

기획-개발 간극 해소가 핵심 가치다. 기획자가 작성한 PRD(제품 요구사항 문서)를 Claude Code에 제시하면, 에이전트가 그 문서를 읽고 개발 가능한 수준의 설계서와 초기 코드를 생성한다.

이를 통해 기획자는:
- 개발자에게 설명하는 시간을 줄인다.
- 프로토타입을 빠르게 만들어 아이디어를 검증한다.
- 기술적 제약을 사전에 파악하고 기획을 조정한다.

### 5.3 디자이너에게

UI 일관성 통제가 핵심 가치다. 디자인 시스템과 컴포넌트 규칙을 CLAUDE.md의 style.md에 기록해두면, 에이전트가 새 화면을 만들 때 자동으로 그 규칙을 따른다.

## 6. 예제 프로젝트: 멀티 게시판 허브 전체 설계 개요

이 시리즈 전체를 통해 구축할 프로젝트는 멀티 게시판 허브다. 하나의 플랫폼에서 8종의 게시판을 통합 관리하는 커뮤니티 서비스다.

### 6.1 8종 게시판 유형

| 게시판 유형 | 설명 | 주요 특징 |
|-------------|------|-----------|
| 일반 게시판 | 일반적인 텍스트 게시글 | 좋아요, 댓글, 검색 |
| 갤러리 게시판 | 이미지 중심 게시글 | 썸네일 그리드, 이미지 업로드 |
| 동영상 게시판 | 동영상 임베드/업로드 | YouTube 임베드, 직접 업로드 |
| Q&A 게시판 | 질문-답변 형식 | 채택 기능, 답변 정렬 |
| 공지 게시판 | 관리자 전용 작성 | 상단 고정, 읽음 표시 |
| FAQ 게시판 | 자주 묻는 질문 | 아코디언 형식, 카테고리 |
| 비공개 문의 | 1:1 문의 | 작성자+관리자만 열람 |
| 자유 게시판 | 익명 허용 게시판 | 익명 옵션, 신고 기능 |

### 6.2 기술 스택

```
+--------------------------------------------------+
|                   프론트엔드                      |
|         SvelteKit 2.x (TypeScript)               |
|   TailwindCSS + shadcn-svelte + Lucide Icons     |
+--------------------------------------------------+
                      | REST API
+--------------------------------------------------+
|                    백엔드                         |
|          NestJS 10.x (TypeScript)                |
|        JWT Auth + Passport + Multer              |
+--------------------------------------------------+
                      | Prisma ORM
+--------------------------------------------------+
|                  데이터베이스                      |
|           PostgreSQL 16 (Prisma v5)              |
|         Full-text Search + JSONB + UUID          |
+--------------------------------------------------+
```

### 6.3 핵심 기능 목록

- **인증**: 이메일/비밀번호 회원가입, JWT 로그인, 리프레시 토큰
- **회원 관리**: 프로필, 포인트, 차단, 알림
- **게시글**: 작성, 수정, 삭제, 조회수, 좋아요, 북마크
- **파일**: 이미지/동영상 업로드, 썸네일 자동 생성
- **댓글**: 계층형 댓글(대댓글), 좋아요, 신고
- **검색**: 전문 검색(Full-text), 태그 검색
- **관리자**: 게시판 설정, 회원 관리, 신고 처리

## 7. Claude Code가 실제로 할 수 있는 것 vs 없는 것

현실적인 기대치를 설정하는 것이 중요하다. Claude Code는 강력한 도구지만 만능은 아니다.

### 7.1 할 수 있는 것

| 범주 | 구체적 예시 |
|------|-------------|
| 코드 생성 | CRUD API 전체 구현, 컴포넌트 생성, 타입 정의 |
| 리팩터링 | 중복 코드 제거, 패턴 일관화, 타입 강화 |
| 디버깅 | 에러 메시지 분석, 원인 파악, 수정 제안 및 적용 |
| 테스트 | 단위 테스트, 통합 테스트 자동 작성 |
| 문서화 | JSDoc, README, API 문서 자동 생성 |
| 스키마 설계 | ERD 제안, Prisma 스키마 작성 |
| 코드 리뷰 | 잠재적 버그, 보안 취약점, 성능 이슈 지적 |
| 마이그레이션 | 라이브러리 버전 업그레이드, 프레임워크 마이그레이션 |

### 7.2 할 수 없는 것 (또는 주의가 필요한 것)

| 범주 | 설명 | 대안 |
|------|------|------|
| 비즈니스 판단 | "이 기능이 사용자에게 필요한가?" 판단 불가 | 인간이 PRD에서 결정 |
| 실시간 데이터 | 현재 프로덕션 DB 상태 모름 (MCP 연결 시 가능) | MCP 연동 |
| UI/UX 감각 | 기술적으로는 구현하지만 미적 판단은 부족 | 디자이너 리뷰 필수 |
| 보안 보장 | 취약점을 줄이지만 완전한 보안 감사는 불가 | 보안 전문가 리뷰 |
| 복잡한 알고리즘 최적화 | 성능 병목이 복잡할 경우 한계 있음 | 프로파일링 후 수동 최적화 |
| 법적 책임 | 생성된 코드의 법적 책임은 개발자에게 있음 | 라이선스 직접 확인 |

## 8. 에이전트 퍼스트 시대, 개발자와 기획자의 역할 변화

### 8.1 개발자의 역할 변화

에이전트 퍼스트 시대의 개발자는 코드를 직접 작성하는 장인에서 에이전트를 지휘하는 엔지니어링 디렉터로 전환된다.

중요해지는 역량:
- **시스템 아키텍처 설계**: 에이전트가 구현하기 좋은 구조를 설계하는 능력
- **프롬프트 엔지니어링**: 에이전트에게 명확한 지시를 전달하는 능력
- **코드 리뷰 및 검증**: 에이전트가 생성한 코드의 품질을 판단하는 능력
- **하네스 설계**: 에이전트가 잘못된 방향으로 가지 않도록 제어하는 능력

상대적으로 덜 중요해지는 것:
- 단순 반복 코드 타이핑 속도
- 기본 CRUD 구현 지식 암기
- 보일러플레이트 코드 패턴 기억

### 8.2 기획자의 역할 변화

기획자는 이제 문서를 작성하는 사람에서 에이전트와 함께 프로덕트를 직접 만드는 사람으로 진화할 수 있다.

에이전트 친화적인 PRD를 작성하면, 기획자가 직접 Claude Code를 실행하여 프로토타입을 확인하는 것이 가능해진다. 이는 개발자에게 "이런 것을 만들어 달라"고 설명하는 과정 없이 빠르게 검증할 수 있음을 의미한다.

### 8.3 팀 협업 패턴의 변화

```
기존 워크플로우:
기획 -> 디자인 -> 개발 -> QA -> 배포
(각 단계 사이에 긴 대기 시간 존재)

에이전트 퍼스트 워크플로우:
기획(PRD) + 디자인(스타일 가이드) -> Claude Code 자율 구현 -> 검토 -> 배포
(병렬 진행, 빠른 반복)
```

## 10. 시작하기 전 마음 준비

### 10.1 에이전트와의 협업 마인드셋

Claude Code를 처음 사용하면 몇 가지 공통적인 반응이 나타난다.

**"와, 신기하다!"** — 처음 몇 분간의 반응. 에이전트가 자율적으로 파일을 읽고 코드를 작성하는 모습을 처음 볼 때의 반응이다.

**"이게 맞나? 내가 원한 게 이게 아닌데."** — 에이전트가 자신의 기대와 다르게 구현했을 때. 이것이 학습의 출발점이다. 더 명확한 CLAUDE.md와 프롬프트 작성법을 배워야 하는 신호다.

**"이 정도면 충분히 쓸 만하다."** — 에이전트의 한계와 강점을 파악하고 나서의 반응. 이 단계에서 진정한 생산성 향상이 시작된다.

### 10.2 이 시리즈를 최대한 활용하는 법

1. **실습을 빠뜨리지 않는다**: 이론을 읽는 것만으로는 부족하다. 직접 코드를 실행해야 감이 생긴다.
2. **예제 프로젝트를 끝까지 따라간다**: 15편 전체를 통해 멀티 게시판 허브를 실제로 완성한다.
3. **실수를 두려워하지 않는다**: 에이전트가 잘못된 코드를 생성해도 Git으로 되돌릴 수 있다.
4. **CLAUDE.md를 꾸준히 개선한다**: 에이전트와 함께 일하면서 불편한 점이 생기면 CLAUDE.md를 수정한다.

## 11. 정리 및 체크리스트

### 이 편에서 배운 내용

- 에이전트 퍼스트 패러다임: AI가 스스로 계획하고 실행하는 새로운 개발 방식
- Claude Code: Anthropic의 CLI 기반 에이전틱 코딩 도구
- ReAct 루프: 추론(Reason) -> 행동(Act) -> 관측(Observe)의 자율 실행 사이클
- 에코시스템: CLI, CLAUDE.md, MCP, Hooks, 서브에이전트
- 예제 프로젝트: 멀티 게시판 허브 (8종 게시판, SvelteKit + NestJS + PostgreSQL 16)

### 체크리스트

- [ ] 에이전트 퍼스트와 코파일럿의 차이를 설명할 수 있다
- [ ] Claude Code의 5가지 에코시스템 구성 요소를 나열할 수 있다
- [ ] ReAct 루프의 3단계를 순서대로 설명할 수 있다
- [ ] 멀티 게시판 허브의 8종 게시판을 나열할 수 있다
- [ ] 자신의 역할에 맞는 학습 경로를 파악했다
