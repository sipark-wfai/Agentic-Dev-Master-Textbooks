## 1. 에이전트가 설계서를 처리하는 방식

Claude Code는 설계서를 읽을 때 다음을 추출한다.

- **엔티티 추출**: 테이블 이름, 필드명, 데이터 타입
- **관계 추출**: 1:N, N:M, 1:1 관계와 FK 컬럼
- **엔드포인트 추출**: HTTP 메서드, URL 패턴, 요청/응답 스키마
- **제약 조건 추출**: NOT NULL, UNIQUE, DEFAULT 값, CHECK 조건
- **비즈니스 규칙 추출**: 접근 제어, 상태 전이 규칙

에이전트 친화적인 설계서는 이 추출 과정이 오류 없이 진행되도록 **명확한 구조**와 **일관된 용어**를 사용한다.

### 1.1 좋은 설계서 vs 나쁜 설계서

**나쁜 설계서 (모호함)**:
```
게시글 테이블은 사용자와 연결되고, 게시판에 속한다.
몇 가지 상태 값을 가질 수 있다.
```

**좋은 설계서 (명확함)**:
```
Post 모델:
- id: UUID, PK
- title: VARCHAR(200), NOT NULL
- content: TEXT, NOT NULL
- status: ENUM(PUBLISHED, DRAFT, DELETED), DEFAULT PUBLISHED
- boardId: UUID, FK -> Board.id, NOT NULL
- authorId: UUID, FK -> User.id, NOT NULL
- deletedAt: TIMESTAMP, NULL (soft delete용)
```

## 2. ERD 작성 가이드 (Mermaid erDiagram)

### 2.1 Mermaid 기본 문법

```
erDiagram
    모델명 {
        타입 필드명 "설명(선택)"
    }
    모델A ||--o{ 모델B : "관계명"
```

관계 기호:
- `||--||` : 1:1
- `||--o{` : 1:N (0 이상)
- `||--|{` : 1:N (1 이상)
- `}o--o{` : N:M

### 2.2 멀티 게시판 전체 ERD

```mermaid
erDiagram
    User {
        uuid id PK
        string email UK
        string hashedPassword
        string nickname UK
        enum role "USER|ADMIN"
        boolean isActive
        DateTime createdAt
        DateTime updatedAt
        DateTime deletedAt<!-- R3 수정: Mermaid erDiagram에서 datetime은 비표준. DateTime으로 변경 -->
    }

    Board {
        uuid id PK
        string name
        string slug UK
        enum boardType "GENERAL|GALLERY|VIDEO|QNA|NOTICE|FAQ|INQUIRY|FREE"
        string description
        boolean isActive
        int sortOrder
        json settings
        datetime createdAt
        datetime updatedAt
    }

    Post {
        uuid id PK
        string title
        text content
        enum status "PUBLISHED|DRAFT"
        int viewCount
        boolean isAnonymous
        boolean isPinned
        json metadata "게시판 유형별 추가 데이터"
        uuid boardId FK
        uuid authorId FK
        DateTime createdAt
        DateTime updatedAt
        DateTime deletedAt<!-- R3 수정: Mermaid erDiagram에서 datetime은 비표준. DateTime으로 변경 -->
    }

    Comment {
        uuid id PK
        text content
        int depth "최대 2"
        uuid postId FK
        uuid authorId FK
        uuid parentId FK
        DateTime createdAt
        DateTime updatedAt
        DateTime deletedAt<!-- R3 수정: Mermaid erDiagram에서 datetime은 비표준. DateTime으로 변경 -->
    }

    File {
        uuid id PK
        string originalName
        string storedName
        string filePath
        string mimeType
        bigint fileSize
        string thumbnailPath
        uuid postId FK
        uuid uploaderId FK

    }

    Tag {
        uuid id PK
        string name UK
        string color
    }

    PostTag {
        uuid postId FK
        uuid tagId FK
    }

    PostLike {
        uuid userId FK
        uuid postId FK
        datetime createdAt
    }

    CommentLike {
        uuid userId FK
        uuid commentId FK
        datetime createdAt
    }

    User ||--o{ Post : "작성"
    User ||--o{ Comment : "작성"
    User ||--o{ File : "업로드"
    User ||--o{ PostLike : "좋아요"
    User ||--o{ CommentLike : "좋아요"
    Board ||--o{ Post : "포함"
    Post ||--o{ Comment : "포함"
    Post ||--o{ File : "첨부"
    Post ||--o{ PostTag : "태그됨"
    Post ||--o{ PostLike : "받음"
    Comment ||--o{ Comment : "대댓글"
    Comment ||--o{ CommentLike : "받음"
    Tag ||--o{ PostTag : "붙음"
```

### 2.3 ERD를 Prisma 스키마로 변환

Claude Code는 위의 ERD를 읽고 Prisma 스키마를 자동 생성할 수 있다.

```

  모든 관계와 FK를 정확하게 표현하고,
  UUID는 gen_random_uuid() 기본값을 사용해줘.
```

## 4. 유스케이스 명세서 및 시퀀스 다이어그램

### 4.1 유스케이스 명세서 형식

```markdown
## 유스케이스: UC-001 게시글 작성

**액터**: 로그인한 USER
**전제 조건**: 사용자가 로그인 상태이고, 유효한 boardId가 존재한다
**기본 흐름**:
1. 사용자가 게시판 페이지에서 "글쓰기" 버튼을 클릭한다
2. 시스템이 게시글 작성 폼을 표시한다
3. 사용자가 제목, 본문을 입력한다 (선택: 파일 첨부, 태그 추가)
4. 사용자가 "등록" 버튼을 클릭한다
5. 시스템이 입력값을 유효성 검사한다
6. 시스템이 DB에 게시글을 저장한다
7. 시스템이 게시글 상세 페이지로 리다이렉트한다

**대안 흐름**:
3a. 파일 첨부 시: /files/upload API 선행 호출 -> fileId 획득
3b. GALLERY 게시판: 이미지 최소 1개 필수

**예외 흐름**:
5a. 제목이 2자 미만: "제목을 2자 이상 입력하세요" 에러 표시
5b. 공지 게시판에서 USER가 시도: "권한이 없습니다" 에러 표시
6a. DB 저장 실패: "잠시 후 다시 시도해주세요" 에러 표시

**사후 조건**: 게시글이 DB에 저장되고 목록에 표시된다
```

### 4.2 로그인 시퀀스 다이어그램 (텍스트 형식)

```
<!-- R3 수정: 아래는 Mermaid sequenceDiagram 형식이 아닌 텍스트 흐름 표현. 실제 Mermaid 렌더링은 sequenceDiagram 블록 내에 작성 필요 -->
사용자 -> 프론트엔드: POST /auth/login {email, password}
프론트엔드 -> 백엔드: POST /api/v1/auth/login
백엔드 -> DB: SELECT * FROM users WHERE email = ?
DB -> 백엔드: User 레코드 반환
백엔드 -> 백엔드: bcrypt.compare(password, hashedPassword)

[비밀번호 불일치]
백엔드 -> 프론트엔드: 401 Unauthorized

[비밀번호 일치]
백엔드 -> 백엔드: jwt.sign(payload, secret) => accessToken
백엔드 -> 백엔드: jwt.sign(payload, refreshSecret) => refreshToken
백엔드 -> 프론트엔드: 200 OK {accessToken, refreshToken, user}
         Set-Cookie: refreshToken=...; HttpOnly; Secure; SameSite=Strict
프론트엔드 -> 프론트엔드: localStorage에 accessToken 저장
프론트엔드 -> 사용자: 메인 페이지로 이동
```

### 4.3 파일 업로드 + 게시글 작성 흐름

```
사용자 -> 프론트엔드: 이미지 파일 선택 (갤러리 게시판)
프론트엔드 -> 백엔드: POST /api/v1/files/upload (multipart)
백엔드 -> 백엔드: MIME type 검증 + 매직 바이트 검증
백엔드 -> 파일시스템: 파일 저장 (uploads/2026/06/{uuid}.jpg)
백엔드 -> 백엔드: 썸네일 생성 (200x200 crop)
백엔드 -> DB: INSERT INTO files (...)
백엔드 -> 프론트엔드: 201 {fileId, url, thumbnailUrl}

프론트엔드 -> 프론트엔드: fileId 저장

사용자 -> 프론트엔드: 제목, 설명 입력 후 "등록" 클릭
프론트엔드 -> 백엔드: POST /api/v1/boards/{boardId}/posts
                      {title, content, fileIds: [fileId]}
백엔드 -> DB: INSERT INTO posts (...)
백엔드 -> DB: UPDATE files SET postId = ... WHERE id IN (...)
백엔드 -> 프론트엔드: 201 PostResponseDto
프론트엔드 -> 사용자: 게시글 상세 페이지로 이동
```

## 6. 설계서 완성도 자가 검증 체크리스트

### ERD 완성도
- [ ] 모든 모델이 정의됐다 (User, Board, Post, Comment, File, Tag, Like)
- [ ] 모든 FK 관계가 명시됐다
- [ ] 관계의 카디널리티가 정확하다 (1:N, N:M)
